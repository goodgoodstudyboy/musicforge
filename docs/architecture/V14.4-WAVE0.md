# v14.4 Wave 0 Audit

## Scope

Wave 0 implements only the feature freeze, canonical capability and state
registries, package/schema registry, dependency baseline, directional quality
ratchet, and startup state-authority validation. It creates no CLI command, API
route, Store, public evidence package, Studio panel, or business behavior. Its
new internal documents are the signed runtime state-authority policy and the
runtime package-writer policy shipped as package data. Runtime behavior changes
are limited to fail-closed state composition and registered package-type guards.

Baseline: v14.3.5 at `131258b4bcf9786bc155e3327a64836bf5aca037`.

## Canonical Capability Registry

The registry contains 146 reviewed business and governance capabilities. A capability is not
a discovered symbol: its Store, CLI, parser registration, API, Studio, package,
verifier, schema, release-check, tests, owner, source of truth, classification,
dependencies, migration declaration, and rollback declaration are fields of
one stable `capability_id`.

Every observed surface has exactly one capability owner. Sixty capabilities
currently bind a Store, at least one public CLI/API entry, and a verifier in the
same row. Capabilities that do not naturally expose all three surfaces retain
explicit empty surface lists rather than synthetic entries.

## State Authority Registry

All 132 Store classes have explicit state declarations. Roles are 95
`authority`, 13 `evidence`, 10 `projection`, 9 `workflow`, and 5 `adapter`.
Each declaration names its entity, access mode, generation semantics, source,
and a physical namespace composed from an explicit `root_authority_id` and
relative path template. The 95 roots have finite composition bindings; no
Store class or `python://` symbol creates uniqueness. Every namespace has an
independent normalized source span, exact expression-source hash, root ID, and
relative path hash. Same-root equality and parent/child overlap fail. The real server
composition resolves every runtime-required root before background services
start; `doctor` and the Wave 0 release check invoke the same platform resolver.
Unresolved, ambiguous, equal, or parent/child runtime paths fail closed.
The signed runtime policy is package data loaded with `importlib.resources`, so
wheel installs apply the same checks without depending on a source checkout.
The loader verifies the policy, embedded Registry, embedded Baseline, frozen
state snapshot, non-empty required sections, and their mutual hashes.

The existing composition contains 375 physical overlap pairs. Each pair is an
independent approved migration exception bound to both Store IDs, root IDs,
namespace identity hashes, the approved Wave 0 baseline, approval identity and
time, ADR, owner, and v14.4.0 expiry. A path or evidence change invalidates the
old exception; class-scoped roots and aggregate waivers cannot hide overlap.
Expiry uses semantic version ordering, so every remaining exception becomes a
hard blocker when the application version reaches 14.4.0.

## Package And Schema Registry

The central package registry classifies every observed discriminator as a
top-level package, report, sidecar, event, or document. It binds all 542 unique
observed package types, all 2,687 legacy raw-write source positions, 35 parameterized
package writers, and all 246 schema constants to capabilities. Its exact-value
sets contain 559 active source literals and 35 writer-specific runtime sets.
Those runtime sets cover 109 distinct values, and the largest production writer
set contains 19 values. Each package type has either an explicit schema
declaration or a reasoned `not_applicable` declaration. Any unregistered inline
dict literal, subscript assignment, `update`, `setdefault`, `__setitem__`,
`operator.setitem`, `getattr(..., "__setitem__")`, method alias, mapping
comprehension, generator update, keyword `dict`, or pair-based `dict` write
fails the gate unless its exact legacy site is registered. Lexical constant
aliases used as keys are resolved. An unresolved key or value remains a
fail-closed raw-write site bound to its normalized lexical source hash.

Source evidence is independent of the running Python AST representation. Full
writer modules are hashed from UTF-8 source after CRLF/CR normalization to LF;
expression and scope evidence uses exact normalized source fragments selected
by stable line/column/end coordinates. Candidate analysis labels at the same
physical position are a sorted set and never allocate or reorder identities.

Wave 0 does not attempt to interpret Python inheritance, MRO, wildcard
re-exports, factories, descriptors, or dynamic dispatch. Parameterized legacy
writers have explicit qualified-symbol contracts and call the canonical
`require_registered_package_type()` guard at the write boundary. The packaged,
integrity-bound runtime policy maps each writer one-to-one to an exact frozen
type set. Production writers cannot use a catch-all set; attack and test values
are isolated to the attack-corpus writer. The scanner also freezes the exact
canonical import alias and binding hash, so a same-name function, foreign
import, attribute lookalike, or later rebinding does not satisfy the contract.
Only two explicitly declared projection writers accept a nullable discriminator;
unknown writers and every other `None` value fail before document creation.
That check remains effective through inheritance, re-export, factory, or method
alias dispatch because it executes inside the writer. Independently, every
active-tree `musicforge_*` literal is frozen by value; a new literal fails the
gate without requiring call-graph resolution. A contract metadata rewrite,
missing guard, unknown writer, or unregistered runtime value fails closed.

## Directional Quality Ratchet

The baseline binds typing limits, each Explicit Any file budget, every
module-size debt entry, mypy scope, coverage minimums, architecture limits, and
local/CI performance budgets. Maxima may only decrease, coverage minima may
only increase, architecture violations may only decrease, and each per-file
budget is compared independently. ARCH-014 and TYPE-003 remain due in v14.4.0.

## Frozen Metadata And Waivers

The baseline stores every canonical registry field, not only document hashes or
counts. Component mapping, owner, classification, source of truth, dependency
declaration, state namespace, and package/schema declaration rewrites fail even
after a document is re-signed. A permitted change requires an entry in
`architecture-v14.4-wave0-waivers.json` naming one exact target field, current
baseline integrity hash, old/new value hashes, reason, owner, expiry version,
approval status, approver, approval time, and an ADR containing the same
binding. This authorizes one old-to-new transition; a later baseline or value
cannot reuse it.

All four registry envelopes use exact package-type/schema contracts frozen in
baseline schema 5. The capability, State, Package, and waiver registries use
schemas 1, 4, 7, and 2 respectively. Schema downgrade is blocking. The updater refuses a missing
baseline and has no bootstrap or force-rebaseline path; the initial Wave 0
baseline migration is closed.

The normal updater builds and validates every candidate document in memory
before touching the working tree. A candidate State Authority policy must match
the independently approved runtime anchor; otherwise the updater returns
non-zero and directs the operator to the approved anchor migration. Successful
preflight stages every output in its destination directory before atomic
replacement. A replacement error or failed final `evaluate_wave0()` restores
the exact original bytes for every target and reports failure rather than a
partial success.

# v14.2.8 MusicForge Explicit Any 对象别名数据流安全修复施工图

## 1. 定位

v14.2.8 是 v14.2.7 的安全热修复，不扩展业务功能。它修复 collector
schema 10 只污染 Attribute/Subscript 写入的语法根名称、未追踪对象别名的
绕过。

v14.2.7 tag 不移动、不删除。只有 v14.2.8 完成最终 SHA 测试、CI、Reviewer
Package 和 Release 后，才将 v14.2.7 标记为 superseded。

## 2. 攻击面

核心攻击先令 `Alias` 成为 Any 相关 uncertain，再执行：

```python
Holder = [None]
Ref = Holder
Ref[0] = Alias
Alias = Holder[0][0]
```

运行时 `Ref` 与 `Holder` 指向同一对象，但 schema 10 只污染 `Ref`，使后续
100 个 `Alias` 注解绕过 total、layer 和 file ratchet。

## 3. 安全不变量

1. `Name = Name` 和多级直接别名必须共享对象身份。
2. 任一可能别名写入 Any/uncertain 时，整个 may-alias 组必须被污染。
3. 分支合并采用保守并集，不能因另一分支 rebind 洗白真实别名。
4. 普通顺序 rebind 必须断开旧别名，避免无关 false positive。
5. 无法可靠建模的 Any 相关动态逃逸必须 fail closed。
6. 只有类型注解消费 unknown/uncertain 时产生 hard blocker。
7. schema 10 的所有 ceiling 和固定 hash 不得提高。

## 4. 实施

- Collector scope 同时保存 binding kind 和 possible object identities。
- 直接别名复制 identity set；新对象和普通 rebind 分配新 identity。
- if/try/loop/match 合并 binding 与 may-alias 状态。
- Attribute/Subscript 写入污染所有 identity set 相交的名称。
- 原地 augmented assignment 污染当前对象的整个 may-alias 组。
- 动态调用同时识别直接 Any 和派生 uncertain 参数的保守逃逸。
- unknown 与 Any-related uncertain 分离，避免普通循环参数污染正常类型。
- 新增 schema 11、ADR-023、10-to-11 migration record。
- 新增 `v1428.explicit_any_object_alias_scope_smoke`，进入 v14/latest/GA/
  security/full。

## 7. Stop Conditions

- 任一对象别名攻击 count 不是 100。
- rebind negative case 产生 blocker。
- active tree 出现 scope-flow blocker 或任一 ceiling 提高。
- Ruff、mypy、pytest、release-check、CI 或 Reviewer Package 状态不确定。

## 8. 准确口径

v14.2.8 关闭已知对象别名洗白路径，不宣称手写 collector 已完整实现 Python
语义。v14.3 必须切换到明确的符号/别名数据流模型；ARCH-014 和 TYPE-003
继续保持开放。

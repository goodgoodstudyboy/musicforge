# v14.2.10 MusicForge Explicit Any 别名 Fail-Closed 语义收口施工图

## 1. 定位

v14.2.10 是 v14.2.9 数据流内核的边界修复，不扩展产品业务，也不继续堆叠
孤立 AST 特判。目标是让无值注解、扩展解构和有限跨过程写入遵循 Python
真实运行时语义，并在无法证明安全时 fail closed。

公开的 v14.2.9 tag 不移动、不删除。v14.2.10 完成最终 SHA CI、Nightly、
Reviewer Package 和 Release 后，v14.2.9 才标记为 superseded。

## 2. 必须关闭的攻击

1. `Ref = Holder; Ref: object` 不得断开运行时 alias。
2. `Head, *Middle, Ref = (..., Holder)` 必须从尾部映射 `Ref`。
3. `store(Holder)` 中的 `target[0] = Alias` 必须阻断不受支持的
   Any-relevant 跨过程写入，并将有限 direct-call effect 传播到 `Holder`。

三条攻击均要求：runtime 为 `typing.Any`、100 个 annotations、Ruff 与 strict
mypy 通过、collector 计数 100，并同时触发 scope、total、layer、file 门禁。

## 3. 数据流语义

- 无值 `AnnAssign` 只统计 annotation，不修改 binding 或 object identity。
- 对已知长度字面量容器记录 length；starred unpack 的 suffix 从末尾定位。
- 未知长度 unpack 保留完整 origins，结果保持 unknown，直到 annotation 消费。
- 函数参数建模为无来源 escaped object。
- Any/uncertain 写入无来源 escaped object 时产生
  `unsupported_interprocedural_any_write`。
- 直接名称调用消费有限 parameter-write summary，将污染传播到实参。
- 普通 unknown 值不是 Any；不得为了 fail closed 污染全部生产代码。
- 不做通用 Python 跨过程解释。无法可靠分析的动态 Any 写入不得成为类型别名
  权威来源。

## 4. 不变量

1. schema 升级为 13。
2. Explicit Any 总量保持 11,993，affected files 保持 461。
3. layer、file、complexity、recovery ceilings 全部不得提高。
4. active tree scope blocker 必须为零。
5. 不增加 mypy exclude、ignore-errors、全文件 Ruff suppression 或动态 globals
   注入。
6. 不移动、不删除既有公开 tag。

## 5. 实施

1. 扩展 `explicit_any_dataflow.py` 的长度、starred unpack 和 unresolved escape
   语义。
2. 修复 collector 的无值 `AnnAssign`。
3. 增加有限 direct-call member-write summary，并对不支持的 Any/uncertain
   parameter write fail closed。
4. 增加 kernel 单测、三条 100-annotation 端到端回归和安全负向用例。
5. 升级 policy schema、ADR、updater 和 material index。
6. 增加 `v14210.explicit_any_alias_fail_closed_smoke`，接入所有 v14 发布
   profile。
7. 运行 Ruff、mypy、完整 pytest、doctor、v14/security/latest/GA/full、
   Reviewer Package、最终 SHA Quality 和 Nightly LTS。

## 6. Stop Conditions

- 任一 ceiling 增长。
- 任一攻击未产生四层失败。
- active tree 新增 scope blocker。
- 正常非 Any 跨过程写入被误判。
- 完整 pytest、CI、tag、Release 或 reviewer evidence 未闭环。

## 7. 准确口径

v14.2.10 关闭当前三条已知数据流边界，不宣称实现完整 Python 解释器。
ARCH-014 与 TYPE-003 仍由 v14.3 处理；v14.2.10 只在不扩大任何预算的前提下
恢复质量门禁的可信度。

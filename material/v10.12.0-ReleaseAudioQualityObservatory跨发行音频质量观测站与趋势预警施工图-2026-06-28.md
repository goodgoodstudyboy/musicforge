# v10.12.0 Release Audio Quality Observatory 跨发行音频质量观测站与趋势预警施工图

## 1. 给开发的交接说明

当前稳定基线是 v10.11.1。

v10.11.1 已经把单个 Release 的音频基线治理和回归响应闭环收住：baseline 必须 approved/current，Regression Response 必须绑定当前 Release audio evidence，不同 Release 的 unrelated baseline 会被 hard block。

v10.12.0 的方向是把“单个 Release 的音频质量治理”升级成“跨 Release 的音频质量观测站”：

> 我们不只要知道某一次发行有没有过线，还要知道最近十次发行质量有没有下降，哪些问题反复出现，哪个风格/项目/renderer profile 更容易出问题，哪些 baseline 已经老化，下一次发行前应该优先预防什么。

这版要做一个可落地的 Release Audio Quality Observatory。它不是新的音乐生成能力，而是质量治理能力：聚合 v10.2-v10.11 的真实听审、Certification、Timeline、Regression、Baseline、Response 证据，生成跨发行趋势、风险预警、回归热区、建议动作，并接入 GA / Release signoff 的可选门禁。

开发开工前必须先确认 v10.11.1 发布干净，不要在未提交工作区上继续堆 v10.12。

## 3. 为什么 v10.12 做 Quality Observatory

到 v10.11 为止，音频治理链已经很完整：

- v10.2：Audio Lab 做真实 WAV / 人工听审。
- v10.3：Audio Fix Sprint 修复单个听审问题。
- v10.4：Audio Campaign 批量听审。
- v10.5：Campaign Governance 把听审战役接入准出。
- v10.6：Release-driven Campaign 自动从 Release tracks 创建听审战役。
- v10.7：Audio Campaign Remediation 把听审问题编排成修复闭环。
- v10.8：Release Audio Certification 做总闸。
- v10.9：Release Audio Timeline 记录长期质量证据。
- v10.10：Regression Guard 比较当前与基线是否退步。
- v10.11：Baseline Governance 和 Regression Response 形成“发现退步 -> 处理退步”的闭环。

现在剩下的问题是“跨发行趋势不可见”：

1. **质量慢性下降**
   - 每次发行都 passed，但平均 manual rating 逐步下滑。
   - high issue 没有单次爆发，但 5 次发行后累计明显增加。

2. **问题反复出现**
   - mix_balance、harsh_highs、vocal_masking 等 marker 反复出现。
   - 同一个 project/style/renderer profile 下更容易出某类问题。

3. **基线老化**
   - baseline 太旧，已经不能代表当前制作水准。
   - active baseline 本身低于最近 accepted release 的质量。

4. **修复成本上升**
   - 每次 release 都要大量 remediation 才能过线。
   - fix sprint 的 recheck 次数变多，说明生成/混音质量在退化。

5. **准出前缺少预警**
   - Release signoff 只知道当前证据 passed，不知道这次是否处于高风险趋势。
   - GA readiness 无法提示“虽然通过，但最近质量趋势值得关注”。

v10.12 就是为这些问题建一个 deterministic observatory。

## 4. 总目标

v10.12.0 要新增 Release Audio Quality Observatory：

1. 聚合多个 Release 的 audio evidence：
   - Audio Campaign
   - Audio Campaign Governance
   - Remediation
   - Audio Certification
   - Timeline
   - Regression Guard
   - Baseline Governance
   - Regression Response
2. 生成跨发行质量趋势：
   - rating trend
   - issue trend
   - health trend
   - remediation trend
   - baseline drift trend
3. 生成 Quality Risk Register：
   - repeated issue
   - degrading rating
   - baseline stale
   - high remediation cost
   - evidence coverage gap
4. 生成 Prevention Recommendations：
   - 下一次听审优先关注哪些 track / style / marker。
   - 哪些 baseline 应该更新。
   - 哪些 regression response pattern 应沉淀成固定检查。
5. 支持 Observatory Report / Export / ZIP / Offline verifier。
6. 接入 Release signoff / GA readiness 可选门禁：
   - `require_release_audio_quality_observatory=true`
7. Studio 新增 Quality Observatory 面板。
8. release-check 新增 `v1012.release_audio_quality_observatory_smoke`。

## 5. 明确不做什么

v10.12 不做：

- 不自动修改音乐。
- 不自动创建 Audio Fix Sprint。
- 不自动替换 baseline。
- 不自动签核或阻断所有 release。
- 不用 provider / LLM 判断质量。
- 不把 synthetic/fake WAV 计入 release-ready 趋势。
- 不把 Observatory Report 当作单个 Release 的替代证据。单个 Release 仍必须有 Certification / Timeline / Regression / Response。
- 不做云端监控或远程 telemetry。只做本地 deterministic aggregation。

Observatory 的职责是预警、汇总、建议和可选门禁，不是自动修复。


Scope rules：

## 19. Offline Verifier

新增 `verify_release_audio_quality_observatory_package()`。

必须校验：

- ZIP exists / readable。
- duplicate entry failed。
- dangerous path / backslash / drive path / `.MusicForge` variants failed。
- nested zip failed。
- manifest package_type == `release_audio_quality_observatory`。
- fixed allow-list。
- manifest.files[] 必须等于固定结构。
- 每个 JSON sidecar integrity hash。
- source_hash 在 source-index / trend / heatmap / drift / remediation / risk / recommendation / summary 中一致。
- evidence-fingerprints 必须和外部 evidence 反查一致。
- report 不允许仅靠自身重签放行。

## 20. Release signoff gate

Release signoff payload 新增：

```json
{
  "require_release_audio_quality_observatory": true,
  "release_audio_quality_observatory_id": "aqo-000001",
  "require_no_critical_audio_quality_risk": true
}
```

Gate 规则：

- 如果 `require_release_audio_quality_observatory=false`，不阻断。
- 如果 required：
  - Observatory report 必须 current。
  - ZIP verification 必须 passed。
  - evidence fingerprints 必须可反查当前 release evidence。
  - 如果 `require_no_critical_audio_quality_risk=true`，critical risk 直接 failed，force=true 不能绕过。
  - warning risk 可以进入 acceptance_gate summary，但不自动 hard block，除非 thresholds 配置为 failed。

注意：

- Observatory gate 不能替代 v10.8/v10.9/v10.10/v10.11 单 Release gate。
- 它只能补充趋势层风险。

## 23. release-check

新增：

```text
v1012.release_audio_quality_observatory_smoke
```

Profiles：

- `v10`
- `ga`
- `latest`
- `full`
- `quick` 可加入，如果耗时低于 10 秒。

Smoke 覆盖：

1. 创建两个或三个 signed Release audio evidence 样本。
2. 创建 Observatory。
3. Refresh 生成 trend / heatmap / drift / risk / recommendation。
4. Export / ZIP / verify passed。
5. GA readiness with observatory passed/warning。
6. 人为制造 rating drop，risk register warning/failed。
7. `require_no_critical_audio_quality_risk=true` 时 critical risk gate failed。
8. 篡改 trend-report 并重签，verifier failed。
9. 篡改 evidence-fingerprints，verifier failed。
10. 删除一个外部 Certification verification report，verifier failed。
11. declared extra ZIP entry failed。
12. duplicate ZIP entry failed。
13. redaction polluted report failed。

Smoke detail 示例：

```text
observatory=passed, trend=warning, risks=2, ga=passed/warning, critical_gate=failed, trend_full_resign=failed, evidence_missing=failed, declared_extra=failed, redaction=failed
```

## 26. P1 风险清单

### P1：Observatory 只信包内自证

风险：篡改 trend/risk/recommendation 后重算 integrity。

必须防：

- verifier 从外部 evidence fingerprints 反查 Certification / Timeline / Regression / Response。
- trend/risk 必须能由 source-index 重新推导关键字段。

### P1：旧 evidence 被复用

风险：Release 更新了 Certification / Timeline，但 Observatory 仍使用旧 fingerprint。

必须防：

- evidence-fingerprints 绑定 zip sha / size / manifest hash / verification report hash。
- gate 每次都重新读取当前 local evidence 或外部 evidence root。

### P1：critical risk 被 warning 化

风险：critical issue 被 report 重签降成 warning。

必须防：

- risk severity 从 source issue taxonomy 重新推导。
- `require_no_critical_audio_quality_risk=true` 用重新推导结果。

### P1：fake/test WAV 混入趋势

风险：测试 WAV 被算进 release-ready trend。

必须防：

- source discovery 必须检查 Certification / Audio Campaign 的 real_audio / manual review gate。
- fake/test evidence 只能进入 warning，不可算作 accepted quality。

### P1：baseline drift 漏报

风险：active baseline 已过期，但 observatory 仍显示 passed。

必须防：

- baseline age 根据 release ordering 计算。
- revoked/superseded baseline 被 current release 使用直接 failed。

## 28. 给开发的话

这版是 v10 音频治理的“观测站”，不是一个孤立证明包。你要做的是把过去十个版本积累下来的真实音频证据串起来，让系统能回答三个问题：

1. 最近发行质量有没有变差？
2. 哪些问题反复出现？
3. 下一次发行前应该优先防什么？

实现时不要图省事只做 JSON 汇总。所有趋势和风险都必须能从外部证据重建，所有 verifier 都必须挡住“包内整体重签”。每个 Phase 做完就提交并推 GitHub，不要等最后堆一个大提交。

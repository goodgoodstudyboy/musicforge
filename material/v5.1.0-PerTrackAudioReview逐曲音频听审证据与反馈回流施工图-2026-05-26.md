# v5.1.0 Per-Track Audio Review 逐曲音频听审证据与反馈回流施工图

日期：2026-05-26

角色定位：reviewer / planner

当前稳定基线：v5.0.0

目标版本：v5.1.0

---

## 1. 背景

v5.0.0 已经完成 Real Audio Baseline：

- Renderer Profile
- WAV Audio Health
- Audio Artifact Manifest
- Acceptance 强制真实 WAV + manual listening evidence
- Release Audio QA
- Release Signoff audio gate
- `verify-release --require-audio --require-human-review`

这一步已经把 MusicForge 从 MIDI-only 推进到真实 WAV 音频验收。

但 v5.0 还有一个必须继续收紧的点：

> `require_human_audio_review` 目前确认的是 Acceptance Suite 里存在 manual WAV accepted evidence，但还不是 Release 里每一首 track 都绑定了“这个 WAV 被人听过”的证据。

这意味着：

- Release 里有 5 首歌，但 Acceptance Suite 里只有 1 首 manual WAV accepted，现有 gate 可能只看到“有人工 WAV 证据”。
- 人工听审证据没有强绑定到 Release Track。
- 听审 marker 还不能稳定回流到 ReviewTask / Fix Sprint。
- “这首歌听过”和“某个验收 case 听过”之间缺少可审计映射。

v5.1.0 要解决这个问题。

---

## 2. 版本定位

v5.1.0 的定位是：

> 每一首准备发行的 track，都必须有绑定到当前 WAV artifact 的人工听审证据；听审中提出的问题可以直接回流为 ReviewTask 或 Acceptance Fix Sprint 输入。

关键词：

- Per-track
- Current WAV artifact
- Manual review evidence
- Marker to section/beat mapping
- Feedback to ReviewTask
- Release signoff hard gate
- Offline verifier evidence

---

## 3. 明确不做

v5.1.0 不做以下内容：

- 不做混音控制台，volume/pan/mute/solo 放 v5.2。
- 不做 MP3/AAC 多格式验收，放 v5.3。
- 不做外部音乐生成 provider，放 v6.0 以后。
- 不做 AI 自动听审替代人工。
- 不做 vocal、人声合成、音色克隆。
- 不做平台自动上传。
- 不做移动端复杂播放体验。

v5.1 只做一件事：**把真实 WAV 的人工听审证据和 Release Track 一一绑定，并让反馈进入修复闭环。**

---

## 4. 当前 v5.0 缺口

### 4.1 人工听审粒度不够

v5.0 Release audio gate 重点检查：

- Release Audio QA 是否 passed。
- Acceptance report 是否存在 manual WAV accepted evidence。
- synthetic 是否不能冒充 manual。

但它还没有强制：

- release track 1 对应哪个 review。
- review 绑定的 `wav_sha256` 是否正好是 track 1 当前 WAV。
- review 是否覆盖 Release 内全部 track。
- track WAV 重渲染后，对应 review 是否 stale。

### 4.2 marker 没有音频时间映射

Human review 可以有 markers，但 v5.0 尚未形成统一规则：

- marker time 是否是 WAV 秒数。
- 如何映射到 SongPlan beat。
- 如何定位 section。
- 如何定位 track。
- 如何创建 ReviewTask。

v5.1 需要形成最小闭环。

### 4.3 Release verifier 证据不足

v5.0 `verify-release --require-human-review` 能检查 signoff 里有 manual WAV evidence，但还不能在 ZIP 内独立证明：

- 每个 track 都有 review evidence。
- review evidence 的 `wav_sha256` 匹配包内 `song.wav`。
- review evidence 没被篡改。
- review notes / markers 已脱敏。

v5.1 要把这些 evidence 写进 Release Export / ZIP，并让 verifier 能离线检查。

---

## 5. 总体目标

v5.1.0 完成后，系统应该支持：

1. 为 Release 中每首 track 创建人工音频听审记录。
2. 每条听审记录绑定：
   - release_id
   - track_id
   - project_id
   - version_id
   - audio_artifact_id
   - wav_sha256
   - audio_health_hash
   - renderer_profile_hash
3. Release Signoff 开启 `require_per_track_audio_review=true` 时，所有 track 必须有当前 manual accepted review。
4. WAV、audio artifact、audio health 任一变化，旧 track review 必须 stale。
5. 听审 marker 可以映射到 section / beat。
6. 用户可以从 marker 创建 ReviewTask。
7. Release Export / ZIP 写入逐曲听审 evidence。
8. `verify-release --require-human-review` 可以离线检查逐曲 evidence。
9. release-check 增加 v5.1 smoke，覆盖 per-track gate、stale、tamper、feedback task。

## 6. 数据模型

### 6.1 新模块建议

新增模块：

```text
song_agent/audio_review_evidence.py
```

职责：

- 管理 Release Track Audio Review。
- 计算 review source hash。
- 判断 review current / stale。
- 输出脱敏 summary。
- 把 marker 映射到 SongPlan section / beat。
- 从 review marker 创建 ReviewTask。

### 6.2 存储目录

建议存储在 Release 目录下：

```text
.musicforge/
  releases/
    release-000001/
      audio-reviews/
        reviews.json
        events.jsonl
        review-000001.json
        review-000002.json
      release-audio-review-summary.json
```

理由：

- 逐曲听审是 Release 级证据。
- Release Track 顺序、project/version 绑定会变化。
- Signoff gate 直接从 Release 目录读取更清晰。

不要放到单个 Project 目录下作为唯一来源，因为一个 Project Version 可以被多个 Release 复用。

### 6.4 状态集合

`status`：

- `accepted`
- `needs_fix`
- `rejected`
- `waived`

`review_mode`：

- `manual`
- `synthetic`

v5.1 gate 只接受 `manual`。

`category`：

- `arrangement`
- `melody`
- `harmony`
- `rhythm`
- `mix_balance`
- `sound_quality`
- `structure`
- `hook`
- `other`

### 6.5 Source Hash

review source hash 必须绑定：

- release track identity：
  - release_id
  - track_id
  - project_id
  - version_id
- audio artifact summary：
  - audio_artifact_id
  - wav_sha256
  - source_hash
  - integrity_hash
- audio health summary：
  - wav_sha256
  - audio_health_hash
  - status
- song-plan identity：
  - song-plan payload hash
  - duration
  - section map

不能绑定：

- review notes 自身
- imported response 自身
- event history

否则导入 review 后会把自己判成 stale。

## 7. 逐曲听审 Current / Stale 规则

一条 TrackAudioReview 只有在以下条件都满足时才 current：

- release track 仍存在。
- track_id 对应 project_id / version_id 没变。
- Final Export 里的 `song.wav` 存在。
- audio artifact 存在且 current。
- `wav_sha256` 等于当前 WAV hash。
- `audio_health_hash` 等于当前 health report integrity hash。
- audio health status 是 `passed` 或 `warning`。
- review integrity hash 正确。
- review notes / markers 没有敏感信息。

以下情况必须 stale：

- Release track 被 refresh 后 version 变了。
- Project Final Export 重建。
- WAV 重渲染。
- audio artifact manifest 被改。
- audio health report 被改。
- song-plan 变化导致 section mapping 变化。
- review JSON 被手动篡改。

## 8. API 设计

### 8.1 Release Track Audio Reviews

新增 API：

```text
GET  /api/releases/<release_id>/audio-reviews
POST /api/releases/<release_id>/audio-reviews
GET  /api/releases/<release_id>/audio-reviews/<review_id>
POST /api/releases/<release_id>/audio-reviews/<review_id>
POST /api/releases/<release_id>/audio-reviews/<review_id>/delete
POST /api/releases/<release_id>/audio-reviews/<review_id>/refresh
```

创建请求：

```json
{
  "track_id": "track-000001",
  "status": "accepted",
  "review_mode": "manual",
  "reviewer": {
    "name": "liuhuanji",
    "role": "owner"
  },
  "rating": 4,
  "playback_confirmed": true,
  "notes": "整体通过，副歌鼓稍微抢。",
  "tags": ["release-ok", "drums-loud"],
  "markers": [
    {
      "time_seconds": 37.2,
      "severity": "medium",
      "category": "mix_balance",
      "message": "鼓稍微抢"
    }
  ]
}
```

响应：

```json
{
  "ok": true,
  "review": {},
  "summary": {
    "review_id": "arv-000001",
    "track_id": "track-000001",
    "status": "accepted",
    "current": true,
    "stale": false,
    "marker_count": 1
  }
}
```

规则：

- 已签核 Release 不允许新增/修改/delete review，必须 reset signoff。
- 如果 track 没有 current audio artifact，创建 review 返回 409。
- `review_mode=synthetic` 可以保存，但不能用于 signoff gate。
- `reviewer.name`、`notes`、`markers.message` 必须做值级脱敏。

### 8.2 Review Summary

```text
POST /api/releases/<release_id>/audio-reviews/refresh-summary
GET  /api/releases/<release_id>/audio-reviews/summary
```

summary 示例：

```json
{
  "release_id": "release-000001",
  "status": "passed",
  "track_count": 3,
  "covered_track_count": 3,
  "manual_accepted_track_count": 3,
  "needs_fix_track_count": 0,
  "rejected_track_count": 0,
  "stale_review_count": 0,
  "missing_track_ids": [],
  "blocking_track_ids": [],
  "source_hash": "...",
  "integrity_hash": "..."
}
```

### 8.3 Marker -> ReviewTask

新增 API：

```text
POST /api/releases/<release_id>/audio-reviews/<review_id>/markers/<marker_id>/create-review-task
```

请求：

```json
{
  "title": "Fix chorus drum balance",
  "priority": "medium",
  "target_track": "drums",
  "instruction": "Reduce drum density or velocity around this chorus marker."
}
```

响应：

```json
{
  "ok": true,
  "review_task": {},
  "marker": {
    "marker_id": "m-000001",
    "review_task_id": "review-task-000123"
  }
}
```

规则：

- 只有 current review 的 marker 可以创建 ReviewTask。
- 同一个 marker 重复创建时，若已有 open ReviewTask，返回 existing，不重复创建。
- 如果 marker 无法映射 section，仍可创建 task，但 target 只能是 project/version + time_seconds，不可伪造 section。

### 8.4 Batch Create From Human Review Pack

如果要复用 v4.6 Human Review Pack：

```text
POST /api/releases/<release_id>/audio-reviews/import-human-review-pack
```

请求：

```json
{
  "suite_id": "suite-000001",
  "pack_id": "hrpack-000001",
  "import_id": "hrimport-000001",
  "mapping": [
    {
      "track_id": "track-000001",
      "case_id": "case-000001"
    }
  ]
}
```

规则：

- case 的 `wav_sha256` 必须等于 release track 当前 `song.wav` hash。
- case 的 `review_mode` 必须 manual。
- case 的 status 必须 accepted 才能作为通过证据。
- song_id 可以辅助匹配，但不能替代 WAV hash 匹配。
- mismatch 返回 409。

## 11. Release Signoff Gate

Release Signoff payload 新增：

```json
{
  "require_audio_health": true,
  "require_per_track_audio_review": true
}
```

如果 `require_per_track_audio_review=true`：

必须满足：

- Release Audio QA passed。
- Audio Review Summary passed。
- 每个 track 至少一条 current manual accepted review。
- 没有 track 是 needs_fix / rejected。
- 没有 stale review。
- 没有敏感信息。

阻断示例：

- missing review：409
- synthetic only：409
- WAV hash changed：409
- review JSON tampered：409
- notes contains local path/token：409
- marker invalid time：409

force 规则：

- 对 `require_per_track_audio_review=true`，不建议允许 force 绕过。
- 如果业务坚持要允许 force，只能 force `needs_fix`，不能 force missing/stale/tampered/synthetic-only。
- reviewer 建议 v5.1 先做 hard block，不允许 force 绕过。

## 13. verify-release 增强

`verify-release --require-human-review` 在 v5.1 之后应该检查：

- `audio-reviews/summary.json` 存在。
- summary hash 与 manifest 匹配。
- 每个 track 都有 review JSON。
- review JSON hash 与 manifest 匹配。
- review `wav_sha256` 等于 ZIP 内该 track `song.wav` 的 sha256。
- review `review_mode=manual`。
- review `status=accepted`。
- review `playback_confirmed=true`。
- review marker time 不为负，不超过 WAV duration。
- review notes / marker message 无敏感信息。
- duplicate review entry 不能绕过。

兼容策略：

- v5.0 ZIP 没有 `audio-reviews/summary.json` 时：
  - 不加 `--require-human-review`：warning。
  - 加 `--require-human-review`：failed。

## 14. Marker 映射规则

### 14.1 秒数到 beat

基本换算：

```text
beat = time_seconds * bpm / 60
```

需要从 SongPlan 获取：

- bpm
- sections start beat / duration

### 14.2 beat 到 section

如果：

```text
section.start_beat <= beat < section.start_beat + section.duration_beats
```

则 marker 映射到该 section。

输出：

```json
{
  "beat": 74.4,
  "section_id": "section-003",
  "section_role": "chorus",
  "local_beat": 10.4
}
```

### 14.3 边界

- `time_seconds < 0`：拒绝 400。
- `time_seconds > wav_duration + 1.0`：拒绝 400。
- section 找不到：允许保存 marker，但 `mapped.status=unmapped`。
- bpm 缺失：允许保存 marker，但 `mapped.status=no_bpm`。

## 16. 与 Acceptance / Human Review Pack 的关系

v5.1 不废弃 Acceptance Suite 和 Human Review Pack。

关系应该是：

- Acceptance Suite：更偏“测试集 / 回归听审”。
- Human Review Pack：更偏“外部听审包”。
- Release Audio Review：更偏“发行曲目逐曲签核证据”。

Release Signoff 可以同时要求：

- Acceptance Suite release-ready。
- Release Audio QA passed。
- Per-track Audio Review passed。

Human Review Pack 的 response 可以导入成 Release Audio Review，但必须经过 track mapping 和 WAV hash 匹配。

## 17. 安全要求

### 17.1 路径安全

Release Audio Review 不允许用户传入本机音频路径。

它只能引用当前 Release Track 的 Final Export `song.wav`。

### 17.2 脱敏

以下字段必须值级脱敏：

- reviewer.name
- reviewer.role
- notes
- tags
- marker.message
- imported response metadata

必须拦截：

- `sk-...`
- GitHub token
- Bearer token
- Windows path
- UNC path
- `/Users/...`
- `/home/...`

### 17.3 Integrity

每个 review 有：

- `source_hash`
- `integrity_hash`

summary 有：

- `source_hash`
- `integrity_hash`

signoff 读取时必须重新校验，不可只信旧 summary。

### 17.4 签核后只读

Release signed 后：

- 不能新增 review。
- 不能修改 review。
- 不能 delete review。
- 不能 create ReviewTask from marker。
- 不能重新 refresh summary。

必须 reset Release signoff 后才能变更。

## 19. release-check v5.1 smoke

必须新增：

```text
v5.1 per-track audio review smoke
```

流程：

1. 创建两个 Project。
2. 每个 Project 生成 final export。
3. 为每个 final export 加当前 WAV 和 audio artifact。
4. 创建 Release，加入两个 tracks。
5. 跑 Release Audio QA，状态 passed。
6. 只给第一首创建 manual accepted review。
7. `require_per_track_audio_review=true` signoff 必须 409。
8. 给第二首创建 synthetic accepted review。
9. signoff 仍必须 409。
10. 给第二首创建 manual accepted review。
11. signoff passed。
12. 导出 Release ZIP。
13. 外部目录 `verify-release --require-audio --require-human-review` passed/warning。
14. 篡改第二首 WAV，verifier failed 或 Audio Review stale。
15. 篡改 review JSON 的 `wav_sha256`，verifier failed。
16. 篡改 review notes 为 `C:\Users\demo\secret.wav`，redaction failed。
17. 从 marker 创建 ReviewTask，重复创建返回 existing。

输出示例：

v5.1 per-track audio review smoke: ok

## 21. Reviewer P1 检查清单

- Release 里两首歌，只听审一首，signoff 是否 409。

- audio-health 被篡改后旧 review 是否 stale。

## 25. 结论

v5.0 证明了系统可以生成、检查、交付真实 WAV。

v5.1 要证明的是：

> 每一首准备发行的歌，确实有人听过当前这份 WAV，并且这条证据不能被旧音频、旧报告、synthetic review 或篡改 JSON 冒充。

这一步做完后，MusicForge 的 Release Signoff 才真正从“流程上通过”变成“逐曲音频证据上通过”。

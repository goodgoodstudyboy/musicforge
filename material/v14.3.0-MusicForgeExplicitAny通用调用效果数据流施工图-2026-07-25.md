# v14.3.0 MusicForge Explicit Any 通用调用效果数据流施工图

## 1. 定位

v14.3.0 是质量门禁结构修复版，不增加业务功能。目标是替换 v14.2.x
对调用副作用的局部补丁，使 Explicit Any collector 能处理“先运输普通别名，后写入
Any”的时序。

## 2. 必须修复的攻击

- `Store.append(Holder)` 后从 `Store[0]` 取回并污染。
- `Store.extend([Holder])` 的嵌套运输。
- `setattr(Box, "value", Holder)` 的属性运输。
- 本地 helper 将一个参数存入另一个参数。
- 本地 helper 将单个参数存入捕获的全局或闭包容器。
- `sink = Store.append; sink(Holder)` 的方法别名调用。
- `sink = Helper.retain` 的 classmethod 绑定参数偏移。
- 本地函数返回参数别名。
- decorator 替换本地函数后运输参数别名。
- class decorator 替换类成员实现后运输参数别名。
- escaped callable instance 通过 `__call__` 保存普通参数别名。

每个攻击必须在运行时产生 100 个 Any 注解，同时 collector 必须计数 100，并触发
scope、total、layer、file 四层门禁。Ruff 和 strict mypy 通过不能让攻击绕过
collector。

## 3. 实现顺序

1. 在 `explicit_any_dataflow.py` 引入并查集 may-alias component。
2. 将 cells、wildcard、escape 和 taint 聚合到 component root，避免大模块二次方扫描。
3. 未知调用统一连接 receiver、对象参数、返回值，不依赖 API 名称。
4. 本地函数摘要增加有向 may-store-alias、捕获对象绑定和 returns-alias-of。
5. 已知无存储调用使用声明式 effect，且本地同名函数优先。
6. 未知函数/class decorator 禁止继续信任装饰前摘要，并区分可信 class/function 与未知 callable role。
7. comprehension 只传播元素、键值和迭代源，不把 callable 名称伪装成返回别名。
8. collector schema 升级到 14，保留 schema 13 全部 ceiling。
9. 新增 ADR-026、`v143.explicit_any_call_effect_dataflow_smoke` 和攻击回归。

## 4. 不变量

- 不提高 Explicit Any total、affected-file、layer、file budget。
- 不提高复杂度和 recovery ceiling。
- 普通非 Any 调用不得产生 scope blocker。
- 本地同名函数不得借 builtin effect summary 绕过分析。
- release-check 必须在 v14/latest/security/ga 发布 profile 可达。

## 5. 验收

必须通过定向 collector/kernel 测试、全仓 Ruff、全活跃树 mypy、完整 pytest、doctor、
`git diff --check`、v14/latest/security/ga/full release-check。提交后在干净工作区重跑
GA，再推送 annotated tag 和 GitHub Release；CI、Nightly 或 reviewer package 未闭环
时停止发布。

ARCH-014 和 TYPE-003 由 ADR-027 单次顺延到 v14.4.0。本版不得把日期修改解释为债务
关闭，也不得提高任何数值预算；v14.4 在无更高优先级安全缺陷时必须是纯清债版本。

# MusicForge v0.5.0 施工图：音频渲染与 Studio 试听

当前稳定版本是 `v0.4.0`。项目已经具备：

- 单首歌生成。
- 多 Agent 节点生成和节点重试。
- provider 配置和脱敏。
- 批量 CSV 生产。
- Studio job / batch 工作台。
- MIDI 输出。

下一步应该让用户在浏览器里直接听到生成结果。`v0.5.0` 的核心是把 `song.mid` 渲染为 `song.wav`，并在 Studio 中播放。

## 1. v0.5.0 一句话目标

把 MusicForge 从“生成 MIDI 文件”升级为“生成可试听音频”的本地工具。

```text
SongPlan -> song.mid -> song.wav -> Studio <audio> playback
```

## 2. 为什么现在做音频

`v0.4.0` 已经可以批量生成 MIDI。但对普通使用者来说，MIDI 仍然不是最终可判断的结果。用户需要直接听：

- 旋律是否像歌。
- 和声是否顺。
- 节奏是否正确。
- batch 结果里哪首可继续优化。

因此 `v0.5.0` 不应该继续堆 agent，而应该把结果变成可听的 WAV。

## 3. v0.5.0 不做什么

本版本保持范围清楚。

不做：

- 不做人声合成。
- 不做歌词演唱。
- 不做 AI audio model 直出成品歌。
- 不做 MP3 作为必需功能。
- 不做 DAW 控制。
- 不做混音母带。
- 不做波形编辑器。
- 不做复杂音频分析。
- 不要求用户必须安装 FluidSynth 才能使用 MIDI 生成。

核心原则：

```text
音频渲染失败不能影响 SongPlan 和 MIDI 的生成。
```

## 4. 技术路线选择

### 4.1 第一版选择 FluidSynth + SoundFont

推荐第一版只做：

```text
FluidSynth CLI + .sf2/.sf3 SoundFont -> WAV
```

原因：

- 开源。
- 本地运行。
- 命令行可调用。
- 适合从 MIDI 渲染 WAV。
- 不需要引入大型 Python 音频依赖。

### 4.2 为什么不直接接 AudioCraft / MusicGen

这些模型适合以后做“音频模型后端”，但不是 v0.5.0 的第一目标。

当前系统的核心资产是结构化 SongPlan 和 MIDI。如果直接接 audio model，会跳过已有可控链路，调试成本很高。应先把 MIDI 渲染成可听音频，再考虑更复杂模型。

### 4.3 后续扩展

`v0.5.x` 之后可以考虑：

- MuseScore CLI 渲染。
- FFmpeg 转 MP3。
- Tone.js / WebAudio 浏览器 MIDI 播放。
- AudioCraft / MusicGen adapter。
- DAW adapter。

但 v0.5.0 只做 FluidSynth WAV。

## 5. 配置设计

新增本地配置文件：

```text
.musicforge/renderer.json
```

注意：`.musicforge/` 已经被 `.gitignore` 忽略，不会提交。

### 5.1 RendererConfig

新增：

```text
song_agent/renderers/audio.py
tests/test_audio_renderer.py
```

建议 dataclass：

```python
@dataclass
class RendererConfig:
    renderer_type: str = "fluidsynth"
    fluidsynth_path: str = "fluidsynth"
    soundfont_path: str = ""
    sample_rate: int = 44100
    output_format: str = "wav"
    gain: float = 0.6
```

### 5.2 配置字段

支持字段：

```json
{
  "renderer_type": "fluidsynth",
  "fluidsynth_path": "fluidsynth",
  "soundfont_path": "C:\\path\\to\\soundfont.sf2",
  "sample_rate": 44100,
  "output_format": "wav",
  "gain": 0.6
}
```

### 5.3 校验规则

必须校验：

- `renderer_type` 只支持 `fluidsynth`。
- `fluidsynth_path` 非空。
- `soundfont_path` 非空。
- soundfont 文件存在。
- soundfont 后缀建议 `.sf2` / `.sf3`，不强制也可以，但要 warning。
- `sample_rate` 在 8000 到 192000。
- `output_format` 只支持 `wav`。
- `gain` 在 0.0 到 10.0。

### 5.4 环境变量覆盖

建议支持：

```text
MUSICFORGE_RENDERER_TYPE
MUSICFORGE_FLUIDSYNTH_PATH
MUSICFORGE_SOUNDFONT_PATH
MUSICFORGE_AUDIO_SAMPLE_RATE
MUSICFORGE_AUDIO_GAIN
```

优先级：

```text
env > .musicforge/renderer.json > defaults
```

### 5.5 不保存用户机器路径到仓库

文档里不要写真实本机路径。示例用：

```text
C:\path\to\soundfont.sf2
```

不要写用户真实目录。

## 6. API 设计

新增 API：

```text
GET  /api/renderer
POST /api/renderer
POST /api/renderer/reset
POST /api/renderer/test
POST /api/jobs/<job_id>/render-audio
GET  /api/jobs/<job_id>/audio
```

### 6.1 GET /api/renderer

返回公开配置：

```json
{
  "configured": true,
  "config": {
    "renderer_type": "fluidsynth",
    "fluidsynth_path": "fluidsynth",
    "soundfont_path": "C:\\path\\to\\soundfont.sf2",
    "soundfont_exists": true,
    "sample_rate": 44100,
    "output_format": "wav",
    "gain": 0.6
  }
}
```

Renderer config 不包含 secret，但路径可能包含用户名。API 本地用可以返回，README 和 release docs 不要写真实路径。

### 6.2 POST /api/renderer

保存配置：

```json
{
  "renderer_type": "fluidsynth",
  "fluidsynth_path": "fluidsynth",
  "soundfont_path": "C:\\path\\to\\soundfont.sf2",
  "sample_rate": 44100,
  "gain": 0.6
}
```

返回：

```json
{
  "ok": true,
  "configured": true,
  "config": {}
}
```

### 6.3 POST /api/renderer/reset

删除 `.musicforge/renderer.json`。

### 6.4 POST /api/renderer/test

只做环境检测，不渲染 job：

- FluidSynth 可执行。
- SoundFont 文件存在。
- 输出目录可写。

推荐返回：

```json
{
  "ok": true,
  "renderer": {
    "renderer_type": "fluidsynth",
    "fluidsynth_path": "fluidsynth",
    "soundfont_exists": true
  },
  "message": "Renderer test completed."
}
```

如果失败：

```json
{
  "error": "SoundFont file does not exist."
}
```

### 6.5 POST /api/jobs/<job_id>/render-audio

对已有 job 的 `renders/song.mid` 渲染 WAV。

行为：

- job 不存在：404。
- MIDI 不存在：409。
- renderer 未配置：400。
- 渲染成功：写 `renders/song.wav`。
- 渲染失败：job 不变成 failed，只返回错误，并写 renderer error artifact 可选。

返回成功：

```json
{
  "ok": true,
  "job_id": "demo",
  "audio": "runs/demo/renders/song.wav",
  "artifact": {
    "name": "song.wav",
    "path": "runs/demo/renders/song.wav",
    "size_bytes": 123456
  }
}
```

### 6.6 GET /api/jobs/<job_id>/audio

返回 `renders/song.wav`。

如果不存在：

- 404 或 409 都可以，建议 404：

```json
{
  "error": "Audio render is not available for this job."
}
```

Content-Type：

```text
audio/wav
```

## 7. 渲染器实现

### 7.1 文件

新增：

```text
song_agent/renderers/audio.py
```

建议函数：

```python
def load_renderer_config() -> tuple[RendererConfig, dict[str, str]]:
    ...

def save_renderer_config_from_dict(data: dict[str, Any]) -> RendererConfig:
    ...

def reset_renderer_config() -> None:
    ...

def renderer_configured(config: RendererConfig) -> bool:
    ...

def test_renderer_config(config: RendererConfig) -> dict[str, Any]:
    ...

def render_audio(midi_path: Path, wav_path: Path, config: RendererConfig) -> Path:
    ...
```

### 7.2 命令构造

FluidSynth 命令建议：

```text
fluidsynth -ni <soundfont> <midi> -F <wav> -r <sample_rate> -g <gain>
```

Python 中必须用 list 参数，不要拼 shell 字符串：

```python
cmd = [
    config.fluidsynth_path,
    "-ni",
    config.soundfont_path,
    str(midi_path),
    "-F",
    str(wav_path),
    "-r",
    str(config.sample_rate),
    "-g",
    str(config.gain),
]
subprocess.run(cmd, ...)
```

不要用 `shell=True`。

### 7.3 错误处理

定义异常：

```python
class RendererError(ValueError): ...
class RendererConfigError(RendererError): ...
class RendererExecutionError(RendererError): ...
```

执行失败时错误信息要短，不要把巨量 stderr 原样返回。

建议截断：

```text
最多 500 字符
```

### 7.4 测试不依赖真实 FluidSynth

单元测试不要要求机器安装 FluidSynth。

策略：

- `render_audio(..., runner=fake_runner)` 可注入 fake runner。
- fake runner 创建一个最小 WAV 文件。
- 测试命令参数是否正确。
- 测试失败路径。

例如：

```python
def fake_runner(cmd, timeout):
    wav_path = Path(cmd[cmd.index("-F") + 1])
    wav_path.write_bytes(b"RIFF....WAVEfmt ")
```

## 8. Job 集成

### 8.1 Artifacts

渲染成功后 job artifacts 增加：

```json
{
  "audio": "runs/<job>/renders/song.wav"
}
```

`GET /api/jobs/<job_id>/artifacts` 也应能发现 `song.wav`。

### 8.2 validator/report

`validator-report.json` 可增加 audio 检查：

```json
{
  "audio": {
    "exists": true,
    "path": "runs/demo/renders/song.wav",
    "size_bytes": 123456
  }
}
```

如果改动大，可以先只让 artifacts 发现，不改 validator。推荐 v0.5.0 加上 audio 字段，便于 Studio 显示。

### 8.3 自动渲染还是手动渲染

v0.5.0 推荐先做手动渲染：

```text
生成 MIDI 后，用户点击 Render Audio。
```

不要默认每个 job 都自动渲染。原因：

- 用户可能没有配置 FluidSynth。
- batch 里自动渲染会拖慢。
- 渲染失败不应该让生成 job 看起来失败。

后续 v0.5.1 可加“生成完成后自动渲染”开关。

## 12. Windows 注意事项

Windows 路径经常包含空格。

必须：

- subprocess 使用 list 参数。
- 不拼接 shell 命令字符串。
- 不要求用户把路径加引号。
- 保存路径时保持原始字符串。

示例：

```text
C:\Program Files\FluidSynth\bin\fluidsynth.exe
C:\SoundFonts\FluidR3_GM.sf2
```

代码必须能处理。

## 15. Reviewer 核验重点

reviewer 检查 `v0.5.0` 时重点看：

- 没有 renderer 配置时，原 MIDI 生成是否不受影响。
- renderer test 错误是否清晰。
- subprocess 是否使用 list 参数，不能 shell=True。
- Windows 含空格路径是否能处理。
- render audio 失败是否不会把 job 标成 failed。
- `song.wav` 是否写到 `runs/<job>/renders/song.wav`。
- `GET /api/jobs/<job_id>/audio` 是否只读 job 自己目录。
- Studio 是否能显示 Render Audio 和播放器。
- `.musicforge/renderer.json` 是否未提交。
- secret/path scan 是否无真实本机路径。
- 测试是否不依赖真实 FluidSynth。

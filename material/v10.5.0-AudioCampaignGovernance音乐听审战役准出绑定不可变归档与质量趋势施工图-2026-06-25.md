# v10.5.0 Audio Campaign Governance 音乐听审战役准出绑定、不可变归档与质量趋势施工图

> 目标读者：MusicForge 开发执行人员  
> 当前稳定基线：v10.4.1  
> 规划角色：Reviewer / Planner  
> 计划版本：v10.5.0  
> 文档日期：2026-06-25

---

## 1. 背景

v10.4.0 已经把 Audio Campaign 做出来：可以把多个 Audio Lab Listening Session 聚合成批量真实听审战役，识别 fake/test WAV、manual review、Audio Fix Sprint closeout、campaign signoff、export/ZIP 和离线 verifier。

v10.4.1 修掉了一个关键问题：签核后的 Campaign 不再被 `refresh_report()`、API/CLI report 读取路径静默重算；显式 refresh 会 409；export/ZIP 前会校验 signoff、campaign-report、case-index、source hash 的绑定。

因此 v10.4.1 现在已经可以作为稳定基线。但它仍然只是“一个独立的音频战役证据”。它还没有变成系统级发布准出门禁：

- GA readiness 还不会强制要求 Audio Campaign。
- Release Signoff 还不会强制绑定 Audio Campaign。
- Campaign 签核后没有正式不可变 Archive 包。
- 签核 reset 还没有 approved Change Request 约束。
- Campaign 数据还没有形成趋势分析：哪些风格反复出问题，哪些问题最常见，哪些 Fix Sprint 真正有效。
- 开发跑完一批听审后，缺少一个面向负责人/业务的 campaign closeout 摘要。

v10.5.0 要做的是：把 Audio Campaign 从“能跑的批量听审工具”提升为“发布准出治理对象”。

---

## 2. 一句话目标

> v10.5.0 把 Audio Campaign 正式接入 GA / Release 准出门禁，并新增不可变归档、Change Request reset、质量趋势分析和 release-ready 证据绑定，让“这批歌已真实听审并准出”成为系统级门禁，而不是单独报告。

## 4. 总目标

v10.5.0 完成后，系统应支持：

1. 在 GA readiness 中要求一个当前 signed Audio Campaign。
2. 在 Release Signoff 中要求一个当前 signed Audio Campaign。
3. 生成 Audio Campaign Archive，作为签核后不可变交付证据。
4. 使用离线 verifier 验证 Audio Campaign Archive。
5. signed campaign reset 必须走 approved Change Request。
6. reset 成功后旧 signoff/archive 变为 superseded，不允许静默覆盖。
7. 生成 Campaign Analytics，统计问题类型、风格弱项、修复有效性、复验通过率。
8. 在 Studio 里提供 Campaign Governance 面板。
9. 在 release-check 中覆盖 GA gate、Release gate、Archive verifier、CR reset、analytics。

---

## 5. 不做什么

v10.5.0 明确不做：

- 不接外部音乐 API。
- 不做云端协作。
- 不做多人账号系统。
- 不做版权指纹检测。
- 不做 DAW 级编辑。
- 不把 synthetic review 放行成 release-ready。
- 不允许 provider 自动签核。
- 不把 Public Trust Center / Trust Operations 的证明链重新搬一遍。
- 不把真实 WAV 或 SoundFont 提交仓库。
- 不绕过 v10.4.1 的 signed frozen 语义。

```json
    "signoff_hash": "...",
    "campaign_report_hash": "...",

    "applied_at": null,
```

约束：

- reset 必须传 `change_request_id`。
- CR 必须存在。
- CR 必须 `status=approved`。
- CR integrity 必须 OK。
- CR source 必须匹配当前 campaign signoff。
- CR 只能用一次。
- reset 后 CR 变 `applied`，写入 reset history。

## 9. 准出绑定：GA Readiness

### 9.1 CLI

扩展：

```powershell
python -m song_agent.cli ga-check --require-audio-campaign acmp-000001
python -m song_agent.cli verify-ga-readiness-report ga-report.json --require-audio-campaign --audio-campaign-archive .musicforge\audio-campaigns\acmp-000001\archive\audio-campaign-archive.zip --audio-campaign-archive-verification ...
```

### 9.2 Gate 规则

当启用 `require_audio_campaign` 时：

- Audio Campaign 必须 signed。
- Audio Campaign report 必须 passed。
- Audio Campaign ZIP verifier 必须 passed。
- Audio Campaign Archive verifier 必须 passed。
- Campaign case_count 必须大于 0。
- manual_review_count 必须等于 case_count。
- real_audio_count 必须等于 case_count。
- open blocker 必须为 0。
- fake/test WAV count 必须为 0。
- synthetic review count 必须为 0。

### 9.3 不允许的降级

- 不能只传 campaign id 而不传 archive verification。
- 不能只传 campaign ZIP 而没有 archive。
- 不能用 unsigned campaign。
- 不能用 stale campaign。
- 不能用 old verification report。

## 10. 准出绑定：Release Signoff

### 10.1 Release Signoff 新增参数

建议在 Release Signoff payload 中新增：

```json
{
  "require_audio_campaign": true,
  "audio_campaign_id": "acmp-000001",
  "audio_campaign_archive_zip": "...",
  "audio_campaign_archive_verification_report": "..."
}
```

### 10.2 Release gate

如果 Release Signoff 启用 `require_audio_campaign=true`：

- Campaign source 必须覆盖当前 Release tracks。
- 每个 Release track 必须在 Campaign case-index 中有对应 case。
- 每个 case 必须 manual accepted 或 recheck accepted。
- 每个 case WAV hash 必须匹配 Release final/export 使用的 WAV 或 mastered WAV。
- Campaign Archive verifier passed。
- Campaign signoff 不 stale。
- Campaign signoff hash 和 Archive manifest source 一致。

### 10.3 暂不强制默认开启

v10.5 初期建议：

- 提供 Release Signoff gate。
- 不默认强制所有 Release 都必须绑定 Campaign。
- README 明确建议 release_candidate / audio_required 场景开启。

v10.6 再考虑是否让 release_candidate profile 默认启用。

```python
AudioCampaignGovernanceStore.refresh_governance_report(campaign_id)

```

### 11.2 Archive 不可变规则

- Campaign signed 后可以生成 archive。
- Archive 生成后，如果 Campaign signoff 未 reset，不允许静默重建 archive。
- 删除 archive/export 后再次 build 也必须 409，除非 reset 后重新 signoff。
- Archive manifest 绑定 campaign ZIP、campaign verification report、signoff、governance report、analytics summary。
- Archive verifier 必须离线验证所有 sidecar。

### 11.3 Archive verifier

新增：

```text
python -m song_agent.cli verify-audio-campaign-archive-package <zip>
```

检查：

- package_type == `audio_campaign_archive`
- ZIP entry allow-list
- duplicate entry failed
- dangerous path failed
- backslash failed
- nested ZIP failed
- `.musicforge/` internal path failed
- manifest file hash 对账
- campaign-report integrity
- campaign-signoff integrity
- campaign-verification-report status passed
- campaign-verification-report zip_sha256 绑定 campaign ZIP
- governance-report integrity
- analytics-summary integrity
- redaction scan

## 24. 给开发的话

v10.5 不是再做一个面板，而是把 v10.4 的 Audio Campaign 变成真正的发布准出门禁。

你实现时要牢记四条：

1. signed evidence 必须不可变。
2. reset signed evidence 必须有 approved Change Request。
3. GA / Release gate 不能只信一个 campaign id，必须信 archive + verifier + hash binding。
4. analytics 只能给判断和建议，不能绕过人工听审。

这版最容易犯的错是“包内自证”。凡是强门禁，都要问一句：如果有人改了 ZIP 里的 report、manifest、summary，然后重算 hash，verifier 能不能发现？如果不能，就要加外部 verification binding 或 signed frozen source binding。

# MusicForge v1.4.1 到 v1.5.0 施工图：候选审计链、候选试听与成本报表

> 基准版本：v1.4.0  
> 规划日期：2026-05-07  
> 执行原则：先用 v1.4.1 修 Candidate apply 审计链，再用 v1.5.0 把候选从“能看”升级成“能听、能算成本、能做 Prompt A/B”。  
> 当前提醒：本地工作区已经出现 v1.4.1 相关代码改动，开发应先完成验证、提交、推送、tag、release，再进入 v1.5.0。

---

## 1. 当前状态

v1.4.0 已完成：

- Candidate Group 持久化。
- `provider-edit-candidates` prompt template。
- Provider 一次返回 2-5 个候选 patch。
- 每个候选本地 apply、validate、quality/critic score、ranking。
- Candidate APIs：生成、列表、详情、apply、delete。
- Studio Candidates tab：生成候选、查看排序、应用候选。
- apply 候选后才创建正式 child Project Version。
- candidate group 绑定 parent song-plan hash，父版本变化后拒绝 stale apply。
- Project provider usage 包含 candidate group generation usage。
- release-check 包含 v1.4 candidate edit smoke。

v1.4.0 核验结论：

```text
python -m pytest -q
398 passed, 1 skipped

python -m song_agent.cli doctor
通过

python -m song_agent.cli release-check
通过
```

v1.4.0 发现的非阻断问题：

- apply candidate 后，正式 child version 的 `edit-metadata.json` 没有显式 `candidate_group_id` / `candidate_id` 字段。
- group id 被塞进通用 `preview_id` 字段，不够直观。
- candidate id 主要存在于 intent payload 和 group 文件中，如果以后删除 candidate group，正式版本的候选来源审计会变弱。

所以 v1.4.1 必须先补候选来源审计链。

## 2. 总路线

推荐路线：

1. **v1.4.1：Candidate Apply 审计链小修**
   - 显式保存 `candidate_group_id`、`candidate_id`、rank、score。
   - Compare / Studio 展示候选来源。
   - 删除 candidate group 后，正式版本仍保留来源摘要。
   - release-check 增加 candidate metadata smoke。

2. **v1.5.0：候选试听与成本报表**
   - 候选 MIDI preview。
   - 候选 WAV preview。
   - Studio 候选试听。
   - Provider usage / cost report。
   - Prompt A/B 测试雏形。

一句话：

> v1.4.1 让候选“可追溯”，v1.5.0 让候选“可试听、可核算、可比较 prompt 成本”。

## 4. v1.4.1 Package A：child version edit metadata 显式候选来源

### 4.1 问题

v1.4.0 apply candidate 时，正式 version 能创建成功，但 metadata 不够明确。

当前不理想状态：

```json
{
  "preview_id": "cg-001"
}
```

期望状态：

```json
{
  "candidate_group_id": "cg-001",
  "candidate_id": "cand-002",
  "candidate": {
    "candidate_group_id": "cg-001",
    "candidate_id": "cand-002",
    "rank": 1,
    "score": 91,
    "summary": "Brighten chorus harmony",
    "status": "ready"
  }
}
```

### 4.2 推荐实现

修改 `JobStore.create_edit_job()`：

- 增加参数：

```python
candidate_group_id: str | None = None
candidate_id: str | None = None
candidate: dict[str, Any] | None = None
```

- 写入 job `edit_metadata`。
- 写入 job `input_payload` 的安全摘要。
- 后台 `_run_edit_job()` 重建 `edit-metadata.json` 时保留这些字段。

修改 candidate apply：

- 调用 `create_edit_job()` 时传入：
  - `candidate_group_id`
  - `candidate_id`
  - `candidate` 摘要

### 4.3 candidate 摘要字段

建议只保存安全小字段：

```json
{
  "candidate_group_id": "cg-001",
  "candidate_id": "cand-002",
  "rank": 1,
  "score": 91,
  "quality_overall": 88,
  "summary": "Brighten chorus harmony",
  "created_at": "..."
}
```

不要把完整 patch、完整 SongPlan、provider raw response 复制进这个摘要。完整内容仍留在 candidate group 目录。

### 4.4 测试

新增或确认：

- apply candidate 后，`GET /api/projects/<id>/versions/<v>/edit` 返回：
  - `candidate_group_id`
  - `candidate_id`
  - `candidate.rank`
  - `candidate.score`
- 删除 candidate group 后，再读 version edit metadata，上述字段仍存在。
- provider key 不出现在 candidate 摘要里。

### 4.5 验收


## 7. v1.5.0 总目标

v1.5.0 的主题：

> Candidate Audition and Cost Report：候选不只看评分，还要能试听，并能看清 provider 调用成本。

v1.4.0 解决了：

```text
一条指令 -> 多个候选 -> 本地验证 -> 排序 -> 选择 apply
```

v1.5.0 要补：

```text
候选 -> MIDI preview -> WAV preview -> Studio 试听 -> usage/cost report -> Prompt A/B
```

核心价值：

- 用户可以听候选，而不是只看分数。
- 用户可以知道一次多候选调用花了多少 token。
- 用户可以比较不同 prompt template 的效果和成本。

## 8. v1.5.0 Package A：Candidate MIDI Preview

### 8.1 目标

每个 ready candidate 生成可下载/可试听基础 MIDI。

### 8.2 存储结构

在 candidate 目录下新增：

```text
.musicforge/projects/<project-id>/candidate-groups/<group-id>/candidates/<candidate-id>/
  candidate-song-plan.json
  song.mid
  render-report.json
```

### 8.3 生成时机

推荐默认行为：

- 创建 candidate group 时，对每个 ready candidate 立即生成 MIDI。
- 如果 MIDI render 失败，candidate status 可以仍是 ready，但 `midi_status=failed`；是否允许 apply 取决于 SongPlan validator，不取决于 preview MIDI。

### 8.4 API

新增：

```text
GET  /api/projects/<project-id>/candidate-groups/<group-id>/candidates/<candidate-id>/midi
POST /api/projects/<project-id>/candidate-groups/<group-id>/render-midi
```

`render-midi` 可用于旧 group 或失败重试。

### 8.5 数据字段

CandidateSummary 增加：

```json
{
  "midi_status": "completed",
  "midi_path": "...",
  "midi_error": null,
  "midi_size_bytes": 1234
}
```

API 返回不要泄露绝对路径，可以返回 artifact URL：

```json
{
  "midi_url": "/api/projects/<id>/candidate-groups/<gid>/candidates/<cid>/midi"
}
```

### 8.6 安全规则

- 下载接口必须使用 group_id/candidate_id 格式校验。
- 文件必须解析在 candidate 目录内。
- 不允许从 candidate metadata 中读取任意 path 下载。

### 8.7 测试

- 创建 candidate group 后每个 ready candidate 有 `song.mid`。
- MIDI 下载接口返回 `MThd`。
- 非法 candidate id 被拒。
- 越界 path 无法下载。
- render-midi 重跑成功。

### 8.8 验收

```powershell

python -m pytest -q
```

## 9. v1.5.0 Package B：Candidate WAV Preview

### 9.1 目标

如果 renderer 已配置，candidate 可以渲染 WAV，并在 Studio 里试听。

### 9.2 存储结构

```text
candidates/<candidate-id>/
  song.mid
  song.wav
  audio-render-report.json
```

### 9.3 API

新增：

```text
POST /api/projects/<project-id>/candidate-groups/<group-id>/render-audio
POST /api/projects/<project-id>/candidate-groups/<group-id>/candidates/<candidate-id>/render-audio
GET  /api/projects/<project-id>/candidate-groups/<group-id>/candidates/<candidate-id>/audio
```

行为：

- group render-audio：渲染所有 ready candidate。
- candidate render-audio：只渲染单个 candidate。
- 如果 renderer 未配置，返回清晰 400。
- 如果 MIDI 不存在，先生成 MIDI 或返回 409，二选一。推荐自动先生成 MIDI。

### 9.4 数据字段

CandidateSummary 增加：

```json
{
  "audio_status": "completed",
  "audio_path": "...",
  "audio_error": null,
  "audio_size_bytes": 123456,
  "audio_url": "/api/projects/<id>/candidate-groups/<gid>/candidates/<cid>/audio"
}
```

### 9.5 Studio

Candidate card 增加：

- Render MIDI。
- Download MIDI。
- Render Audio。
- Download WAV。
- `<audio controls>`。

如果 WAV 不存在，显示 Render Audio，而不是坏播放器。

### 9.6 测试

- fake renderer 成功渲染 candidate WAV。
- renderer 未配置返回 400。
- audio 下载返回 WAV bytes。
- audio path 越界被拒。
- Studio HTML 包含 candidate audio controls。

## 11. v1.5.0 Package D：Prompt A/B 测试雏形

### 11.1 目标

让同一条 instruction 可以用不同 prompt template 生成候选，比较质量和成本。

### 11.2 范围控制

v1.5.0 只做轻量 A/B：

- 用户选择 2 个 template。
- 每个 template 生成一组 candidates。
- 系统展示两组 ranking 和 usage。
- 用户手动选择 apply。

不做自动 prompt 优化，不做 prompt marketplace。

### 11.3 API

新增：

```text
POST /api/projects/<project-id>/versions/<version-id>/prompt-ab
GET  /api/projects/<project-id>/prompt-ab/<ab-id>
POST /api/projects/<project-id>/prompt-ab/<ab-id>/delete
```

payload：

```json
{
  "instruction": "Give me 3 stronger chorus options.",
  "candidate_count": 3,
  "template_ids": ["provider-edit-candidates", "provider-edit-candidates-alt"]
}
```

### 11.4 存储结构

```text
.musicforge/projects/<project-id>/prompt-ab/<ab-id>/
  ab.json
  groups/
    cg-001-ref.json
    cg-002-ref.json
```

也可以只存 group ids，不复制 group 内容。

### 11.5 Studio

Candidates tab 增加 Prompt A/B 小区：

- Template A。
- Template B。
- Generate A/B。
- 两组候选对比。
- usage 对比。

### 11.6 测试

- A/B 创建两个 candidate group。
- 两组都有 ranking。
- usage 分别记录。
- 删除 A/B 不删除已 apply 的正式版本。

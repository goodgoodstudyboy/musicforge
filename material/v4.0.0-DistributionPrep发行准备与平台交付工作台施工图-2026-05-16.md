# v4.0.0 Distribution Prep 发行准备与平台交付工作台施工图

日期：2026-05-16

当前稳定基线：v3.9.1

目标版本：v4.0.0

定位：v3.9.1 已经具备 Release Workspace、Release ZIP、Release Metadata、Release Signoff、外部 verify-release。v4.0.0 要把系统从“可验收的本地 Release 包”推进到“发行前交付准备包”：围绕目标平台或交付场景建立 Distribution Profile、音频母版要求、封面图要求、metadata 映射、平台 CSV、QA、Package ZIP、Package Signoff 和离线 verifier。v4.0.0 仍然只做本地准备和验收，不上传任何平台，不接发行商 API。

---

## 1. 背景

MusicForge 现在的交付链路已经比较完整：

```text
Project
  -> Final Export
  -> Delivery QA / Signoff
  -> Release Workspace
  -> Release QA / Release Export / Release ZIP
  -> Release Metadata / Metadata QA / Metadata Export
  -> Release Signoff
  -> verify-release
```

这条链路能回答：

- 单曲成品是否可交付。
- 多曲目 Release 是否组包完整。
- Release ZIP 是否能离开本机独立验收。
- Release metadata 是否填齐、脱敏、和 tracklist 对齐。
- 签核后是否防止静默改写。

但真实发行前还缺一个更靠后的工作台：

- 要投到哪个交付场景。
- 目标场景要求哪些文件。
- 是否必须有 WAV。
- 是否必须有 cover artwork。
- artwork 的格式、尺寸、大小是否合规。
- metadata 是否能映射成平台录入表。
- CSV 是否有公式注入风险。
- lyrics / credits / explicit / instrumental 是否适合交付。
- 每个平台或场景的 checklist 是否完成。
- 最终交给发行人员的是哪个 package。
- package 离开 `.musicforge/` 后是否仍可验证。

v4.0.0 要补的是“发行准备与平台交付工作台”。

---

## 2. 一句话目标

让一个已签核的 Release 可以进一步生成一个本地 Distribution Package：

```text
Signed Release
  -> Distribution Target
  -> Distribution Profile
  -> Artwork import / validation
  -> Audio master check
  -> Metadata mapping
  -> Distribution QA
  -> Distribution Export folder
  -> Distribution ZIP
  -> Distribution Signoff
  -> verify-distribution-package
```

最低成功标准：

```text
一个 2-track Release
  -> Release 已 signoff
  -> Metadata QA passed/warning
  -> 选择 generic_dsp profile
  -> 导入 cover artwork
  -> 检查 WAV / metadata / cover / credits / lyrics
  -> 生成 distribution-export/
  -> 生成 distribution-package.zip
  -> verify-distribution-package passed/warning
  -> Distribution Signoff
```

## 4. 核心概念

### 4.1 Distribution Profile

Profile 描述一个交付场景需要什么。

示例：

```json
{
  "profile_id": "generic_dsp",
  "name": "Generic DSP",
  "schema_version": 1,
  "requires": {
    "release_signoff": true,
    "release_zip_verify": true,
    "metadata": true,
    "audio_wav": true,
    "cover_art": true,
    "lyrics": "warning",
    "credits": "warning",
    "upc": "warning",
    "isrc": "warning"
  },
  "audio": {
    "allowed_formats": ["wav"],
    "require_header_valid": true
  },
  "artwork": {
    "allowed_formats": ["jpg", "jpeg", "png"],
    "square_required": true,
    "min_width": 1400,
    "min_height": 1400,
    "max_size_mb": 20
  },
  "metadata": {
    "csv_formula_escape": true,
    "required_release_fields": ["title", "display_artist", "primary_artist"],
    "required_track_fields": ["title", "display_artist"]
  }
}
```

注意：这些 profile 是本地验收模板，不代表任何平台的官方实时规范。

### 4.2 Distribution Target

Target 是某个 Release 的发行准备目标。

```json
{
  "target_id": "target-000001",
  "release_id": "release-000001",
  "profile_id": "generic_dsp",
  "name": "Generic DSP delivery",
  "status": "draft",
  "created_at": "...",
  "updated_at": "...",
  "options": {
    "require_audio": true,
    "require_cover_art": true,
    "require_lyrics": false,
    "require_upc": false,
    "require_isrc": false
  },
  "latest_qa_summary": {},
  "latest_export_summary": {},
  "latest_signoff_summary": {}
}
```

### 4.3 Artwork Record

Artwork 是 Release 级素材，不放进 Project。

```json
{
  "artwork_id": "artwork-000001",
  "release_id": "release-000001",
  "filename": "cover.png",
  "content_type": "image/png",
  "size_bytes": 123456,
  "sha256": "...",
  "width": 3000,
  "height": 3000,
  "format": "png",
  "source": "user_upload",
  "created_at": "..."
}
```

v4.0.0 只支持 PNG/JPEG header 解析，不引入图像处理依赖。

## 7. Distribution QA

### 7.1 QA 状态

```text
passed
warning
failed
stale
```

规则：

- blocking failed -> `failed`
- no blockers but warnings -> `warning`
- clean -> `passed`
- source hash changed -> `stale`

### 7.2 Release checks

| check_id | 说明 | severity |
|---|---|---|
| release_exists | Release exists | blocking |
| release_signed | Release must be signed | blocking |
| release_export_exists | Release Export exists | blocking |
| release_zip_exists | Release ZIP exists | blocking |
| release_zip_verify | verify-release passed/warning | blocking |
| release_not_hidden | Release is not hidden | blocking |

### 7.3 Metadata checks

| check_id | 说明 | severity |
|---|---|---|
| metadata_exists | Release Metadata exists | blocking |
| metadata_qa_current | Metadata QA source hash current | blocking |
| metadata_qa_allows_export | Metadata QA passed/warning | blocking |
| metadata_export_present | release-metadata/platform/credits present | blocking |
| platform_csv_safe | CSV has no formula injection | blocking |
| lyrics_safe | lyrics text redaction clean | blocking |
| upc_present | UPC present if profile requires | blocking or warning |
| isrc_present | ISRC present if profile requires | blocking or warning |

### 7.4 Audio checks

| check_id | 说明 | severity |
|---|---|---|
| track_audio_exists | each track has WAV if required | blocking |
| track_audio_header | WAV starts RIFF/WAVE | blocking |
| audio_manifest_hash | audio copied file hash matches manifest | blocking |
| audio_optional_missing | audio missing when optional | warning |

v4.0.0 不要求转码。若没有 WAV，QA 要明确告诉用户先配置 renderer 并重新生成 Project Final Export / Release Export。

### 7.5 Artwork checks

| check_id | 说明 | severity |
|---|---|---|
| artwork_exists | cover exists if required | blocking |
| artwork_extension | png/jpg/jpeg only | blocking |
| artwork_header | header valid | blocking |
| artwork_dimensions | can parse dimensions | blocking |
| artwork_square | square if profile requires | blocking |
| artwork_min_size | width/height >= profile min | blocking |
| artwork_size_limit | file size <= profile limit | blocking |
| artwork_redaction | manifest has no sensitive fields | blocking |

### 7.6 Target / package stale checks

Source hash must include:

- Release document source.
- Release Export manifest hash.
- Release ZIP sha256.
- Release signoff hash.
- Release metadata hash.
- Metadata QA hash.
- Artwork record hash.
- Profile hash.
- Target options hash.

Any change -> QA/package/signoff stale.

## 8. CSV Injection 防护

v4.0.0 必须补齐 v3.9.1 后续项：平台 CSV 安全。

CSV 单元格如果以这些字符开头：

```text
=
+
-
@
\t
\r
\n
```

处理方式：

- export 阶段统一前置 `'`。
- QA 阶段发现 raw metadata 中存在这种开头时给 warning。
- verifier 阶段扫描导出 CSV，若仍有未处理公式开头则 failed。

注意：

- 不要破坏普通负数场景，因为 metadata 字段理论上不需要负数。
- CSV 写入必须继续使用 `csv.DictWriter`。
- 不允许手写逗号拼接。

## 9. Distribution Export 内容

`distribution-export/` 建议结构：

```text
distribution-export/
  distribution-manifest.json
  README.txt
  release.json
  tracklist.json
  release-metadata.json
  platform-metadata.csv
  credits.csv
  lyrics/
    01-title.txt
  artwork/
    cover.png
  audio/
    01-title.wav
    02-title.wav
  docs/
    checklist.json
    submission-notes.md
```

### 9.1 distribution-manifest.json

必须包含：

```json
{
  "schema_version": 1,
  "release_id": "release-000001",
  "target_id": "target-000001",
  "package_id": "package-000001",
  "profile_id": "generic_dsp",
  "generated_at": "...",
  "source_hash": "...",
  "qa_source_hash": "...",
  "release_signoff_hash": "...",
  "release_export_manifest_hash": "...",
  "metadata_payload_hash": "...",
  "artwork": {},
  "tracks": [],
  "files": [
    {
      "path": "audio/01-title.wav",
      "size_bytes": 123,
      "sha256": "..."
    }
  ],
  "sidecars": {
    "distribution_signoff": {
      "path": "distribution-signoff.json",
      "payload_hash": "..."
    }
  },
  "summary": {
    "track_count": 2,
    "file_count": 12,
    "qa_status": "passed",
    "signoff_status": "not_signed"
  },
  "zip": {}
}
```

原则：

- `files[]` 是唯一允许 entry 列表来源。
- `zip.entries` 只能做参考，不参与放行。
- signoff sidecar 必须 hash-bound。
- manifest 不得包含本机绝对路径。

## 10. Distribution Package ZIP

ZIP 名称：

```text
musicforge-<release-id>-<target-id>-distribution-package.zip
```

ZIP entry 规则沿用 release verifier：

- no absolute path。
- no `..`。
- no empty segment。
- no backslash。
- no duplicate entry。
- no symlink。
- entry count limit。
- compressed size limit。
- uncompressed size limit。

新增 package verifier 要独立检查：

- distribution-manifest.json exists。
- release.json / tracklist.json exists。
- release-metadata.json exists if profile requires metadata。
- platform-metadata.csv exists。
- credits.csv exists。
- cover exists if profile requires cover art。
- WAV exists if profile requires audio。
- all manifest file hashes match ZIP bytes。
- distribution-signoff.json hash matches manifest sidecar record。
- manifest without zip hash matches signoff export_manifest_hash。
- redaction scan clean。

`distribution-signoff.json` 是 legal sidecar，但必须像 v3.8.1 的 `release-signoff.json` 一样被 hash-bound：

- `distribution-manifest.json.sidecars.distribution_signoff.payload_hash` 必须覆盖 signoff 展示字段。
- Verifier 必须校验该 payload hash。
- 不能只依赖 `export_manifest_hash`，否则 signed_by / signed_at 可被篡改后仍显示通过。

## 14. 与现有系统的关系

### 14.1 Release Signoff

Distribution 必须依赖 Release Signoff，但不修改 Release Signoff。

```text
Release Signoff
  -> immutable Release Export / ZIP
  -> Distribution Target reads it
  -> Distribution Package has its own signoff
```

### 14.2 Release Metadata

Distribution 使用 v3.9 metadata export。

如果 metadata QA stale 或 failed：

- Distribution QA failed。
- Distribution export blocked。

顺序要求：

- Metadata init / QA / Export 必须发生在 Release Signoff 之前。
- 如果 Metadata Export 更新了 Release Export manifest，必须重新 build Release ZIP。
- 之后才能 Release Signoff。
- Release Signoff 后，v3.9.1 会阻止 Release Export / Metadata Export / Release ZIP 被静默改写。

### 14.3 Project Final Export

Distribution 不直接读 Project 原始 workspace。

优先来源：

```text
Signed Release Export / Release ZIP
```

原因：

- Release Export 已经经过 QA/signoff。
- 避免绕过 Release 层的 frozen snapshot。

实现要求：

- Distribution Export 只能从已签核 Release 的 `release-export/` 和 `release-export.zip` 读取。
- 不允许从 `.musicforge/projects/`、Project `final-export/`、run dir 或任何 Project 原始工作区复制文件。
- 音频、metadata、lyrics、credits、tracklist 都以 signed Release Export 的内容为准。

### 14.4 verify-release

Distribution QA 可以调用现有 `verify_release_zip()` 对 Release ZIP 做前置验证。

但 Distribution Package verifier 必须是独立模块，不能直接复用 release verifier 的 manifest 规则。

## 15. 安全和不可变性

### 15.1 禁止明文敏感信息

任何导出和报告不得包含：

- token。
- api key。
- bearer。
- GitHub PAT。
- provider raw response。
- 本机绝对路径。
- UNC path。
- `C:\Users\...`。
- `/Users/...`。
- `/home/...`。

### 15.2 Package signed 后禁止改写

以下操作必须 409：

- 修改 target options。
- import/delete artwork。
- refresh QA 写入。
- build export。
- build zip。
- sign again。
- signed target 不允许 `POST qa/refresh` 写入新 QA。

允许：

- GET detail。
- GET ZIP。
- GET verifier report。
- reset signoff。

说明：

- `GET qa` 允许读取现有 QA。
- `POST qa/refresh` 是写操作，signed target 必须 409。
- reset distribution signoff 后才允许 refresh QA、export、zip、artwork import/delete、target option update。

### 15.3 ZIP 安全

继续覆盖：

- duplicate entry。
- backslash entry。
- `../evil`。
- absolute path。
- fake `zip.entries` spoof。
- ZIP bomb。
- oversized text scan skip must not hide required JSON/CSV files。

## 20. reviewer 重点检查项

开发完成后 reviewer 必须重点查：

### P1：签核后 package 被改写

复现：

1. build package。
2. signoff。
3. 再 POST export/zip/artwork import/update target。
4. 必须 409。

### P1：Package verifier 信任 manifest.zip.entries

Verifier 只能信 `manifest.files[] + legal sidecars`。

### P1：Artwork path / filename 注入

必须阻断：

```text
../cover.png
C:\cover.png
cover\evil.png
"cover.png"
cover.png\r\nContent-Type: text/html
```

### P1：CSV formula injection

导出的 CSV 不允许裸露：

```text
=
+
-
@
```

开头公式必须 escaped 或 verifier failed。

### P1：本机路径泄露

Distribution manifest、QA report、verification report、README、CSV、lyrics 都不能出现：

```text
C:\Users
\\server\share
/Users/
/home/
api_key=
sk-
Bearer
```

### P1：离线 verifier 依赖 workspace

必须把 ZIP 复制到外部 temp dir 再验证。

### P2：Profile 伪装成官方平台规范

文档和 UI 要说明 profile 是本地交付模板，不是平台官方实时规则。

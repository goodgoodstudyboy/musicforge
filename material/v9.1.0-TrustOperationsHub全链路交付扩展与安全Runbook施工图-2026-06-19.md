# v9.1.0 Trust Operations Hub 全链路交付扩展与安全 Runbook 施工图

> 当前稳定基线：v9.0.1  
> v9.0.1 已修复 Hub 签核不可变和 `--require-signed` 外部 sidecar 门禁。  
> v9.1.0 的目标，是把 Trust Operations Hub 从 PTC / Publication / Monitoring 的信任中枢，扩展成覆盖 Release / Distribution / Submission / Operations / Public Trust Center 的全链路交付运营中枢，并增加只执行安全动作的 Hub Runbook。

---

## 0. 给开发的话

你接手 v9.1.0 时，不要把它理解成“再加几个 summary 字段”。

这版要做的是：

```text
把 v9.0 的 Trust Operations Hub
从公开证明链路总览
升级成真正的交付运营总控台
```

现在 v9.0.1 已经有：

- Hub Report。
- Hub ZIP。
- Hub verifier。
- Hub signoff。
- signoff-history 不可变保护。
- 外部 `hub-signoff` / `hub-verification-report` 签核门禁。
- PTC verification / publication channel state / publication monitoring verification 的外部绑定。

但 v9.0.1 仍然有一个业务缺口：

```text
它还没有真正统一 Release / Distribution / Submission / Operations 这些交付链路。
```

所以 v9.1.0 要补齐：

- Release readiness。
- Distribution readiness。
- Submission readiness。
- Submission Evidence readiness。
- Release Operations readiness。
- Public Trust Center readiness。
- Publication readiness。
- Monitoring readiness。
- Cross-link blocker register。
- Cross-link manual action queue。
- Hub Runbook safe action queue。

核心原则：

- Hub 只聚合证据，不伪造证据。
- Hub verifier 只信独立 sidecar / external report，不信 Hub 自己 summary 自证。
- Hub Runbook 只能执行安全动作。
- manual review、signoff、reset、submit、accepted、provider、upload 绝不能自动跑。
- 已签核 Hub 不能被 refresh/export/zip/runbook 静默改写。
- 所有可导出的 ZIP 都必须固定 allow-list、路径安全、hash 对账、redaction scan。

## 2. v9.0.1 还缺什么

v9.0.1 的 Hub 主要覆盖：

- Public Trust Center verification。
- Publication channel state。
- Publication monitoring verification。

这很好，但还不是完整业务闭环。

真正对业务有用的问题是：

```text
这个 release 现在到底能不能交付？
哪个平台能交？
哪个 submission 已接受？
哪个 evidence 已归档？
哪个 operations 包已签核？
哪个 PTC 已公开？
哪个 publication 通道仍 current？
是否还有 open critical incident？
```

v9.0.1 还没有把这些链路统一进 Hub：

- Release Export / Release ZIP / Release Signoff。
- Distribution Target / Distribution ZIP / Distribution Signoff。
- Submission Package / Submission Signoff / submitted / accepted。
- Submission Evidence Archive。
- Release Operations Dashboard / Signoff / Archive / Audit / Reviewer Pack。
- Public Trust Center / Distribution Kit / Acceptance Board / Publication Channel / Monitoring。

因此 v9.1.0 要补：

```text
全链路交付 evidence ingestion + readiness matrix + blocker/action/runbook
```

## 3. v9.1.0 一句话目标

新增 Trust Operations Hub Delivery Expansion + Safe Runbook：

```text
Release / Distribution / Submission / Operations / PTC / Publication / Monitoring
    -> Trust Operations Hub Delivery Evidence Index
    -> Trust Operations Hub Cross-link Readiness Matrix
    -> Cross-link Blocker Register
    -> Manual Action Queue
    -> Safe Runbook Queue
    -> Hub Export / ZIP / Verification / Signoff
```

产出：

- `delivery-evidence-index.json`
- `delivery-readiness-matrix.json`
- `delivery-blocker-register.json`
- `delivery-manual-action-queue.json`
- `runbooks/<runbook-id>/runbook.json`
- `runbooks/<runbook-id>/runbook-result.json`
- `runbooks/<runbook-id>/runbook-export/`
- `runbooks/<runbook-id>/trust-operations-hub-runbook.zip`

## 4. 非目标

v9.1.0 不做这些：

- 不自动 submit 到任何平台。
- 不自动 mark accepted。
- 不自动 approve Change Request。
- 不自动 reset signoff。
- 不自动 sign Hub / Release / Distribution / Submission / Operations。
- 不自动跑 provider。
- 不自动上传外部文件。
- 不接真实第三方发布平台 API。
- 不做 SaaS 多用户权限。
- 不做联网 webhook。

如果某个动作会改变“业务决策状态”，它必须是 manual_required。

## 7. Delivery Evidence Index

新增 `delivery-evidence-index.json`。

它是 v9.1.0 的核心数据结构。

示例：

```json
{
  "schema_version": 1,
  "package_type": "musicforge_trust_operations_hub_delivery_evidence_index",
  "hub_id": "hub-default",
  "report_id": "toh-report-000001",
  "generated_at": "2026-06-19T00:00:00+00:00",
  "evidence": [
    {
      "component_type": "release",
      "component_id": "rel-000001",
      "requirement": "release_signed",
      "status": "passed",
      "source_kind": "release_export",
      "package_path": "external",
      "package_sha256": "abc...",
      "manifest_hash": "def...",
      "verification_report_hash": "ghi...",
      "signoff_hash": "jkl...",
      "current": true,
      "stale": false,
      "summary": {
        "release_id": "rel-000001",
        "signoff_status": "signed"
      }
    }
  ],
  "summary": {
    "total": 1,
    "passed": 1,
    "failed": 0,
    "missing": 0,
    "stale": 0
  },
  "integrity_hash": "..."
}
```

每条 evidence 必须只保存脱敏摘要：

- 不保存本机绝对路径。
- 不保存 token。
- 不保存 provider raw response。
- 不保存 source_path。
- 不保存本机用户名。

本地真实文件路径只能放在非导出的：

```text
delivery-source-paths.json
```

## 8. v9.1 必须支持的 evidence 类型

### 8.1 Release Evidence

来源：

- Release Export manifest。
- Release ZIP。
- Release verification report。
- Release signoff summary。

要求：

- `release_zip_exists`
- `release_zip_verified`
- `release_signed`
- `release_export_not_stale`

阻断：

- 缺 ZIP。
- verification failed。
- signoff missing。
- signoff source 与 ZIP / manifest 不匹配。
- ZIP 被替换。

### 8.2 Distribution Evidence

来源：

- Distribution target export。
- Distribution ZIP。
- Distribution verification report。
- Distribution signoff。

要求：

- `distribution_target_signed`
- `distribution_package_verified`
- `distribution_package_current`

按 target 维度记录：

```text
release_id + target_id
```

阻断：

- target 未签核。
- target ZIP 缺失。
- verification failed。
- template/checklist/layout/audio/rights/format decision gate failed。

### 8.3 Submission Evidence

来源：

- Submission package。
- Submission verification report。
- Submission status。
- Submission signoff。

要求：

- `submission_package_signed`
- `submission_package_verified`
- `submission_status_submitted_or_accepted`

阻断：

- package 未签核。
- package 未验证。
- item 还不是 submitted / accepted。
- pending warning 未处理。

### 8.4 Submission Evidence Archive

来源：

- Submission Evidence Archive ZIP。
- verification report。
- signoff summary。

要求：

- `submission_evidence_signed`
- `submission_evidence_verified`

阻断：

- evidence archive missing。
- verification failed。
- signoff missing。
- attachment hash mismatch。

### 8.5 Release Operations Evidence

来源：

- Release Operations report。
- Operations Signoff。
- Operations Archive。
- Operations Audit。
- Operations Reviewer Pack。

要求：

- `operations_signed`
- `operations_archive_verified`
- `operations_audit_passed`
- `operations_reviewer_pack_verified`

阻断：

- Archive verification missing。
- Audit failed。
- Reviewer Pack missing audit verification。
- Signoff reset 后未重建证据。

### 8.6 Public Trust Center Evidence

保留 v9.0 支持：

- PTC verification。
- Publication channel state。
- Publication monitoring verification。

新增纳入：

- Public Trust Center package。
- Anchor Registry。
- Anchor Transparency。
- Distribution Kit。
- Acceptance Board Signoff。
- Publication package。
- Publication monitoring run。

要求：

- `public_trust_center_verified`
- `acceptance_board_signed`
- `publication_current`
- `publication_monitoring_clean`
- `no_open_critical_incidents`

```json

  "actions": [
    {
      "action_id": "toh-action-000001",
      "action_type": "signoff_required",
      "status": "manual_required",
```

## 12. Safe Runbook

新增 Trust Operations Hub Runbook。

Runbook 是 v9.1.0 的第二个核心功能。

它用于：

```text
把 Hub 的安全刷新动作排成队列
一键执行 refresh/export/zip/verify
不执行任何业务决策动作
```

### 12.1 Runbook 数据结构

```json
{
  "schema_version": 1,
  "package_type": "musicforge_trust_operations_hub_runbook",
  "runbook_id": "toh-runbook-000001",
  "hub_id": "hub-default",
  "status": "draft",
  "created_at": "2026-06-19T00:00:00+00:00",
  "source": {
    "hub_report_hash": "...",
    "delivery_matrix_hash": "...",
    "blocker_register_hash": "..."
  },
  "items": [
    {
      "item_id": "toh-runbook-item-000001",
      "action_type": "hub_refresh",
      "safe": true,
      "status": "pending",
      "component_type": "hub",
      "component_id": "hub-default"
    }
  ],
  "manual_actions": [
    {
      "action_type": "signoff_required",
      "status": "manual_required"
    }
  ],
  "integrity_hash": "..."
}
```

### 12.2 允许自动执行的 safe actions

只允许：

- `hub_refresh`
- `hub_export`
- `hub_build_zip`
- `hub_verify_zip`
- `delivery_refresh`
- `release_operations_refresh`
- `public_trust_center_verify`
- `publication_monitoring_refresh`
- `run_release_check_latest_skip_tests`

其中 `run_release_check_latest_skip_tests` 可选，默认不要自动跑完整 pytest。

### 12.3 禁止自动执行的 actions

必须进入 manual_required：

- `signoff`
- `reset_signoff`
- `approve_change_request`
- `submit`
- `mark_accepted`
- `upload_attachment`
- `import_response`
- `provider_generate`
- `manual_review`
- `force_signoff`

### 12.4 Runbook stale guard

Runbook 创建时绑定：

- Hub report hash。
- Delivery matrix hash。
- Blocker register hash。
- Manual action queue hash。
- Source paths hash。

执行前必须重新检查。

如果 Hub 或底层 evidence 已变化：

```text
run-safe -> 409 stale
```

例外：

- runbook 自己执行 `hub_refresh` 后，后续 item 可以继续基于新的 current state 执行。
- 但必须把 state transition 写入 `runbook-events.jsonl`。

## 17. 外部绑定规则

所有 require 类 verifier 都必须支持“外部绑定”。

例如 `--require-distribution-ready`：

不能只信 Hub ZIP 里的：

```text
delivery-evidence-index.json
```

必须用：

```text
--distribution-verification-dir
```

重新读取真实 verification reports，并比较：

- package sha256。
- manifest hash。
- verification report hash。
- signoff hash。
- target id。
- status。

如果没传外部 evidence：

```text
failed
```

不要让 Hub ZIP 自证。

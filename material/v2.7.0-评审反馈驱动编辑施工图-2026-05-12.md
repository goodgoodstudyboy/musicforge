# v2.7.0 评审反馈驱动编辑施工图

日期：2026-05-12

当前基线：v2.6.0

目标版本：v2.7.0

定位：在 v2.6.0 已经把试听评审、评分、备注、marker、audition asset 沉淀做成闭环之后，把这些“用户反馈”转化为下一轮可执行编辑。v2.7.0 的核心不是再增加一个面板，而是让 MusicForge 第一次具备“听了、评价了、根据评价继续改”的反馈驱动创作循环。

---

## 1. 背景

到 v2.6.0，MusicForge 已经具备：

- Project Editor 可创建 Preview。
- Preview / Parent / Audition 可试听。
- Audition Review Board 可评分、收藏、设置 status、写 notes、打 marker。
- Audition 可保存为 Creative Asset。
- Review summary 已进入 Apply metadata、Compare、Project Export、Final Export。
- release-check 已覆盖 v2.6 audition review smoke。

这说明系统已经收集到了“用户认为哪里好、哪里不好”的结构化反馈。

但当前反馈还只是记录：

- `notes` 不会变成 edit intent。
- `marker kind=fix` 不会生成局部修复。
- `status=needs_fix` 不会推动下一轮版本。
- `favorite audition` 沉淀成 asset 后，还不会自动推荐加入 Context Pack。
- Review Board 里的下一步动作还不够明确。

v2.7.0 要补齐“反馈 -> 编辑 -> 新版本”的链路。

---

## 2. 一句话目标

v2.7.0 要把 MusicForge 从“试听评审系统”推进到“反馈驱动编辑系统”：

- 从 audition review 生成结构化 `ReviewEditIntent`。
- 支持从 review 创建本地 deterministic edit version。
- 支持从 review 创建 provider edit preview，作为可选增强。
- 支持把 favorite / high-rating audition asset 推荐加入 Context Pack。
- Studio Review Board 增加 Next Action：Create Edit、Provider Preview、Add to Context、Reject。
- Apply / Compare / Export / Final Export 记录 review source 和 next-action provenance。

---

## 3. 不做什么

v2.7.0 必须继续收住边界：

- 不做自动无限迭代。
- 不做“AI 自己决定最终版本”。
- 不做多轮 agent 自主修改全项目。
- 不做实时音频分析。
- 不做从 WAV 自动识别问题。
- 不做复杂自然语言 parser。
- 不做 provider 强依赖；local review edit 必须可跑。
- 不把 review notes 原文大段塞进 Final Export。
- 不把 audition WAV 复制进正式版本。

这版只做“用户明确触发的一步式 review-driven edit”。

---

## 4. 用户价值

目标用户工作流：

1. 用户在 Audition Review Board 里听一个 audition。
2. 标记：
   - rating=4
   - status=needs_fix
   - notes=`bass 太满，chorus 第二遍需要更强`
   - marker=`fix @ beat 16`
3. 用户点击 `Create Edit From Review`。
4. 系统根据 review 生成本地 edit intent：
   - bass track density 降低
   - chorus section energy 提升
5. 系统创建新 Project Version。
6. 用户继续 Preview / Audition / Review。

另一个工作流：

1. 用户把一个 5 分 audition 保存成 Asset。
2. 点击 `Add to Context Pack`。
3. 系统生成一个包含该 asset 的 Context Pack。
4. 后续生成/编辑可选择这个 Context Pack。

---

## 5. 核心设计原则

### 5.1 用户触发，不自动改歌

Review 本身不能自动修改 Project Version。

必须由用户点击：

- `Create Local Edit`
- `Create Provider Preview`
- `Add to Context`

才能产生新版本或新上下文。

### 5.2 先 local，再 provider

v2.7.0 必须保证不配置 provider 也能完成核心链路。

实现顺序：

1. Review -> Local EditIntent
2. Local EditIntent -> Project Version
3. Provider Review Preview 可选

### 5.3 Review 不可信，必须脱敏和白名单

用户 notes / marker label 是自由文本，不能直接作为路径、字段名或任意操作。

必须：

- 脱敏。
- 截断。
- 通过白名单规则映射到已有 `EditIntent`。
- 不能生成未知 edit_type。
- 不能生成任意 patch op。

### 5.4 继续复用现有编辑系统

不要新写一套 apply engine。

应复用：

- `song_agent.edits.EditIntent`
- `apply_edit_intent`
- `build_edit_metadata`
- 现有 Project edit job / version 写入逻辑
- provider edit preview 现有链路

## 7. 数据模型

### 7.1 ReviewEditIntent

新增结构：

```json
{
  "schema_version": 1,
  "review_edit_id": "review-edit-001",
  "project_id": "project-001",
  "parent_version_id": "v001",
  "preview_id": "preview-001",
  "audition_id": "audition-001",
  "source": {
    "review": {},
    "markers": [],
    "audition_summary": {},
    "asset_refs": []
  },
  "mode": "local",
  "intents": [],
  "instruction": "Reduce bass density and lift chorus energy.",
  "confidence": 0.74,
  "warnings": [],
  "created_at": "..."
}
```

说明：

- `review_edit_id` 可以存在于 Project event / job metadata，不一定需要单独 store。
- 如果为了 preview/history 可追踪，建议写入：

```text
.musicforge/projects/<project-id>/review-edits/<review-edit-id>/review-edit.json
```

### 7.2 ReviewEditSource

必须记录：

- project_id
- parent_version_id
- preview_id
- audition_id
- audition source
- audition range
- track_mode
- rating
- status
- favorite
- marker summary
- sanitized notes excerpt
- asset ids
- source_plan_hash

不能记录：

- 本机路径
- raw provider response
- token/key
- 完整长 notes

### 7.3 intent 映射结果

最终应输出现有 `EditIntent`：

```json
{
  "edit_type": "track_density",
  "target": {
    "track_name": "bass",
    "field": "notes"
  },
  "instruction": "Reduce bass density based on audition review.",
  "preserve": ["tempo", "key", "structure", "lyrics", "harmony"],
  "strength": 4,
  "provider_mode": "local",
  "payload": {
    "density_scale": 0.72,
    "source": "review_marker"
  }
}
```

## 8. Review -> EditIntent 映射规则

v2.7.0 先做 deterministic heuristic，不做复杂 NLP。

### 8.1 输入信号

来源：

- review.status
- review.rating
- review.favorite
- review.notes
- review.tags
- markers.kind
- markers.label
- audition.track_mode
- audition.track_ids
- audition.range.mode
- audition.range.section_name
- audition.source

### 8.2 关键词映射

中文和英文都要支持基础关键词。

#### energy / lift

关键词：

- `energy`
- `lift`
- `stronger`
- `bigger`
- `more intense`
- `更强`
- `能量`
- `加强`
- `高潮`
- `更炸`

生成：

- `section_energy`
- target section 优先来自 audition range section / marker 所在 section
- strength 6-8

#### density reduce

关键词：

- `too busy`
- `too dense`
- `crowded`
- `reduce`
- `less`
- `太满`
- `太密`
- `减少`
- `稀疏`

如果同时出现 bass / drum / melody / chords：

- 生成对应 track 的 `track_density`
- strength 3-5
- payload density_scale < 1

#### density increase

关键词：

- `more`
- `add`
- `fill`
- `empty`
- `thin`
- `太空`
- `太少`
- `加一点`
- `更丰富`

生成：

- `track_density`
- strength 5-7
- payload density_scale > 1

#### melody variation

关键词：

- `hook`
- `melody`
- `variation`
- `catchy`
- `旋律`
- `副歌`
- `hook`
- `变化`

生成：

- `melody_variation`
- section 优先 range section
- preserve harmony / tempo / key

#### arrangement variation

关键词：

- `arrangement`
- `transition`
- `drop`
- `build`
- `break`
- `编曲`
- `过渡`
- `drop`
- `铺垫`

生成：

- `arrangement_variation`

#### reject

如果：

- status=`reject`
- rating <= 2

默认不创建 edit，返回 warning：

```text
Review is rejected; no safe local edit intent was generated.
```

用户可以 force create，但 v2.7.0 可以不做 force。

### 8.3 marker 映射

marker.kind：

- `fix` / `issue`：优先生成修复类 intent。
- `hook` / `keep`：默认 preserve，不直接改该片段。
- `drop`：倾向 arrangement / energy。
- `note`：只作为 instruction context。

### 8.4 target 选择

优先级：

1. audition `track_mode=solo` 且只有一个 track_id -> 对应 track。
2. notes 中出现 bass/drum/melody/chords 关键词 -> 对应 track。
3. marker 所在 beat 对应 section -> 对应 section。
4. audition range `section` -> 对应 section。
5. fallback -> 第一个 chorus/verse/intro section。

target 只能使用当前 parent version 中真实存在的 section/track name。

## 9. 后端任务

### Phase 1：Review Edit Core

新增 `song_agent/review_edits.py`。

建议实现：

- `ReviewEditError`
- `ReviewEditIntent`
- `build_review_edit_source(...)`
- `infer_review_edit_intents(parent_plan, audition_manifest, audition_plan)`
- `review_edit_instruction(...)`
- `review_edit_summary(...)`
- `validate_review_edit(...)`

输入：

- parent SongPlan
- audition manifest
- audition plan
- optional payload:
  - mode
  - selected_intents
  - force
  - provider_mode

输出：

- intents: list[`EditIntent`]
- warnings
- source summary

限制：

- intents 最多 4 个。
- 每个 intent 必须通过 `validate_edit_intent(parent_plan, intent)`。
- 如果没有安全 intent，返回 409。
- notes 长度进入 parser 前要截断，例如 2000。
- 关键词匹配前要 lower，但原文存储必须脱敏。

### Phase 2：Local Review Edit API

新增 API：

```text
POST /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/review-edit
```

Payload：

```json
{
  "mode": "local",
  "version_name": "Review edit from chorus audition",
  "version_note": "Reduce bass density",
  "intent_overrides": [],
  "asset_refs": [],
  "context_pack_id": ""
}
```

行为：

1. 读取 project / preview / audition。
2. 解析 preview parent version。
3. 读取 parent SongPlan。
4. 确认 preview parent job / base hash 仍匹配。
5. 读取 audition plan。
6. infer review edit intents。
7. 依次 apply `apply_edit_intent`。
8. 写新的 job / Project Version。
9. metadata 写：

```json
{
  "edit_source": "audition_review",
  "review_edit": {...},
  "audition_summary": {...},
  "review_summary": {...}
}
```

10. Project event：
    - `audition_review_edit_created`

返回：

```json
{
  "ok": true,
  "version": {},
  "job": {},
  "review_edit": {},
  "intents": []
}
```

错误：

- rejected/no intent：409
- stale parent：409
- invalid override：400
- unknown audition：404

### Phase 3：Review Edit Preview API

为了避免直接创建版本，也可以提供 dry-run preview：

```text
POST /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/review-edit-preview
```

返回：

- inferred intents
- warnings
- estimated changed sections/tracks
- candidate quality
- validator summary

不写 Project Version。

是否写 preview 文件：

- v2.7.0 建议写轻量 store：

```text
.musicforge/projects/<project-id>/review-edits/<review-edit-id>/
  review-edit.json
  candidate-song-plan.json
  validator-report.json
```

也可以先不持久化，只返回响应。但为了 Studio 可回看，建议持久化。

### Phase 4：Provider-backed Review Edit Preview

可选增强，但建议写在同版后半段。

新增 prompt template：

```text
provider-review-edit-intent
```

输入：

- parent song plan
- audition summary
- review notes
- markers
- supported operations
- asset refs
- reference refs
- context pack summary

输出仍必须是现有 ProviderEditPatch schema。

API：

```text
POST /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/provider-review-edit-preview
```

必须：

- provider 未配置时返回 400。
- mock provider 要覆盖测试。
- provider 输出仍走 `ProviderEditPatch.from_dict`。
- 不允许 provider 返回 path/token/api_key 字段。
- preview 不自动 apply。

如果开发时间不足，provider 阶段可降级为 v2.7.1。

### Phase 5：Favorite Asset -> Context Pack

新增 API：

```text
POST /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/create-context-pack
```

行为：

1. 找 audition review 中 `last_asset_id`，或 payload 指定 `asset_id`。
2. 校验 asset 存在、未 hidden、source hash fresh。
3. 创建 Context Pack。
4. created_from 写：

```json
{
  "source_type": "audition_review",
  "project_id": "...",
  "preview_id": "...",
  "audition_id": "...",
  "rating": 5,
  "status": "keep"
}
```

5. selection 写：

```json
{
  "mode": "audition_review",
  "selected_by": "user",
  "score_summary": [...]
}
```

返回 pack。

限制：

- 最多引用 5 个 assets，复用现有 Context Pack 限制。
- 不自动加入所有 favorite；v2.7.0 只做用户点击。

## 11. 安全与边界

### 11.1 Review text 不可直接执行

禁止：

- notes 直接拼成 path。
- notes 直接变成 arbitrary operation。
- marker label 直接变成 edit field。
- provider 返回未校验 patch。

必须：

- 白名单 edit types。
- 白名单 target。
- 白名单 payload keys。
- 复用 `EditIntent.from_dict` / `validate_edit_intent`。

### 11.2 Stale 检查

必须检查：

- preview parent job 是否仍匹配。
- parent song-plan hash 是否等于 preview.base_plan_hash。
- audition source_plan_hash 是否仍可解释。
- 如果 audition plan 缺失，返回 409 或 404，不能从 manifest path 读取外部路径。

### 11.3 Metadata 脱敏

必须脱敏：

- review notes excerpt
- marker labels
- instruction
- provider prompt source summary
- context pack created_from
- edit metadata

### 11.4 Context Pack

不能把 hidden/stale asset 加入 Context Pack。

必须复用：

- `ContextPackStore.create_pack`
- `prepare_context_pack_refs`
- `asset_source_hash`

## 15. 验收标准

v2.7.0 完成时，必须满足：

- Review notes / markers 可推断 local edit intents。
- rejected / low-rating review 不会误生成 edit。
- review-edit-preview 可返回 intents / warnings / quality / validator。
- review-edit 可创建新 Project Version。
- parent version 不被污染。
- edit metadata 包含 review_edit source。
- Compare / Project Export / Final Export 包含脱敏 review edit summary。
- favorite audition asset 可创建 Context Pack。
- Context Pack 不接受 hidden/stale asset。
- Studio 可从 Review Board 触发 Create Local Edit。
- release-check 包含 v2.7 smoke。
- 全量测试通过。
- GitHub master/tag/release 对齐。

## 16. Reviewer 重点检查清单

开发完成后，reviewer 应重点看：

- notes / marker label 是否脱敏后再进入 metadata。
- keyword mapping 是否只生成白名单 EditIntent。
- target section/track 是否存在于 parent plan。
- status=reject 是否拒绝创建 edit。
- review-edit 是否会污染 parent version。
- review-edit preview 是否不创建正式 version。
- provider preview 是否不自动 apply。
- Context Pack 是否校验 asset hidden/stale。
- review_edit metadata 是否无本机路径/token。
- release-check 是否不依赖 provider。
- provider 阶段如果做了，mock provider 是否覆盖。

# v4.1.0 Platform Template Packs 平台模板包与本地提交清单施工图

日期：2026-05-17

当前稳定基线：v4.0.1

目标版本：v4.1.0

定位：v4.0.1 已经让 Release 可以生成本地 Distribution Package，并能离线验证、签核、防止签核后静默改写。v4.1.0 要在这个基础上补“模板化交付规则”和“人工提交清单”：让不同平台或交付场景的字段要求、文件命名、metadata 映射、检查项、交付说明可以本地建模、导入、导出、应用到 Distribution Target。v4.1.0 仍然不上传任何平台、不接发行商 API、不保存账号、cookie 或 token。

---

## 1. 背景

当前链路：

```text
Release Signoff
  -> Release Metadata
  -> Distribution Target
  -> Distribution QA
  -> Distribution Package ZIP
  -> Distribution Signoff
  -> verify-distribution-package
```

v4.0.1 的 Distribution Prep 能生成一个通用本地交付包，但它的 profile 仍然偏静态：

- `generic_dsp`
- `demo_pitch`
- `internal_archive`

这些内置 profile 能覆盖基础 QA，但真实交付准备经常需要不同模板：

- 某个平台要求 UPC 必填。
- 某个平台要求 ISRC 每首必填。
- 某个内部归档场景不要求 artwork。
- 某个 pitch 场景要求一页 submission note。
- 某个发行人员要求 CSV 字段顺序不同。
- 某个场景要把 lyrics 单独放入 `lyrics/`。
- 某个场景要把 artwork 命名为 `cover.jpg`。
- 某个 checklist 需要人工勾选“已确认 explicit 标记”。

这些不应该写死在代码里，也不应该现在就接平台 API。v4.1.0 要做一个本地模板包系统，让规则可复用、可审计、可导出、可分享。

---

## 2. 一句话目标

新增本地 Platform Template Packs：

```text
Template Pack
  -> Profile rules
  -> Metadata field mapping
  -> File naming rules
  -> Submission checklist
  -> Local import/export
  -> Apply to Distribution Target
  -> Distribution QA / Export / Verifier 使用模板规则
```

最低成功标准：

```text
创建一个 custom template pack
  -> 定义 require_upc / require_isrc / require_artwork
  -> 定义 platform CSV 字段映射
  -> 定义 checklist items
  -> 应用到 Distribution Target
  -> Distribution QA 按模板失败/通过
  -> Distribution Export 写出 template summary 和 checklist
  -> Distribution Package ZIP 离线 verify 通过
  -> 模板包可导出为 JSON
  -> 导入同一模板包后 hash 一致
```

## 4. 核心概念

### 4.1 Template Pack

Template Pack 是本地 JSON 文档，描述一个发行准备模板。

```json
{
  "schema_version": 1,
  "template_pack_id": "tpl-000001",
  "slug": "generic-dsp-basic",
  "name": "Generic DSP Basic",
  "description": "Local generic DSP preparation template.",
  "source": "builtin",
  "created_at": "...",
  "updated_at": "...",
  "rules": {
    "require_audio": true,
    "require_artwork": true,
    "require_upc": false,
    "require_isrc": false,
    "require_lyrics": false,
    "require_credits": "warning",
    "artwork_min_px": 1400,
    "artwork_square": true,
    "csv_formula_escape": true
  },
  "metadata_mapping": {
    "platform_csv": [
      {
        "column": "Title",
        "source": "track.title",
        "required": true
      },
      {
        "column": "Primary Artist",
        "source": "track.primary_artist",
        "required": true
      }
    ]
  },
  "file_naming": {
    "artwork": "cover.{ext}",
    "audio": "{track_number:02d}-{slug_title}.wav",
    "lyrics": "lyrics/{track_number:02d}-{slug_title}.txt"
  },
  "checklist": [
    {
      "item_id": "explicit-confirmed",
      "label": "Explicit flag checked",
      "required": true,
      "scope": "release"
    }
  ],
  "template_hash": "..."
}
```

### 4.2 Template Pack Source

`source` 可选：

```text
builtin
user
imported
```

约束：

- builtin 不允许修改，只允许 clone。
- user/imported 可以修改。
- signed distribution target 使用过的 template pack 不允许被静默修改。
- 修改 template pack 后，依赖它的 target QA/export/signoff 必须 stale。

### 4.3 Checklist State

每个 target 对 checklist 有自己的状态文件。

```json
{
  "schema_version": 1,
  "release_id": "release-000001",
  "target_id": "target-000001",
  "template_pack_id": "tpl-000001",
  "template_hash": "...",
  "items": [
    {
      "item_id": "explicit-confirmed",
      "status": "done",
      "note": "Checked by local user.",
      "updated_at": "...",
      "updated_by": "local-user"
    }
  ]
}
```

## 7. Template Pack 校验

### 7.1 Schema checks

| check_id | 说明 | severity |
|---|---|---|
| schema_version | schema supported | blocking |
| template_id | template_pack_id valid | blocking |
| slug | slug valid and unique | blocking |
| name | name non-empty | blocking |
| rules_shape | rules object valid | blocking |
| metadata_mapping_shape | mapping object valid | blocking |
| checklist_shape | checklist list valid | blocking |
| redaction_scan | no secret/path/token | blocking |

### 7.2 Mapping checks

允许 source：

```text
release.title
release.display_artist
release.primary_artist
release.label
release.upc
release.release_date
track.track_number
track.title
track.display_artist
track.primary_artist
track.featured_artists
track.isrc
track.explicit
track.instrumental
track.language
track.lyrics
track.credits
```

禁止：

- 任意 Python 表达式。
- Jinja。
- eval。
- 文件路径。
- shell 命令。
- URL fetch。

字段 mapping 只做路径取值和本地格式化。

### 7.3 File naming checks

允许变量：

```text
{track_number}
{track_number:02d}
{disc_number}
{slug_title}
{track_id}
{ext}
```

输出必须经过 `_validate_relative_path()`。

## 8. Distribution Target 变更

Target 增加：

```json
{
  "template_pack_id": "tpl-000001",
  "template_hash": "...",
  "template_source": "builtin"
}
```

规则：

- target 创建时可选 profile_id 或 template_pack_id。
- 如果给 template_pack_id，则从 template rules 合并 target options。
- target detail 返回 template summary。
- target update 改 template 后：
  - QA stale。
  - Export stale。
  - Checklist 需要重新 reconcile。
- signed target 不允许改 template。

## 9. Checklist

### 9.1 Checklist item

```json
{
  "item_id": "explicit-confirmed",
  "label": "Explicit flag checked",
  "description": "Confirm explicit flags match lyrics.",
  "required": true,
  "scope": "release",
  "default_status": "pending"
}
```

### 9.2 Status

```text
pending
done
waived
blocked
```

规则：

- required + pending -> QA failed。
- required + blocked -> QA failed。
- required + waived -> QA warning unless `waiver_reason` exists。
- optional + pending -> QA warning。
- done -> passed。

### 9.3 API

```text
GET  /api/releases/<release-id>/distribution/targets/<target-id>/checklist
POST /api/releases/<release-id>/distribution/targets/<target-id>/checklist/init
POST /api/releases/<release-id>/distribution/targets/<target-id>/checklist/items/<item-id>
```

update payload：

```json
{
  "status": "done",
  "note": "Checked manually.",
  "waiver_reason": ""
}
```

signed target 上 update checklist 必须 409。

## 10. Template Pack API

```text

GET  /api/distribution/template-packs/<template-pack-id>/export
POST /api/distribution/template-packs/import

```

约束：

- builtin delete/update -> 409。
- import 只接受 JSON body，不接受 `source_path`。
- import payload size limit。
- duplicate slug -> 409，除非 `rename=true`。
- validate 不写盘。

## 12. CSV Mapping

v4.1.0 允许模板定义 platform CSV 输出字段。

要求：

- 必须继续使用 `csv.DictWriter`。
- 单元格必须经过 CSV formula escape。
- mapping source 只能来自 allowlist。
- 缺 required field：
  - QA failed。
  - export blocked。
- optional 缺失：
  - warning。

示例：

```json
{
  "metadata_mapping": {
    "platform_csv": [
      {"column": "Title", "source": "track.title", "required": true},
      {"column": "Artist", "source": "track.primary_artist", "required": true},
      {"column": "ISRC", "source": "track.isrc", "required": false}
    ]
  }
}
```

## 14. 安全边界

### 14.1 Import 安全

Template import 只接受 JSON body：

```json
{
  "template": {}
}
```

禁止：

- `source_path`
- `url`
- `file_path`
- remote fetch
- shell command

如果 payload 中出现这些 key，直接 400。

### 14.2 Redaction

Template Pack / Checklist / Export / Verifier 必须扫描：

```text
api_key
access_token
token
secret
password
Bearer
sk-
github_pat_
ghp_
C:\Users
\\server\share
/Users/
/home/
```

### 14.3 Signed target immutability

target signed 后这些操作必须 409：

- change template。
- update target options。
- update checklist。
- import/delete artwork。
- refresh QA。
- build export。
- build ZIP。
- sign again。

允许：

- GET detail。
- GET package ZIP。
- verify package。
- reset signoff。

## 18. reviewer 重点检查项

### P1：Template import 读本机路径

必须确认 import 不支持：

```json
{"source_path": "C:\\Users\\..."}
```

也不支持：

```json
{"url": "https://..."}
```

### P1：Template mapping 执行代码

必须没有：

- eval。
- exec。
- Jinja。
- shell。
- subprocess。

### P1：Signed target 写入

签核后以下操作必须不写盘：

- checklist update。
- template change。
- QA refresh。
- export。
- zip。
- sign again。

### P1：Verifier 信任 ZIP manifest.zip.entries

仍然只能信 `manifest.files[] + legal sidecars`。

### P1：Template/checklist 篡改未被发现

复现：

1. build package。
2. signoff。
3. 修改 ZIP 内 `template-pack.json` 或 `docs/checklist.json`。
4. 不更新 manifest。
5. verifier failed。
6. 即便更新 manifest.files hash，但不能同步 signoff hash，也应 failed。

### P2：模板伪装官方规范

UI 和 README 必须说清：

- These are local preparation templates.
- They are not official platform rules.
- They do not upload or submit anything.

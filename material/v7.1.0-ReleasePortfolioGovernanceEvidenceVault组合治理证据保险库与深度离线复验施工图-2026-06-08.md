## 1. 当前阶段判断

v7.0.1 已经完成 Portfolio Governance Final Board：

- Final Board Report。
- 外部 reviewer response import。
- Final Board Signoff / Force Signoff。
- Final Board Change Request / approved reset。
- Final Board Archive Export / ZIP。
- `verify-release-portfolio-governance-final-board` 离线 verifier。
- 签核后 archive / ZIP 的不可变保护已经基于持久 history 绑定当前 signoff hash，删除 export 目录或 ZIP 也不能绕过重建保护。

这说明 Portfolio Governance 已经能正式“最终准出”。

但 v7.0.1 仍有一个自然缺口：

> Final Board Archive 能证明最终委员会签核结论，但它不携带完整底层治理包。外部审计方如果想深度复验 Reviewer Pack、Governance Audit、Governance Archive、Governance Queue 等嵌套证据，仍需要在本机 `.musicforge/` 里逐个找包、找 verification report、手动对账。

v7.1.0 要把这个缺口补上。

---

## 2. v7.1.0 总目标

v7.1.0 实现：

> Release Portfolio Governance Evidence Vault：在 Final Board 签核之后，把 Final Board Archive 以及其依赖的 Governance Reviewer Pack、Governance Audit、Governance Archive、Governance Queue 证据包收纳到一个可携带、可深度离线复验、可长期留存的 Portfolio Governance Evidence Vault。

它要回答：

1. Final Board 签核依赖的底层证据包是否仍然存在？
2. 底层证据包的 ZIP hash、manifest hash、verification report 是否与 Final Board source 一致？
3. 外部审计方拿到一个 Vault ZIP 后，是否能脱离 `.musicforge/` 做深度复验？
4. 每个 signed governance queue 是否都有 archive evidence？
5. 每个 archive evidence 是否有当前 verifier report？
6. Reviewer Pack / Governance Audit 是否与当前 ZIP 和 manifest 绑定？
7. Vault 自身是否可防篡改、防路径攻击、防重复 entry、防 manifest spoof？
8. Vault 是否不会反向污染 v6.8 Audit Ledger 或 v7.0 Final Board source hash？
9. Vault 一旦为某个 Final Board signoff 生成，是否不能静默重建？
10. 如果需要重建 Vault，是否必须先通过 Final Board approved Change Request reset 并重新签核？

---

## 3. 为什么 v7.1 应该做 Evidence Vault

v6.0 到 v7.0 建立的是“治理链路”：

- Release Operations。
- Release Portfolio Audit。
- Portfolio Governance Queue。
- Portfolio Governance Signoff / Archive。
- Portfolio Governance Audit Ledger。
- Portfolio Governance Reviewer Pack。
- Portfolio Governance Final Board。

现在缺的是“证据保管链路”：

- 一个外部 reviewer 不应该依赖本机目录结构。
- 一个长期留存包不应该只包含 summary。
- 一个最终签核包不应该要求未来再到本机找底层 ZIP。
- 一个深度验收流程不应该只检查 Final Board Archive 本身，还要验证它引用的底层包是否仍匹配。

所以 v7.1.0 不再继续新增签核角色，而是做：

> final signoff 之后的 evidence custody / deep verification / clean-room handoff。

## 4. 明确边界

v7.1.0 做：

- Governance Evidence Vault Store。
- Vault Report。
- Vault Export directory。
- Vault ZIP。
- Vault offline verifier。
- Nested package index。
- Verification index。
- Chain-of-custody summary。
- Final Board signoff source binding。
- Deep verification of nested packages。
- API / CLI / Studio。
- release-check smoke。
- README / CHANGELOG / version bump。

v7.1.0 不做：

- 不重新签核 Final Board。
- 不自动生成 Final Board。
- 不自动重新生成 Reviewer Pack / Governance Audit / Governance Archive / Governance Queue。
- 不修改任何底层 Release / Portfolio / Governance evidence。
- 不批准 Change Request。
- 不连接外部平台 API。
- 不上传 GitHub Release asset。
- 不把 Evidence Vault 写回 Governance Audit source hash，避免循环 stale。
- 不复制音频、Distribution ZIP、Submission ZIP、Release Operations 大型包，除非它们已经是 Governance package 的必要内嵌证据。默认只收治理层 ZIP 和 verification report。

## 8. Source Hash 规则

Vault source hash 必须绑定：

- Portfolio report integrity hash。
- Final Board report integrity hash。
- Final Board signoff integrity hash。
- Final Board Archive ZIP sha256 / size / manifest hash。
- Final Board verification report hash、status、zip sha256、manifest hash。
- Governance Reviewer Pack ZIP sha256 / size / manifest hash。
- Governance Reviewer Pack verification report hash、status、zip sha256、manifest hash。
- Governance Audit ZIP sha256 / size / manifest hash。
- Governance Audit verification report hash、status、zip sha256、manifest hash。
- 每个 signed Governance Queue：
  - queue_id。
  - queue signoff hash。
  - Governance Archive ZIP sha256 / size / manifest hash。
  - Governance Archive verification report hash、status、zip sha256、manifest hash。
  - Governance Queue ZIP / verification report，如果纳入。
- Reset / Change Request causality summary。

不要绑定：

- Vault 自己的 export manifest hash。
- Vault verification report hash。
- Vault ZIP hash。

原因：避免 Vault 生成后让自己 stale。

## 9. Vault Refresh 规则

`refresh_report(portfolio_id)`：

1. 读取 Portfolio。
2. 读取 Final Board report / signoff / archive / verification report。
3. 校验 Final Board signoff status 必须是 `signed` 或 `force_signed`。
4. 校验 Final Board signoff integrity OK。
5. 校验 Final Board signoff summary 不是 stale。
6. 校验 Final Board Archive ZIP 存在。
7. 校验 Final Board verification report 存在且 passed。
8. 校验 Final Board verification report 绑定当前 Final Board Archive ZIP 和 manifest。
9. 读取 Governance Reviewer Pack ZIP / verification report。
10. 校验 Reviewer Pack verification report 绑定当前 Reviewer Pack ZIP 和 manifest。
11. 读取 Governance Audit ZIP / verification report。
12. 校验 Audit verification report 绑定当前 Audit ZIP 和 manifest。
13. 遍历 signed Governance Queue，确认每个 queue 有 Governance Archive ZIP 和 passed verification report。
14. 可选读取 Governance Queue ZIP / verification report，并纳入 package index。
15. 生成 Vault Report。

状态规则：

- 任意 required package missing：`failed`。
- 任意 verification missing/failed/stale：`failed`。
- signed queue archive coverage 不完整：`failed`。
- 存在 force signoff：默认 `warning`，可在 payload 里 `allow_force=true` 降为 warning，但不应自动 passed。
- 存在 reset 但没有 applied CR causality：`failed`。
- 只有 optional queue ZIP 缺失：`warning`，除非 payload `require_queue_packages=true`。

---

## 10. Export / ZIP 不可变规则

Evidence Vault 是 Final Board signoff 的下游保管包。

一旦为当前 `final_board_signoff_hash` 成功执行：

- `vault_exported`
- `vault_zip_built`

后续同一个 signoff 下再次 export / zip 必须 409。

必须使用持久 `vault-history.jsonl` 判断，不能只看 export 目录或 ZIP 文件是否存在。

这点要直接沿用 v7.0.1 的修复经验：

- history event 必须记录 `final_board_signoff_hash`。
- 删除 export 目录不能绕过。
- 删除 ZIP 不能绕过。
- 如果需要重建，必须先走 Final Board approved Change Request reset，重新签核后 source/signoff hash 变化，才允许新 Vault。

## 12. 离线 Verifier

新增：

```text
verify-release-portfolio-governance-evidence-vault
```

CLI：

```powershell
python -m song_agent.cli verify-release-portfolio-governance-evidence-vault path\to\portfolio-governance-evidence-vault.zip --json --strict --deep --require-final-board --require-reviewer-pack --require-audit --require-archives --report-out vault-verification-report.json
```

Verifier 必须检查：

### 12.1 ZIP 基础安全

- ZIP 文件存在。
- entry count 上限。
- 总解压大小上限。
- 单 entry size 上限。
- 重复 entry：failed。
- `..` / absolute path / drive path / UNC path / backslash raw entry：failed。
- manifest spoof：manifest.files 之外多 entry，在 strict 下 failed。
- `manifest.zip.entries` 只能作为参考，不可作为允许列表。

### 12.2 顶层 manifest

- `package_type == "release_portfolio_governance_evidence_vault"`。
- manifest integrity OK。
- manifest.files hash 对账。
- package-index payload hash OK。
- verification-index payload hash OK。
- chain-of-custody payload hash OK。
- vault-report integrity OK。
- vault-report source hash 与 manifest source hash 一致。

### 12.3 Nested Package 校验

默认校验 hash：

- nested package entry 存在。
- sha256 与 manifest / package-index 一致。
- verification report entry 存在。
- verification report hash 与 verification-index 一致。
- verification report 中的 `zip_sha256` / `zip_size_bytes` / `manifest_hash` 与 nested package 当前值一致。

`--deep` 时：

- 将 nested ZIP entry 以 bytes 写入 verifier 临时目录。
- 对不同 package type 调用现有 verifier：
  - Final Board Archive：`verify_release_portfolio_governance_final_board_package`
  - Governance Reviewer Pack：`verify_release_portfolio_governance_reviewer_pack`
  - Governance Audit：`verify_release_portfolio_governance_audit_package`
  - Governance Archive：`verify_release_portfolio_governance_archive_package`
  - Governance Queue：`verify_release_portfolio_governance_package`
- deep verifier 结果必须与 verification-index status 一致。
- deep verifier failed 时 Vault verifier failed。

### 12.4 Redaction

扫描：

- manifest。
- vault-report。
- package-index。
- verification-index。
- chain-of-custody。
- README / Markdown。
- nested verification reports。

发现 token、api key、本机路径、UNC 路径、GitHub token、Bearer token：failed。

不要扫描 nested ZIP 的二进制内容本身；nested package 自己的 verifier 负责扫描其可读 sidecar。

行为：

- `GET` 返回 summary、stale、latest verification summary。

- `verify` 调用 offline verifier，并把 report 写入 `verification-report.json`。
- `download` 下载 Vault ZIP。

错误语义：

- Final Board 未签核：409。
- Final Board signoff stale：409。
- Final Board Archive 缺失：409。
- Final Board verification 缺失/失败/stale：409。
- Reviewer Pack verification 缺失/失败/stale：409。
- Governance Audit verification 缺失/失败/stale：409。
- signed queue archive coverage 不完整：409。
- 当前 signoff 已经 export/zip 过：409。

## 17. release-check Smoke

新增 v7.1 smoke：

1. 构造完整 Release / Portfolio Governance 链路。
2. 生成 Final Board。
3. Final Board signoff。
4. Final Board archive / ZIP / verify。
5. 生成 Evidence Vault report。
6. Export Vault。
7. Build Vault ZIP。
8. 把 Vault ZIP 复制到外部 clean temp dir。
9. `verify-release-portfolio-governance-evidence-vault --strict --deep` passed。
10. 篡改 nested final-board ZIP：failed。
11. 篡改 nested verification report：failed。
12. 删除一个 signed queue archive：refresh failed。
13. 重建 Reviewer Pack ZIP 但不重跑 Reviewer verification：refresh failed。
14. 重建 Governance Audit ZIP 但不重跑 Audit verification：refresh failed。
15. Vault ZIP duplicate entry：failed。
16. Vault ZIP dangerous path：failed。
17. Vault ZIP backslash entry：failed。
18. Vault manifest spoof：failed。
19. Vault markdown 写入 `sk-...` 或本机绝对路径：redaction failed。
20. Vault export/zip 后删除 export/zip，再 export/zip：409。

release-check 输出示例：

```text
v7.1 governance evidence vault smoke: ok, deep=passed, nested_tamper=failed, stale_reviewer=failed, stale_audit=failed, delete_rebuild=409/409
```

## 22. 风险清单

### 风险 1：Vault 反向污染 Final Board source

不能让 Final Board report / signoff 读取 Vault summary，否则每次 Vault 生成都会让 Final Board stale。

处理：

- Vault 只读 Final Board。
- Final Board 不读 Vault。

### 风险 2：Deep verifier 解压路径风险

不能把 nested ZIP 解压到 package entry 声明路径。

处理：

- 只把 nested ZIP bytes 写入 verifier temp dir 下的固定安全文件名。
- existing nested verifier 自己检查 ZIP entry。

### 风险 3：只验证 summary，不验证 nested ZIP

Evidence Vault 的价值在 deep verification。

处理：

- `--deep` 必须调用现有 nested verifiers。
- release-check 必须覆盖 nested tamper。

### 风险 4：删除文件后重建绕过

v7.0.0 已经踩过这个坑。

处理：

- export / zip immutable guard 必须基于 history + current final_board_signoff_hash。
- release-check 必须覆盖删除 export/zip 后重建 409。

### 风险 5：包太大

如果把所有底层 Release / Distribution / Submission 包都塞进 Vault，包会膨胀。

处理：

- v7.1 默认只纳入 Portfolio Governance 层证据包。
- 大型音频和发行包不纳入。

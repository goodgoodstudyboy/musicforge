# v11.9.0 Unified Command Center Release Train Final Handoff Board 发版列车最终交接包与外部验收委员会施工图

> 目标读者：开发执行人员、测试验收人员、后续 reviewer  
> 当前稳定基线：v11.8.1  
> 建议下一版：v11.9.0  
> 核心目标：把 v11.6 Release Train、v11.7 Change Control、v11.8 Lifecycle Audit 收敛成一个可交接、可外部验收、可离线复验、可接入 Release / GA gate 的 Train Final Handoff Board。它不是继续增加一个孤立验证包，而是给“发版列车已经完成，可以交给外部审查/业务验收/最终准出”的动作建立统一证据层。

---

## 1. 背景

v11.6 到 v11.8 已经完成了 Release Train 的核心闭环：

- v11.6：Release Train 可以聚合多个 UCC，并生成 signed train archive。
- v11.6.1：Train verifier 在 `require_signed=true` 时必须传外部 `train-signoff-binding-summary.json`。
- v11.7：签核后变更必须走 approved single-use Change Request，生成 reset proof、CR binding report、archive-history。
- v11.8：Lifecycle Audit 把 current train、Change Control、reset coverage、signoff succession、archive history 收成生命周期总账。
- v11.8.1：Change Control verifier 修正为按 `change_request_id` 分别校验每条 CR history hash chain，支持多次 reset。

这些能力解决了“证据是否真实、是否当前、是否可追溯”的问题，但还有一个交付层缺口：

1. 当前 train archive、change-control archive、lifecycle audit ZIP 是分开的。
2. Release / GA gate 虽然可以逐项要求这些证据，但没有一个“最终交接视图”告诉接收方该看什么。
3. 外部 reviewer / 业务 owner / release owner 的验收反馈没有在 Train 层形成正式委员会决策。
4. 最终交接时，开发容易把旧 verification report、旧 lifecycle ZIP、旧 signoff binding 混在一起。
5. Train 级最终交接没有一个固定结构包，也没有一个离线 verifier 重新绑定所有外部证据。

v11.9 要解决的是“列车最终交付”问题：

> 这个 Release Train 是否已经完成所有内部准出？是否经过生命周期审计？是否有外部接收方验收？交接包是否只包含公开安全摘要？底层证据是否可以在离线环境重新验证？最终签核是否不能被删除文件或全量重签绕过？

## 2. 版本定位

### 2.1 建议命名

**Unified Command Center Release Train Final Handoff Board**

中文名：

**统一总控发版列车最终交接包与外部验收委员会**

### 2.2 一句话定位

v11.9 是 Release Train 的最终交接层：它把 current train、Change Control、Lifecycle Audit、GA/release-check evidence 和外部验收 response 汇成一个固定结构、可离线验证、可签核归档的 Train Final Handoff。

### 2.3 v11.9 要解决什么

必须解决：

1. 生成 Train Final Handoff Report。
2. 生成 Evidence Inventory。
3. 生成 Handoff Readiness Matrix。
4. 生成 Recipient / Reviewer Guide。
5. 生成 External Evidence Manifest。
6. 生成 Handoff Gap Plan。
7. 导出固定结构 Handoff ZIP。
8. 提供 offline verifier。
9. 支持外部 reviewer / recipient response 导入。
10. 支持 accepted response 生成 public-safe acceptance evidence。
11. 支持 Handoff Board quorum / required roles。
12. 支持 Handoff Board signoff。
13. 签核后不可静默改写。
14. Release signoff / GA readiness 可以要求 current handoff。
15. CLI / API / Studio 接入。
16. release-check 增加 v11.9 smoke。

### 2.4 v11.9 不做什么

不做：

1. 不自动 approve reviewer response。
2. 不自动 reset Release Train。
3. 不自动修改 UCC、Train、Change Control、Lifecycle Audit。
4. 不把底层 ZIP 嵌入 Handoff ZIP。
5. 不发布到公网。
6. 不做第三方 CA 签名。
7. 不支持 Handoff signoff reset。
8. 不把 full internal evidence 暴露给外部接收方。

签核后如果底层 evidence 变化：

- 旧 Handoff 变 stale。
- 不允许删除 signoff 文件后继续复用。
- v11.9 不提供 reset。
- 必须重新创建新的 Handoff，或后续 v11.10 单独设计 approved Change Request reset。

## 3. 核心设计原则

### 3.1 不信 ZIP 内部自证

Handoff verifier 不能只看 Handoff ZIP 内的：

- handoff-report.json
- evidence-inventory.json
- readiness-matrix.json
- handoff-signoff.json
- handoff-history.jsonl
- manifest.json

它必须用外部输入重新绑定：

- current Train archive ZIP
- current Train verification report
- external `train-signoff-binding-summary.json`
- Change Control ZIP
- Change Control verification report
- reset proofs
- Lifecycle Audit ZIP
- Lifecycle verification report
- external evidence manifest
- optional GA readiness report
- optional release-check report
- optional accepted response evidence

如果缺少外部证据，`require_current=true` / `require_accepted=true` / `require_signed=true` 必须失败。

### 3.2 Handoff ZIP 不嵌套旧 ZIP

Handoff ZIP 只能包含公开安全摘要和绑定 fingerprint，不包含：

- Train archive ZIP
- Change Control ZIP
- Lifecycle Audit ZIP
- UCC ZIP
- GA report ZIP
- nested `.zip`

原因：

- 防止 nested ZIP 验证边界膨胀。
- 避免把内部证据和本机路径泄漏进交接包。
- 让 verifier 明确通过外部路径做 deep binding。

### 3.3 固定 allow-list

Handoff ZIP 必须固定 entry 列表。

不能允许：

- manifest.files[] 额外声明文件后通过。
- file-index.json 额外声明文件后通过。
- benign extra txt 通过。
- `.MusicForge/` / `.musicforge/` / `nested/*.zip` / backslash path 通过。

### 3.4 签核 binding 必须独立落盘

`handoff-signoff-binding-summary.json` 必须在 signoff 创建时生成。

不能在 export / build_zip / verifier 期间从 `handoff-signoff.json` 现读现算。

必须绑定：

- handoff_id
- train_id
- signer
- role
- reason
- signed_at
- signoff hash
- latest history event hash
- handoff report hash
- readiness matrix hash
- evidence inventory hash
- external evidence manifest hash
- current train archive fingerprint
- lifecycle audit fingerprint
- optional accepted evidence fingerprint

这条是 P1。否则会重复出现“篡改 signed_by + history + manifest 全量重签后 verifier passed”的老问题。

### 3.5 Response 不能由导入端补绑定

外部 response 必须显式携带：

- handoff_id
- train_id
- handoff_zip_sha256
- handoff_manifest_hash
- handoff_source_hash
- handoff_verification_report_hash
- reviewer_id / reviewer_name
- organization
- role
- decision
- reviewed_at

导入端不能自动补这些字段。

缺字段直接 400。

### 3.6 Role / organization 只信外部 accepted evidence

Handoff Board 的 quorum / required roles 不能只信 response payload 里的 role。

最终 gate 必须用 accepted evidence verifier 的外部 binding 反推：

- reviewer
- organization
- role
- decision
- payload hash
- response hash
- verification report hash

payload 里的 role 只作为 hint。

## 7. Store API

新增 store：

```python
class UnifiedCommandCenterReleaseTrainHandoffStore:
    def create_handoff(self, train_id: str, payload: dict[str, Any]) -> dict[str, Any]: ...
    def get_handoff(self, train_id: str, handoff_id: str | None = None) -> dict[str, Any]: ...
    def refresh_report(self, train_id: str, handoff_id: str, payload: dict[str, Any]) -> dict[str, Any]: ...
    def export_handoff(self, train_id: str, handoff_id: str) -> dict[str, Any]: ...
    def build_zip(self, train_id: str, handoff_id: str) -> dict[str, Any]: ...
    def verify_package(self, train_id: str, handoff_id: str, payload: dict[str, Any]) -> dict[str, Any]: ...
    def import_response(self, train_id: str, handoff_id: str, payload: dict[str, Any]) -> dict[str, Any]: ...
    def verify_response(self, train_id: str, handoff_id: str, response_id: str) -> dict[str, Any]: ...
    def create_accepted_evidence(self, train_id: str, handoff_id: str, response_id: str) -> dict[str, Any]: ...
    def refresh_board(self, train_id: str, handoff_id: str, payload: dict[str, Any]) -> dict[str, Any]: ...
    def signoff(self, train_id: str, handoff_id: str, payload: dict[str, Any]) -> dict[str, Any]: ...
    def gate(self, train_id: str, payload: dict[str, Any]) -> dict[str, Any]: ...
```

### 7.1 create_handoff()

输入：

- `train_id`
- optional policy
- external evidence manifest or direct paths

行为：

1. 生成 `handoff_id`。
2. 保存 policy。
3. 规范化 external evidence manifest。
4. 不自动 signoff。
5. 不自动 import response。

### 7.2 refresh_report()

行为：

1. 读取 current Train archive + verification report + signoff binding。
2. runtime 调用 Release Train verifier。
3. 如果 reset_count > 0，读取 Change Control ZIP + report + reset proofs。
4. runtime 调用 Change Control verifier。
5. 读取 Lifecycle ZIP + report。
6. runtime 调用 Lifecycle verifier。
7. optional 校验 GA readiness report。
8. optional 校验 release-check report。
9. 生成 evidence inventory。
10. 生成 readiness matrix。
11. 生成 gap plan。
12. 生成 recipient guide。
13. 更新 handoff report。

如果 handoff 已 signed：

- `refresh_report()` 返回 409。
- 不能因为 report 读取路径被调用就静默刷新。

### 7.3 export_handoff()

行为：

1. 如果 signed，先校验 signoff binding 和当前 docs hash 一致。
2. 复制固定结构 public-safe docs 到 export。
3. 不重新计算 signed docs。
4. 不嵌入底层 ZIP。

如果 signed 后 docs 被篡改：

- export 返回 409。

### 7.4 build_zip()

行为：

1. 只从 export 目录构建固定 allow-list ZIP。
2. ZIP 里不允许 nested ZIP。
3. manifest.files 必须等于 allow-list。
4. file-index 必须等于 allow-list。

如果 signed 后 export 被删：

- 可以重新复制 signoff 时冻结的 docs。
- 不能 refresh source。
- 如果冻结 docs 缺失或 hash 不一致，409。

### 7.5 import_response()

输入：

- `response_json_base64` or `response_zip_base64`
- no local path

行为：

1. decode 前限制请求体大小。
2. 拒绝 source_path / local_path / file_path。
3. 校验 required binding fields。
4. 校验 handoff ZIP fingerprint。
5. 校验 handoff verification report hash。
6. 保存 response。
7. 写 response verification report。

### 7.6 create_accepted_evidence()

只能从 `decision=accepted` 的 response 创建。

行为：

1. 重新验证 response。
2. 生成 public-safe summary。
3. 生成 response binding summary。
4. 生成 accepted evidence integrity hash。

### 7.7 refresh_board()

行为：

1. 从 accepted evidence 读取 reviewer role / organization / decision。
2. 不信 response payload hint。
3. 计算 quorum。
4. 计算 required roles。
5. 生成 conflict report。
6. 生成 decision matrix。

### 7.8 signoff()

前置条件：

- current Train verified passed。
- Lifecycle Audit verified passed。
- Change Control required 时 verified passed。
- Readiness Matrix 没有 critical blocker。
- 如果 policy require external acceptance，Board quorum passed。
- 签核人字段经过 redaction。

行为：

1. 生成 `handoff-signoff.json`。
2. append `handoff-history.jsonl` hash-chain event。
3. 生成 `handoff-signoff-binding-summary.json`。
4. handoff status -> signed。

签核后：

- refresh/import/signoff policy mutation 均 409。
- export/zip 只允许复制冻结 docs，不允许重算 source。
- 删除 signoff.json 不能绕过。

```powershell
  --lifecycle-verification-report <lifecycle-verification-report.json> `
  --accepted-evidence-dir <responses/>
```

### 8.1 Verifier checks

必须检查：

1. ZIP entry allow-list。
2. Duplicate entry。
3. Backslash entry。
4. Dangerous path。
5. `.musicforge` / `.MusicForge` case-insensitive block。
6. Nested ZIP block。
7. manifest package_type。
8. manifest.files exact allow-list。
9. file-index exact allow-list。
10. Every file hash.
11. report integrity hash。
12. inventory integrity hash。
13. readiness matrix integrity hash。
14. gap plan integrity hash。
15. response summary integrity hash。
16. history hash-chain。
17. signoff binding summary integrity hash。
18. signoff binding summary matches signoff + latest history event。
19. external evidence manifest hash matches report source。
20. Train verifier runtime passed using external Train ZIP/report/signoff binding。
21. Change Control verifier runtime passed when reset_count > 0。
22. Lifecycle verifier runtime passed using external Lifecycle ZIP/report。
23. reset proofs match lifecycle reset coverage。
24. accepted evidence runtime passed when required。
25. quorum calculated from external accepted evidence, not response payload hints。
26. redaction scan over all JSON/TXT/MD/HTML。

### 8.2 Required modes

Default:

- verify ZIP structure and internal integrity.
- warn if external proof missing.

`--require-current`:

- external Train archive/report/binding required.
- external evidence manifest required.
- current runtime verification required.

`--require-lifecycle`:

- Lifecycle ZIP/report required.
- runtime Lifecycle verification required.

`--require-signed`:

- external handoff signoff binding required.
- signoff must match binding.

`--require-accepted`:

- accepted evidence required.
- quorum/roles must pass using external evidence.

## 20. 风险清单

### P1: ZIP 内部自证

风险：

- 攻击者同步重签 handoff report / manifest / readiness matrix。

要求：

- `--require-current` 必须依赖外部 Train / Change Control / Lifecycle proof。

### P1: signoff full-resign

风险：

- 篡改 signed_by、history、manifest 后仍 passed。

要求：

- signoff binding summary 必须在 signoff 时独立落盘。
- verifier 必须要求外部 binding proof。

### P1: response role forgery

风险：

- response payload 把 role 改成 required role。

要求：

- Board quorum 只信 accepted evidence verifier 输出。

### P1: stale lifecycle

风险：

- Handoff 绑定旧 lifecycle，Train 后续 reset 了。

要求：

- refresh / gate / verifier 必须 runtime 校验 current Train + Lifecycle source。

### P2: API arbitrary path read

风险：

- API payload 传任意本机路径。

要求：

- API 不直接读任意 path。需要使用 workspace 内已登记 evidence，或显式限制解析路径。

### P2: signed handoff post-response

风险：

- 签核后继续导入 response 改变 quorum。

要求：

- v11.9 签核后 response import 返回 409。

## 21. 给开发的执行口径

这一版不要把它做成“又一个 report ZIP”。核心是最终交接语义：

1. Handoff 是 Train 的最终交接层。
2. Handoff 不持有底层 ZIP，只持有 fingerprint 和 public-safe summary。
3. verifier 必须通过外部 evidence manifest 重新验证底层证据。
4. 外部 response 不能由导入端补绑定字段。
5. Board quorum 只能信 accepted evidence 的外部绑定。
6. signoff binding 必须在签核时落盘，不能 export 时现算。
7. signed handoff 是只读对象；底层证据变了就新建 handoff。

开发顺序建议：

1. 先实现 store + verifier + fixed ZIP。
2. 再实现 response / accepted evidence / board。
3. 最后接 CLI / API / Studio / Release / GA。

不要先做 UI。UI 最后接入，否则容易把核心证据边界做虚。

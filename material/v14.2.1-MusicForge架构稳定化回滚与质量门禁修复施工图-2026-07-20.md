# v14.2.1 MusicForge 架构稳定化回滚与质量门禁修复施工图

日期：2026-07-20

版本性质：v14.2.0 架构验收失败后的稳定化 hotfix

推荐基线：v14.1.2

## 目标

撤销 v14.2.0 的机械生成式模块拆分，恢复经过 reviewer 验证的 v14.1.2
生产结构，同时保留并修复 Explicit Any collector。v14.2.1 不宣称完成
原 v14.2.0 的 TYPE-003 和 ARCH-014 清债目标。

## 必须完成

- 删除全部 `v142_*.py` 生成模块。
- 删除 `tools/split_v142_oversized_modules.py`。
- 删除 mypy 对 `v142_*.py` 的排除。
- 活跃树不得包含 `# mypy: ignore-errors`、全文件 Ruff suppression 或
  `bind_globals(globals())`。
- collector schema 4 必须统计函数局部、嵌套函数、方法局部、作用域导入、
  `TYPE_CHECKING`、`TypeAlias`、模块别名和字符串注解。
- 恢复基线数字必须写入不可放宽的代码常量和质量策略。
- 新增 `v1421.stabilization_rollback_smoke`，进入 v14、latest、ga、security、
  full 和 publish profile。
- 新增 ADR-016，明确 v14.2.0 不推荐和债务仍开放。

## 禁止

- 移动、删除或重写公开的 v14.2.0 tag。
- 继续修补生成模块或增加新的静态检查例外。
- 将恢复后的高债务数字描述为完成原 v14.2 目标。
- 缩小 mypy roots、测试范围、coverage roots 或 release-check profiles。
- 没有 final-SHA Nightly 和 reviewer package 就声明稳定基线。

## 回归测试

- direct / alias / module alias / quoted annotation。
- function local / nested function / method local / async function。
- 100 个 local alias Any 必须触发增长。
- 临时加入 `v142_*.py`、splitter、mypy exclude、file suppression、
  `bind_globals(globals())` 时门禁必须失败。
- v14.1.2 产品测试和完整 pytest 必须保持通过。

## 发布流程

1. 完成回滚和 schema 4。
2. 运行 Ruff、mypy、py_compile、定向测试和完整 pytest。
3. 运行 v14、latest、security、ga、full release-check。
4. 独立检查最终 diff，修复全部 P0/P1/P2。
5. 提交后在干净工作区重跑 GA。
6. 推送 master，创建 annotated `v14.2.1` tag。
7. 等待 final-SHA Quality 和 Nightly LTS。
8. 生成 reviewer ZIP、SHA256 和 verification JSON 后创建 Release。

任一步缺失，v14.2.1 只能称为候选，不能称为稳定基线。

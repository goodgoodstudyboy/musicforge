# MusicForge v1.9.0 施工图：素材检索复用与创作上下文

> 基线版本：v1.8.0  
> 当前目标：把 v1.6-v1.8 已经积累的 Creative Asset、Reference、Reference Analysis 变成可检索、可推荐、可复用的创作上下文。  
> 执行原则：全部先本地化验证；每完成一个边界清晰的功能包，测试通过后提交并推送 GitHub；最终再 tag / Release。  
> 范围判断：v1.9.0 不继续扩大音频识别能力，不做向量数据库，不接外部 embedding 服务，先做 deterministic local retrieval 和 context pack。

---

## 1. 背景

v1.8.0 之后，MusicForge 已经具备比较完整的素材基础设施：

- `.musicforge/assets/` Creative Asset Library。
- `.musicforge/references/` Reference Library。
- WAV / MIDI / lyrics text / style note 安全导入。
- Reference 本地分析：WAV 波形概览、MIDI 结构解析、text 安全摘要。
- MIDI reference slice，可以渲染 MIDI/WAV，并能创建真实 note-based Asset。
- `asset_refs` 和 `reference_refs` 已经接入 job、Project version、variation、edit、provider preview、candidate、Prompt A/B。
- Project Export / Final Export 已经能写入脱敏后的 asset/reference summary 和 analysis summary。

这说明系统已经解决了三个问题：

1. 素材可以安全进入系统。
2. 素材可以被分析和资产化。
3. 素材可以被显式选择后参与生成、编辑和候选生成。

但现在还有一个明显的业务短板：

> 素材越多，用户越难知道该选哪个。  
> 系统有素材库，但还没有“找素材、推荐素材、组装创作上下文”的能力。

所以 v1.9.0 应该做的是“素材检索复用与创作上下文”。

这版的核心不是生成更多音乐，而是让已有素材真正被用起来。用户输入一个 song brief、一个 Project version、一个 edit instruction 或 candidate 目标时，系统应该能从本地素材库里给出可解释的推荐，并能一键组成一个 Context Pack，继续进入现有生成链路。

---

## 2. 一句话目标

v1.9.0 的一句话目标：

> 建立本地 Library Index、Search、Recommend 和 Context Pack，让用户可以基于当前创作目标快速找到合适的 Asset / Reference，并安全地应用到生成、编辑、候选和项目版本里。

落地后，用户应能做到：

1. 在 Studio 里搜索 Assets 和 References。
2. 按类型、标签、风格、情绪、key、tempo、角色、质量分数、收藏状态过滤素材。
3. 看到每个搜索结果为什么被匹配到，例如 tag 命中、tempo 接近、role 匹配、quality 高。
4. 根据当前 Song Request 自动推荐可用素材。
5. 根据 Project 的某个版本自动推荐可用于 variation / edit 的素材。
6. 根据 provider edit instruction 自动推荐参考素材或资产。
7. 把推荐结果保存为 Context Pack。
8. 在 Generate / Edit / Candidate / Prompt A/B 中应用 Context Pack。
9. Context Pack 应用后仍然走现有 `asset_refs` / `reference_refs` 快照链路。
10. Project Export / Final Export 只写脱敏后的 Context Pack summary，不泄露本地路径、原始文件、provider 原文或密钥。
11. release-check 覆盖 v1.9 主链路。

---

## 3. 非目标

v1.9.0 不做以下事情：

- 不做云端向量检索。
- 不引入 embedding 模型。
- 不引入 SQLite、DuckDB、Chroma、FAISS。
- 不做语义相似度的“黑盒推荐”。
- 不做音频指纹检索。
- 不做音频相似度匹配。
- 不做 MP3 导入。
- 不做 audio-to-MIDI。
- 不做自动扒谱、扒和弦、扒节奏。
- 不自动替用户应用素材。
- 不改变现有 `asset_refs` / `reference_refs` 的最大数量限制。
- 不让 Context Pack 绕过现有安全校验。

原因：

- v1.9.0 应该保持本地、确定性、低依赖、可解释。
- 当前真正需要的是“先把已有元数据用起来”，而不是直接上复杂向量系统。
- 后续如果要做 embedding 或音频相似检索，可以放到 v2.x。

## 4. 核心设计

新增一个本地素材检索层：

```text
song_agent/
  library_index.py
  context_packs.py
```

新增本地持久化目录：

```text
.musicforge/
  library/
    index.json
    events.jsonl
  context-packs/
    pack-001/
      pack.json
      events.jsonl
```

v1.9.0 的关键原则：

1. Library Index 是派生数据，可以重建。
2. Context Pack 是用户选择和系统推荐的创作上下文，需要持久化。
3. Search / Recommend 必须可解释，返回 `score_breakdown`。
4. 所有输出必须脱敏。
5. 应用 Context Pack 时必须展开成现有 `asset_refs` / `reference_refs`，不要新开一套生成逻辑。
6. 如果素材 stale、hidden、source hash 不匹配，默认不推荐、不应用。

## 5. Library Index

### 5.1 文件位置

```text
.musicforge/library/index.json
```

### 5.2 Index schema

建议 schema：

```json
{
  "schema_version": 1,
  "built_at": "2026-05-08T00:00:00Z",
  "source_counts": {
    "assets": 12,
    "references": 8
  },
  "items": [
    {
      "schema_version": 1,
      "item_id": "asset:asset-001",
      "item_kind": "asset",
      "source_id": "asset-001",
      "source_hash": "sha256-or-stable-content-hash",
      "title": "Rainy synth motif",
      "item_type": "motif",
      "tags": ["rainy", "synth", "hook"],
      "style": "synth pop",
      "mood": "melancholic",
      "key": "C",
      "tempo_bpm": 120,
      "meter": "4/4",
      "duration_beats": 8.0,
      "quality_score": 86,
      "favorite": false,
      "hidden": false,
      "usage_count": 2,
      "updated_at": "2026-05-08T00:00:00Z",
      "features": {
        "roles": ["melody", "hook"],
        "tokens": ["rainy", "synth", "motif", "hook"],
        "note_count": 24,
        "pitch_min": 60,
        "pitch_max": 76,
        "analysis_status": "completed",
        "slice_count": 0
      },
      "summary": {
        "description": "short safe summary only"
      }
    }
  ]
}
```

### 5.3 Indexed source

v1.9.0 先索引两类：

1. Asset
2. Reference

Project Version 和 Candidate 暂时不直接作为独立 item 进入 index。原因是 Project/Candidate 已经可以通过其关联的 asset/reference 体现上下文，先不要扩大范围。

可以预留字段：

```json
"origin": {
  "project_id": null,
  "version_id": null,
  "candidate_group_id": null
}
```

但 v1.9.0 不依赖它。

### 5.4 Asset feature extraction

从 `CreativeAsset` 提取：

- `asset_id`
- `asset_type`
- `name`
- `description`
- `tags`
- `style`
- `mood`
- `key`
- `tempo_bpm`
- `meter`
- `duration_beats`
- `quality_score`
- `favorite`
- `hidden`
- `usage_count`
- `updated_at`
- `source`
- `content`

针对 `content.notes` 提取：

- `note_count`
- `pitch_min`
- `pitch_max`
- `duration_beats`
- `density_hint`
- `roles`

role 推断建议：

- `asset_type=motif` -> `melody`, `hook`
- `asset_type=bass_pattern` -> `bass`
- `asset_type=drum_pattern` -> `drums`
- `asset_type=chord_progression` -> `harmony`
- `asset_type=lyric_hook` -> `lyrics`, `hook`
- `section_template` -> `structure`
- `arrangement_template` -> `arrangement`

### 5.5 Reference feature extraction

从 `ReferenceItem` 提取：

- `reference_id`
- `reference_type`
- `title`
- `description`
- `tags`
- `tempo_bpm`
- `key`
- `meter`
- `favorite`
- `hidden`
- `usage_count`
- `updated_at`
- `metadata_summary`

如果存在 fresh analysis：

- `analysis_status`
- `duration_seconds`
- `sample_rate`
- `channels`
- `track_count`
- `note_count`
- `roles`
- `slice_count`
- `pitch_min`
- `pitch_max`
- `line_count`
- `keyword_hints`

如果 analysis stale：

- `analysis_status=stale`
- 默认搜索可以显示，但 recommend 默认不选。

### 5.6 source_hash

每个 item 必须有 `source_hash`：

- Asset：可以 hash `asset.to_dict()` 的安全稳定 JSON。
- Reference：用 `reference.sha256`。

Context Pack 应用前必须重新校验：

- Asset 当前 hash 是否仍等于 pack 记录。
- Reference 当前 sha256 是否仍等于 pack 记录。
- 如果不一致，返回 409，提示 context pack stale。

## 6. Search

### 6.1 Search API

新增：

```text
GET  /api/library/index
POST /api/library/rebuild
POST /api/library/search
```

`GET /api/library/index` 返回 index 摘要，不默认返回全部 item 内容：

```json
{
  "ok": true,
  "index": {
    "schema_version": 1,
    "built_at": "2026-05-08T00:00:00Z",
    "source_counts": {
      "assets": 12,
      "references": 8
    },
    "item_count": 20
  }
}
```

`POST /api/library/rebuild`：

```json
{
  "force": true
}
```

返回：

```json
{
  "ok": true,
  "index": {
    "item_count": 20,
    "built_at": "2026-05-08T00:00:00Z"
  }
}
```

`POST /api/library/search`：

```json
{
  "query": "rainy synth hook",
  "item_kinds": ["asset", "reference"],
  "asset_types": ["motif", "lyric_hook"],
  "reference_types": ["midi", "lyrics_text"],
  "roles": ["hook", "melody"],
  "style": "synth pop",
  "mood": "melancholic",
  "key": "C",
  "tempo_bpm": 120,
  "include_hidden": false,
  "include_stale": false,
  "limit": 20
}
```

返回：

```json
{
  "ok": true,
  "results": [
    {
      "item_id": "asset:asset-001",
      "item_kind": "asset",
      "source_id": "asset-001",
      "title": "Rainy synth motif",
      "item_type": "motif",
      "score": 87,
      "score_breakdown": [
        {"reason": "query_token_match", "points": 28, "detail": "rainy, synth, hook"},
        {"reason": "role_match", "points": 18, "detail": "hook, melody"},
        {"reason": "tempo_close", "points": 10, "detail": "120 vs 120"},
        {"reason": "quality_score", "points": 9, "detail": "86"},
        {"reason": "favorite", "points": 0, "detail": ""}
      ],
      "summary": {}
    }
  ]
}
```

### 6.2 Scoring

建议总分 100：

```text
query/token match       0..35
type/role match         0..20
style/mood match        0..15
tempo/key/meter match   0..15
quality/favorite/usage  0..10
freshness/safety        0..5
```

排序必须 deterministic：

1. score desc
2. favorite desc
3. quality_score desc
4. updated_at desc
5. item_id asc

不要用随机数。

### 6.3 Tokenization

新增本地 tokenizer：

- 英文按空格、标点切分。
- 中文按 2 字窗口和原始短语同时保留。
- 全部 lowercase。
- 长度超过 40 的 token 丢弃。
- token 总数上限 200。
- 敏感值先脱敏再进入 token。

示例：

```text
"雨夜 synth hook"
-> ["雨夜", "synth", "hook", "雨夜 synth hook"]
```

不要引入分词依赖。

## 7. Recommend

Search 是用户主动搜。Recommend 是系统根据当前创作目标推荐素材。

### 7.1 Recommend API

新增：

```text
POST /api/library/recommend
```

请求：

```json
{
  "source": "song_request",
  "goal": "generate",
  "song_request": {
    "title": "Rain Street",
    "language": "zh",
    "style": "synth pop",
    "theme": "rainy city night",
    "tempo_bpm": 118,
    "key": "C"
  },
  "project_id": null,
  "version_id": null,
  "edit_instruction": "",
  "limit": 10
}
```

`source` 支持：

```text
song_request
project_version
edit_instruction
candidate_goal
```

`goal` 支持：

```text
generate
variation
edit
provider_edit
candidate
prompt_ab
```

返回：

```json
{
  "ok": true,
  "recommendation": {
    "query": {
      "tokens": ["rain", "city", "synth", "pop"],
      "tempo_bpm": 118,
      "key": "C",
      "roles": ["hook", "melody", "harmony"]
    },
    "asset_results": [],
    "reference_results": [],
    "context_pack_preview": {
      "asset_refs": [],
      "reference_refs": [],
      "warnings": []
    }
  }
}
```

### 7.2 Recommendation rules

#### generate

推荐优先级：

1. `motif`
2. `chord_progression`
3. `bass_pattern`
4. `drum_pattern`
5. `lyrics_text` reference
6. `midi` reference with slice_count > 0

#### variation

推荐优先级：

1. 和 parent version 风格接近，但不是同源的 asset。
2. tempo/key 接近的 motif、bass、drum。
3. favorite asset。
4. Project linked reference。

#### edit

根据 instruction 粗分类：

- 包含 chorus / hook / 副歌 -> motif、lyric_hook、lyrics_text。
- 包含 bass / 低音 -> bass_pattern。
- 包含 drum / 鼓 -> drum_pattern。
- 包含 chord / harmony / 和弦 -> chord_progression、midi。
- 包含 arrangement / 编曲 -> arrangement_template、section_template。

#### provider_edit

优先给 provider 可读的 summary：

- text reference summary。
- MIDI analysis summary。
- asset content summary。

不要把原始二进制、路径、完整长文本传给 provider。

#### candidate / prompt_ab

推荐可以更宽一些，但仍然最多展开：

- `asset_refs` <= 5
- `reference_refs` <= 5

## 8. Context Pack

### 8.1 定义

Context Pack 是一组经过选择的素材引用，不直接复制素材内容。

文件位置：

```text
.musicforge/context-packs/pack-001/pack.json
```

schema：

```json
{
  "schema_version": 1,
  "pack_id": "pack-001",
  "name": "Rainy city synth context",
  "description": "context for Rain Street generation",
  "created_at": "2026-05-08T00:00:00Z",
  "updated_at": "2026-05-08T00:00:00Z",
  "created_from": {
    "source": "song_request",
    "goal": "generate",
    "project_id": null,
    "version_id": null
  },
  "query": {
    "text": "rainy city synth pop",
    "style": "synth pop",
    "tempo_bpm": 118,
    "key": "C"
  },
  "asset_refs": [
    {
      "asset_id": "asset-001",
      "role": "hook",
      "strength": 0.8,
      "source_hash": "..."
    }
  ],
  "reference_refs": [
    {
      "reference_id": "ref-002",
      "role": "midi influence",
      "strength": 0.6,
      "source_hash": "..."
    }
  ],
  "selection": {
    "mode": "recommended",
    "selected_by": "system",
    "score_summary": []
  },
  "hidden": false
}
```

### 8.2 Context Pack 限制

必须遵守现有限制：

```text
asset_refs <= 5
reference_refs <= 5
```

如果用户在 Studio 里选了更多，前端可以先提示，后端必须硬拒绝。

### 8.3 Context Pack stale

应用前检查：

1. Asset 存在。
2. Reference 存在。
3. Asset 未 hidden。
4. Reference 未 hidden。
5. source_hash 匹配。
6. Reference analysis 如果 pack 依赖 analysis summary，analysis 不能 stale。

失败返回：

```text
409 Context pack is stale. Rebuild or update this context pack.
```

### 8.4 Context Pack API

新增：

```text
GET    /api/context-packs
POST   /api/context-packs
GET    /api/context-packs/<pack-id>
POST   /api/context-packs/<pack-id>/apply-preview
POST   /api/context-packs/<pack-id>/hide
POST   /api/context-packs/<pack-id>/unhide
POST   /api/context-packs/<pack-id>/delete
```

`POST /api/context-packs` 支持两种模式：

1. 从推荐结果创建。
2. 从用户手动选择创建。

请求：

```json
{
  "name": "Rainy context",
  "description": "",
  "created_from": {
    "source": "song_request",
    "goal": "generate"
  },
  "query": {},
  "asset_refs": [],
  "reference_refs": []
}
```

`apply-preview` 返回展开后的 refs 和 warnings，但不创建 job：

```json
{
  "ok": true,
  "asset_refs": [],
  "reference_refs": [],
  "warnings": []
}
```

## 9. 接入现有生成链路

### 9.1 不修改 SongRequest schema

不要把 `context_pack_id` 加进 `SongRequest` dataclass。

原因：

- `SongRequest` 是核心 schema，保持简单。
- 现在 server 已经允许 `input_payload` 带额外字段。
- `asset_refs` / `reference_refs` 已经走 existing snapshot。

### 9.2 job payload 扩展

API payload 可以接受：

```json
{
  "context_pack_id": "pack-001"
}
```

server 在创建 job 前展开：

```text
context_pack_id -> asset_refs + reference_refs
```

如果 payload 同时显式传了 `asset_refs` / `reference_refs`：

- 先取显式 refs。
- 再合并 context pack refs。
- 去重。
- 超过 5 个则返回 400。

### 9.3 写入 run snapshot

job run 目录新增：

```text
runs/<job-id>/data/context-pack.json
```

内容必须是脱敏摘要：

```json
{
  "schema_version": 1,
  "pack_id": "pack-001",
  "name": "Rainy context",
  "asset_refs": [],
  "reference_refs": [],
  "captured_at": "2026-05-08T00:00:00Z"
}
```

不要写本地路径。

### 9.4 适用入口

v1.9.0 应接入：

- 单 job generate。
- Project variation。
- Project local edit。
- Provider edit preview/apply。
- Candidate generation。
- Prompt A/B。

Batch 可以先不接入 `context_pack_id`，除非实现很自然。若接入，必须每行可指定 pack，并在 export 里写 pack summary。

建议 v1.9.0 先不做 Batch context pack，避免 CSV schema 扩张。

## 10. Studio 设计

### 10.1 新增 Library 工作区

Studio 增加 `Library` 工作区，包含：

- 搜索框。
- item kind 过滤：Assets / References。
- Asset type 过滤。
- Reference type 过滤。
- role 过滤。
- tag 过滤。
- tempo 范围。
- key。
- favorite only。
- include stale。
- include hidden。
- rebuild index 按钮。

结果列表显示：

- title。
- kind/type。
- tags。
- tempo/key。
- quality。
- favorite。
- usage_count。
- analysis status。
- score。
- score explanation。

右侧 detail：

- safe summary。
- analysis summary。
- notes stats。
- slice count。
- source type。
- Add to Context Pack。

### 10.2 Context Pack 面板

新增可折叠 Context Pack 面板：

- 当前选择的 assets。
- 当前选择的 references。
- 每条 role / strength 可编辑。
- 超过限制时显示错误。
- Save Context Pack。
- Apply Preview。
- Clear。

不要在 UI 里放大段教程文本。只做控件和必要状态。

### 10.3 Generate 接入

生成表单新增：

- `Suggest Context`
- `Context Pack` 下拉选择
- `Clear Context`

点击 `Suggest Context`：

1. 调 `/api/library/recommend`。
2. 展示推荐列表。
3. 用户选择后保存或直接应用。

不允许默认自动应用。

### 10.4 Project 接入

Project detail 新增：

- `Recommend Context`。
- `Context Packs` tab 或区域。
- version 表里显示使用过的 context pack。

Project Edit / Candidates：

- 加 Context Pack 下拉。
- 加 Suggest Context。

### 10.5 Job detail 接入

Job detail 显示：

- context pack name。
- asset refs count。
- reference refs count。
- stale 状态。

如果 job 是历史 job，没有 context pack，应显示空状态，不报错。

## 11. 导出与审计

### 11.1 Project Export

Project export 增加：

```json
"context_packs": [
  {
    "pack_id": "pack-001",
    "name": "Rainy context",
    "used_by_versions": ["v002"],
    "asset_count": 2,
    "reference_count": 1,
    "created_from": {},
    "query": {}
  }
]
```

必须脱敏：

- 不写本地路径。
- 不写原始文件名以外的路径。
- 不写 provider raw response。
- 不写 token/key。

### 11.2 Final Export

Final Export manifest 增加：

```json
"context_pack": {
  "pack_id": "pack-001",
  "name": "Rainy context",
  "asset_count": 2,
  "reference_count": 1
}
```

不要复制 Context Pack 里引用的原始 Reference 文件。

### 11.3 Events

写事件：

```text
library_index_rebuilt
library_search_requested
library_recommend_requested
context_pack_created

```

事件里不能有敏感值。

## 12. 安全边界

### 12.1 路径安全

Context Pack 删除必须限制在：

```text
.musicforge/context-packs/<pack-id>/
```

删除前：

- resolve。
- relative_to base。
- 拒绝 symlink。

### 12.2 脱敏

所有 summary / query / description / score detail 都走统一 redaction：

- `sk-*`
- GitHub token
- Bearer token
- Windows path
- UNC path
- local_path/path/source/raw_provider_response 等污染字段

### 12.3 stale

Search 可以展示 stale，但必须标记。

Recommend 默认不推荐 stale。

Apply 必须拒绝 stale。

### 12.4 hidden

Search 默认不展示 hidden。

Recommend 不推荐 hidden。

Apply 拒绝 hidden。

### 12.5 auth

新增 API 全部受现有 Bearer auth 保护。

`GET /api/info` 不增加任何本地路径泄露。

## 18. reviewer 重点检查点

开发完成后，reviewer 优先检查：

### P1：Context Pack 是否能绕过 refs 限制

复现：

1. 创建 6 个 asset refs。
2. 创建 context pack。
3. 或者 pack 5 个，payload 显式再传 1 个。

预期：

- 返回 400。
- 不创建 job。
- 不写半成品 run。

### P1：stale pack 是否还能应用

复现：

1. 创建 pack。
2. 修改 asset.json 或 reference.json sha。
3. apply。

预期：

- 返回 409。
- 不写 job。

### P1：hidden 素材是否还能被推荐/应用

复现：

1. 创建 pack。
2. hide asset/reference。
3. recommend 和 apply。

预期：

- recommend 不出现。
- apply 返回 409。

### P1：导出是否泄露敏感信息

污染字段：

```text
sk-secret
Authorization: Bearer token
D:\Music\private.wav
\\server\share\file.mid
content_base64
raw_provider_response
local_path
```

预期：

- Project Export 没有。
- Final Export manifest 没有。
- ZIP 里没有。

### P2：搜索排序是否稳定

重复跑 10 次同一 query。

预期：

- 结果顺序一致。

### P2：index rebuild 和 search 并发

复现：

1. 一边 rebuild。
2. 一边 search。

预期：

- 不读到半写 JSON。
- 不抛 Windows permission error。

### P2：Studio 是否会自动应用推荐

预期：

- 不会自动应用。
- 用户必须明确 Save / Apply。

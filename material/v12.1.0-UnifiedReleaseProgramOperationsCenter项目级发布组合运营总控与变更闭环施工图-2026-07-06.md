# v12.1.0 Unified Release Program Operations Center 项目级发布组合运营总控与变更闭环施工图

> 建议下一版：v12.1.0  
> 当前稳定基线：v12.0.0  
> 核心目标：把 v12.0 的 Unified Release Program Board 从“Program 级准出签核”升级为“Program 级运营闭环”。v12.1 不再继续做单个 Train 或单个 evidence 的小模块，而是一次性补齐 Program 签核后的变更控制、持续复核、运行手册、生命周期审计、外部验证包和 GA/Release gate，使多 Train Program 能长期可维护、可复核、可交接。

---

## 1. 背景

v12.0 已经完成了第一层 Program Board：

- 多个 signed Release Train Handoff 可以组合成一个 Unified Release Program。
- Program 有 train item、dependency graph、readiness matrix、risk register、exception register、gap plan。
- Program 可以签核，并导出固定结构 Program ZIP。
- Verifier 已经要求外部 Handoff evidence manifest、Program signoff binding、current handoff verification。
- v12 smoke 已覆盖 missing binding、declared extra、signoff full-resign、deferred-only 等关键风险。

这让系统第一次具备了 Train-of-Trains 的最终准出能力。

但 v12.0 仍然有几个真实运营缺口：

1. Program 签核后如果底层 Train Handoff、Release Train Archive、UCC Handoff 或外部证据变更，目前缺少 Program 级持续复核。
2. Program 签核后如果必须重新打开，v12.0 只能新建 Program，缺少受控 Change Request reset / successor revision。
3. Program 级 safe actions 没有 runbook；开发和 release owner 仍要手动按顺序 refresh/export/zip/verify。
4. Program 生命周期缺少独立 audit archive，难以审计“签核、重开、重签、最终交接”的完整链路。
5. GA readiness 可以要求 Unified Release Program，但没有要求 Program 持续复核清洁、Program change control 清洁、Program lifecycle audit 清洁。

因此 v12.1 建议进入：

**Unified Release Program Operations Center**

它不是替换 v12.0 Program Board，而是在其上增加运营层：

- Program Change Control
- Program Operations Runbook
- Program Continuous Review
- Program Lifecycle Audit
- Program Operations Archive / Handoff Pack
- Release / GA gate 总接入

## 2. 版本定位

### 2.1 一句话

v12.1 是 Program 级“签核后治理层”：解决 Program 签核之后如何受控复核、受控重开、受控重签、受控交接。

### 2.2 和 v12.0 的关系

v12.0：

- 证明“这个 Program 当前可以签核”。

v12.1：

- 证明“这个 Program 在签核后仍然可追踪、可复核、可安全重开、可完整交接”。

### 2.3 本版要解决的问题

1. signed Program 发生底层 evidence drift 时，系统能发现并阻断 Release / GA gate。
2. signed Program 需要修改时，只能通过 approved Program Change Request reset。
3. reset 后旧签核不能继续作为 ready evidence。
4. 每次 reset / re-signoff 都进入 history hash chain。
5. Program Operations Runbook 只自动执行 safe action，不做签核、reset、external response、manual approval。
6. Program Continuous Review 生成 drift report / incident candidates / remediation draft。
7. Program Lifecycle Audit 可以离线证明 Program 从创建到最终签核的完整历史。
8. Program Operations Archive 固定结构、不可静默重建、可离线验证。
9. Release signoff / GA readiness 可以要求 Program operations clean。
10. release-check 增加 v12.1 smoke。

### 2.4 本版不做什么

v12.1 不做以下内容，避免范围失控：

- 不自动创建新的 Train Handoff。
- 不自动批准 Program Change Request。
- 不自动把 deferred train 改成 required 或删除 train。
- 不做 provider 调用。
- 不做人工 reviewer response 采集，Program 外部委员会可留到 v12.2。
- 不做跨多个 Program 的 portfolio ranking，留到 v12.3 或 v13。
- 不引入真实公钥签名或第三方 CA。
- 不改变 v12.0 Program ZIP 的核心语义，只在 operations 层新增包和 gate。

## 5. 数据模型

### 5.1 Program Change Request

```json
{
  "schema_version": 1,
  "package_type": "musicforge_unified_release_program_change_request",
  "change_request_id": "urpcr-000001",

  "status": "draft|approved|rejected|applied|expired",
  "change_type": "reset_signoff|replace_train_handoff|update_dependency|resolve_deferred|metadata_only",
  "reason": "Train handoff was rebuilt after release owner review.",
  "requested_by": "release.manager@example",
  "approved_by": "program.owner@example",
  "created_at": "...",
  "approved_at": "...",
  "expires_at": "...",
  "target": {
    "program_signoff_hash": "...",
    "program_zip_sha256": "...",
    "program_manifest_hash": "...",
    "affected_item_ids": ["train-audio"],
    "affected_train_ids": ["rt-audio"]
  },
  "allowed_actions": [
    "reset_program_signoff",
    "refresh_program_report",
    "rebuild_program_zip"
  ],
  "source": {
    "program_source_hash": "...",
    "program_signoff_hash": "...",
    "program_history_latest_event_hash": "...",
    "external_evidence_manifest_hash": "..."
  },
  "payload_hash": "...",
  "integrity_hash": "..."

```

规则：

- `approved` 才能 reset。
- `applied` 不能再次使用。
- `expired` 不能使用。
- `target.program_signoff_hash` 必须匹配当前 active signoff。
- `allowed_actions` 只允许有限白名单。
- `reset_signoff` 不允许顺带修改 train item。
- 如果要替换 train handoff，必须先 reset，再进入未签核状态修改，再重新 signoff。

## 7. Verifier 设计

新增 CLI：

```text
python -m song_agent.cli verify-unified-release-program-operations-package <zip>
python -m song_agent.cli verify-unified-release-program-continuous-review-package <zip>
python -m song_agent.cli verify-unified-release-program-lifecycle-audit-package <zip>
```

也可以先只做一个：

```text
python -m song_agent.cli verify-unified-release-program-operations-package <zip>
```

参数：

```text
--strict
--require-current
--require-signed-program
--require-continuous-review-clear
--require-lifecycle-audit
--program-zip <path>
--program-verification-report <path>
--program-signoff-binding <path>
--external-evidence-manifest <path>
--report-out <path>
--json
```

### 7.1 必须做的检查

ZIP 层：

- ZIP exists
- duplicate entry failed
- dangerous path failed
- raw backslash entry failed
- `.musicforge` case-insensitive failed
- nested ZIP failed
- file count / size limits
- fixed allow-list
- manifest.files[] fixed allow-list
- file hash / size match

Manifest 层：

- package_type 正确
- source hash 完整
- files hash 完整
- sidecars hash 完整
- no local path
- redaction scan

外部绑定层：

- Program ZIP sha/size/manifest hash 匹配外部 Program verification report。
- Program verification report status 必须 passed。
- Program signoff binding 必须匹配 ZIP 内 signoff summary。
- External evidence manifest 必须能按 item_id + train_id + handoff_id + evidence_type 反查 Program item。
- Continuous review 必须重新从外部 Program evidence 推导，不信 ZIP 内 summary 自证。
- Lifecycle audit 必须重建 history chain。

### 7.2 不允许的自证

以下字段不能单独作为通过依据：

- `program-summary.status`
- `continuous-review-summary.status`
- `lifecycle-audit-summary.status`
- `change-control-summary.status`
- `manifest.source.*`
- `evidence-index.*`

它们只能作为展示字段。Verifier 必须用外部 Program ZIP、verification report、signoff binding、external evidence manifest 重算。

## 8. Store API

新增类：

```python
class UnifiedReleaseProgramOperationsStore:
    def create_change_request(self, program_id: str, payload: dict) -> dict: ...
    def approve_change_request(self, program_id: str, change_request_id: str, payload: dict) -> dict: ...
    def reset_program_signoff(self, program_id: str, payload: dict) -> dict: ...

    def create_runbook(self, program_id: str, payload: dict) -> dict: ...
    def run_safe(self, program_id: str, runbook_id: str, payload: dict) -> dict: ...
    def export_runbook(self, program_id: str, runbook_id: str) -> dict: ...
    def build_runbook_zip(self, program_id: str, runbook_id: str) -> dict: ...
    def verify_runbook_zip(self, program_id: str, runbook_id: str, payload: dict) -> dict: ...

    def refresh_continuous_review(self, program_id: str, payload: dict) -> dict: ...
    def export_continuous_review(self, program_id: str, review_id: str) -> dict: ...
    def build_continuous_review_zip(self, program_id: str, review_id: str) -> dict: ...
    def verify_continuous_review_zip(self, program_id: str, review_id: str, payload: dict) -> dict: ...

    def refresh_lifecycle_audit(self, program_id: str, payload: dict) -> dict: ...
    def export_lifecycle_audit(self, program_id: str) -> dict: ...
    def build_lifecycle_audit_zip(self, program_id: str) -> dict: ...
    def verify_lifecycle_audit_zip(self, program_id: str, payload: dict) -> dict: ...

    def export_operations_archive(self, program_id: str) -> dict: ...
    def build_operations_archive_zip(self, program_id: str) -> dict: ...
    def verify_operations_archive_zip(self, program_id: str, payload: dict) -> dict: ...

    def gate(self, program_id: str, payload: dict) -> dict: ...
```

### 8.1 reset_program_signoff 规则

必须满足：

- Program 当前已签核。
- payload 包含 `change_request_id`。
- Change Request 存在。
- Change Request status 是 `approved`。
- Change Request 没过期。
- Change Request target signoff hash 匹配当前 active signoff。
- Change Request allowed_actions 包含 `reset_program_signoff`。
- Change Request 未被使用。

成功后：

- `program-signoff.json` 可以标记 invalidated 或移动到 signed history，不能简单删除。
- `program-signoff-binding-summary.json` 可以保留历史副本，但 active gate 不能再用它。
- `program-history.jsonl` 追加 reset event。
- `change-control-history.jsonl` 追加 reset event。
- Change Request 标记 `applied`。
- Program status 变成 `open` 或 `reset`.
- Program ZIP / verification report 标记 stale。

### 8.2 signed guard

已签核且未 reset：

- `refresh_report()` 阻断。
- `add_train_item()` 阻断。
- `update_train_item()` 阻断。
- `remove_train_item()` 阻断。
- `export_program()` 阻断，除非 v12.0 已允许签核后一次 immutable archive build；v12.1 不能放宽。
- `build_zip()` 阻断，除非和 v12.0 签核 binding 完全一致且是首次 immutable build。

v12.1 新增 operations archive 可以在 signed 状态下生成，但它不能改写 v12.0 Program docs。

## 15. 安全边界

### 15.1 不信内部自证

Operations Archive 内部的 summary 不能自证 passed。Verifier 必须重新读取：

- external Program ZIP
- external Program verification report
- external Program signoff binding
- external evidence manifest

### 15.2 签核不可变

签核后：

- 删除 `program-signoff.json` 不能让 Program 回到 open。
- 删除 `unified-release-program.zip` 不能让 export/zip 重新静默生成。
- 篡改 history 后 verifier 必须 failed。
- reset 必须 approved CR。

### 15.3 CR 单次使用

- 一个 CR 只能 reset 一次。
- CR applied 后再次使用必须 409。
- CR target signoff hash 不匹配必须 409。

### 15.4 Safe action 不越权

Runbook 不能执行：

- signoff
- reset
- approve CR
- modify train items
- replace evidence
- import external response

### 15.5 路径与脱敏

所有 ZIP / JSON / Markdown：

- 不保留本机绝对路径。
- 不保留 token、api_key、Bearer。
- 不保留 raw provider response。
- 不允许 source_path / local_path / file_path 进入 package。

## 21. 给开发的话

这版请不要把它理解成“给 v12.0 加一个 reset 按钮”。v12.1 的目标是把 Program 签核后的运营闭环一次打通：Change Request reset、safe runbook、continuous review、lifecycle audit、operations archive、Release/GA gate 必须是一条完整链。

实现时有三个原则：

1. **所有签核后变更都必须有 approved CR。** 删除文件、重新 export、重新 zip 都不能绕过 history。
2. **所有 verifier 都不能信包内 summary 自证。** 必须用外部 Program ZIP、verification report、signoff binding、external evidence manifest 反推。
3. **runbook 只能跑 safe action。** signoff、reset、approve、replace evidence 都必须 manual_required。

只要这三条守住，v12.1 就会把 v12 从“Program 准出包”推进到“Program 级发布运营系统”。

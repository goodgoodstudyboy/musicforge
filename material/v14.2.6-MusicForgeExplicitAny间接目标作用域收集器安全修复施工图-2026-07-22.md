# v14.2.6 MusicForge Explicit Any 间接目标作用域收集器安全修复施工图

日期：2026-07-22

版本性质：v14.2.5 质量门禁 hotfix

推荐基线：v14.1.2，直到本版完成最终发布验收

## 问题

schema 8 会把 `for`、`with` 和 `match` 的间接 target 直接记为 `other`。
class body 可通过 `global Alias` 将这些 target 写回模块作用域；运行时
Alias 已成为 `typing.Any`，但后续 100 个注解仍可被 collector 计为 0。

## 实施范围

- collector 升级到 schema 9。
- 无法精确推导的间接 target 使用 `uncertain` binding，不得降级成可信
  `other`。
- `for`/`async for`、`with`/`async with`、`match` capture 使用同一规则。
- annotation 解析到 uncertain binding 时必须计数并产生 hard blocker。
- 普通非类型间接 binding 不得误报。
- 精确攻击语料进入独立
  `v1426.explicit_any_indirect_target_scope_smoke`。
- 不提高 total、layer、affected-file、per-file、复杂度或 recovery
  ceiling。

## 测试与审查

- 三种 100 annotation 攻击都验证 runtime Alias、annotation 数量、
  collector、scope blocker、total/layer/file ratchet。
- 攻击文件必须同时通过项目 Ruff 和 strict mypy，证明门禁不能依赖其他
  工具偶然拦截。
- 定向 collector、matrix、updater、文档治理测试通过。
- 全仓 Ruff、完整 active-tree mypy、全量 pytest 和 coverage 通过。
- v14/latest/security/GA/full release-check 通过。
- 实际 diff review 不得出现 suppression、生成模块、预算放宽或业务改动。

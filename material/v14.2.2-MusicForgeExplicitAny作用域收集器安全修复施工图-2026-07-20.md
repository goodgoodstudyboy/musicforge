# v14.2.2 MusicForge Explicit Any 作用域收集器安全修复施工图

日期：2026-07-20

版本性质：v14.2.1 质量门禁 hotfix

推荐基线：v14.1.2，直到本版完成最终发布验收

## 问题

schema 4 只展开 `TYPE_CHECKING` 分支中的 import。普通 `if`、
`try/except` 和函数内条件 import 可以把 `typing.Any` alias 带入注解，
但 collector 返回零。同时，未绑定到 typing 的普通同名 class 或变量
会被误判为 `typing.Any`。

## 实施范围

- collector 升级到 schema 5。
- 遍历同一 lexical scope 的 `if`、`try/except`、`with`、`for`、
  `while`、`match` 分支绑定。
- 分支冲突 fail closed；任一分支可能为 Any 时必须计数。
- 普通 class、function、parameter、assignment 和非 typing import 形成
  shadow binding，不得默认解释成 typing。
- direct、alias、module alias、nested、quoted、`TYPE_CHECKING`、
  `TypeAlias` 能力必须保留。
- schema 升级不能放宽 v14.2.1 recovery ceilings，也不能借升级重置
  total、layer、affected-file 或 per-file ratchet。

## 发布门禁

- 单测覆盖普通和函数内 `if`、`try/except`、100 个条件 alias、class
  shadow、function shadow、assignment shadow。
- 攻击语料同时进入 `v1421.stabilization_rollback_smoke`。
- 新增 `v1422.explicit_any_scope_smoke` 并进入全部 v14 发布 profile。
- Ruff、完整 active-tree mypy、pytest、v14/latest/security/GA/full 均通过。
- final SHA 必须有 Quality、Nightly LTS 和独立 reviewer package。

## 非目标

- 不修改领域业务、持久化格式或公开接口。
- 不重新尝试 v14.2.0 的机械模块拆分。
- 不宣称 ARCH-014 或 TYPE-003 已关闭。
- 不移动或删除任何既有公开 tag。

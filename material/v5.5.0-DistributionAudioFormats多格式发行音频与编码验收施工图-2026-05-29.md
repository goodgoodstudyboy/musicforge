# v5.5.0 Distribution Audio Formats 多格式发行音频与编码验收施工图

日期：2026-05-29

角色定位：reviewer / planner

当前稳定基线：v5.4.1

目标版本：v5.5.0

---

## 1. 背景

v5.0 到 v5.4.1 已经把“真实音频是否可信”推进到了发行前的核心位置：

- v5.0.0：真实 WAV 基线、Audio Artifact、Release Audio QA。
- v5.1.0：逐曲人工 WAV 听审证据。
- v5.2.0 / v5.2.1：Mix State、Stem Health、当前 mix evidence。
- v5.3.0 / v5.3.1：Audio Revision Workbench，marker -> issue -> candidate -> A/B review -> apply -> recheck -> closeout。
- v5.4.0 / v5.4.1：Mastering QA，selected mastered WAV、人工 A/B review、Release Signoff gate、`verify-release --require-mastering`。

现在系统能回答：

> 当前 Release 的每首歌是否有真实 WAV？是否有人听过？是否经过音频修复？是否经过母带 QA？发行包里的 `song.wav` 是否来自 selected mastered candidate？

但真实交付时，平台和客户通常不会只要一个 WAV：

- 有的平台要 WAV master。
- 有的平台要 FLAC。
- 有的试听包要 MP3 320k。
- 有的短视频或播客链路可能要 AAC / M4A。
- 同一个 Release 可能需要同时交付“平台包”和“客户试听包”。
- 这些派生格式必须能证明来自当前 selected mastered WAV，而不是旧 WAV、假 MP3、手工替换文件或未审计编码产物。

v5.4 的施工图已经明确把 MP3 / AAC / FLAC 多格式编码放到 v5.5。现在正好接上。

---

## 2. 版本定位

v5.5.0 要做的是：

> 基于 v5.4.1 可信 selected mastered WAV，生成可审计、可复验、可分发的多格式音频派生包。

它不是一个完整媒体工厂，也不是云转码平台。它仍然是本地优先、可重复、可审计的工程能力。

核心目标：

1. 定义本地编码器配置和编码 profile。
2. 支持从 Release Export 中的 selected mastered WAV 生成派生格式。
3. 支持 MP3 / FLAC / AAC 的本地编码入口。
4. 每个派生音频都写 manifest，绑定源 WAV、Mastering QA、Release Export、encoder profile、命令摘要和输出 hash。
5. Distribution Target 可以声明需要哪些音频格式。
6. Distribution Export 可以按 target/template 选择对应格式，而不是永远复制 WAV。
7. `verify-release` 和 `verify-distribution-package` 能离线验证派生音频证据。
8. Release Signoff / Distribution Signoff 可以要求多格式音频 evidence。

一句话：

> v5.4 解决“母带 WAV 是否可信”，v5.5 解决“交付出去的 MP3/AAC/FLAC 是否可信”。

---

## 3. 明确不做

v5.5.0 不做以下内容：

- 不做云转码。
- 不调用外部音乐生成 API。
- 不上传平台。
- 不做 DRM、水印、ISRC 注册、UPC 申请。
- 不做 Apple Digital Masters / Spotify / YouTube Music 的官方认证流程。
- 不做响度重新母带；编码前必须使用 v5.4 selected mastered WAV。
- 不做自动替代人工听审。编码后可以做 header/size/hash/简单音频健康检查，但“听起来是否正常”仍应由人工抽检。
- 不强制用户本机必须安装 FFmpeg。没有 FFmpeg 时应能保存配置、跑失败报告、跑 fake runner 测试，但不能伪造真实编码成功。

注意：MP3/AAC/FLAC 的编码能力建议通过本机 FFmpeg 实现。所有命令必须使用 list argv + `shell=False`，禁止 shell 拼接。

---

## 4. 为什么现在做

v5.4.1 之前做多格式编码会很危险，因为源音频本身还没有最终可信边界。现在不同：

- Release Export 已经能把 selected mastered WAV 写进 `tracks/<track>/song.wav`。
- Mastering evidence 已经能离线验证。
- Release Signoff 已经能阻止 analysis-only 或 stale export。
- Distribution Layout 已经能按模板命名音频文件。

所以 v5.5 的重点不是“新增一个转 mp3 的按钮”，而是建立一条证据链：

```text
selected mastered WAV
  -> encoded derivative
  -> derivative manifest
  -> Release Export summary
  -> Distribution Layout source
  -> Distribution Package ZIP
  -> offline verifier
```

只要中间任何环节被篡改、过期、路径污染、格式伪装，都应该被发现。

## 6. 核心概念

### 6.1 Encoder Profile

Encoder Profile 表示“如何编码”。

建议内置 profile：

- `mp3_320`
- `mp3_v0`
- `flac_lossless`
- `aac_256`
- `wav_master`

其中 `wav_master` 是 passthrough，不重新编码，只复制 selected mastered WAV 并写 manifest。

建议字段：

```json
{
  "schema_version": 1,
  "profile_id": "mp3_320",
  "name": "MP3 320 kbps",
  "engine": "ffmpeg",
  "format": "mp3",
  "extension": "mp3",
  "codec": "libmp3lame",
  "bitrate_kbps": 320,
  "quality": null,
  "sample_rate": 44100,
  "channels": 2,
  "container": "mp3",
  "allow_distribution": true,
  "built_in": true,
  "notes": "",
  "created_at": "...",
  "updated_at": "...",
  "integrity_hash": "..."
}
```

AAC 建议：

```json
{
  "profile_id": "aac_256",
  "format": "aac",
  "extension": "m4a",
  "codec": "aac",
  "bitrate_kbps": 256,
  "container": "ipod"
}
```

FLAC 建议：

```json
{
  "profile_id": "flac_lossless",
  "format": "flac",
  "extension": "flac",
  "codec": "flac",
  "compression_level": 8,
  "container": "flac"
}
```

### 6.2 Encoder Config

Encoder Config 表示本机工具路径。

建议：

```text
.musicforge/audio-encoder.json
```

字段：

```json
{
  "engine": "ffmpeg",
  "ffmpeg_path": "ffmpeg",
  "ffprobe_path": "ffprobe",
  "timeout_seconds": 300,
  "max_parallel": 2
}
```

环境变量覆盖：

- `MUSICFORGE_FFMPEG_PATH`
- `MUSICFORGE_FFPROBE_PATH`
- `MUSICFORGE_AUDIO_ENCODER_TIMEOUT`

安全要求：

- 不把本机绝对路径写入 export/ZIP。
- API 返回 config 时路径要脱敏或只返回 basename / exists。
- 命令执行使用 list argv。
- `shell=False`。
- 超时必须终止。
- stderr/stdout 只保留短摘要，必须走 `sanitize_sensitive_text()`。

### 6.3 Format Set

Format Set 表示“一个 Release 或 Distribution Target 需要哪些格式”。

建议先不做复杂全局库，可以在 target options 里支持：

```json
{
  "audio_format_profiles": ["wav_master", "mp3_320", "flac_lossless"],
  "primary_audio_format": "flac_lossless"
}
```

后续如果用户需要，可以升级为：

```text
.musicforge/audio-format-sets/<format-set-id>/format-set.json
```

v5.5.0 可以先预留 summary 字段，不强制做完整 FormatSetStore。

每个格式一个 manifest：


## 7. 编码引擎设计

### 7.1 支持模式

建议支持两种引擎：

1. `passthrough`
   - 用于 `wav_master`
   - 从 Release Export `tracks/.../song.wav` 复制
   - 仍写 manifest

2. `ffmpeg`
   - 用于 mp3/aac/flac
   - 通过本机 FFmpeg 编码
   - 没配置或执行失败时返回 failed report

### 7.2 命令生成

示例：

MP3 320：

```python
[
  ffmpeg_path,
  "-y",
  "-hide_banner",
  "-nostdin",
  "-i", source_wav,
  "-vn",
  "-ar", "44100",
  "-ac", "2",
  "-codec:a", "libmp3lame",
  "-b:a", "320k",
  output_mp3,
]
```

FLAC：

```python
[
  ffmpeg_path,
  "-y",
  "-hide_banner",
  "-nostdin",
  "-i", source_wav,
  "-vn",
  "-codec:a", "flac",
  "-compression_level", "8",
  output_flac,
]
```

AAC / M4A：

```python
[
  ffmpeg_path,
  "-y",
  "-hide_banner",
  "-nostdin",
  "-i", source_wav,
  "-vn",
  "-ar", "44100",
  "-ac", "2",
  "-codec:a", "aac",
  "-b:a", "256k",
  "-f", "ipod",
  output_m4a,
]
```

规则：

- 输出路径必须在 `.musicforge/releases/<release-id>/encoded-audio/` 内。
- `profile.extension` 必须匹配输出文件后缀。
- 如果 profile format 是 mp3，输出不能是 `.wav`。
- 如果 FFmpeg 返回 0 但输出文件不存在或 header 不符，仍是 failed。

### 7.3 Header / Format 检查

不要只看扩展名。

建议最小 header 检查：

- WAV：`RIFF....WAVE`
- FLAC：`fLaC`
- MP3：`ID3` 或 MPEG frame sync `0xFFEx`
- M4A/AAC：ISO BMFF `ftyp` box，major brand 包含 `M4A` / `isom` / `mp42` 等允许值

如果 ffprobe 可用，可以补充：

- duration
- codec_name
- sample_rate
- channels
- bit_rate

但 v5.5 不应该强依赖 ffprobe。没有 ffprobe 时至少 header + size + sha256。

## 8. Source Hash 设计

派生音频 source 必须绑定当前发行音频证据。

建议 source payload：

```json
{
  "release_id": "...",
  "release_export_manifest_hash": "stable_hash(manifest without zip)",
  "release_export_zip_sha256": "...",
  "mastering": {
    "summary_hash": "...",
    "selected_candidate_id": "...",
    "selected_candidate_hash": "..."
  },
  "tracks": [
    {
      "track_id": "...",
      "directory": "tracks/01-title",
      "source_wav_sha256": "...",
      "source_wav_size_bytes": 12345
    }
  ],
  "profile": {
    "profile_id": "mp3_320",
    "profile_hash": "..."
  }
}
```

如果以下任一项变化，旧 encoded audio 必须 stale：

- Release Track 增删或排序变化。
- Release Export 重建且 manifest hash 变化。
- selected mastering candidate 变化。
- `tracks/.../song.wav` hash 变化。
- encoding profile 变化。
- encoder command policy 变化。

## 9. API 设计

### 9.1 Encoder Config / Profiles

```text
GET  /api/audio-encoding/config
POST /api/audio-encoding/config
POST /api/audio-encoding/config/test
POST /api/audio-encoding/config/reset

GET  /api/audio-encoding/profiles
POST /api/audio-encoding/profiles

POST /api/audio-encoding/profiles/<profile-id>
POST /api/audio-encoding/profiles/<profile-id>/clone
POST /api/audio-encoding/profiles/<profile-id>/delete
```

Profile 规则：

- built-in 只读。
- clone 后可改。
- delete 前如果有 signed distribution target 依赖，应拒绝。
- update 后相关 encoded summaries 应 stale。

### 9.2 Release Encoding

```text
GET  /api/releases/<release-id>/encoded-audio
POST /api/releases/<release-id>/encoded-audio/render
POST /api/releases/<release-id>/encoded-audio/render-format
GET  /api/releases/<release-id>/encoded-audio/formats/<profile-id>
GET  /api/releases/<release-id>/encoded-audio/formats/<profile-id>/tracks/<track-id>/audio
POST /api/releases/<release-id>/encoded-audio/verify
POST /api/releases/<release-id>/encoded-audio/reset
```

`render` payload：

```json
{
  "profile_ids": ["mp3_320", "flac_lossless"],
  "force": false
}
```

返回：

```json
{
  "ok": true,
  "release_id": "...",
  "summary": {
    "status": "completed",
    "profiles": [...]
  },
  "formats": [...]
}
```

失败不应抛 traceback：

- FFmpeg missing -> `400 Encoder executable was not found.`
- source export stale -> `409 Release Export is stale. Rebuild export before encoding.`
- mastering missing when required -> `409 Mastering QA evidence is missing.`
- signed release mutation -> `409 Signed releases cannot mutate encoded audio. Reset signoff first.`

### 9.3 Distribution Target 格式选择

Distribution Target options 增加：

```json
{
  "audio_format_profiles": ["mp3_320"],
  "primary_audio_format": "mp3_320",
  "require_encoded_audio": true
}
```

模板 rules 可增加：

```json
{
  "required_audio_formats": ["mp3_320", "flac_lossless"],
  "primary_audio_format": "flac_lossless"
}
```

合并优先级：

```text
target.options > template.rules > distribution profile default > wav_master
```

## 10. Distribution Layout 改造

当前 `distribution_layout.py` 的 `_audio_source_rel()` 只在 Release Export 里找：

- `tracks/<dir>/song.wav`
- `tracks/<dir>/song.mid`

v5.5 要扩展为：

1. 根据 target/template 选定 audio format。
2. 如果目标格式是 `wav_master`，继续使用 Release Export `tracks/.../song.wav`。
3. 如果目标格式是 `mp3_320`，使用 encoded audio source：

```text
encoded-audio/formats/mp3_320/tracks/<track-id>/song.mp3
```

但有两种实现方式：

### 10.1 推荐实现：Distribution Export 读取 encoded store

不要把 encoded audio 先塞进 Release Export 的 `tracks/` 目录。

Distribution Export 构建 layout 时传入 `encoded_audio_summary` 和 `encoded_audio_root`，让 layout entries 能表达：

```json
{
  "kind": "audio",
  "track_id": "track-000001",
  "source_kind": "encoded_audio",
  "source_profile_id": "mp3_320",
  "source_rel": "formats/mp3_320/tracks/track-000001/song.mp3",
  "path": "audio/01-title.mp3",
  "ext": "mp3"
}
```

然后 `_copy_layout_entries()` 按 `source_kind` 决定从哪里复制：

- `release_export` -> `release_export_dir`
- `encoded_audio` -> `.musicforge/releases/<release-id>/encoded-audio`
- `artwork` -> artwork store

### 10.2 不推荐实现

不要为了偷懒把 MP3/FLAC 复制到 Release Export `tracks/<track>/` 下。这会污染 Release Export 的职责：Release Export 是 mastered WAV 证据包，不应成为多格式派生产物仓库。

## 11. Release Export / ZIP 接入

Release Export 可以写入 compact summary，但不复制所有派生音频，避免 Release ZIP 膨胀。

建议新增：

```text
encoded-audio-summary.json
```

Release manifest 增加：

```json
{
  "encoded_audio": {
    "status": "completed",
    "profile_count": 3,
    "profiles": [
      {
        "profile_id": "mp3_320",
        "status": "completed",
        "track_count": 10,
        "source_hash": "...",
        "manifest_hash": "..."
      }
    ],
    "summary_path": "encoded-audio-summary.json",
    "summary_hash": "..."
  }
}
```

Release ZIP verifier 不要求 Release ZIP 包含派生音频本体，除非用户传：

```text
verify-release --require-encoded-audio mp3_320 flac_lossless
```

如果 v5.5 暂时不想改 verify-release 参数为多值，可以先做：

```text
verify-release --require-encoded-audio
```

并根据 signoff gate 中的 `required_audio_format_profiles` 验证 summary。

## 12. Distribution Export / ZIP 接入

Distribution Package 是派生音频真正进入交付包的地方。

目标：

- Target 需要 MP3，则 package 内 `audio/*.mp3` 来自 encoded manifest。
- Target 需要 FLAC，则 package 内 `audio/*.flac` 来自 encoded manifest。
- Target 需要 WAV，则沿用 mastered WAV。
- 多格式 target 可以生成多个目录：

```text
audio/mp3/01-title.mp3
audio/flac/01-title.flac
audio/wav/01-title.wav
```

建议布局规则：

单格式默认：

```text
audio/{track_number:02d}-{slug_title}.{ext}
```

多格式默认：

```text
audio/{format}/{track_number:02d}-{slug_title}.{ext}
```

模板可覆盖：

```json
{
  "file_naming": {
    "audio": "audio/{format}/{track_number:02d}-{slug_title}.{ext}"
  }
}
```

新增 layout 变量：

- `format`
- `profile_id`
- `codec`
- `bitrate_kbps`

需要扩展 `AUDIO_VARIABLES`。

## 13. QA / Gate 设计

### 13.1 Release Encoded Audio QA

新增 summary：

```json
{
  "status": "completed",
  "release_id": "...",
  "required_profiles": ["mp3_320", "flac_lossless"],
  "completed_profiles": ["mp3_320", "flac_lossless"],
  "missing_profiles": [],
  "stale_profiles": [],
  "failed_profiles": [],
  "source_hash": "...",
  "integrity_hash": "..."
}
```

检查项：

- source current
- profile integrity ok
- all release tracks covered
- output exists
- output path safe
- output hash matches manifest
- output extension matches profile
- output header matches profile
- file size > minimum
- no local path / secret in manifest

### 13.2 Release Signoff Gate

Release Signoff payload 增加：

```json
{
  "require_encoded_audio": true,
  "required_audio_format_profiles": ["mp3_320", "flac_lossless"]
}
```

Gate 规则：

- missing profile -> 409
- stale encoded manifest -> 409
- failed output -> 409
- tampered manifest -> 409
- force 不能绕过 stale/tamper/path unsafe
- warning 可按 profile policy 或 force+override reason 处理

### 13.3 Distribution QA

Distribution QA 应检查 target 要求的格式：

- 如果 `require_encoded_audio=true`，目标格式不是 `wav_master`，则对应 encoded manifest 必须 current。
- package layout source 必须来自 encoded store。
- package 中实际文件 hash 必须等于 encoded manifest output hash。
- package 文件后缀必须匹配 target format。

## 14. Offline Verifier

### 14.1 verify-release

扩展：

```powershell
python -m song_agent.cli verify-release release-export.zip --require-encoded-audio
python -m song_agent.cli verify-release release-export.zip --require-encoded-audio --require-audio-formats mp3_320,flac_lossless
```

Release ZIP 只验证 summary 和 manifest evidence，不一定验证派生文件本体。

### 14.2 verify-distribution-package

扩展：

```powershell
python -m song_agent.cli verify-distribution-package distribution-package.zip --require-encoded-audio
```

必须验证：

- distribution manifest audio entries 指向 encoded profile。
- encoded evidence sidecar 存在。
- package audio file hash 匹配 encoded manifest。
- header 与扩展名匹配。
- MP3 不可用 WAV header 冒充。
- FLAC 必须 `fLaC`。
- M4A 必须 ISO BMFF。
- duplicate entry / backslash entry / zip bomb 继续沿用 v3.8+ 规则。

Distribution Package 建议加入：

```text
encoded-audio/
  summary.json
  manifests/
    mp3_320.json
    flac_lossless.json
```

这样离线 verifier 不依赖 `.musicforge/`。

## 15. Security / Redaction

必须继承已有安全原则：

- 不复制任意 `source_path`。
- 不信 manifest 中的路径；路径必须解析到允许根目录。
- 不把 `ffmpeg_path`、本机绝对路径、临时目录写入 ZIP。
- 不把 stderr 原文长文本写入导出包。
- 所有 JSON export 走 `sanitize_metadata()`。
- ZIP verifier 使用 raw central directory name 检查反斜杠。
- 检查 duplicate entries。
- 检查总解压大小。
- 检查 CSV formula injection 与 redaction 扫描。

新增风险：

### 风险 1：假格式

文件叫 `.mp3` 但内容是 WAV。

处理：header check + verifier check。

### 风险 2：旧编码产物

Release 重新 mastering 后，旧 MP3 仍被打包。

处理：encoded manifest source hash 绑定 selected mastering candidate hash 和 Release Export manifest hash。

### 风险 3：FFmpeg 命令泄露本机路径

处理：manifest 只记录 command template hash，不记录完整 argv。

### 风险 4：Distribution target 改格式后 package 未重建

处理：Distribution QA source hash 纳入 target audio format options 和 encoded manifest hash。

### 风险 5：签核后重新编码

处理：Release signed 后禁止 encoded audio render/reset；Distribution signed 后禁止 target 变更和 package 重建。

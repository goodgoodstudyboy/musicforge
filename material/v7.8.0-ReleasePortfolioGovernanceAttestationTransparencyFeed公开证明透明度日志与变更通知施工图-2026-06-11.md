# v7.8.0 Release Portfolio Governance Attestation Transparency Feed 公开证明透明度日志与变更通知施工图

> 本文是给开发执行的 v7.8.0 施工图。当前稳定基线是 v7.7.1。v7.7.1 已修复 Registry / Portal `--require-accepted-evidence` 只信公开摘要导致的伪造 accepted evidence 绕过问题：Registry / Portal export 已写入 `data/accepted-evidence-verification-summary.json`，离线 verifier 必须校验 summary、manifest、verification sidecar 三方一致。

v7.8.0 的目标是把 v7.2 到 v7.7 已经形成的公开证明链路，继续升级为“外部可追踪、可复验、可判断是否仍然当前”的透明度日志和变更通知层。

一句话：

> v7.8.0 要让外部方拿到一个公开证明 Portal / Registry / Accepted Evidence 后，能够通过一个独立的 Transparency Feed 判断：当前证明链路是否仍然有效、是否被撤销或替换、是否新增 accepted evidence、是否有新的 change notice，以及这些变化是否能离线验证。

---

## 1. 背景

当前 v7 链路已经有了完整的公开证明主干：

- v7.0：Final Board，组合治理最终委员会签核。
- v7.1：Evidence Vault，组合治理证据保险库和深度离线复验。
- v7.2：Public Attestation，公开证明证书包。
- v7.3：Attestation Registry，公开证明登记册，支持 publish / revoke / supersede。
- v7.4：Attestation Portal Snapshot，静态公开门户快照。
- v7.5：Release Check Verification Matrix，发布验证矩阵。
- v7.6：Portal Review Response，外部审查响应闭环。
- v7.7：Accepted Evidence，把 accepted 外部审查响应登记成公开摘要证据。
- v7.7.1：修复 Registry / Portal accepted evidence 摘要伪造绕过。

现在系统已经能证明：

```text
Evidence Vault
  -> Public Attestation
  -> Registry
  -> Portal Snapshot
  -> Review Pack
  -> Review Response
  -> Accepted Evidence
  -> Registry / Portal require accepted evidence
```

但还有一个明显缺口：

1. 外部审查方拿到一个 Portal ZIP 后，不知道后续是否发生了新版本、撤销、替换或 accepted evidence 变化。
2. Registry 里有状态，但外部方需要打开完整 Registry ZIP 才能判断，而且 Registry 主要描述“条目状态”，不是“变更通知”。
3. Portal 展示的是当前快照，不是变更历史。
4. Accepted Evidence 证明外部 accepted，但如果后续重新发布 Portal、替换 Registry current entry、撤销 entry，外部方需要一个轻量、公开、离线可验证的变更 feed。
5. 现在缺少一个专门给外部审计/合作方/业务方查看的“公开证明透明度日志”。

v7.8 要补的是：

```text
Public Attestation / Registry / Portal / Accepted Evidence
  -> Transparency Feed
  -> Change Notices
  -> Transparency ZIP
  -> Offline Verifier
```

这个层不是替代 Registry，也不是替代 Portal，而是把公开证明链路的关键状态变化整理成可携带、可离线验证、可被外部方快速理解的透明度日志。

## 2. 业务定位

### 2.1 给谁用

v7.8 的 Transparency Feed 主要面向：

- 外部 reviewer：确认自己接受过的 Portal 是否仍是当前公开证明。
- 发行/运营负责人：确认公开证明是否有撤销、替换、accepted evidence 变化。
- 法务/审计人员：查看公开证明链路的变更历史，但不接触 `.musicforge/` 内部私有证据。
- 开发/Reviewer：离线复验公开包是否被篡改，是否存在 summary 伪造。

### 2.2 解决什么问题

用一句具体流程描述：

```text
外部 reviewer 在 v7.7 接受了 Portal A。
后来内部重新生成了 Public Attestation B，Registry current entry 被 supersede。
业务方需要给外部 reviewer 一个轻量包，说明：
  - 你之前接受的 Portal A 已经不是当前版本。
  - 当前版本是 Portal B。
  - Accepted Evidence A 仍然存在，但不再代表当前版本。
  - 新版本是否已经有新的 Accepted Evidence。
  - 这些结论都能离线验证。
```

v7.8 的 Transparency Feed 就是这层。

## 3. v7.8.0 目标

新增 Release Portfolio Governance Attestation Transparency Feed。

核心能力：

1. 从当前 Public Attestation / Registry / Portal / Review Response / Accepted Evidence 派生 public-safe transparency feed。
2. 生成 deterministic event list，表达公开证明链路的关键变化。
3. 支持 change notice：
   - initial publish
   - current registry entry changed
   - registry entry revoked
   - registry entry superseded
   - portal snapshot rebuilt
   - accepted evidence added
   - accepted evidence archived
   - accepted evidence stale
   - accepted evidence verification changed
4. 支持 Transparency Export / ZIP。
5. 新增离线 verifier：`verify-release-portfolio-governance-attestation-transparency`
6. Registry / Portal / Accepted Evidence 指纹必须被 feed 绑定，不能只信公开摘要。
7. Feed 必须支持 hash chain，能发现事件重排、删除、插入、篡改。
8. Feed ZIP 不嵌套任何 Registry / Portal / Attestation / Evidence Vault / Accepted Evidence ZIP。
9. Studio 增加 Transparency 面板。
10. API / CLI 接入。
11. release-check matrix 新增 `v78.attestation_transparency_feed_smoke`。
12. README / CHANGELOG / version bump 到 `7.8.0`。

---

## 4. 非目标

v7.8 不做：

- 不做公网托管。
- 不做自动上传到 GitHub Pages / S3 / IPFS。
- 不做邮件通知。
- 不做 webhook。
- 不做在线订阅。
- 不做法律电子签章。
- 不自动 publish / revoke / supersede Registry entry。
- 不自动 archive Accepted Evidence。
- 不自动 approve / apply Change Request。
- 不自动 reset Final Board / Governance signoff。
- 不把完整内部 `.musicforge/` 证据打进透明度包。
- 不把 nested ZIP 打进透明度包。
- 不把完整 reviewer notes / response attachments 打进透明度包。
- 不把本机路径、provider key、GitHub token、renderer path、SoundFont path 等敏感信息写进包。

v7.8 只做本地生成、公开安全摘要、变更通知、离线验证。

Public State 必须通过 `stable_hash(public_state)` 得到：

```text

```

注意：

- 字段必须 public-safe。
- 不允许本机绝对路径。
- 不允许 token/key。
- 不允许完整 notes。
- 不允许附件内容。
- 不允许 nested package bytes。

### 7.2 Transparency Event

Transparency Event 是从 Public State / Registry entries / Accepted Evidence state 派生的稳定事件。

建议字段：

```json
{
  "event_id": "att-trans-event-000001",
  "event_type": "registry_current_published",
  "severity": "info",
  "portfolio_id": "pfa-000001",
  "attestation_profile": "public_summary",
  "source": {
    "public_state_hash": "...",
    "registry_current_entry_id": "attreg-entry-000003",
    "current_certificate_id": "att-cert-000003",
    "portal_manifest_hash": "...",
    "accepted_evidence_id": "apae-..."
  },
  "summary": {
    "title": "Current public attestation entry is published",
    "message": "Registry current entry attreg-entry-000003 is published and linked to certificate att-cert-000003."
  },
  "created_at": "2026-06-11T00:00:00+00:00",
  "previous_event_hash": "",
  "event_hash": "..."
}
```

`event_hash`：

```text
stable_hash(event without event_hash)
```

Hash chain：

```text
event[0].previous_event_hash = ""
event[n].previous_event_hash = event[n-1].event_hash
```

Verifier 必须能抓：

- event_hash 不匹配。
- previous_event_hash 不匹配。
- event_id 重复。
- event 顺序被调换。
- event 被删除后 chain 断裂。
- event 被插入后 chain 与 feed hash 不一致。

### 7.3 Change Notice

Change Notice 是给外部方看的“发生了什么变化”。

Notice 不一定等于 event。Event 是机器链路，Notice 是业务摘要。

建议 notice 类型：

```text
initial_publish
registry_current_changed
registry_entry_revoked
registry_entry_superseded
portal_snapshot_changed
accepted_evidence_added
accepted_evidence_archived
accepted_evidence_stale
accepted_evidence_verification_changed
public_state_refreshed
```

Notice 字段：

```json
{

  "notice_type": "accepted_evidence_added",
  "severity": "info",
  "portfolio_id": "pfa-000001",

  "from_state_hash": "...",
  "to_state_hash": "...",
  "source_event_ids": ["att-trans-event-000004"],
  "title": "Accepted external review evidence added",
  "message": "Current Portal has accepted external review evidence apae-abc123.",
  "public_references": {
    "current_entry_id": "attreg-entry-000003",
    "current_certificate_id": "att-cert-000003",
    "accepted_evidence_id": "apae-abc123",
    "accepted_evidence_manifest_hash": "..."
  },
  "created_at": "2026-06-11T00:00:00+00:00",

```


## 9. Source 构建规则

新增 Store 必须从现有 Store 读取当前公开证据：

- `ReleasePortfolioGovernanceAttestationStore`
- `ReleasePortfolioGovernanceAttestationRegistryStore`
- `ReleasePortfolioGovernanceAttestationPortalStore`
- `ReleasePortfolioGovernanceAttestationPortalReviewStore`
- `ReleasePortfolioGovernanceAttestationAcceptedEvidenceStore`

构建 source 时必须读取：

1. Registry ZIP verification report。
2. Portal ZIP verification report。
3. Public Attestation ZIP verification report。
4. Accepted Evidence verification report，如果存在。
5. Accepted Evidence public summary。
6. Registry current entry source。
7. Portal report source。
8. Evidence Vault public fingerprints。
9. Final Board signoff hash。

不能只读取 manifest 摘要字段。尤其不能重复 v7.7.0 的错误：只信 `external_review` 字符串。

建议：

```python
def build_public_state(portfolio_id: str, profile: str = "public_summary") -> dict:

def build_source(portfolio_id: str, profile: str = "public_summary") -> dict:

        "registry_zip_sha256": ...,
```

## 10. Store 设计

类名建议：

```python
class ReleasePortfolioGovernanceAttestationTransparencyStore:
    ...
```

必须提供：

```python
def refresh_feed(portfolio_id: str, payload: dict | None = None, *, now: str | None = None) -> dict: ...
def read_feed(portfolio_id: str, *, profile: str = "public_summary", default: dict | None = None) -> dict: ...
def feed_is_stale(portfolio_id: str, feed: dict | None = None, *, profile: str = "public_summary") -> bool: ...
def read_report(portfolio_id: str, *, profile: str = "public_summary", default: dict | None = None) -> dict: ...
def export_transparency(portfolio_id: str, payload: dict | None = None, *, now: str | None = None) -> dict: ...
def build_zip(portfolio_id: str, payload: dict | None = None, *, now: str | None = None) -> dict: ...
def verify_transparency(portfolio_id: str, payload: dict | None = None, *, now: str | None = None) -> dict: ...
def list_notices(portfolio_id: str, *, profile: str = "public_summary") -> list[dict]: ...
def get_notice(portfolio_id: str, notice_id: str, *, profile: str = "public_summary") -> dict: ...
def summary(portfolio_id: str, *, profile: str = "public_summary") -> dict: ...
```

### 10.1 Refresh 行为

`refresh_feed()`：

1. 重建 Public State。
2. 重建 Source。
3. 生成 deterministic events。
4. 生成 deterministic notices。
5. 计算 checks/blockers/warnings。
6. 写 `transparency-feed.json`。
7. 写 `transparency-report.json`。
8. 追加 `transparency-history.jsonl`。

如果上游证据缺失：

- Registry verification missing：feed status failed。
- Portal verification missing：feed status failed。
- Attestation verification missing：feed status failed。
- Accepted Evidence missing：不一定 failed，除非 payload 指定 `require_accepted_evidence=true`。

### 10.2 Export 行为

`export_transparency()`：

1. 如果 feed 不存在，自动 refresh。
2. 如果 feed integrity failed，409。
3. 如果 feed stale，409。
4. 如果 report failed，409。
5. 生成 export 目录。
6. 不写 nested ZIP。
7. 写 public-safe JSON 和 README。
8. 生成 manifest。

### 10.3 ZIP 行为

`build_zip()`：

1. 读取 export manifest。
2. 校验 export manifest source 与当前 feed source 一致。
3. 校验 accepted evidence / registry / portal verification summary 没有 stale。
4. 写 ZIP。
5. 更新 manifest.zip。

### 10.4 重复构建策略

沿用项目现有风格：

- 同一个 source state 已 export，再次 export 返回 409。
- 同一个 source state 已 build ZIP，再次 build ZIP 返回 409。
- 上游 source 变化后，必须 refresh feed，再 export / zip。

不要静默覆盖历史 export。

## 12. Notice 生成规则

初版可以由当前 feed 派生，不需要复杂 diff。

建议最少生成：

1. `initial_publish`
   - current entry present and published。
2. `accepted_evidence_added`
   - accepted evidence current and verification passed。
3. `accepted_evidence_missing`
   - no accepted evidence。
4. `registry_current_revoked`
   - current entry revoked。
5. `portal_snapshot_changed`
   - portal source hash 与上次 feed 不同。
6. `public_state_refreshed`
   - 每次 refresh 都有一个状态摘要 notice。

如果能读取上一次 feed，则生成 from/to diff：

```python
previous = read_feed(...)
current = new_feed
if previous.source_hash != current.source_hash:
    compare previous.current_public_state and current.current_public_state
```

必须注意：

- 不要把上次 feed 当成真相，只能用于 diff 展示。
- 当前 verifier 仍以当前 feed / manifest / sidecar 为准。

- report integrity hash 正确。
- report source_hash 正确。

- report.source.public_state_hash == feed.source.public_state_hash。

Sidecar 级：

- 所有 data/*.json source_hash 必须等于 feed.source_hash 或 report.source_hash，按设计统一。

  - portal verification passed。

- `--require-contiguous-chain`：
  - event chain must be continuous with no duplicate ids and no broken previous hash。

Redaction：

- scan json/txt/md/html。
- local path failed。
- token/key failed。
- blocked key failed。
- provider snapshot / renderer path failed。

## 20. 安全边界

### 20.1 不信任摘要

这是 v7.8 的第一原则。

不允许：

```text
manifest.external_review.external_review_status == accepted
```

就判断 accepted evidence 成立。

必须反查：

- accepted evidence verification summary。
- accepted evidence ZIP sha。
- accepted evidence manifest hash。
- accepted evidence verification report hash。
- accepted evidence source hash。

### 20.2 不嵌套 ZIP

Transparency ZIP 只放摘要和 JSON，不放：

- Registry ZIP。
- Portal ZIP。
- Public Attestation ZIP。
- Evidence Vault ZIP。
- Accepted Evidence ZIP。
- Review Pack ZIP。
- Review Response ZIP。

### 20.3 不泄漏本机信息

必须统一使用 `sanitize_metadata` 和 redaction scanner。

重点防：

- `C:\Users\...`
- `D:\...`
- `\\server\share\...`
- `//server/share/...`
- `githubkey.txt`
- `sk-...`
- `ghp_...`
- `Bearer ...`
- `provider-snapshot.json`
- `renderer.json`
- `soundfont`

### 20.4 不自动变更治理状态

Transparency 是观察层，不是执行层。

不允许：

- refresh feed 自动 publish registry。
- refresh feed 自动 archive accepted evidence。
- notice 自动 create Change Request。
- verify failed 自动 reset signoff。

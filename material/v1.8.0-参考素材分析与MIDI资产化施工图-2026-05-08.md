# MusicForge v1.8.0 施工图：参考素材分析与 MIDI 资产化

> 基线版本：v1.7.2  
> 当前目标：在已经安全导入 Reference 的基础上，增加本地可验证的分析、预览、MIDI 切片和资产化能力。  
> 执行原则：全部先本地化验证；每完成一个边界清晰的功能包，测试通过后提交并推送 GitHub；最终再 tag / Release。  
> 范围判断：v1.8.0 不继续扩大上传格式，先把 WAV / MIDI / text reference 的本地分析链路做扎实。

---

## 1. 背景

v1.7.2 之后，MusicForge 已经具备安全的 Reference Library：

- `.musicforge/references/` 本地参考库。
- WAV / MIDI / lyrics text / style note 安全导入。
- 文件类型、文件头、UTF-8、文件名、大小、SHA-256 去重校验。
- Reference API、Project link/unlink、download、hide/favorite/delete。
- `reference_refs` 接入 job、Project version、variation、edit、provider preview、candidate、Prompt A/B。
- Reference -> Asset 转换。
- Project Export / Final Export 写脱敏 reference summary，不复制原始素材文件。
- 自由文本值级脱敏已经覆盖 API key、GitHub token、Bearer token、本机路径、Windows 任意盘符路径、UNC 网络共享路径。

v1.7.x 已经解决“安全把外部素材带进系统”的问题。

但当前还有一个业务短板：

> Reference 只是被安全存起来了，系统还不理解它。  
> WAV 只有播放器，MIDI 只做轻量 seed，text 只有 excerpt。  
> 用户很难判断某个 Reference 能不能变成好用的素材，也很难从 MIDI 里抽出具体片段。

所以 v1.8.0 应该做“参考素材分析与 MIDI 资产化”。

这版不追求 AI 音频识别，不做 audio-to-MIDI，也不做 MP3。它应该做的是：用标准库能稳定实现的方式，把已经导入的素材变得更可见、更可检索、更可复用。

---

## 2. 一句话目标

v1.8.0 的一句话目标：

> 对已导入 Reference 做本地安全分析，生成可审计的 analysis report，并支持从 MIDI reference 中抽取可试听、可保存、可复用的 Creative Asset。

落地后，用户应能做到：

1. 对 WAV reference 生成时长、采样率、声道、位深、峰值、RMS、简单波形 envelope。
2. 在 Studio Reference detail 中看到 WAV 波形概览和基础音频信息。
3. 对 MIDI reference 解析 header、PPQ、track 数、tempo、program、channel、note 分布、音域、时长。
4. 从 MIDI reference 中看到可抽取片段建议，例如 melody motif、bass pattern、drum pattern、chord-like note blocks。
5. 预览 MIDI reference 的整段或切片。
6. 从 MIDI 切片创建真实 note-based Creative Asset，而不是 v1.7 的固定 seed。
7. 对 text reference 生成安全摘要、关键词、行数、字符数、语言粗识别。
8. Reference summary / provider prompt summary 可以使用分析结果，但仍不泄露本地路径或原始二进制。
9. Project export / Final Export 可以包含脱敏 analysis summary。
10. release-check 覆盖 Reference analysis 主链路。

---

## 3. 非目标

v1.8.0 不做以下事情：

- 不做 MP3 导入。
- 不做 audio-to-MIDI。
- 不做人声识别。
- 不做音频扒旋律。
- 不做音频扒和弦。
- 不做音频鼓点识别。
- 不做高准确率 BPM/key 自动检测。
- 不引入 numpy、librosa、essentia、ffmpeg 等重依赖。
- 不做云端音频分析。
- 不把原始 reference 文件默认复制进 Final Export ZIP。
- 不做完整 DAW piano-roll 编辑器。
- 不做向量数据库。

原因：

- v1.8.0 仍然应该保持“本地、可测试、低依赖、可审计”。
- 高级音频识别需要外部依赖或模型，不适合和 Reference 基础分析混在一个版本里。
- 现在最需要的是把 MIDI 资产化做实，把 WAV 可视化和 metadata 做实。

## 4. 核心设计

新增一个分析层：

```text
song_agent/
  reference_analysis.py
```

分析结果写入 Reference 目录：

```text
.musicforge/
  references/
    ref-001/
      reference.json
      original/
        reference.wav
      analysis.json
      slices.json
      preview/
        full.mid
        slice-001.mid
        slice-001.wav
      events.jsonl
```

### 4.1 Analysis Report

统一 schema：

```json
{
  "schema_version": 1,
  "reference_id": "ref-001",
  "reference_type": "midi",
  "source_sha256": "...",
  "status": "completed",
  "analyzed_at": "2026-05-08T00:00:00Z",
  "summary": {},
  "warnings": [],
  "errors": []
}
```

`source_sha256` 必须绑定当前 `reference.json.sha256`。

如果 Reference 文件被污染或替换，旧 `analysis.json` 必须判定 stale。

### 4.2 Slice Manifest

MIDI reference 可生成切片建议：

```json
{
  "schema_version": 1,
  "reference_id": "ref-002",
  "source_sha256": "...",
  "slices": [
    {
      "slice_id": "slice-001",
      "slice_type": "motif",
      "name": "Track 1 bars 1-2 motif",
      "track_index": 1,
      "channel": 0,
      "start_beat": 0.0,
      "duration_beats": 8.0,
      "note_count": 12,
      "pitch_min": 60,
      "pitch_max": 72,
      "quality_hint": 82,
      "midi_status": "not_started",
      "audio_status": "not_started"
    }
  ]
}
```

切片不是最终编辑；它是“可保存为 Asset 的候选片段”。

## 5. WAV 分析

### 5.1 只支持 PCM WAV

v1.8.0 只分析标准库 `wave` 能读取的 WAV。

允许：

- PCM WAV。
- mono / stereo。
- 8 / 16 / 24 / 32 bit 按能安全处理的范围读取。

不支持：

- compressed WAV。
- float WAV。
- 非标准 chunk。

不支持时，analysis 返回：

```json
{
  "status": "failed",
  "errors": ["Unsupported WAV encoding."]
}
```

不要影响 Reference 原文件下载和基础信息展示。

### 5.2 WAV summary

建议字段：

```json
{
  "duration_seconds": 12.34,
  "sample_rate": 44100,
  "channels": 2,
  "sample_width_bytes": 2,
  "frame_count": 544194,
  "peak": 0.82,
  "rms": 0.18,
  "loudness_hint": "medium",
  "silence_ratio": 0.08,
  "envelope": [
    {"time": 0.0, "peak": 0.12, "rms": 0.04},
    {"time": 0.1, "peak": 0.18, "rms": 0.06}
  ]
}
```

Envelope 限制最多 256 个点，避免 JSON 过大。

### 5.3 不做 BPM/key

v1.8.0 不从 WAV 推断 BPM/key。

如果用户已经手动填了 tempo/key，可以在 summary 中显示：

```json
{
  "manual_tempo_bpm": 118,
  "manual_key": "C"
}
```

但不要伪装成自动检测。

## 6. MIDI 分析

### 6.1 新增轻量 MIDI parser

新增：

```text
song_agent/midi_analysis.py
```

或放进 `reference_analysis.py` 的内部模块也可以，但建议独立，后面会复用。

需要支持：

- Standard MIDI header `MThd`。
- format 0 / 1。
- track count。
- division / PPQ。
- track chunks `MTrk`。
- delta time variable length quantity。
- running status。
- note_on / note_off。
- tempo meta event。
- time signature meta event。
- program change。
- channel。
- end of track。

不需要支持：

- sysex 语义解析。
- lyric meta 深度解析。
- controller 语义。
- pitch bend 语义。
- SMPTE division。

遇到无法解析的事件，要能跳过或记录 warning，不要直接崩掉整个 server。

### 6.2 MIDI summary

建议字段：

```json
{
  "format": 1,
  "track_count": 4,
  "ppq": 480,
  "duration_beats": 64.0,
  "duration_seconds": 128.0,
  "tempo_bpm": 120,
  "time_signature": "4/4",
  "channels": [0, 1, 9],
  "programs": [
    {"channel": 0, "program": 0},
    {"channel": 1, "program": 33}
  ],
  "note_count": 320,
  "pitch_min": 36,
  "pitch_max": 84,
  "drum_note_count": 96,
  "track_summaries": [
    {
      "track_index": 1,
      "name": "Track 1",
      "channel": 0,
      "note_count": 84,
      "pitch_min": 60,
      "pitch_max": 76,
      "duration_beats": 64.0,
      "likely_role": "melody"
    }
  ]
}
```

### 6.3 Role inference

轻量 heuristics：

| Role | 判断 |
| --- | --- |
| `drums` | channel 9 或大量 GM drum pitch |
| `bass` | pitch median < 52，单音为主 |
| `melody` | pitch median >= 56，单音为主，note_count 适中 |
| `chords` | 同时发声较多，polyphony 高 |
| `unknown` | 其他 |

这只是 hint，不是强判定。

### 6.4 切片建议

MIDI analysis 生成最多 24 个 slice。

规则：

- 按 4 或 8 bars 切。
- 忽略空片段。
- note_count 太少不建议。
- 超长片段截断。
- 每个 likely_role 至少保留前几个高质量片段。

Slice type 映射：

- `melody` -> `motif`
- `bass` -> `bass_pattern`
- `drums` -> `drum_pattern`
- `chords` -> `chord_progression`

## 7. Text 分析

Text reference 分析不做大模型。

建议 summary：

```json
{
  "character_count": 480,
  "line_count": 24,
  "word_count": 90,
  "language_hint": "zh",
  "keywords": ["雨夜", "城市", "朋友"],
  "safe_excerpt": "...",
  "contains_chord_like_tokens": false,
  "contains_lyrics_like_lines": true
}
```

### 7.1 关键词

用简单规则：

- 英文：按空格分词，去掉短词和停用词。
- 中文：不做复杂分词，只抽连续汉字短片段和高频字符组合。
- 限制最多 20 个 keywords。

### 7.2 安全

Text analysis 必须走 `sanitize_sensitive_text()` 和 `sanitize_metadata()`。

如果 text 原文里有 token/path，analysis summary 不能带出。

## 8. API 设计

新增 API：

```text
GET  /api/references/<reference-id>/analysis
POST /api/references/<reference-id>/analyze
GET  /api/references/<reference-id>/slices
POST /api/references/<reference-id>/slices
POST /api/references/<reference-id>/slices/<slice-id>/render-midi
POST /api/references/<reference-id>/slices/<slice-id>/render-audio
GET  /api/references/<reference-id>/slices/<slice-id>/midi
GET  /api/references/<reference-id>/slices/<slice-id>/audio
POST /api/references/<reference-id>/slices/<slice-id>/create-asset
```

### 8.1 Analyze

`POST /api/references/<id>/analyze`

Payload：

```json
{
  "force": false
}
```

行为：

- 如果 `analysis.json` 存在且 `source_sha256` 匹配，返回 existing。
- 如果 `force=true`，重跑分析。
- 如果 reference hidden，仍允许分析，但不能用于 generation。
- 如果文件缺失，返回 409。
- 如果 analysis stale，返回 stale 状态或重跑，按 payload 决定。

### 8.2 Slices

`GET /api/references/<id>/slices`

- 如果没有分析或不是 MIDI，返回 409 或空列表。
- 如果 `slices.json` stale，返回 409 stale。

`POST /api/references/<id>/slices`

- 对 MIDI reference 生成或刷新切片建议。
- 支持 `force`。

### 8.3 Slice preview

渲染逻辑：

- 从 MIDI analysis events 生成一个 minimal `SongPlan` 或直接写 MIDI slice。
- 优先复用现有 MIDI renderer。
- `slice-xxx.mid` 必须绑定当前 `source_sha256`。
- 如果 stale，下载返回 409。

### 8.4 Slice create asset

`POST /api/references/<id>/slices/<slice-id>/create-asset`

Payload：

```json
{
  "name": "Verse motif",
  "tags": ["verse", "motif"],
  "favorite": true
}
```

Asset content 必须是真实 note-based：

```json
{
  "kind": "motif",
  "reference_id": "ref-002",
  "slice_id": "slice-001",
  "notes": [
    {"pitch": 64, "start_beat": 0.0, "duration_beats": 1.0, "velocity": 88}
  ],
  "midi_sha256": "..."
}
```

不要继续使用 v1.7 的固定 placeholder seed。

## 11. Provider Prompt 集成

Provider prompt 可以使用 analysis summary。

允许：

- WAV duration/sample rate/loudness hint。
- MIDI track role summary。
- MIDI slice summary。
- text keywords/safe excerpt。

禁止：

- 原始音频 bytes。
- base64。
- 本地 path。
- 完整 MIDI note dump。
- 超长 envelope。

建议 provider prompt summary 限制：

- 单个 reference summary <= 2000 字符等价 JSON。
- 所有 references summary <= 6000 字符等价 JSON。

如果超限，截断并写 warning。

## 12. 数据兼容和 Stale 规则

### 12.1 旧 Reference

v1.7.x 的 reference 没有 `analysis.json`。

API 行为：

- `GET /analysis` 返回 `status=not_analyzed`，不要 500。
- Studio 显示 Analyze 按钮。

### 12.2 Stale

如果：

- `analysis.source_sha256 != reference.sha256`
- `slices.source_sha256 != reference.sha256`
- preview manifest 绑定 hash 不一致

则：

- analysis 显示 stale。
- slices 显示 stale。
- slice MIDI/WAV 下载返回 409。
- create asset 返回 409。

### 12.3 Force

`force=true` 会：

- 重写 `analysis.json`。
- 清理旧 `slices.json`。
- 清理 `preview/` 下旧 slice 产物。
- 写 event。

## 15. 安全准则

开发必须遵守：

1. 不读取任意本地路径，只分析 ReferenceStore 管理的固定 original file。
2. `analysis.json` 绑定 `source_sha256`。
3. stale analysis 不得用于 export/provider/slice create。
4. slice preview 下载必须校验 `source_sha256`。
5. slice audio 路径必须在 `.musicforge/references/<id>/preview/` 内。
6. Project export / Final Export 只写小型 summary。
7. Provider prompt 不含原始文件、base64、完整 note dump、完整 envelope。
8. 所有文本都走 `sanitize_sensitive_text()` / `sanitize_metadata()`。
9. 所有新增 API 都受 auth 保护。
10. 不新增重依赖。

## 17. Reviewer 检查重点

### P1 必查

- Analysis 是否能越界读取 ReferenceStore 之外的文件。
- Stale analysis/slices 是否仍可下载或 create asset。
- Provider prompt 是否包含完整 note dump、base64、本地 path。
- Final Export 是否复制了原始 reference 文件或 preview 文件。
- Slice download 是否信任 JSON 中的污染路径。
- MIDI parser 是否可能被畸形 VLQ 或超长 event 卡死。

### P2 必查

- WAV envelope 是否被限制大小。
- MIDI event 数量是否有上限。
- Running status 是否解析正确。
- Note on velocity 0 是否当作 note off。
- Slice asset note start 是否归零到 slice 内。
- Drum channel 是否保持 channel 9 / GM pitch 语义。
- Analysis failure 是否返回清晰错误，不影响 Reference 读取。

### P3 必查

- UI 是否能在窄屏下显示。
- 文案是否简洁。
- README / CHANGELOG / version 是否一致。
- release-check 是否覆盖 v1.8 主链路。

## 18. 版本节奏

建议开发按这个顺序推进：

1. Package A 完成后推 GitHub。
2. Package B 完成后推 GitHub。
3. Package C 完成后推 GitHub。
4. Package D 完成后推 GitHub。
5. Package E 完成后推 GitHub。
6. Package F 全量验证后 tag / Release。

每包推送前至少跑：

```powershell
python -m pytest <相关测试> -q
git diff --check
git status --short --branch
git push origin master
```

最终发布：

```powershell
python -m pytest -q
python -m song_agent.cli doctor
python -m song_agent.cli release-check
git status --short --branch
git diff --check
git push origin master
git tag -a v1.8.0 -m "v1.8.0"
git push origin v1.8.0
```

如果 GitHub 连接不稳定，可以沿用此前验证过的方式处理网络问题，但不能把 token 写入 remote URL、代码或文档。

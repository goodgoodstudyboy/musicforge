# v12.10.0 Unified Release Program Continuity Command Center Signoff / Archive 施工图

日期：2026-07-10

基线版本：v12.9.0 提交候选

目标版本：v12.10.0

主题：项目级连续性总控签核、不可变归档与最终移交包

---

## 1. 背景

v12.9 已经把 v12.3-v12.8 的连续性证据聚合成 Unified Release Program Continuity Command Center。

v12.9 的核心价值是“运行时复验总闸”：

- 重新验证底层 Evidence Vault、Vault Operations、Continuity Recovery、Continuity Distribution Kit、Continuity Acceptance Board、Continuity Acceptance Change Control。
- 不再只相信旧 verification report。
- 用 `component_type + component_id + generation` 绑定外部 evidence。
- Release / GA gate 可以要求 Command Center ready。

但 v12.9 仍然缺一个“最终冻结层”：

- Command Center ready 只是当前状态，不是正式签核。
- 没有独立的签核历史 hash chain。
- 没有不可变 archive。
- 没有可交给外部接收方或审计方的最终 handoff package。
- Release / GA 只能要求 Command Center ready，还不能要求“已签核并归档的 Command Center”。

v12.10 要解决这个问题。

---

## 2. 一句话目标

v12.10 新增 Continuity Command Center Signoff / Archive：在 v12.9 runtime ready 的基础上，生成不可抵赖的签核、签核绑定 sidecar、历史 hash chain、不可变 archive ZIP 和最终 handoff package，并把它接入 Release signoff 与 GA readiness。

---

## 3. 版本定位

v12.10 不是新增一个新的业务链路，而是把 v12.9 的 Command Center 变成可正式准出的冻结层。

关系如下：

```text

v12.4 Vault Operations
v12.5 Continuity Recovery
v12.6 Continuity Distribution Kit
v12.7 Continuity Acceptance Board
v12.8 Acceptance Change Control / Lifecycle
        |
        v
v12.9 Continuity Command Center
        |
        v
v12.10 Command Center Signoff / Archive / Final Handoff
```

## 6. 核心 P1 边界

### 6.1 P1：签核不能靠 archive 时现算

错误做法：

```text
export_archive() 时读取 signoff.json
再从 signoff.json 现算 binding summary
然后写进 ZIP
```

这样会导致攻击者同步篡改：

```text
signoff.json
history.jsonl
manifest.json
binding-summary.json
```

然后 verifier 可能只看到内部自洽，错误通过。

正确做法：

```text
signoff() 创建时立即生成 command-center-signoff-binding-summary.json
archive 只能复制这个 sidecar
verifier 必须要求外部 --signoff-binding
Release / GA gate 必须传外部 signoff binding
```

### 6.2 P1：签核后 archive 不能重新计算 source

签核时必须冻结：

- Command Center ZIP sha256 / size。
- Command Center manifest hash。
- Command Center verification report hash。
- external evidence manifest hash。
- current generation。
- acceptance signoff hash。
- acceptance history event hash。
- signoff payload hash。
- signoff hash。
- signoff history event hash。

archive/export/zip 只能复制 frozen snapshot。

如果当前 Command Center ZIP 或底层 evidence 已变化：

- `export_archive()` 返回 409。
- `build_archive_zip()` 返回 409。
- `gate()` 返回 failed。
- `force=true` 不能绕过。

### 6.3 P1：Archive verifier 不能只信 ZIP 内部自洽

Archive verifier 必须要求外部 evidence：

```text
--signoff-binding
--command-center-zip
--command-center-verification-report
--command-center-evidence-manifest
```

验证时必须：

- 校验 archive 内 binding summary 与外部 signoff binding 完全一致。
- 校验 signoff binding 反查 archive 内 signoff/history。
- 重新 runtime verify v12.9 Command Center。
- 校验 Command Center verification report 绑定当前 Command Center ZIP。
- 校验 Command Center ZIP 绑定 external evidence manifest。

### 6.4 P1：delete signoff.json 不能绕过签核状态

签核状态以 history hash chain 为准，不以 `signoff.json` 是否存在为准。

如果 history 中 latest event 是 signed：

- `signoff()` 再次调用必须 409。
- `refresh` 类 mutation 必须 409。
- `reset` 必须走 approved Change Request。
- 删除 `signoff.json` 不能让系统回到 unsigned。

### 6.5 P1：reset 必须 approved CR，且 single-use

reset 必须满足：

- Change Request 存在。
- `change_type == "reset_command_center_signoff"`。
- `allowed_actions` 包含 `reset_command_center_signoff`。
- approval integrity OK。
- approval target/source 匹配原 CR。
- CR 尚未 applied。
- reset 后写入 reset proof。
- CR 标记 applied。

reset 后：

- signoff gate failed。
- archive export/zip blocked。
- 必须重新运行 v12.9 Command Center。
- 必须重新 signoff。

## 9. Store API

类名：

```python
UnifiedReleaseProgramContinuityCommandCenterSignoffStore
```

方法：

```python
get_state(program_id)
preflight(program_id, payload=None)
signoff(program_id, payload)
reset_signoff(program_id, change_request_id, payload=None)
export_archive(program_id, payload=None)
build_archive_zip(program_id, payload=None)
verify_archive_zip(program_id, payload=None)
export_final_handoff(program_id, payload=None)
build_final_handoff_zip(program_id, payload=None)
verify_final_handoff_zip(program_id, payload=None)
gate(program_id, required=False, ...)
```

### 9.1 preflight()

必须检查：

- Command Center ZIP 存在。
- Command Center verification report 存在。
- external evidence manifest 存在。
- Command Center verification report integrity OK。
- Command Center ZIP hash/size/manifest hash 与 verification report 匹配。
- runtime verify Command Center passed。
- Command Center report status ready。
- current generation signed。
- no blockers。

### 9.2 signoff()

输入：

```json
{
  "signed_by": "program owner",
  "role": "release_owner",
  "reason": "Ready for continuity handoff"
}
```

必须：

- sanitize human text。
- 先跑 `preflight()`。
- 如果 history latest 是 signed，返回 409。
- 生成 signoff。
- 生成 signoff binding summary。
- 写 history event。
- 不生成 archive ZIP。

### 9.3 export_archive()

必须：

- 读取签核时 frozen source。
- 重建 history chain。
- 校验 external signoff binding summary。
- runtime verify 当前 Command Center。
- 当前 Command Center fingerprint 必须等于 signoff binding。
- 只能复制 frozen signoff docs。
- 不允许重新计算 signoff source。

如果失败返回 409。

### 9.4 build_archive_zip()

必须：

- 先执行 export_archive 的同等校验。
- 固定 ZIP entries。
- 不允许 declared extra。
- 不允许 nested ZIP。
- 不允许 `.MusicForge/`。
- 不允许 raw backslash entry。
- 不允许 trailing bytes。

### 9.5 reset_signoff()

必须：

- 需要 approved CR。
- CR single-use。
- 写 reset proof。
- 写 history reset event。
- 删除或标记当前 signoff inactive。
- reset 后 archive/export/zip/gate 都 failed。

## 10. Offline verifier

函数：

```python
verify_unified_release_program_continuity_command_center_signoff_package(
    zip_path,
    *,
    strict=False,
    require_signed=False,
    signoff_binding_path=None,
    command_center_zip_path=None,
    command_center_verification_report_path=None,
    command_center_external_evidence_manifest_path=None,
)
```

### 10.1 固定 archive allow-list

Archive ZIP 只允许：

```text
manifest.json
README.txt
command-center-signoff.json
command-center-signoff-binding-summary.json
command-center-signoff-history.jsonl
command-center-signoff-policy.json
command-center-signoff-state.json
command-center-fingerprint-summary.json
command-center-verification-summary.json
external-evidence-manifest-summary.json
final-handoff-checklist.json
```

多一个文件也 failed。

少一个文件也 failed。

### 10.2 必须校验

- ZIP readable。
- no duplicate entries。
- fixed allow-list。
- no raw backslash。
- no absolute path。
- no `..`。
- no `.MusicForge/`。
- no nested ZIP。
- no trailing data。
- manifest package type。
- manifest files exact。
- file sha256/size。
- redaction scan。
- signoff integrity。
- binding integrity。
- history hash chain。
- latest event is signed。
- signoff hash equals history event。
- binding summary equals external `--signoff-binding`。
- binding source equals external Command Center ZIP/report/manifest。
- runtime verify Command Center passed。

### 10.3 full-resign 攻击必须失败

回归场景：

1. 生成签核 archive。
2. 篡改 `signed_by`。
3. 重算 signoff integrity。
4. 重算 history hash chain。
5. 重算 binding summary。
6. 重算 manifest。
7. 重新打 ZIP。
8. 使用原外部 `--signoff-binding` 验证。

必须 failed。

失败点建议：

```text
urpcccs_external_signoff_binding_match
```

## 17. 必补测试

### 17.1 Happy path

- 准备 v12.9 Command Center ready。
- signoff。
- export archive。
- build archive ZIP。
- verify archive ZIP。
- build handoff ZIP。
- Release gate passed。
- GA gate passed。

### 17.2 Missing external signoff binding

- archive ZIP 内有 binding。
- verifier 不传外部 `--signoff-binding`。
- require signed 时必须 failed。

### 17.3 full-resign signed_by

- 篡改 signed_by。
- 重算 signoff/history/binding/manifest。
- 外部 binding 仍使用原始 sidecar。
- verifier 必须 failed。

### 17.4 stale Command Center after signoff

- signoff 后污染 v12.9 Command Center 底层 evidence。
- `export_archive()` 必须 409。
- `build_archive_zip()` 必须 409。
- Release gate 必须 409。
- GA verifier 必须 failed。

### 17.5 delete signoff guard

- signoff 后删除 `command-center-signoff.json`。
- 再次 signoff 必须 409。
- archive build 必须 failed 或 409。
- reset 必须走 CR。

### 17.6 reset CR wrong action

## 21. 给开发的话

v12.10 的核心不是再堆一个 report，而是把 v12.9 的 Command Center 正式冻结成“可签核、可归档、可移交”的准出证据。

实现时优先顺序是：

1. 先做 signoff-time binding sidecar。
2. 再做 history hash chain。
3. 再做 archive verifier 的外部 binding proof。
4. 再接 Release / GA gate。
5. 最后做 API/CLI/文档。

不要让 archive/verifier 只看 ZIP 内部自洽。只要看到“从 signoff.json 现算 binding summary”这种实现，就是 P1。

v12.10 必须坚持一个原则：

```text
签核发生在 signoff() 那一刻。
archive 只能复制签核时冻结的证据。
verifier 必须用外部 binding proof 和当前 v12.9 Command Center runtime verify 反查。
```

做到这一点，v12.10 才能作为 v12 Program Continuity 这条链路的真正准出层。

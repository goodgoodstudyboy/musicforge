# MusicForge v1.7.0 施工图：参考音频与外部素材导入层

> 基线版本：v1.6.1  
> 当前目标：把 MusicForge 从“只能复用系统内部生成素材”推进到“能安全导入外部参考素材，并让这些参考进入 Project / Asset / Export 工作流”。  
> 执行原则：全部先本地化验证；每完成一个边界清晰的功能包，测试通过后提交并推送 GitHub；最终再 tag / Release。  
> 测试判断：这一版需要大量测试，而且测试重点应偏安全、边界、导出脱敏和并发，而不是只测 happy path。

---

## 1. 背景

v1.6.1 之后，系统已经具备“创作资产库”：

- 可以从 Job / Project Version / Candidate 中抽取素材。
- 可以保存 motif、chord progression、drum pattern、bass pattern、lyric hook 等结构化资产。
- 可以在生成、编辑、candidate、Prompt A/B 中通过 `asset_refs` 引用资产。
- Project export / Final Export 会写入脱敏后的 asset reference summary。
- 已修复污染 metadata 在 Project export / Final Export 中泄露的风险。

但当前资产库仍有一个限制：

> 资产主要来自 MusicForge 自己生成的结果，用户还不能把外部参考音频、MIDI、歌词笔记、风格笔记安全地导入系统。

真实创作流程里，用户经常会有这些输入：

- 一段自己哼唱或制作的 WAV 小样。
- 一个已有 MIDI 片段。
- 一份歌词草稿。
- 一段风格参考描述。
- 一个来自外部工具的编曲备注。
- 某个 Project 的外部参考素材集合。

所以 v1.7.0 应该补上“外部参考素材导入层”。

这不是直接做音频识别，也不是自动扒谱。v1.7.0 先把文件导入、校验、标注、预览、绑定 Project、转成 Creative Asset 的基础设施做牢。后续 v1.8.0 再考虑自动分析、相似检索、BPM/key 推断、audio-to-MIDI 等更重能力。

---

## 2. 一句话目标

v1.7.0 的一句话目标：

> 允许用户在 Studio 中安全导入本地参考素材，形成 `.musicforge/references/` 参考库，并把参考素材绑定到 Project、生成输入、Creative Asset 和导出追踪中。

落地后，用户应能做到：

1. 在 Studio 上传一个 WAV 参考音频。
2. 在 Studio 上传一个 MIDI 参考片段。
3. 上传歌词草稿或风格笔记文本。
4. 给参考素材补充 tempo、key、meter、tags、source note、license note。
5. 在 Reference Library 中搜索、筛选、隐藏、收藏、删除。
6. 在 Project 中绑定参考素材。
7. 从 MIDI / text reference 手动创建 Creative Asset。
8. 在生成、edit、candidate、Prompt A/B 时选择若干 reference 作为上下文。
9. Project export / Final Export 中出现脱敏后的 reference summary。
10. 不泄露本地绝对路径、token、provider 原始响应、用户本机敏感信息。

---

## 3. 非目标

v1.7.0 不做以下事情：

- 不做 MP3 导入。
- 不做真实 audio-to-MIDI。
- 不做 WAV 自动扒旋律、扒和弦、扒鼓点。
- 不做自动 BPM/key 检测。
- 不做 waveform 缩略图。
- 不做向量数据库、embedding 检索、相似旋律搜索。
- 不把原始参考文件默认塞进 Final Export ZIP。
- 不允许 API 通过任意本地路径导入文件。
- 不允许 provider 直接拿到原始音频二进制。
- 不做云端素材同步。
- 不做版权授权系统，只记录用户填写的 license note / source note。

原因很简单：v1.7.0 的核心风险是“外部文件进入本地系统”。先把边界做稳，后面的智能分析才有可靠基础。

---

## 4. 为什么这一版需要大量测试

需要。

这一版和 v1.6 的内部 asset 不一样。v1.6 的素材主要来自系统自己生成的 `SongPlan`，输入相对可控；v1.7.0 会接收用户上传的外部文件，风险明显更高。

必须重点测试：

- 文件名路径穿越：`../../secret.wav`、`C:\Users\...\token.txt`、`\\server\share\a.wav`。
- Windows 特殊文件名：`CON.wav`、`NUL.mid`、超长文件名、空文件名。
- 文件大小限制：大 WAV、大 text、大 base64 body。
- MIME / 扩展名伪造：`.wav` 实际是 JSON，`.mid` 实际是文本。
- 文件头校验：WAV 必须是 `RIFF....WAVE`，MIDI 必须是 `MThd`。
- base64 解码失败、空内容、null byte、非法 UTF-8。
- 导出脱敏：reference metadata 中污染 `api_key`、`path`、`local_path`、`token`、`raw_provider_response` 不能进入 export。
- 下载安全：下载接口只能返回 `.musicforge/references/<ref-id>/original/` 下的受控文件。
- 删除安全：拒绝删除 symlink 或越界目录。
- 并发导入：同文件名或同内容并发上传不能互相覆盖。
- 鉴权覆盖：开启 access token 后所有 reference API 都要被 Bearer auth 保护。
- Studio 轮询和文件写入：不能读到半写 JSON。

建议 v1.7.0 至少新增 40-70 个聚焦测试。这个数量是合理的，不算过度。

## 5. 核心概念

### 5.1 Reference

Reference 是用户导入的外部参考素材。

它和 Creative Asset 的区别：

| 概念 | 用途 | 是否结构化 | 是否直接影响生成 |
| --- | --- | --- | --- |
| Reference | 外部参考文件或笔记 | 部分结构化 | 默认只提供上下文 |
| Creative Asset | 可复用创作素材 | 强结构化 | 可以通过 `asset_refs` 影响生成 |

Reference 更像“资料库”，Asset 更像“积木库”。

Reference 可以转成 Asset，但不应该默认自动转。原因：

- WAV 不能在 v1.7.0 自动转成旋律或和弦。
- MIDI 可以提取信息，但需要用户指定用途。
- 文本 reference 可能是歌词、风格备注、版权说明，不能自动当成 lyric hook。

### 5.2 Reference Types

v1.7.0 建议只支持这些类型：

| Type | 文件 | 校验方式 | Studio 预览 | 可转 Asset |
| --- | --- | --- | --- | --- |
| `audio_wav` | `.wav` | RIFF/WAVE header + size limit | `<audio controls>` | 暂不自动 |
| `midi` | `.mid`, `.midi` | `MThd` header + size limit | 下载 / metadata | 可手动生成 motif/chord/drum/bass seed |
| `lyrics_text` | `.txt`, `.md` | UTF-8 + size/line limit | text preview | 可转 `lyric_hook` |
| `style_note` | `.txt`, `.md` | UTF-8 + size/line limit | text preview | 可转 `section_template` / prompt context |

暂不支持 `.mp3`。

理由：

- 标准库很难可靠校验 MP3。
- 浏览器能播不代表服务器能安全判断。
- 这一版要优先稳定本地验证链路。

## 6. 存储设计

### 6.1 根目录

新增本地参考库：

```text
.musicforge/
  references/
    ref-001/
      reference.json
      original/
        reference.wav
      preview.json
      events.jsonl
    ref-002/
      reference.json
      original/
        reference.mid
      events.jsonl
```

不要使用用户上传的原始文件名作为真实存储路径。

建议固定存储为：

- `original/reference.wav`
- `original/reference.mid`
- `original/reference.txt`
- `original/reference.md`

原始文件名只放在 `reference.json` 的 `original_filename`，并且需要清洗。

### 6.2 `reference.json`

建议 schema：

```json
{
  "schema_version": 1,
  "reference_id": "ref-001",
  "reference_type": "audio_wav",
  "title": "chorus groove reference",
  "description": "A local WAV reference for the chorus groove.",
  "tags": ["chorus", "groove"],
  "favorite": false,
  "hidden": false,
  "created_at": "2026-05-08T00:00:00Z",
  "updated_at": "2026-05-08T00:00:00Z",
  "original_filename": "chorus.wav",
  "stored_filename": "reference.wav",
  "extension": ".wav",
  "media_type": "audio/wav",
  "size_bytes": 123456,
  "sha256": "...",
  "duration_seconds": null,
  "tempo_bpm": 118,
  "key": "C",
  "meter": "4/4",
  "source_note": "User imported local demo.",
  "license_note": "User-owned reference.",
  "linked_project_ids": ["project-001"],
  "derived_asset_ids": [],
  "usage_count": 0,
  "preview": {
    "file_url": "/api/references/ref-001/file",
    "text_excerpt": null,
    "midi_header": null,
    "audio_status": "available"
  }
}
```

### 6.3 不存什么

`reference.json` 不允许保存：

- 本地绝对路径。
- provider API key。
- access token。
- raw provider response。
- 上传时客户端真实路径。
- 未脱敏 source metadata。

如果 payload 中出现这些字段，必须丢弃或替换为 `[redacted]`。

## 7. 文件导入规则

### 7.1 API 输入形式

建议先用 JSON + base64，不做 multipart。

原因：

- 现有 server 是标准库 HTTP server。
- JSON body 处理路径已成熟。
- multipart parser 容易引入新的边界问题。
- v1.7.0 文件大小限制不大，base64 可以接受。

请求示例：

```json
{
  "filename": "chorus.wav",
  "content_base64": "...",
  "reference_type": "audio_wav",
  "title": "Chorus reference",
  "tags": ["chorus", "demo"],
  "tempo_bpm": 118,
  "key": "C",
  "meter": "4/4",
  "source_note": "My local demo.",
  "license_note": "Owned by user."
}
```

### 7.2 大小限制

建议限制：

| Type | 最大原始字节数 |
| --- | --- |
| `audio_wav` | 50 MB |
| `midi` | 2 MB |
| `lyrics_text` | 256 KB |
| `style_note` | 256 KB |

同时限制 JSON body 的 `content_base64` 字符串长度，避免 decode 前就把内存撑爆。

### 7.3 文件头校验

必须做：

- WAV：前 4 字节是 `RIFF`，第 8-12 字节是 `WAVE`。
- MIDI：前 4 字节是 `MThd`。
- Text：必须 UTF-8 decode 成功，不允许 `\x00`，单行长度上限建议 2000 字符。

扩展名和 reference_type 不匹配时直接 400。

### 7.4 文件名处理

文件名只用于展示，不用于真实路径。

必须处理：

- 去掉路径部分，只保留 basename。
- 空文件名使用 `untitled.wav` 这类兜底名。
- 过长文件名截断。
- 控制字符移除。
- Windows reserved names 不能原样作为展示名。
- 不允许把上传文件名拼进真实 path。

### 7.5 去重策略

建议 v1.7.0 做“软去重”：

- 计算 sha256。
- 如果同 sha256 已存在，不覆盖旧 reference。
- 新建 reference 时写 `duplicate_of: "ref-xxx"`，或直接返回 existing reference。

更建议第一版采用：

> 同内容重复导入直接返回 existing reference，并在响应里带 `duplicate: true`。

这样最简单，也避免同一份外部文件复制很多次。

## 8. 后端模块设计

新增模块：

```text
song_agent/
  references.py
```

建议结构：

```python
REFERENCE_ROOT = Path(".musicforge") / "references"

@dataclass(frozen=True)
class ReferenceItem:
    ...

@dataclass(frozen=True)
class ReferenceImportRequest:
    ...

class ReferenceStore:
    def list_references(...)
    def read_reference(reference_id: str)
    def import_reference(payload: dict[str, Any])
    def update_reference(reference_id: str, patch: dict[str, Any])
    def hide_reference(reference_id: str, hidden: bool = True)
    def favorite_reference(reference_id: str, favorite: bool = True)
    def delete_reference(reference_id: str)
    def file_path(reference_id: str)
    def link_project(reference_id: str, project_id: str)
    def unlink_project(reference_id: str, project_id: str)
    def create_asset_from_reference(reference_id: str, payload: dict[str, Any])
```

### 8.1 ID 分配

参考现有 `AssetStore`：

- `ref-001`
- `ref-002`
- `ref-003`

并发下必须在 lock 内分配 ID，目录创建用 `mkdir(..., exist_ok=False)` 原子占位。

### 8.2 JSON 写入

沿用 `write_json()`。

如果 `write_json()` 已是原子替换，直接使用；如果不是，开发需要先确认。Reference 这类 Studio 会频繁轮询的 JSON，不能半写。

### 8.3 删除安全

删除 reference 目录前必须：

- `resolve()`。
- 确认位于 `.musicforge/references/` 下。
- 拒绝 symlink。
- 拒绝不存在或格式非法的 ID。

### 8.4 下载安全

`GET /api/references/<id>/file` 只允许返回：

```text
.musicforge/references/<id>/original/reference.<ext>
```

不能信任 `reference.json` 里的任意 path。

## 9. API 设计

新增 API：

```text
GET  /api/references
POST /api/references/import
GET  /api/references/<reference-id>
POST /api/references/<reference-id>
POST /api/references/<reference-id>/hide
POST /api/references/<reference-id>/unhide
POST /api/references/<reference-id>/favorite
POST /api/references/<reference-id>/unfavorite
POST /api/references/<reference-id>/delete
GET  /api/references/<reference-id>/file
POST /api/references/<reference-id>/link-project
POST /api/references/<reference-id>/unlink-project
POST /api/references/<reference-id>/create-asset
GET  /api/projects/<project-id>/references
POST /api/projects/<project-id>/references/link
POST /api/projects/<project-id>/references/unlink
```

### 9.1 `GET /api/references`

Query 支持：

- `q`
- `type`
- `tag`
- `favorite=1`
- `hidden=false`
- `include_hidden=1`
- `project_id`
- `limit`

响应：

```json
{
  "references": [],
  "count": 0,
  "filters": {}
}
```

### 9.2 `POST /api/references/import`

成功：

- 新建：`201 Created`
- 重复：`200 OK`，`duplicate: true`

失败：

- base64 错误：400
- 扩展名不支持：400
- header 不匹配：400
- size 超限：413 或 400
- auth 缺失：401

### 9.3 `POST /api/references/<id>`

只允许更新 metadata：

- `title`
- `description`
- `tags`
- `favorite`
- `tempo_bpm`
- `key`
- `meter`
- `source_note`
- `license_note`

不允许更新：

- `sha256`
- `stored_filename`
- `size_bytes`
- `original path`
- `reference_type`

### 9.4 `create-asset`

只做受控转换：

- `midi` -> `motif` / `chord_progression` / `drum_pattern` / `bass_pattern` 的 seed asset。
- `lyrics_text` -> `lyric_hook`。
- `style_note` -> `section_template` 或只生成 textual asset。
- `audio_wav` 暂不支持自动创建 asset，返回 400：`audio_wav references cannot be converted to CreativeAsset in v1.7.0.`

MIDI 转 Asset 第一版不要做复杂解析。

建议：

- 只读取 MIDI header 和有限 track info。
- 允许用户手动填写 asset_type、name、tags、notes。
- `content` 里保存轻量 summary，不做全量 MIDI 解析。

## 11. 生成链路集成

### 11.1 新增 `reference_refs`

建议 payload 字段：

```json
{
  "reference_refs": [
    {
      "reference_id": "ref-001",
      "role": "style_reference",
      "strength": 0.7
    }
  ]
}
```

规则：

- 最多 5 个 reference。
- hidden reference 不可使用。
- 不存在的 reference 直接 400。
- `strength` 限制 0.0 到 1.0。
- role 使用白名单。

建议 role：

- `style_reference`
- `lyrics_reference`
- `arrangement_reference`
- `midi_reference`
- `audio_reference`

### 11.2 本地 deterministic 行为

Local deterministic pipeline 不需要强行解析 reference。

第一版行为：

- 如果有 `reference_refs`，写 `data/reference-refs.json`。
- 生成 summary / job metadata 中保留脱敏 reference summary。
- `usage_count` +1。
- 不强行改变 SongPlan。

后续如果要影响生成，应鼓励用户先把 reference 转成 Creative Asset，再通过 `asset_refs` 影响生成。

### 11.3 Provider 行为

Provider prompt 可以使用 reference summary，但不能包含：

- 原始文件 bytes。
- 本地路径。
- 未脱敏 metadata。
- 超长文本。

文本 excerpt 建议限制 1000 字符。

WAV reference 只提供：

- title
- tags
- tempo/key/meter
- user notes
- `reference_type=audio_wav`

## 12. Project / Export 集成

### 12.1 Project Version

Project Version metadata 应记录：

```json
{
  "reference_refs": [
    {
      "reference_id": "ref-001",
      "role": "style_reference",
      "strength": 0.7,
      "captured_at": "..."
    }
  ]
}
```

### 12.2 Project Export

Project export 中包含脱敏 reference summary：

```json
{
  "reference_refs": [
    {
      "reference_id": "ref-001",
      "reference_type": "audio_wav",
      "title": "chorus reference",
      "tags": ["chorus"],
      "tempo_bpm": 118,
      "key": "C",
      "used_by_versions": ["v002"]
    }
  ]
}
```

不包含：

- 原始文件。
- 原始 path。
- `source_note` 全量。
- `license_note` 之外的敏感字段。

### 12.3 Final Export

v1.7.0 默认只导出 reference summary，不复制原始参考文件。

Final Export manifest 增加：

```json
{
  "reference_refs": []
}
```

如果后续要支持 `include_references=true`，必须另开 v1.7.1 或 v1.8.0 做完整路径/ZIP 安全测试。

## 15. Tiny fixture 建议

不要提交大二进制。

测试里用代码构造 tiny WAV：

```python
def tiny_wav_bytes() -> bytes:
    return (
        b"RIFF"
        + (36).to_bytes(4, "little")
        + b"WAVE"
        + b"fmt "
        + (16).to_bytes(4, "little")
        + (1).to_bytes(2, "little")
        + (1).to_bytes(2, "little")
        + (8000).to_bytes(4, "little")
        + (16000).to_bytes(4, "little")
        + (2).to_bytes(2, "little")
        + (16).to_bytes(2, "little")
        + b"data"
        + (0).to_bytes(4, "little")
    )
```

tiny MIDI 可以复用现有 MIDI renderer 生成，也可以写最小 `MThd` header fixture。

建议优先复用 `render_midi()` 生成真实 MIDI，这样测试更贴近系统。

## 16. 安全准则

开发必须遵守：

1. 不允许用户传入服务器本地 path 让后端读取。
2. 上传内容只能来自 request body。
3. 原始文件名不参与真实路径拼接。
4. 下载只读固定 original file。
5. 删除只删 resolved reference dir。
6. symlink 一律拒绝。
7. Project export / Final Export 一律二次脱敏。
8. Provider prompt 不包含 bytes/base64/path。
9. `.musicforge/references/` 不加入 Git。
10. 所有 reference API 都受 auth 保护。

- Provider prompt 是否泄露 base64 / local path / token。
- Auth 是否覆盖所有 reference API。

- WAV / MIDI header 校验是否真实做了。

- duplicate sha256 策略是否稳定。
- Project export / Final Export 是否二次脱敏。

### P3 必查

- UI 是否能在窄屏下正常显示。

# v7.7.0 Release Portfolio Governance Attestation Accepted Evidence 公开证明外部接受证据登记与门户摘要施工图

> 本文是给开发执行的 v7.7.0 施工图。当前稳定基线是 v7.6.1。v7.6.1 已经修复 Portal Review Response 的关键安全问题：外部 response 必须显式携带 `review_pack_id` 和 `review_pack_source_hash`，裸 JSON 不再由导入端自动补 source binding。

v7.7.0 的目标是把 v7.6 的 `accepted` 外部审查响应，安全地登记成 Public Attestation / Registry / Portal 可展示、可验证、可离线复验的 accepted evidence summary。

一句话：

> v7.7.0 要让“外部审查方已接受当前公开证明”成为公开证明链路中的一等证据，但不修改历史 Registry event，不自动 publish / revoke / supersede，不暴露完整敏感 notes。

---

## 1. 背景

当前 v7 公开证明链路已经完成：

- v7.1：Evidence Vault，深度证据保险库。
- v7.2：Public Attestation，公开证明证书包。
- v7.3：Attestation Registry，公开证明登记册。
- v7.4：Attestation Portal Snapshot，静态门户快照。
- v7.5：Release Check Verification Matrix，发布验证矩阵。
- v7.6：Portal Review Response，外部审查响应导入与 Change Request draft。
- v7.6.1：修复裸 JSON response 被自动补 source binding 的安全问题。

现在链路已经能做到：

```text
Portal Snapshot
  -> Review Pack
  -> External Reviewer Response
  -> Import / Verify
  -> accepted / needs_changes / rejected
```

但还有一个公开侧缺口：

1. `accepted` response 只存在 Portal Review Response 模块里。
2. Registry / Portal public summary 还不能清楚显示“当前证明已被外部接受”。
3. accepted response 是否绑定当前 Portal / Registry / Attestation，没有被提升为 Registry / Portal verifier 的一部分。
4. 如果 accepted response stale，当前公开摘要没有统一状态表达。
5. 如果 needs_changes / rejected 存在，也没有一个 public-safe summary 表达“历史审查响应存在，但不能作为 accepted evidence”。

v7.7 要补的是公开摘要层，不是重做 review response。

---

## 2. v7.7.0 目标

新增 Release Portfolio Governance Attestation Accepted Evidence。

核心能力：

1. 从当前 `accepted` Portal Review Response 创建 Accepted Evidence record。
2. Accepted Evidence 必须绑定：
   - Review Response verification report。
   - Review Pack source hash。
   - Portal ZIP / manifest / verification hash。
   - Registry current entry。
   - Public Attestation verification hash。
   - Evidence Vault fingerprint。
   - Final Board signoff hash。
3. Registry export summary 显示 accepted evidence summary。
4. Portal Snapshot 显示 external review status。
5. Registry verifier / Portal verifier / Accepted Evidence verifier 能抓 source mismatch。
6. stale accepted response 不能作为 current accepted evidence。
7. needs_changes / rejected 不能注册为 accepted evidence。
8. accepted evidence 不自动修改历史 Registry events。
9. accepted evidence 不自动 publish / revoke / supersede。
10. release-check matrix 增加 `v77.attestation_accepted_evidence_smoke`。

---

## 3. 非目标

v7.7 不做：

- 不自动 publish Registry entry。
- 不自动 revoke Registry entry。
- 不自动 supersede Registry entry。
- 不修改历史 `registry-events.jsonl`。
- 不把完整 reviewer notes 暴露进 public portal。
- 不把完整 response ZIP 嵌入 Registry ZIP / Portal ZIP。
- 不把 Review Pack ZIP 嵌入 Registry ZIP / Portal ZIP。
- 不做法律签章。
- 不做线上 reviewer 登录。
- 不做多 reviewer quorum。
- 不做 accepted response 的投票/审批流。

v7.7 只做“已接受证据摘要登记 + verifier 绑定 + public-safe 展示”。

## 7. 状态语义

Accepted Evidence 状态：

```text
current
stale
failed
archived
```

### current

条件：

- response decision == accepted。
- response status == accepted。
- response verifier status == passed。
- response source hash 等于当前 Review Pack source hash。
- Review Pack source 绑定当前 Portal / Registry / Attestation。
- accepted evidence integrity OK。
- redaction passed。

### stale

条件：

- Review Pack source 变化。
- Portal ZIP / verification 变化。
- Registry current entry 变化。
- Public Attestation verification 变化。
- Evidence Vault fingerprint 变化。
- Final Board signoff hash 变化。
- response verification report 不是当前 response 生成。

stale evidence 可以保留为历史记录，但不能作为 current accepted。

### failed

条件：

- response decision 不是 accepted。
- response verifier failed。
- response 有 unresolved high / critical finding。
- source hash 缺失。
- redaction failed。
- integrity hash mismatch。

### archived

人工归档历史 accepted evidence，不参与 current summary。

## 13. Stale Guard

Accepted Evidence stale 条件：

- response record source hash 变化。
- response verification report 变化。
- Review Pack source hash 变化。
- Portal ZIP hash 变化。
- Portal manifest hash 变化。
- Portal verification hash 变化。
- Registry current entry id/hash 变化。
- Public Attestation verification hash 变化。
- Evidence Vault fingerprint 变化。
- Final Board signoff hash 变化。

操作规则：

- stale evidence 不能 export 为 current。
- stale evidence 可以 export 为 historical warning，但不能通过 `--require-current`。
- stale evidence 不能写入 Portal `external_review_status=accepted`。
- stale evidence 不能满足 Registry verifier `--require-accepted-evidence`。

## 20. 安全要求

必须满足：

1. Accepted Evidence 只能来自 accepted response。
2. needs_changes / rejected 不能注册为 accepted evidence。
3. stale accepted response 不能注册为 current accepted evidence。
4. response verifier report 必须 passed。
5. response verifier report 必须绑定当前 response。
6. response 必须绑定当前 Review Pack source。
7. Review Pack source 必须绑定当前 Portal / Registry / Attestation。
8. Registry / Portal 只展示脱敏 public summary。
9. 不展示完整 notes。
10. 不嵌套任何 ZIP。
11. 不允许 `.musicforge/` entry。
12. 不允许反斜杠 entry。
13. 不允许 duplicate entry。
14. 不允许 token / 本机路径。
15. 不允许自动 publish / revoke / supersede。

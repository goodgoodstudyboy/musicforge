# v6.5.0 Release Portfolio Audit 跨发行组合审计与趋势治理施工图

日期：2026-06-05

当前稳定基线：v6.4.1

目标版本：v6.5.0

角色定位：reviewer / planner 交给开发执行

---

## 1. 背景

MusicForge 到 v6.4.1 已经把单个 Release 的运营链路推进到比较完整的状态：

- Release Operations Dashboard 能聚合单个 Release 的运营状态。
- Runbook 能把安全动作串起来，但不自动做签核、提交、人工听审等高风险动作。
- Operations Signoff / Archive / Change Request 能做最终运营签核、封存和变更申请。
- Audit Ledger 能把关键动作串成可验证审计账本。
- Reviewer Pack / Retrospective 能把单个 Release 的证据整理成外部 reviewer 可以审阅的包。
- v6.4.1 已经修掉缺失或失败 audit verification 仍能生成 reviewer pack 的风险。

现在的问题是：系统已经能把“一个 Release”交付清楚，但还不能回答“多个 Release 长期来看是否变好”。

开发和业务下一步真正需要的是组合级治理能力：

- 最近 5 个 Release 哪些风险反复出现？
- 哪些 verifier warning 一直没有减少？
- Change Request 是不是越来越多？
- 哪些环节人工卡点最多？
- 哪些 Release Reviewer Pack 虽然能过，但 warning 结构越来越差？
- 哪些 Release 存在 signed / archived / audit / reviewer pack 证据不一致？
- 哪些问题应该进入下一轮 Runbook、Fix Plan 或流程规则治理？

所以 v6.5.0 建议做一个大一点的版本：Release Portfolio Audit。

这不是“再做一个单页统计表”，而是把多个 Release 的 reviewer pack、audit ledger、archive、signoff、change request、runbook、verifier 结果统一抽象成一个可导出、可离线验证、可签核追溯的 Portfolio Audit Package。

---

## 2. v6.5.0 的核心目标

v6.5.0 要实现：

1. 新增跨 Release 的 Portfolio Audit Store。
2. 从多个 Release 中采集 Operations / Audit / Reviewer Pack / Archive / Signoff / Change Request / Runbook 证据。
3. 生成组合级 Portfolio Audit Report。
4. 生成组合级 Trend Report。
5. 生成组合级 Risk Register。
6. 支持导出 Portfolio Audit Package。
7. 支持离线验证 Portfolio Audit ZIP。
8. 在 Studio 增加 Portfolio Audit 工作区。
9. 在 release-check 里加入 v6.5 smoke，证明这个组合级审计包离开本地 workspace 后仍可被验证。

最终用户能做到：

```powershell
python -m song_agent.cli release-portfolio-audit --refresh --json
python -m song_agent.cli release-portfolio-audit --portfolio-id pfa-000001 --export --zip --verify --strict --require-reviewer-packs --json
python -m song_agent.cli verify-release-portfolio-audit-package .musicforge\portfolio-audits\pfa-000001\portfolio-audit.zip --strict --require-reviewer-packs --json
```

---

## 3. 非目标

v6.5.0 不做这些事：

- 不自动修改任何 Release。
- 不自动 reset signoff。
- 不自动 approve Change Request。
- 不自动 close / archive / signoff。
- 不批量重跑所有 Release 的 heavy verifier。
- 不复制大型音频、Distribution ZIP、Submission ZIP 或 Reviewer Pack ZIP。
- 不做外部 SaaS 上传。
- 不引入数据库。
- 不引入第三方依赖。
- 不做 AI/provider 总结。

v6.5.0 只做 deterministic、本地、只读、可导出、可离线验证的组合级审计。

## 7. Source Hash 规则

Portfolio Audit 的 source hash 必须只绑定外部输入，不绑定自身输出。

建议 source hash 输入：

```text
release_id
release status
release operations summary hash
operations signoff hash
operations archive manifest hash
operations archive verification hash
audit ledger report hash
audit package verification status/hash
reviewer pack report hash
reviewer pack verification status/hash
change request ids/status/hash
runbook ids/status/hash
release updated_at 或 event count
```

不要纳入：

- portfolio-audit-report.json 自身
- portfolio-trend-report.json 自身
- portfolio-risk-register.json 自身
- portfolio-export manifest
- portfolio-audit.zip metadata
- verification-report.json

目的：

- Release 证据变了，Portfolio Audit 变 stale。
- Portfolio Audit 自己导出、验证、写事件，不会把自己判 stale。

## 9. Gate 规则

Portfolio Audit 默认是观察型，不应该过度阻断。

但导出和严格验证时要支持 gate：

### 9.1 默认 refresh

默认 refresh 行为：

- 缺 reviewer pack：warning。
- 缺 audit verification：warning。
- release stale：warning。
- redaction 命中：failed。
- snapshot integrity failed：failed。
- duplicate release id：failed。

### 9.2 require_reviewer_packs

启用后：

- 每个 included release 必须有 reviewer pack report。
- reviewer pack report integrity 必须 OK。
- reviewer pack verification report 必须存在。
- reviewer pack verification status 必须 passed。

否则 portfolio report failed。

### 9.3 require_audit

启用后：

- 每个 included release 的 reviewer pack 中必须有 audit summary。
- audit package verification status 必须 passed。
- audit report 不能 failed。

否则 failed。

### 9.4 require_archive

启用后：

- 每个 included release 必须 operations archived。
- archive manifest 必须存在。
- archive verification 必须 passed。

否则 failed。

### 9.5 strict verifier

`verify-release-portfolio-audit-package --strict`：

- 不允许未知 ZIP entry，除非明确 sidecar。
- 不允许重复 entry。
- 不允许反斜杠 entry。
- 不允许路径穿越。
- 不允许本机路径泄露。
- 不允许 manifest.zip.entries 被信任来放行额外文件。
- 所有 manifest.files 必须存在且 sha256 匹配。
- 所有 JSON report integrity hash 必须匹配。

## 10. ZIP Export 设计

Portfolio Audit ZIP 建议包含：

```text
manifest.json
portfolio-audit-report.json
portfolio-trend-report.json
portfolio-risk-register.json
release-index.json
reviewer-pack-summary.json
change-request-summary.json
runbook-summary.json
audit-summary.json
PORTFOLIO_REVIEW.md
PORTFOLIO_RETROSPECTIVE.md
RISK_REGISTER.md
README.txt
```

不要包含：

- release package zip
- distribution package zip
- submission package zip
- reviewer pack zip
- audio files
- local `.musicforge` 原始目录
- provider snapshot raw secret
- renderer config raw path

manifest 建议：

```json
{
  "package_type": "release_portfolio_audit",
  "version": "6.5.0",
  "portfolio_id": "pfa-000001",
  "created_at": "...",
  "source_hash": "...",
  "files": [
    {
      "path": "portfolio-audit-report.json",
      "sha256": "...",
      "size": 1234
    }
  ],
  "sidecars": {
    "portfolio_audit_report": {
      "payload_hash": "..."
    }
  },
  "zip": {
    "entry_count": 0,
    "sha256": null
  }
}
```

注意：

- `zip` 字段不参与核心 sidecar payload hash。
- verifier 不能信 `zip.entry_count` 或 `manifest.zip.entries` 放行文件。
- 允许 sidecar entry 必须写死：`manifest.json` 加 manifest.files[].path。

- manifest.files 对账。
- hash 对账。
- report integrity hash 检查。

## 16. Trend Finding 规则

v6.5 不需要复杂统计模型，先做 deterministic 规则：

### 16.1 Change Request 频率

规则：

- 最近 3 个 Release 中，平均 CR 数 > 历史平均 1.5 倍：warning。
- 最近 3 个 Release 中，每个都有 CR：medium risk。

### 16.2 Verifier Warning 反复出现

规则：

- 同类 warning 出现 >= 2 个 Release：warning。
- 同类 warning 出现 >= 3 个 Release：high risk。

### 16.3 Manual Bottleneck

规则：

- manual_required action 总数持续上升：warning。
- runbook 中 manual_required 超过 safe action 数：medium risk。

### 16.4 Force Signoff

规则：

- 任意 Release 有 force signoff：warning。
- 最近 3 个 Release 出现 >= 2 次 force signoff：high risk。

### 16.5 Archive / Audit 缺失

规则：

- signed 但未 archive verified：warning。
- reviewer pack passed 但 audit verification missing：failed under require_audit。

### 16.6 Stale Evidence

规则：

- stale snapshot：warning。
- stale reviewer pack：failed under require_reviewer_packs。
- stale audit report：failed under require_audit。

## 17. Risk Register 生成规则

示例：

### 17.1 reviewer_pack_missing

条件：

- included release 缺 reviewer pack。

严重度：

- 默认 medium。
- require_reviewer_packs 时 high。

### 17.2 audit_verification_missing

条件：

- reviewer pack 中 audit summary 存在，但 verification missing。

严重度：

- 默认 medium。
- require_audit 时 high。

### 17.3 repeated_change_requests

条件：

- 最近 3 个 Release 都有 CR。

严重度：

- medium。

### 17.4 force_signoff_used

条件：

- 任何 Release 使用 force signoff。

严重度：

- high。

### 17.5 redaction_leak

条件：

- export summary 或 markdown 中出现敏感值。

严重度：

- critical。

### 17.6 verifier_warning_regression

条件：

- verifier warning 总量比上一窗口增加。

严重度：

- low / medium。

## 17.7 Portfolio Risk Score

Portfolio Audit 需要给出一个 deterministic risk score，方便多个 Release 横向排序。

建议范围：

```text
0 = 无明显风险
100 = 不能作为外部审计材料
```

建议计分：

```text
critical risk      +25
high risk          +15
medium risk        +8
low risk           +3
missing reviewer   +12
missing audit      +12
missing archive    +8
force signoff      +10
stale evidence     +8
redaction warning  +25
integrity failed   +40
```

最终：

```text
risk_score = min(100, sum(points))
```

组合状态建议：

```text
0-19    passed
20-39   warning
40-69   high_risk
70-100  failed
```

注意：

- 这个分数不是业务好坏评分，而是运营审计风险评分。
- 分数必须可解释，report 中要列出 score_breakdown。
- 不能引入随机权重或 provider 解释。

## 17.8 Release Readiness Ranking

Portfolio Audit 要输出 release readiness ranking。

建议字段：

```json
{
  "release_id": "rel-000001",
  "readiness_rank": 1,
  "readiness_status": "ready|review_needed|blocked",
  "risk_score": 12,
  "coverage_score": 94,
  "blocker_count": 0,
  "warning_count": 2,
  "recommendation": "ready_for_external_review"
}
```

ranking 规则：

1. blocker_count 少的排前。
2. risk_score 低的排前。
3. reviewer pack / audit / archive 覆盖完整的排前。
4. force signoff 少的排前。
5. 最近更新的 Release 不应天然排前，避免新 Release 掩盖旧风险。

---

## 17.9 Deterministic Recommendations

Portfolio Audit 要生成建议，但必须是规则驱动。

示例：

- `generate_missing_reviewer_pack`：存在 signed Release 但缺 Reviewer Pack。
- `verify_missing_audit_package`：Reviewer Pack 存在但 audit verification missing。
- `reduce_repeated_change_requests`：最近多个 Release 反复出现 CR。
- `review_force_signoff_policy`：出现 force signoff。
- `create_runbook_for_manual_bottleneck`：manual_required 动作持续高。
- `fix_redaction_pipeline`：发现路径或 token 泄露。

每条 recommendation 必须包含：

```json
{
  "recommendation_id": "rec-000001",
  "category": "audit|reviewer_pack|change_control|runbook|redaction",
  "severity": "low|medium|high|critical",
  "release_ids": [],
  "reason": "...",
  "suggested_action": "...",
  "manual_required": true
}
```

不能自动执行 recommendation。v6.6 才考虑 Action Queue。

## 20. Stale 规则

Portfolio Audit stale 条件：

- included release 状态变化。
- included release signoff hash 变化。
- included release archive manifest hash 变化。
- reviewer pack report hash 变化。
- reviewer pack verification report hash 变化。
- audit ledger report hash 变化。
- audit verification status/hash 变化。
- change request 状态变化。
- runbook 状态变化。

不应导致 stale：

- portfolio 自己 verify 了一次。
- portfolio 自己 export/zip。
- portfolio 自己写 event。

## 21. 安全边界

必须覆盖：

- ZIP duplicate entry。
- ZIP raw backslash entry。
- ZIP path traversal。
- ZIP absolute path。
- ZIP bomb：entry count + total uncompressed size。
- manifest spoof。
- `manifest.zip.entries` 不可信。
- report integrity hash。
- release snapshot integrity hash。
- redaction scan。
- external verify 不依赖 workspace。
- 不复制大型二进制。
- 不泄露本机路径。

## 30. Reviewer 重点检查清单

开发交付后 reviewer 要重点看：

- source_hash 是否没有自引用。

- ZIP verifier 是否检查 raw central directory backslash。
- duplicate entry 是否 failed。
- manifest.zip.entries 是否不被信任。
- Markdown / JSON 是否脱敏。
- ZIP 是否不复制大型二进制和本机路径。
- release-check 是否覆盖负例，而不是只测 happy path。

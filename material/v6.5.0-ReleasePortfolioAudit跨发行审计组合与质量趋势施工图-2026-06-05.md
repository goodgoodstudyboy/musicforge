# v6.5.0 Release Portfolio Audit 跨发行审计组合与质量趋势施工图

日期：2026-06-05  
基线版本：v6.4.1  
目标版本：v6.5.0  
角色定位：Reviewer / Planner / Release Governance Portfolio Architect  
项目：MusicForge / song-agent

---

## 1. 背景

v6.4.1 已经把单个 Release 的外部审查包做稳：

- v6.3.1 的 Audit Ledger 证明单个 Release 的证据链顺序、hash、Change Request 因果。
- v6.4.0 的 Reviewer Pack 把机器证据转成人能看的审查包和复盘报告。
- v6.4.1 收紧 `require-audit`，Reviewer Pack 必须有 passed 的 Audit Package verification evidence。

现在单个 Release 已经可以回答：

- 这个 Release 是否签核？
- Archive 是否验证？
- Audit Ledger 是否完整？
- Change Request 是否覆盖 reset？
- Reviewer Pack 是否可给外部 reviewer 看？
- Retrospective 是否能复盘单个 Release？

但团队层面的新问题会出现：

- 最近 10 个 Release，整体交付风险是在下降还是上升？
- 哪些 verifier warning 总是重复出现？
- 哪些 Release 频繁发生 Change Request？
- 哪些阶段最容易卡住？
- 哪些 Release 没有 Reviewer Pack 或 Audit evidence？
- 哪些 Release 是 force signed？
- 哪些 Release 的人工动作太多，说明自动化还有缺口？
- 哪些 Release 适合给外部 reviewer，哪些只能内部复盘？
- release-check 只证明当前代码能跑，但业务需要看到长期运营质量趋势。

所以 v6.5.0 应该做：

> Release Portfolio Audit：跨多个 Release 聚合 Reviewer Pack / Audit Ledger / Operations evidence，生成 portfolio-level 审计报告、趋势报告、风险排名和外部可验证的 Portfolio Audit Package。

---

## 2. 总目标

一句话目标：

> 让 MusicForge 不只会交付单个 Release，还能持续追踪多个 Release 的运营质量、风险趋势、审计覆盖率和流程瓶颈。

完成后，用户应该能：

- 在 Studio 顶层看到 `Portfolio Audit` 工作区。
- 选择全部 Release 或筛选一组 Release。
- 生成 Portfolio Audit Report。
- 看到：
  - Release 覆盖率。
  - Reviewer Pack 覆盖率。
  - Audit Ledger 覆盖率。
  - Archive verified 覆盖率。
  - Signed / force_signed / reset / archived 统计。
  - Change Request 频率。
  - verifier warning / failed 趋势。
  - manual_required 动作趋势。
  - risk hotspots 排名。
  - release readiness ranking。
- 导出 Portfolio Audit Package。
- 在外部目录验证：

```powershell
python -m song_agent.cli verify-release-portfolio-audit-package path\to\portfolio-audit.zip --json --strict --require-current --require-reviewer-packs
```

---

## 3. 非目标

v6.5.0 不做：

- 不改任何 Release / Distribution / Submission 状态。
- 不自动生成缺失的 Reviewer Pack。
- 不自动修复 warning。
- 不跨机器联网拉 GitHub Release。
- 不接 DSP API。
- 不上传外部平台。
- 不做云端 dashboard。
- 不复制单个 Release 的大包 ZIP。
- 不复制音频、artwork、metadata 大文件。
- 不把 portfolio report 当成单个 Release 的签核条件。它是治理和趋势工具，不是交付 gate。

## 6. 数据来源

Portfolio Audit 只读读取：

- `ReleaseStore.list_releases(include_hidden=True)`。
- 每个 Release 的 Operations Audit Report。
- 每个 Release 的 Operations Audit Ledger。
- 每个 Release 的 Reviewer Report。
- 每个 Release 的 Retrospective Report。
- 每个 Release 的 Reviewer Pack verification report。
- 每个 Release 的 Operations Archive verification report。
- 每个 Release 的 Change Request summary。

不要求每个 Release 都完整。缺失证据进入 coverage / warning / blocker。

### 6.1 证据优先级

优先读：

1. Reviewer Report。
2. Retrospective Report。
3. Audit Report。
4. Audit Ledger。
5. Operations Signoff / Archive verifier。

如果 Reviewer Report 存在但 integrity failed：

- 不用它推断 passed。
- 该 Release row 标 `reviewer_pack_status=failed`。
- Portfolio report 出 blocker。

## 7. 覆盖率规则

Coverage 输出：

```json
{
  "reviewer_pack_coverage": 0.83,
  "audit_ledger_coverage": 0.92,
  "archive_verified_coverage": 0.83,
  "signed_coverage": 0.83,
  "reviewable_coverage": 0.75
}
```

计算：

- reviewer_pack_coverage = passed/warning reviewer report count / release_count。
- audit_ledger_coverage = audit report exists and integrity ok / release_count。
- archive_verified_coverage = archive verified true / release_count。
- signed_coverage = signed or force_signed / release_count。
- reviewable_coverage = reviewer status passed or warning / release_count。

如果 release_count == 0：

- status failed。
- blocker `portfolio_no_releases`。

## 8. Risk Score

每个 Release 计算 risk_score：

```text
+100 if reviewer report missing
+100 if reviewer report integrity failed
+80  if audit report missing
+80  if audit report failed
+60  if archive verification missing/failed
+40  if operations signoff missing
+25  per blocker
+10  per warning
+15  per applied Change Request
+10  if force_signed
+5   per manual_required action over 3
-20  if reviewer passed and archive verified and no warnings
```

风险等级：

- `0-19` low
- `20-59` medium
- `60-119` high
- `>=120` critical

risk ranking 按：

1. risk_score desc。
2. blocker_count desc。
3. warning_count desc。
4. release_id asc。

## 10. Recommendations

只用 deterministic 规则，不调用 provider。

建议示例：

- Reviewer Pack coverage < 80%：补齐 Reviewer Pack。
- Audit coverage < 90%：补齐 Audit Ledger。
- Archive verified coverage < 90%：把 Archive Verify 加入 Runbook safe action。
- Change Request frequency high：检查签核前 checklist。
- Force signed count > 0：复盘 force reason。
- Manual action average > 5：识别可安全自动化动作。
- Repeated verifier warning：收紧对应模块。

```text

```

必须检查：

- ZIP open。
- ZIP size limit。
- total uncompressed size limit。
- entry count limit。
- raw central directory entry path。
- unsafe path。
- duplicate entry。
- required entries。
- manifest integrity hash。
- manifest.files shape。
- manifest.files hash 对账。
- strict extra entry failed。
- `manifest.zip.entries` 不能扩权。
- portfolio report integrity hash。
- release-index hash。
- risk-ranking hash。
- reviewer pack coverage data consistency。
- require_current：
  - report status 不能 failed。
  - source_hash 必须存在。

  - 每个 included Release 必须有 reviewer report。
  - reviewer report status 不能 failed。
  - reviewer report integrity must be true。
- redaction scan。
- blocked key scan。

篡改场景必须 failed：

- 改 `portfolio-audit-report.json` summary。
- 改 `release-index.json` risk_score。
- 删除 `PORTFOLIO_REVIEW.md`。
- duplicate `README.txt`。
- dangerous `../evil.txt`。
- raw backslash entry。
- manifest spoof。
- Markdown 注入本机路径/token。

## 16. 安全边界

Portfolio Audit Package 不能包含：

- audio / artwork / package ZIP。
- provider raw response。
- token。
- local absolute path。
- UNC path。
- platform credential。
- source_path / local_path / file_path。

只能包含 summary。

读取 Release 时必须容忍缺文件，不允许因某个坏 Release 让整个 API 崩溃；坏 Release 进入 row blocker。

## 21. Reviewer 验收重点

Reviewer 重点看：

- Portfolio Audit 是否只读。
- 是否不改变任何 Release 状态。
- 是否能容忍坏 Release，不让 API 崩溃。
- risk_score 是否 deterministic。
- coverage 是否按 release_count 正确计算。
- missing reviewer pack 是否不会被算成 passed。
- failed reviewer integrity 是否进入 blocker。
- verifier 是否不信 `manifest.zip.entries`。
- raw backslash entry 是否被抓。
- Markdown 是否脱敏扫描。
- Package 是否不包含单个 Release 的大 ZIP / audio / artwork。
- release-check 是否覆盖两个 Release 的组合场景。

# v8.7.0 Public Trust Center Acceptance Board Signoff 验收委员会签核归档与公开准出绑定施工图

> v8.6.1 已经把多接收方 Acceptance Board 的 quorum / role / external accepted evidence 校验收紧到可用状态。v8.7.0 的目标，是把 v8.6 的 `board-signoff-draft.json` 升级成正式、不可变、可离线验证、可被 Public Trust Center / Distribution Kit / Trust Center Distribution Kit 引用的 Acceptance Board Signoff Archive。  
> 这一步不是再做一个普通报告，而是把“多方验收委员会通过”变成公开交付链上的准出证据。

新增 Public Trust Center Acceptance Board Signoff / Archive：

```text
Acceptance Board ready
  -> Board verification passed
  -> formal board signoff
  -> immutable signoff archive
  -> offline verify
```

## 2. 不做什么

本版必须收住边界：

- 不做第三方 CA 签名。
- 不做区块链或外部公证。
- 不替代 v8.2 Anchor Registry。
- 不替代 v8.3 Anchor Transparency。
- 不自动 approve / revoke / supersede anchor。
- 不自动修改 response / accepted evidence。
- 不自动创建新的 accepted evidence。
- 不自动把 needs_changes / rejected 变成 accepted。
- 不把 board signoff 等同于 human legal contract，只是本地审计签核证据。
- 不允许签核后静默重建 Board export / ZIP / archive。

## 4. 核心设计原则

### 4.1 签核必须绑定当前 Board，而不是绑定“某个 ready 字段”

Board Signoff 必须绑定：

- Board ZIP sha256。
- Board manifest hash。
- Board report integrity hash。
- Board source hash。
- Board verification report hash。
- Board verification zip_sha256。
- Board verification manifest hash。
- quorum requirements。
- quorum participants。
- external Accepted Evidence ZIP hashes。
- external Accepted Evidence verification hashes。
- Distribution Kit ZIP hash。
- Distribution Kit manifest hash。

不能只绑定：

- `board_report.readiness == "ready"`。
- `summary.accepted_count`。
- `board-signoff-draft.json`。

### 4.2 签核后不可变

一旦 Board 正式 signoff：

- policy 不能改。
- report 不能 refresh 覆盖。
- export 不能重建。
- board ZIP 不能重建。
- signoff archive 不能重建成不同内容。
- accepted evidence 变化后，旧 signoff 必须变 stale，而不是被静默刷新。

如果必须修改：

1. 创建 Board Change Request。
2. approve Change Request。
3. reset signoff。
4. refresh/export/zip/verify。
5. 重新 signoff。

### 4.3 离线 verifier 不能只信包内自证

Signoff Archive ZIP 里可以有 report / manifest / sidecar，但 verifier 必须防止：

- 修改 board signoff，然后重算 manifest。
- 修改 board verification summary，然后重算 manifest。
- 替换 board ZIP，却沿用旧 signoff。
- 替换 accepted evidence summary，却沿用旧 quorum。
- 新增 benign extra file 后同步声明。
- 删除 negative response 后伪装 ready。

所以 archive 内必须包含足够的 fingerprint sidecar，并在 verifier 中逐层反查。

### 4.4 外部 source 优先

v8.7 verifier 应支持可选外部输入：

```powershell
--board-zip path\to\public-trust-center-acceptance-board.zip
--board-verification-report path\to\acceptance-board-verification-report.json
--distribution-kit path\to\public-trust-center-distribution-kit.zip
--accepted-evidence-dir path\to\accepted-evidence-zips
```

如果传入外部输入，则必须校验 archive 里的摘要和外部真实文件一致。

如果没有传入外部输入，archive 至少要能做自包含一致性校验，但 README 要写清边界：

> 纯 archive 离线校验只能证明 archive 内证据一致；若要确认 Board ZIP / Accepted Evidence 未被整体替换，应同时传入外部 Board ZIP / Accepted Evidence 或使用上层 Anchor / Distribution Kit。

## 8. ZIP 固定 entry allow-list

Signoff Archive ZIP 建议固定 entry：

```text
board-signoff-archive-manifest.json

board-signoff.json
board-verification-summary.json

distribution-kit-fingerprint-summary.json
change-request-summary.json
chain-of-custody.json

VERIFY.txt
```

不允许：

- 任意额外 `docs/*.txt`。
- nested ZIP。
- `.musicforge/`。
- `.MusicForge/`。
- backslash entry。
- absolute path。
- `..` path。
- duplicate entry。

Verifier 必须检查：

- ZIP actual entries == 固定 allow-list。
- manifest.files == 固定 allow-list minus manifest。
- manifest.zip.entries 只是参考，不得扩展允许列表。
- file hash / size 全部匹配。
- package_type 正确。

## 9. 签核前置条件

`sign()` 必须执行以下 gate：

### 9.1 Board report gate

- Board report exists。
- `readiness == "ready"`。
- `status == "passed"`。
- report integrity OK。
- report source_hash 当前。

### 9.2 Board ZIP gate

- Board export exists。
- Board ZIP exists。
- Board ZIP sha256 匹配 report / manifest / verification。
- Board ZIP verification report exists。
- Board ZIP verification report status == passed。
- verification report hash 当前。

### 9.3 External Accepted Evidence gate

必须通过 v8.6.1 的 external evidence check：

- 每个 quorum participant 有 accepted evidence。
- Accepted Evidence ZIP exists。
- Accepted Evidence verifier passed。
- participant role/organization/result/hash 与 Accepted Evidence public response 匹配。
- role_full_resign 伪造必须失败。

### 9.4 Distribution Kit gate

- Distribution Kit ZIP exists。
- Distribution Kit verifier passed。
- Board source 绑定的 distribution kit 与当前 ZIP 一致。

### 9.5 Policy gate

- policy integrity OK。
- requirements 不能弱于 signoff payload：
  - 如果 payload 要求 min_accepted_count=2，policy 不能是 1。
  - required_roles 必须覆盖 payload 角色。
- signoff payload 可比 policy 更严格，但不能更松。

### 9.6 Existing signoff gate

- 如果已有 signed signoff，重复 sign 必须 409。
- 如果已有 signed signoff，export / zip 不能静默改写。
- reset 前不能覆盖 signoff。

## 10. reset 规则

`reset()` 必须要求：

```json
{
  "change_request_id": "bcr-000001",
  "reason": "Approved board evidence correction."
}
```

必须满足：

- Change Request exists。
- status == approved。
- integrity OK。
- source.current_signoff_integrity_hash == current signoff integrity。
- 未被 applied。

成功 reset 后：

- 当前 signoff status 改为 `reset` 或写入 reset record。
- Change Request status 改为 `applied`。
- 写 history。
- 后续允许 refresh / export / zip / sign。

不允许：

- 无 CR reset。
- draft CR reset。
- rejected CR reset。
- applied CR 重复 reset。
- 篡改 CR reset。
- signoff 已不存在却 reset。

## 11. Archive export 规则

`export_archive()` 必须：

1. 读取当前 signoff。
2. 检查 signoff status == signed。
3. 检查 signoff integrity OK。
4. 检查 signoff source 当前：
   - Board ZIP 当前。
   - Board verification 当前。
   - Distribution Kit 当前。
   - Accepted Evidence 当前。
5. 如果 archive 已存在且 signoff 未变，可以幂等返回。
6. 如果 archive 已存在但内容不匹配，必须重建前做不可变判断。
7. 如果 signoff 后底层证据变更，返回 409 stale，不要导出。

Archive manifest 必须包含：

```json
{
  "schema_version": 1,
  "package_type": "musicforge_public_trust_center_acceptance_board_signoff_archive",
```

## 19. 安全边界

必须覆盖：

### 19.1 ZIP 安全

- duplicate entry。
- backslash raw entry。
- `.musicforge/` 大小写变体。
- nested ZIP。
- absolute path。
- `..`。
- manifest spoof。
- declared extra benign file。
- ZIP bomb。

### 19.2 签核篡改

篡改：

- `signed_by`
- `signed_at`
- `requirements`
- `board.zip_sha256`
- `board_verification.verification_report_hash`
- `accepted_evidence[].role`
- `accepted_evidence[].verification_report_hash`
- `distribution_kit.zip_sha256`

即使重算：

- signoff integrity。
- archive report integrity。
- archive manifest integrity。

也必须 failed，除非外部 source 也一致。

### 19.3 Board ZIP 替换

如果签核后替换 Board ZIP：

- signoff summary stale。
- archive export 409。
- archive verifier 如果传外部 board ZIP，应 failed。

### 19.4 Accepted Evidence 替换

如果签核后替换 accepted evidence ZIP：

- signoff source stale。
- archive export 409。
- verifier with accepted_evidence_dir failed。

### 19.5 Distribution Kit 替换

如果签核后替换 Distribution Kit：

- signoff source stale。
- archive export 409。
- verifier with distribution_kit failed。

### 19.6 删除 export/zip 后重建

签核后：

- 删除 archive 目录再 export，不得绕过不可变保护。
- 删除 ZIP 再 build，不得绕过不可变保护。
- 判断依据必须来自持久 signoff/history，不是只看文件存在。

## 27. Reviewer 验收重点

Reviewer 不只看测试绿，要重点复现：

### 27.1 blocked board 不能签

- role 缺失。
- quorum 不足。
- needs_changes 存在。
- rejected 存在。
- critical finding 存在。

都必须 sign 409。

### 27.2 role full-resign 不能签

复用 v8.6.1 的攻击：

- 原始 role=receiver。
- Board ZIP 内同步伪造成 distribution_partner。
- Board verifier with external accepted evidence failed。
- Board signoff 也必须 409。

### 27.3 签核后不能静默重建

- 删除 archive 目录。
- 删除 archive ZIP。
- 再调用 export / zip。
- 不允许绕过 signed guard。

### 27.4 reset 必须 CR

- 无 CR reset 409。
- draft CR reset 409。
- approved CR reset OK。
- 同一 CR 二次 reset 409。

### 27.5 verifier 防全量重签

篡改以下任一项并同步重签 manifest/report：

- signoff signed_by。
- board zip hash。
- board verification hash。
- accepted evidence role。
- accepted evidence verification hash。
- distribution kit hash。

必须 failed。

## 29. 给开发的话

这版不要急着堆 UI。v8.7 的核心是证据链：Board 已 ready 只是一个计算结果，正式 signoff 必须绑定当前 Board ZIP、Board verifier、Distribution Kit、外部 Accepted Evidence。你实现时优先把 Store 和 verifier 做严，尤其是“签核后不可变”和“全包同步重签失败”这两条。  

开发过程中请先复现 v8.6.1 reviewer 的 role_full_resign 攻击，然后证明 v8.7 signoff 也挡住它。只要 signoff archive verifier 还能靠同一个 ZIP 内的 JSON 自证通过，这版就不算完成。

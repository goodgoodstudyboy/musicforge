# v14.2.9 MusicForge Explicit Any 别名数据流内核重构施工图

## 1. 定位

v14.2.9 是 v14.2.8 的质量门禁热修复，不扩展产品业务。目标不是继续为
单个 AST 节点添加特殊分支，而是将对象身份、成员单元、动态逃逸和污点传播
从 collector 中拆成独立的数据流内核。

公开的 v14.2.8 tag 不移动、不删除。v14.2.9 完成最终 SHA CI、Nightly、
Reviewer Package 和 Release 后，v14.2.8 才可标记为 superseded。

## 2. 已知攻击

以下来源都必须保留 `Holder` 的可能对象身份：

```python
Ref, = (Holder,)
Ref = [Holder][0]
Box.value = Holder; Ref = Box.value
Ref = identity(Holder)
```

之后通过 `Ref[0] = Alias` 写入 Any/uncertain，并从 `Holder` 读回时，100 个
注解必须触发 scope、total、layer、file 四类失败。

## 3. 数据流模型

- `FlowValue` 保存 binding kind、exact identities、escaped 和 origins。
- 对象堆保存静态 attribute/index cell、wildcard cell、origin 和 taint。
- 字面量容器与静态 key 读取精确传播 identity。
- 动态 Call 和无法精确解析的 member read 生成新的 escaped identity，并保留
  参数、receiver、base 的 origins。
- Any/uncertain mutation 沿 identity、origin 和成员可达图传播。
- rebind 分配独立对象并切断旧 alias group。
- branch join 使用 may-alias 并集。
- escaped value 的 mutation 沿可见参数、receiver、base provenance
  fail closed；不可见的跨函数返回语义不在本版手写 AST 的可信范围内。

## 4. 不变量

1. 不使用 `globals()`、动态 default/class base 改写或 generated part module。
2. 不添加 mypy exclude、`ignore-errors` 或全文件 Ruff suppression。
3. Explicit Any 总量、layer、file、affected file ceiling 不得提高。
4. complexity、recovery ceiling 和固定 budget hash 不得改变。
5. active tree scope blocker 必须为零。
6. 运行时真实 Any 攻击必须由 collector 和 ratchet 同时失败。
7. 正常 factory、container 和 rebind 不得污染无关类型。

## 5. 实施顺序

1. 新建 `explicit_any_dataflow.py`，只实现抽象值和对象图。
2. collector 改为消费 FlowValue，不再维护裸 alias identity set。
3. 修复成员写入顺序，先污染左侧来源，再记录右值。
4. 增加数据流内核单测和四条 reviewer 攻击端到端测试。
5. 将数据流内核加入 mypy critical targets，禁止门禁代码逃逸类型检查。
6. schema 升级到 12，新增 ADR-024 和 migration record。
7. 增加 `v1429.explicit_any_alias_dataflow_smoke` 并接入所有 v14 发布 profile。
8. 跑完整 Ruff、mypy、pytest、coverage、release-check 和 reviewer package。

## 6. 验收

- 数据流与 quality ratchet 定向测试通过。
- 四条攻击 runtime 为 Any、100 annotations、Ruff/mypy 通过、collector 100、
  三层预算和 scope flow 均失败。
- `v1429` 执行四条快速攻击探针；同 profile 的 `v141` 负责全活跃树扫描，
  定向 pytest 负责 runtime、Ruff 和 strict mypy 证明。
- active tree 保持 11,993 Explicit Any、461 affected files、0 scope blockers。
- v14/latest/security/GA/full profile 通过。
- 最终提交 SHA 的 Quality 与 Nightly LTS 通过。
- Reviewer ZIP 为 17 个唯一安全 entry，digest 与 sidecar 一致，
  `--require-final` 通过。

## 7. Stop Conditions

- 任一 ceiling 增长。
- 任一攻击未产生 blocker。
- active code 出现 false-positive scope blocker。
- 测试、CI、tag、Release 或 reviewer evidence 未闭环。

## 8. 准确口径

v14.2.9 关闭当前已知的非直接对象别名洗白路径，并建立统一的别名数据流内核。
它不宣称实现完整 Python 解释器。v14.3 继续处理 ARCH-014 与 TYPE-003，且不
允许重新退回逐语法补丁模式。

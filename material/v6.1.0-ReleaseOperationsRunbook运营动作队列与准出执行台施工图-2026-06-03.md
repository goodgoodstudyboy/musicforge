日期：2026-06-03  
基线版本：v6.0.0  
目标版本：v6.1.0  
角色定位：Reviewer / Planner / Release Operations Architect  
项目：MusicForge / song-agent

---

## 1. 背景

v6.0.0 已经把 MusicForge 过去五十多个版本积累的发行链路整合成 Release Operations Dashboard：

- Release / Metadata / Audio / Rights / Format / Distribution / Submission / Submission Evidence / Verifier 状态可以聚合查看。
- Operations Report 能输出 current_stage、next_stage、blockers、warnings、next_actions、evidence_graph、package_summaries。
- Operations Export / ZIP 可以离线验证，证明 Dashboard 自己没有脱敏、hash、ZIP entry、重复 entry 等基础安全问题。

这一步解决的是“看得清”。下一步要解决的是“怎么按正确顺序推进”。

现在的实际使用痛点会变成：

- Dashboard 能告诉开发还有 12 个 blocker，但开发仍然要在多个页面手动找入口。
- 很多动作是安全可重复的，例如 refresh QA、export、build ZIP、verify package，它们不应该要求开发逐个页面点。
- 一些动作是高风险或不可逆的，例如 signoff、reset、record accepted、external submission，它们必须继续保留人工确认。
- release-check 可以跑全链路，但真实项目需要一个“本地 runbook”，把下一步动作排队、执行、记录、失败重试。
- Operations Report 的 next_actions 目前是建议，不是可执行计划。
- 如果 source 在执行过程中变化，必须 stale guard，不能拿旧计划继续跑。

所以 v6.1.0 建议做：

> Release Operations Runbook / Action Queue：把 v6.0 的 next_actions 转换成可审计的本地执行队列，只允许自动执行安全动作，危险动作生成 manual_required 项；每个 action 有 source hash、执行结果、产物摘要、失败重试和离线导出证据。

这不是做“全自动发行机器人”，而是做“本地发行执行台”：让开发可以一键生成 runbook，安全跑完一批 refresh/export/verify，把剩余必须人工确认的动作明确列出来。

## 2. 本版必须先补的 v6.0 缺口

Reviewer 已指出 v6.0.0 有一个测试覆盖缺口：

- `release_operations_verifier.py` 已实现 unsafe ZIP path、反斜杠 raw entry、`manifest.zip.entries` 不能扩权等检查。
- 但 v6.0 release-check smoke 明确断言只覆盖 tamper、duplicate、redaction。

v6.1.0 开工前必须保留并提交这类回归：

- Operations ZIP 中添加 `../evil.txt`，`verify-release-operations-package --strict` 必须 failed，check_id=`zip_entry_path_safe`。
- Operations ZIP central directory 原始 entry 为 `extra\name.txt`，必须 failed，check_id=`zip_entry_path_safe`。
- 往 `operations-manifest.json.zip.entries` 写入 `extra.txt`，并真的往 ZIP 加 `extra.txt`，strict 模式必须 failed，不能因为 `zip.entries` 自报就放行。
- 单元测试和 release-check smoke 都要覆盖。

验收口径：

- `python -m pytest tests\test_release_operations.py tests\test_release_check.py::test_v60_release_operations_dashboard_smoke -q`
- v6.0 smoke detail 里要出现 dangerous/backslash/spoof 均按预期 failed/warning。

## 3. v6.1.0 总目标

新增 Release Operations Runbook。

一句话目标：

> 从 Operations Report 的 blockers / warnings / next_actions 生成一份可执行但受限的 Action Queue，自动执行安全动作，阻断危险动作，记录每一步的输入 hash、输出摘要、错误、重试、跳过原因，并能导出/验证 Runbook Evidence Package。

完成后，用户应能在 Studio 的 Release Operations 面板里：

- 点击 Generate Runbook，从最新 Operations Report 生成动作队列。
- 看到每个 action 的类型、风险等级、依赖、source hash、预计影响、执行方式。
- 一键 Run Safe Actions，只执行允许自动跑的 refresh/export/verify。
- 对 signoff、reset、record accepted、external upload 等动作，只显示 manual_required，不自动执行。
- 对失败项 retry。
- 对不想处理的 warning 标记 waived，并写入原因。
- 重新 refresh Operations Report 后，旧 runbook 如果 source_hash 不一致，要显示 stale，不能继续执行。
- 导出 runbook package，离线证明当时执行过哪些动作、哪些被阻断、哪些需要人工。

## 4. 非目标

v6.1.0 不做以下事情：

- 不接真实 DSP / 发行平台 API。
- 不自动上传任何 ZIP。
- 不自动点击任何外部网页。
- 不自动 signoff Release / Distribution / Submission / Submission Evidence / Operations。
- 不自动 reset 已签核对象。
- 不自动 record-submission / record-feedback / accepted。
- 不自动创建或修改音频、歌词、metadata 内容。
- 不做多人协作、权限流、云同步。
- 不把 GitHub token、provider key、平台后台 URL、cookie、浏览器缓存写入 runbook。

本版只做本地、安全、可重复的运营动作编排。

## 5. 动作分级

必须把 Operations next_actions 显式分成三类。

### 5.1 Auto Safe

允许由 runbook 自动执行，前提是 source_hash 当前、依赖满足：

- `release.qa.refresh`
- `metadata.qa.refresh`
- `metadata.export`
- `release.export`
- `release.zip`
- `release.verify`
- `distribution.qa.refresh`
- `distribution.export`
- `distribution.zip`
- `distribution.verify`
- `submission.qa.refresh`
- `submission.export`
- `submission.zip`
- `submission.verify`
- `submission_evidence.report.refresh`
- `submission_evidence.export`
- `submission_evidence.zip`
- `submission_evidence.verify`
- `operations.refresh`
- `operations.export`
- `operations.zip`
- `operations.verify`

要求：

- 这些动作必须是幂等或可重复覆盖。
- 如果目标已签核且对应模块禁止重导出，runbook 要把 action 标为 blocked_signed，不绕过。
- 执行后必须记录 before_summary、after_summary、status、artifact hash。

### 5.2 Provider Safe 但默认关闭

v6.1.0 暂不执行 provider action。如果未来某些 provider verify / judge 动作需要纳入，必须：

- item 标记 `provider_safe=true`。
- run 请求显式 `include_provider=true`。
- provider usage 必须记录。

本版建议先只保留 schema 字段，不接执行。

### 5.3 Manual Required

只能生成待办，不能自动执行：

- 所有 signoff。
- 所有 reset。
- `submission.record_receipt`
- `submission.record_feedback`
- `submission.mark_accepted`
- 外部 upload。
- 权利清算人工确认。
- 人工听审。
- manual review。
- 任何可能改变业务事实的 action。

这些 item 的状态应是 `manual_required`，并给出：

- 原模块入口 URL/API hint。
- 为什么不能自动执行。
- 需要人工提供什么证据。

## 7. Store/API 设计

### 7.1 Store

新增 `ReleaseOperationsRunbookStore`。

核心方法：

- `create_from_operations_report(release_id, options) -> runbook`
- `list_runbooks(release_id, include_archived=False)`
- `get_runbook(release_id, runbook_id)`
- `run_safe_actions(release_id, runbook_id, options) -> runbook`
- `retry_item(release_id, runbook_id, item_id)`
- `waive_item(release_id, runbook_id, item_id, reason)`
- `archive_runbook(release_id, runbook_id)`
- `refresh_stale_status(release_id, runbook_id)`
- `export_runbook(release_id, runbook_id)`
- `build_zip(release_id, runbook_id)`
- `verify_runbook_zip(path)`

并发要求：

- Store 使用 `RLock`。
- runbook id 分配在 lock 内完成。
- 创建目录用原子 `mkdir(exist_ok=False)`。
- 写 JSON 用现有原子写。
- 异常清理只清理当前未完成占位目录。

### 7.2 API

新增 API：

```text
GET  /api/releases/<id>/operations/runbooks
POST /api/releases/<id>/operations/runbooks
GET  /api/releases/<id>/operations/runbooks/<runbook-id>
POST /api/releases/<id>/operations/runbooks/<runbook-id>/run-safe
POST /api/releases/<id>/operations/runbooks/<runbook-id>/items/<item-id>/retry
POST /api/releases/<id>/operations/runbooks/<runbook-id>/items/<item-id>/waive
POST /api/releases/<id>/operations/runbooks/<runbook-id>/archive
POST /api/releases/<id>/operations/runbooks/<runbook-id>/refresh-stale
POST /api/releases/<id>/operations/runbooks/<runbook-id>/export
POST /api/releases/<id>/operations/runbooks/<runbook-id>/export/zip
POST /api/releases/<id>/operations/runbooks/<runbook-id>/verify
GET  /api/releases/<id>/operations/runbooks/<runbook-id>/export.zip
```

HTTP 口径：

- 创建成功：201。
- run-safe 已启动/完成：200。v6.1 可先同步执行，后续如变慢再异步化。
- stale：409。
- signed mutation blocked：409。
- manual_required action retry：409 或返回 manual_required，不执行。
- unknown action：400。
- unsafe path：409/500 不能吞掉，返回清晰 error。

## 9. Stale Guard

Runbook 必须绑定生成时的 Operations Report：

- `operations_report_id`
- `operations_source_hash`
- `operations_integrity_hash`
- `current_stage`
- `next_stage`

每次执行前：

1. 读取最新 Operations overview 或 refresh。
2. 比较最新 source_hash。
3. 如果不一致，runbook.status=`stale`，所有 pending item 标记 stale。
4. 返回 409，要求重新生成 runbook。

例外：

- `refresh_stale_status` 可以只读判断。
- `archive` 可以执行。
- `export` 旧 runbook 可以导出，但 manifest 必须标 `stale=true`，verify 不能在 `--require-current` 下通过。

## 10. Waiver 设计

某些 warning 可以被业务暂时接受，但 blocker 不建议 waiver。

v6.1 支持：

- warning item waiver。
- manual_required item 可标记 acknowledged，但不能当 completed。

不支持：

- blocking item waiver 后直接 release-ready。
- 通过 waiver 跳过签核。
- 通过 waiver 跳过 accepted evidence。

Waiver 字段：

```json
{
  "waived_by": "local",
  "waived_at": "...",
  "reason": "Known warning accepted for internal archive.",
  "expires_at": null
}
```

Reason 必填，至少 8 个字符，并做脱敏。

## 11. Export / ZIP / Verifier

新增：

```text
song_agent/release_operations_runbook_verifier.py
python -m song_agent.cli verify-release-operations-runbook-package <zip>
```

Runbook Export 内容：

```text
runbook-manifest.json
runbook.json
execution-report.json
operations-report-before.json
operations-report-after.json
README.txt
```

Verifier 必须检查：

- ZIP entry path safe，包括 raw central directory 反斜杠。
- duplicate entry failed。
- manifest.files hash/size match。
- `manifest.zip.entries` 不能扩权。
- runbook integrity hash。
- execution-report integrity hash。
- before/after operations report integrity hash。
- stale 标记与 source hash 一致。
- redaction scan。
- no blocked keys：token、api_key、authorization、cookie、source_path、local_path、raw_provider_response。
- `--require-completed` 时，runbook.status 必须 completed 或 blocked 且没有 failed auto_safe item。
- `--require-current` 时，manifest.stale 必须 false。

注意：

- Verifier 只读 ZIP，不依赖 `.musicforge/`。
- 不解压到磁盘。
- 有 max ZIP size、max uncompressed size、max entry count。

## 18. Reviewer 验收重点

Reviewer 应重点看：

- Runbook 是否会自动执行 signoff 或 accepted。若会，P1。
- source_hash stale 是否能挡住旧 runbook。若不能，P1。
- signed object 是否能被 runbook 静默重导出。若能，P1。
- `manifest.zip.entries` 是否能扩权。若能，P1。
- manual_required 是否被算作 completed。若是，P1。
- verifier 是否依赖当前 workspace。若依赖，P1。
- 是否有本机路径/token/provider raw response 泄露。若有，P1。
- run-safe 是否能部分成功后留下清晰状态，失败可重试。否则 P2。
- Studio 是否把危险动作和安全动作区分清楚。否则 P2。

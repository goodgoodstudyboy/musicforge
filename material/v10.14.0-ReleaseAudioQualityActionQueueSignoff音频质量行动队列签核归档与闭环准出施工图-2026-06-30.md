# v10.14.0 Release Audio Quality Action Queue Signoff 音频质量行动队列签核归档与闭环准出施工图

## 1. 版本定位

v10.13.1 已经把 Release Audio Quality Observatory 的风险和建议转成了 Audio Quality Action Queue，并修复了两个关键口径：

- queue 创建时会持久化 `include_risks` / `include_recommendations` / `severity_floor`。
- verifier 会用同一 selection policy 从外部 Observatory 重建 expected items。
- `manual_required_count` 已改成按唯一 `item_id` 计数，不再把 result 和 manual action 双算。

但 v10.13.1 仍然停在“行动队列已运行并可验证”。它还没有回答这些业务问题：

- 人工动作是否已经被业务确认？
- manual_required 的项是被完成、被豁免，还是被明确拒绝？
- 队列什么时候算正式 closeout？
- 谁签核这份治理结果？
- 签核后还能不能重新 export / zip / run-safe 静默改写？
- Release signoff / GA readiness 是否能要求“队列已正式签核归档”，而不是只要求 queue ZIP 通过 verifier？

v10.14.0 的目标是补上这条闭环：**Release Audio Quality Action Queue Closeout / Signoff / Immutable Archive**。

一句话：v10.13 是“把 Observatory 风险转成治理队列”，v10.14 是“把治理队列处置完成、签核、归档，并作为 Release / GA 的硬证据”。

## 3. 为什么 v10.14 必须做签核归档

现在 Action Queue 已经可以：

- 从 Observatory risks / recommendations 生成 items。
- 运行 safe actions。
- 把 signoff / reset / music change / provider / baseline switch 这类动作标成 manual_required 或 blocked。
- 导出固定结构 ZIP。
- 用外部 Observatory ZIP / verification report / evidence root 重新验证。
- 作为 Release signoff / GA readiness 的可选 gate。

但当前 gate 的语义仍偏弱：

- Queue verifier 只能证明“队列内容和执行结果可信”。
- 它不能证明“所有 manual_required 都被人工处理过”。
- 它不能证明“业务负责人同意这些 waiver / manual completion”。
- 它不能防止签核后删除 ZIP 或改 report 再重建。
- 它也不能保留一份不可变的 closeout 决策历史。

对一个接近 GA/LTS 的系统来说，质量治理链不能只到 action queue。最终必须形成：

```text
Observatory -> Action Queue -> Manual Resolution -> Closeout -> Signoff -> Archive -> Release/GA Gate
```

v10.14 就是把后半段补齐。

## 4. 非目标

v10.14 不做这些事：

- 不自动完成 manual_required。
- 不自动签核 Release。
- 不自动 reset Release / GA / Observatory。
- 不自动 apply Audio Fix Sprint candidate。
- 不自动修改音乐、MIDI、WAV、stem、mastering。
- 不调用 provider。
- 不把 manual waiver 当作问题已修复，只能作为签核证据之一。
- 不做多用户权限系统；仍然采用本地审计字段 `signed_by` / `role` / `reason`。
- 不引入数据库；继续用 `.musicforge/` 文件存储。
- 不做云端发布或远端登记。

## 5. 新增能力总览

v10.14.0 要新增：

- Action Queue manual resolution：
  - 标记 manual item 为 `completed` / `waived` / `rejected` / `deferred`。
  - 每条 resolution 必须绑定原始 `item_id`、resolver、reason、timestamp、payload hash。
- Action Queue closeout：
  - 汇总 completed / waived / rejected / deferred / blocked / failed / pending。
  - critical / blocking item 未处理时 closeout failed。
  - rejected / unresolved critical 不能 force close。
- Action Queue signoff：
  - 对 passed closeout 做签核。
  - 签核写 hash-chain history。
  - 签核后 run-safe / refresh / export / zip / manual resolve 都必须阻断。
- Action Queue archive：
  - 固定结构归档包。
  - 离线 verifier。
  - verifier 绑定 queue ZIP、queue verification report、closeout、signoff、history。
- Release signoff / GA gate：
  - 新增 `require_release_audio_quality_action_queue_signoff=true`。
  - 不能只拿旧 queue ZIP 过关，必须提供 archive ZIP + verification report。
- Studio / CLI / API：
  - 能看到 manual items。
  - 能填写 resolution。
  - 能 closeout / signoff / export archive / verify archive。
- release-check：
  - 新增 `v1014.release_audio_quality_action_queue_signoff_smoke`。

### 7.1 manual-resolutions.json

```json
{
  "schema_version": 1,
  "package_type": "release_audio_quality_action_queue_manual_resolutions",
  "queue_id": "aqa-000001",
  "source_hash": "queue-source-hash",
  "queue_integrity_hash": "action-queue.json integrity_hash",
  "items_hash": "action-items.json integrity_hash",
  "manual_actions_hash": "manual-actions.json integrity_hash",
  "resolutions": [
    {
      "resolution_id": "aqres-000001",
      "item_id": "aqa-item-000003",
      "manual_action_id": "aqman-000001",
      "status": "completed",
      "resolution_type": "manual_completed",
      "resolved_by": "Audio Lead",
      "role": "audio_lead",
      "reason": "Reviewed remediation and confirmed follow-up exists.",
      "evidence": {
        "evidence_type": "external_reference",
        "reference_id": "manual-note-2026-06-30"
      },
      "created_at": "2026-06-30T10:00:00Z",
      "payload_hash": "..."
    }
  ],
  "summary": {
    "manual_required_count": 3,
    "resolved_count": 2,
    "waived_count": 1,
    "rejected_count": 0,
    "deferred_count": 0,
    "unresolved_count": 0
  },
  "integrity_hash": "..."
}
```

允许状态：

- `completed`：人工动作已完成，有证据。
- `waived`：明确豁免，必须写 `reason`，不能用于 critical/blocking 的实质修复类问题，除非 closeout 显式允许。
- `rejected`：人工拒绝处理，closeout 应 failed。
- `deferred`：延期处理，release-ready gate 应 failed，除非是非 blocking 且 closeout policy 允许。

必须脱敏字段：

- `resolved_by`
- `role`
- `reason`
- `evidence`

所有自由文本都走现有 `sanitize_sensitive_text()` / redaction 体系，防止 `sk-...`、本机路径、Bearer token、GitHub token、UNC 路径进入包。

Closeout gate 规则：

- queue ZIP verifier 必须 passed。
- queue source 不能 stale。
- queue status 不能 pending。
- `blocked_count > 0` -> failed。
- `failed_count > 0` -> failed。
- `critical_unhandled_count > 0` -> failed。
- manual_required item 缺 resolution -> failed。
- resolution status 为 rejected -> failed。
- critical/blocking item 被 waived -> failed，除非明确 `allow_critical_waiver=true`，但 v10.14 建议先不支持。
- deferred item 默认 failed。

## 8. Store 设计

建议新增：

```python
class ReleaseAudioQualityActionQueueSignoffStore:
    def __init__(self, action_queue_store: ReleaseAudioQualityActionQueueStore): ...

    def list_manual_items(queue_id: str) -> dict: ...
    def resolve_manual_item(queue_id: str, item_id: str, payload: dict) -> dict: ...
    def refresh_closeout(queue_id: str, *, allow_noncritical_waiver: bool = False) -> dict: ...
    def signoff(queue_id: str, *, signed_by: str, role: str, reason: str) -> dict: ...
    def export_archive(queue_id: str) -> dict: ...
    def build_archive_zip(queue_id: str) -> dict: ...
    def verify_archive(queue_id: str, **kwargs) -> dict: ...
    def gate(queue_id: str | None, *, required: bool) -> dict: ...
```

### 8.1 只读和不可变保护

签核后以下操作必须 409：

- `run_safe(queue_id)`
- `refresh_status(queue_id)`
- `resolve_manual_item(queue_id, ...)`
- `refresh_closeout(queue_id)`
- `export_package(queue_id)`
- `build_zip(queue_id)`
- `export_archive(queue_id)` 如果 archive 已存在且 signoff 已存在。
- `build_archive_zip(queue_id)` 如果 zip 已存在且 signoff 已存在。

但是要允许：

- `read_queue`
- `read_summary`
- `verify_zip`
- `verify_archive`
- `download archive zip`

如果 v10.13 的 `ReleaseAudioQualityActionQueueStore` 当前不知道 signoff 状态，v10.14 要加一个 lightweight guard hook：

```python
signed_guard: Callable[[str], bool] | None
```

或者在 action queue store 初始化时可选注入 signoff store。不要循环 import。

### 8.2 删除文件绕过防护

不能只看 `action-queue-signoff.json` 是否存在。

必须优先读取 `action-queue-signoff-history.jsonl`：

- 如果 history 中最新有效事件是 `action_queue_signoff_created`，则视为 signed。
- 即使 signoff JSON 被删，也要阻断可变写操作。
- verifier 要报告 `signoff_file_missing` failed。

v10.14 暂不设计 reset。后续如果要 reset，必须单独做 approved Change Request reset，不要在本版混进来。

## 9. Offline Verifier

新增：

```text
song_agent/release_audio_quality_action_signoff_verifier.py
```

CLI：

```powershell
python -m song_agent.cli verify-release-audio-quality-action-queue-signoff-archive-package <zip> --strict
```

参数建议：

```text
--strict
--require-current-queue
--queue-zip <path>
--queue-verification-report <path>
--observatory-zip <path>
--observatory-verification-report <path>
--evidence-root <path>
--require-no-unresolved-manual
--require-no-critical-waiver
--json
--report-out <path>
```

Verifier 必须检查：

### 9.1 ZIP 结构

- ZIP exists。
- ZIP size <= max。
- entry count <= max。
- total uncompressed <= max。
- no duplicate entry。
- all entries safe POSIX relative paths。
- no backslash raw entry。
- no `.musicforge/` case-insensitive path。
- no nested ZIP。
- entries exactly equal fixed allow-list。
- manifest.files exactly equal fixed allow-list。

### 9.2 Hash / integrity

- 每个 JSON `integrity_hash` OK。
- manifest binds all files。
- manifest package_type 正确。
- closeout binds queue docs。
- signoff binds closeout。
- history chain valid。
- latest history event binds current signoff。
- README 不参与 gate，但也要进 manifest hash。

### 9.3 外部 queue 绑定

如果 `--require-current-queue`：

- 必须传 queue ZIP 和 queue verification report。
- queue verification report package_type 正确。
- queue verification report integrity OK。
- queue verification report status passed。
- queue ZIP sha/size/manifest hash 与 report 匹配。
- 运行 v10.13 `verify_release_audio_quality_action_queue_package` 并要求 passed。
- archive 内 `queue-verification-report.json` 必须与外部 report 一致或明确绑定同一 fingerprint。

### 9.4 外部 Observatory 绑定

如果 queue verifier 需要 current Observatory：

- 必须传 Observatory ZIP、Observatory verification report、evidence root。
- 继续沿用 v10.13 的 external Observatory checks。
- v10.14 archive verifier 不要只信 archive 内部 queue report。

### 9.5 Manual resolution 语义

- 每个 manual action item 必须最多一个 active resolution。
- resolution.item_id 必须存在于 action-items。
- resolution.manual_action_id 必须存在于 manual-actions。
- manual_required item 缺 resolution -> failed。
- rejected -> failed。
- deferred -> failed。
- critical/blocking waived -> failed。
- completed / waived 必须有 non-empty reason。
- resolver / reason / evidence 必须已脱敏。

### 9.6 Closeout / signoff 语义

- closeout status must be passed。
- signoff status must be signed。
- signoff source.closeout_hash == closeout.integrity_hash。
- signoff source.queue_verification_report_hash matches queue-verification-report.json。
- signoff payload_hash valid。
- signoff integrity_hash valid。
- history latest event payload binds signed_by / role / reason / signoff_hash / closeout_hash。

```json
{
  "require_release_audio_quality_action_queue_signoff": true,
  "release_audio_quality_action_queue_id": "aqa-000001"
}
```

Gate 行为：

- required=false：最多 warning summary。
- required=true：
  - queue 必须存在。
  - queue archive ZIP 必须存在。
  - archive verification report 必须 passed。
  - archive verifier 必须能绑定当前 queue ZIP + queue verification report。
  - queue verifier 必须能绑定当前 Observatory ZIP + Observatory verification report + evidence root。
  - closeout status passed。
  - signoff status signed。
  - history chain valid。
  - source stale -> failed。
  - signoff / closeout / archive tamper -> failed。
  - force=true 也不能绕过 stale / integrity failed / missing signoff。

Release signoff evidence 中写入：

```json
"release_audio_quality_action_queue_signoff": {
  "queue_id": "aqa-000001",
  "status": "passed",
  "archive_status": "passed",
  "closeout_hash": "...",
  "signoff_hash": "...",
  "archive_manifest_hash": "...",
  "archive_zip_sha256": "..."
}
```

## 24. Reviewer 验收重点

Reviewer 不只看测试通过，还要重点复现：

1. manual item unresolved 时 closeout failed。
2. rejected manual item 时 closeout failed。
3. completed manual item 后 closeout passed。
4. signed 后 run-safe / resolve / closeout / export queue / zip queue 都 409。
5. 删除 signoff JSON 不能绕过 signed guard。
6. 篡改 signoff signed_by 并重算 signoff integrity，但不改 history，archive verifier failed。
7. 篡改 closeout summary 并重算 closeout integrity，但不改 signoff source，archive verifier failed。
8. 篡改 manual resolution reason 注入本机路径，redaction failed。
9. archive ZIP 增加额外 txt 并同步重签 manifest，verifier failed。
10. 使用旧 queue verification report，Release/GA gate failed。
11. 使用旧 Observatory ZIP / stale evidence root，Release/GA gate failed。
12. critical item 被 waived，closeout failed。
13. noncritical waiver 可以 warning 通过，前提是 v10.14 明确允许；否则一律 failed。

## 25. 给开发的话

这版不要做成“多一个按钮”。v10.13 已经能生成队列，v10.14 的价值是把队列变成真正能进 Release / GA 准出的签核证据。

请优先保证三件事：

1. **签核不可变**：签了之后，删除文件也不能绕过，必须看 history chain。
2. **外部反查**：archive verifier 不能只信 archive 内部 JSON，必须绑定当前 queue ZIP、queue verification report、Observatory ZIP、Observatory verification report 和 evidence root。
3. **人工动作闭环**：manual_required 不能被 summary 糊弄过去，每一个 item 都要有明确 completed / waived / rejected / deferred 的处置记录。

如果实现中发现某个动作会改变音乐、改变 baseline、reset signoff、调用 provider，直接标成 manual_required 或 blocked；v10.14 不做自动业务变更。

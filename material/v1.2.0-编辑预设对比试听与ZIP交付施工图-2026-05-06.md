# MusicForge v1.2.0 施工图：编辑预设、版本对比试听与 ZIP 交付

> 基准版本：v1.1.1  
> 规划日期：2026-05-06  
> 目标定位：在 v1.1.x 已具备“局部编辑生成项目版本”的基础上，把编辑工作流做成可复用、可对比、可交付的闭环。

---

## 1. 背景

MusicForge 当前已经完成了从单次生成到项目化创作的主链路：

- v0.x：本地生成、Provider、Studio 面板、批量、音频渲染、鉴权、质量层、分轨。
- v1.0.x：Project、版本、Quality Gate、Final Export，并修过 stem 越界和覆盖完整性问题。
- v1.1.x：Project Edit，支持基于任意项目版本做非破坏式局部编辑，新增 edit metadata、diff 增强和 Studio 编辑入口。

现在的短板不是“还能不能生成新版本”，而是：

1. 编辑动作还偏一次性，用户每次都要重新填写意图，不能沉淀成常用预设。
2. 版本越来越多后，Studio 缺少真正面向创作判断的 A/B 对比视图。
3. Final Export 已经能生成目录包，但对普通交付来说还缺一个 ZIP 包。
4. Project 多起来后，列表缺少搜索、筛选和快速定位能力。

所以 v1.2.0 不建议继续扩张底层 agent，而应该收紧到“创作工作台体验”：

> 让用户能把常用编辑保存成预设，用预设快速派生版本，在 Studio 里比较两个版本，选择满意版本，并一键打成 ZIP 交付包。

---

## 2. v1.2.0 总目标

v1.2.0 的目标是补齐 Project Edit 后的实际使用闭环：

1. **Edit Preset Library**：编辑预设库，支持内置预设和用户自定义预设。
2. **Project Compare / A-B Review**：项目版本对比视图，支持查看质量、结构、轨道、edit metadata 和音频试听。
3. **Final Export ZIP**：在现有 Final Export 目录包基础上生成安全 ZIP。
4. **Project Search / Filter**：Studio 项目列表支持搜索与筛选。
5. **Release Check 增强**：把 preset、compare、zip 纳入本地发布前自动核验。

不把 v1.2.0 做成 provider-backed edit 的大版本。Provider 智能编辑可以预留结构和文档，但不作为 v1.2.0 必交付主线。

---

## 3. 非目标

v1.2.0 暂不做这些内容，避免版本发散：

- 不做真正的 DAW 时间轴编辑器。
- 不做波形级剪辑、混音、母带。
- 不做多版本同步播放引擎；v1.2.0 只做简单 A/B 试听和信息对比。
- 不做 provider-backed edit 的完整闭环；最多保留 prompt/schema 的兼容余地。
- 不做用户账号系统，继续沿用本地 Studio + access token 模型。
- 不做云端存储、协作评论和多人权限。

---

## 4. 版本主线

### 推荐发布节奏

v1.2.0 可以拆成 5 个开发包，每个包完成后都要本地验证、提交、推送 GitHub。不要等全部写完再一次性提交。

| 包 | 主题 | 预计提交类型 | 是否可单独验收 |
| --- | --- | --- | --- |
| Package A | Edit Preset 数据层和 API | feat | 是 |
| Package B | Studio Preset 入口和 Project Edit 接入 | feat | 是 |
| Package C | Project Compare API 和 Studio A/B 视图 | feat | 是 |
| Package D | Final Export ZIP | feat | 是 |
| Package E | Project 搜索筛选、release-check、文档发布 | feat/docs/chore | 是 |


如果 `release-check` 因某个开发包尚未覆盖新功能而暂时不适合跑，可以至少跑相关测试和完整 pytest，但最终发布前必须恢复完整 release-check。

## 5. Package A：Edit Preset 数据层和 API

### 5.1 目标

建立本地编辑预设库。预设用于保存常用的 edit intent 参数，后续在 Studio 里可以快速套用到某个 Project version。

预设分两类：

- **built-in presets**：代码内置，随版本发布，不能删除，只能查看和复制。
- **user presets**：用户自定义，写入 `.musicforge/edit-presets.json`，可新增、更新、删除。

### 5.2 推荐文件

新增：

- `song_agent/edit_presets.py`
- `tests/test_edit_presets.py`

可能修改：

- `song_agent/server.py`
- `song_agent/webui.py`
- `README.md`
- `CHANGELOG.md`

### 5.3 数据结构

建议定义：

```python
@dataclass
class EditPreset:
    preset_id: str
    name: str
    description: str
    edit_type: str
    strength: float = 0.5
    target_defaults: dict[str, Any] = field(default_factory=dict)
    payload: dict[str, Any] = field(default_factory=dict)
    preserve: list[str] = field(default_factory=list)
    tags: list[str] = field(default_factory=list)
    built_in: bool = False
    created_at: str | None = None
    updated_at: str | None = None
```

JSON 示例：

```json
{
  "schema_version": 1,
  "presets": [
    {
      "preset_id": "lift-final-chorus",
      "name": "Lift final chorus",
      "description": "Raise the last chorus energy without changing lyrics.",
      "edit_type": "section_energy",
      "strength": 0.7,
      "target_defaults": {"section_role": "chorus", "section_index": -1},
      "payload": {"energy": 0.9},
      "preserve": ["lyrics", "harmony"],
      "tags": ["chorus", "energy"],
      "built_in": false,
      "created_at": "2026-05-06T00:00:00Z",
      "updated_at": "2026-05-06T00:00:00Z"
    }
  ]
}
```

### 5.4 内置预设建议

至少提供这些 built-in presets：

| preset_id | edit_type | 用途 |
| --- | --- | --- |
| `lift-final-chorus` | `section_energy` | 最后一段副歌增强 |
| `soften-first-verse` | `section_energy` | 第一段主歌降低能量 |
| `denser-chorus-drums` | `track_density` | 副歌鼓组更密 |
| `simpler-verse-bass` | `track_density` | 主歌 bass 更克制 |
| `brighter-chorus-harmony` | `section_harmony` | 副歌换成更明亮和弦 |
| `melody-small-variation` | `melody_variation` | 轻微旋律变体 |
| `rewrite-chorus-hook` | `lyrics_rewrite` | 改副歌 hook 文案 |

内置预设里的 `section_harmony` 必须只使用 v1.1.1 白名单支持的和弦：

- `Am7`
- `Cmaj7`
- `Dm7`
- `E7`
- `Fmaj7`
- `G7`

### 5.5 API

新增 API：

```text
GET  /api/edit-presets
POST /api/edit-presets
GET  /api/edit-presets/<preset-id>
POST /api/edit-presets/<preset-id>
POST /api/edit-presets/<preset-id>/delete
POST /api/edit-presets/reset
```

返回建议：

```json
{
  "schema_version": 1,
  "presets": [],
  "built_in_count": 7,
  "user_count": 0
}
```

写入规则：

- `preset_id` 必须是稳定 slug：小写字母、数字、`-`、`_`。
- user preset 不允许覆盖 built-in preset。
- built-in preset 不允许删除。
- API 返回时不包含任何本地敏感路径。
- `.musicforge/edit-presets.json` 必须进 `.gitignore`，不能提交用户本地预设。

### 5.6 校验规则

保存预设时至少校验：

- `edit_type` 在 `EDIT_TYPES` 中。
- `strength` 在合理范围内，例如 `0.0 <= strength <= 1.0`。
- `preserve` 只允许 v1.1.x 支持的 preserve 字段。
- `section_harmony.payload.chords` 必须通过现有和弦白名单。
- 字符串字段要限制长度，避免 Studio 展示溢出。
- `payload` 不能包含路径字段，例如 `path`、`file`、`absolute_path` 这类可疑字段。

### 5.7 测试

新增测试覆盖：

- 默认 built-in presets 能加载。
- user preset 能保存、更新、删除。
- built-in preset 不能删除。
- 非法 preset_id 被拒绝。
- 非法 edit_type 被拒绝。
- 非法 harmony chord 被拒绝。
- `.musicforge/edit-presets.json` 写入是原子替换，避免 Studio 轮询读到半文件。

## 6. Package B：Studio Preset 入口和 Project Edit 接入

### 6.1 目标

让用户在 Studio 的 Project Edit tab 中选择一个预设，自动填充编辑类型、强度、保留项和 payload，减少重复操作。

### 6.2 Studio 改动

Project Edit tab 增加：

- Preset 下拉框。
- Preset 详情预览。
- Apply Preset 按钮。
- Save Current As Preset 按钮。
- Manage Presets 简单面板。

不要做复杂弹窗系统。可以先用当前 webui 的原生布局做一块设置区。

### 6.3 行为规则

选择 preset 后：

1. 自动填充 `edit_type`。
2. 自动填充 `strength`。
3. 自动填充 `preserve`。
4. 自动填充 `payload`。
5. 如果 preset 有 `target_defaults`，尝试匹配当前版本的 edit-targets。
6. 如果 target 不存在，显示 pending/invalid 提示，不自动提交。

保存当前编辑为 preset 时：

- 只保存通用参数，不保存具体 project_id、version_id、job_id。
- 可以保存 section_role 或 track_role 这类相对目标。
- 不要保存本地文件路径。

### 6.4 API 接入

Project Edit 创建接口可以增加可选字段：

```json
{
  "preset_id": "lift-final-chorus",
  "intent": {}
}
```

推荐策略：

- 后端以 `intent` 为最终来源。
- 如果传了 `preset_id`，后端读取 preset 并与 intent merge。
- 显式 intent 字段优先级高于 preset 默认值。
- edit metadata 中记录 `preset_id` 和 `preset_name`，方便之后 diff / compare 展示。

### 6.5 Edit Metadata 扩展

`data/edit-metadata.json` 建议新增：

```json
{
  "preset": {
    "preset_id": "lift-final-chorus",
    "name": "Lift final chorus",
    "built_in": true
  }
}
```

如果没有使用 preset，则 `preset` 可以为 `null`。

### 6.6 测试

新增测试覆盖：

- Project edit API 使用 preset 成功生成 edit job。
- intent 显式字段能覆盖 preset 默认值。
- edit metadata 正确记录 preset。
- 不存在 preset 返回 404 或 400。
- built-in preset 在 Studio HTML 中可见。
- 保存 user preset 的 API 可被 Studio 调用。

## 7. Package C：Project Compare / A-B Review

### 7.1 目标

Project 版本越来越多后，用户需要判断哪个版本更好。v1.2.0 增加版本对比 API 和 Studio Compare tab。

这个能力不是代码 diff，而是创作决策视图：

- 哪个质量分更高？
- 哪个版本通过 Quality Gate？
- 哪些 section 被改了？
- 哪些 track note 数、density、instrument 变化了？
- 使用了什么 edit preset？
- 两个版本的 MIDI / WAV 是否可以下载或试听？

### 7.2 推荐文件

新增：

- `song_agent/project_compare.py`
- `tests/test_project_compare.py`

修改：

- `song_agent/projects.py`
- `song_agent/server.py`
- `song_agent/webui.py`
- `tests/test_server_projects.py`

### 7.3 API

新增：

```text
GET /api/projects/<project-id>/compare?left=<version-id>&right=<version-id>
```

返回示例：

```json
{
  "project_id": "project-demo",
  "left": {
    "version_id": "v001",
    "name": "Original",
    "job_id": "job-a",
    "quality": {"overall": 87},
    "gate": {"status": "passed"},
    "audio_available": true,
    "midi_available": true,
    "edit": null
  },
  "right": {
    "version_id": "v002",
    "name": "Final chorus lift",
    "job_id": "job-b",
    "quality": {"overall": 91},
    "gate": {"status": "passed"},
    "audio_available": true,
    "midi_available": true,
    "edit": {
      "edit_type": "section_energy",
      "preset_id": "lift-final-chorus"
    }
  },
  "summary": {
    "quality_delta": 4,
    "section_changes": 1,
    "track_changes": 2,
    "recommendation": "right"
  },
  "sections": [],
  "tracks": [],
  "artifacts": {}
}
```

### 7.4 对比维度

至少支持这些维度：

| 维度 | 内容 |
| --- | --- |
| Version | version_id、name、parent_version_id、variant_type |
| Quality | overall、dimension scores、warnings |
| Gate | passed / failed / forced |
| Edit | edit_type、instruction、preset、target、preserve |
| Sections | role、bars、energy、tension、chords、lyrics 摘要 |
| Tracks | track_id、role、instrument、note_count、density |
| Artifacts | MIDI、WAV、stems、final export 状态 |

### 7.5 Recommendation 规则

可以先做简单 deterministic 推荐：

- 如果只有一边通过 Quality Gate，推荐通过的一边。
- 如果两边都通过，推荐 quality overall 更高的一边。
- 如果 quality 差距小于 2 分，返回 `tie`。
- 如果质量数据缺失，返回 `unknown`。

不要让推荐影响 final 选择，它只是辅助信息。

### 7.6 Studio Compare Tab

Project 工作区新增 Compare tab：

- 左版本选择器。
- 右版本选择器。
- 两侧基础信息卡片。
- quality/gate 差异区。
- section/track diff 表格。
- edit metadata 摘要。
- MIDI 下载按钮。
- WAV audio controls，如果 WAV 存在。
- Mark Selected / Set Final 的快捷入口可复用现有 API。

注意：

- 不做同步播放，不做复杂波形。
- 如果 WAV 不存在，显示 Render Audio 的提示或链接到 job。
- 不要让 audio player 布局挤压表格，移动端要自然换行。

### 7.7 测试

新增测试覆盖：

- compare 两个普通版本。
- compare 原始版本和 edit 版本。
- compare 不存在版本返回 404。
- quality 缺失时不崩溃。
- recommendation 规则。
- Studio HTML 包含 Compare tab 和必要 JS 函数。
- auth 开启时 compare API 受保护。

## 8. Package D：Final Export ZIP

### 8.1 目标

当前 Final Export 是目录包，适合本机检查，但不适合发给别人。v1.2.0 增加 ZIP 导出。

核心原则：

> ZIP 只能打包现有 final-export 目录内的安全文件，不能读取 manifest 里的任意路径，也不能包含绝对路径、上级路径或 `.musicforge` 敏感配置。

### 8.2 推荐文件

修改：

- `song_agent/final_export.py`
- `song_agent/server.py`
- `song_agent/webui.py`
- `tests/test_final_export.py`
- `song_agent/release_checks.py`

### 8.3 API

新增：

```text
POST /api/projects/<project-id>/final-export/zip
GET  /api/projects/<project-id>/final-export.zip
```

POST 行为：

1. 如果 final-export 目录不存在，返回 409，提示先生成 Final Export。
2. 如果目录存在，生成 `.musicforge/projects/<project-id>/final-export.zip`。
3. 返回 zip 路径、大小、sha256、entry_count。

返回示例：

```json
{
  "project_id": "project-demo",
  "zip_path": ".musicforge/projects/project-demo/final-export.zip",
  "size_bytes": 123456,
  "sha256": "abc...",
  "entry_count": 8
}
```

GET 行为：

- 如果 ZIP 不存在，返回 404。
- 返回 `application/zip`。
- 文件名建议：`musicforge-<project-id>-final-export.zip`。

### 8.4 ZIP 安全规则

必须实现这些保护：

- 使用 `zipfile.ZipFile`，不能 shell 调外部 zip。
- ZIP entry 必须是相对路径。
- 禁止 entry 以 `/`、`\`、盘符、`..` 开头。
- 跳过 symlink、junction 或无法解析到 final-export 目录内的文件。
- 只遍历 `final-export/` 目录，不读取 project 目录其他文件。
- 不允许包含：
  - `.musicforge/provider.json`
  - `.musicforge/renderer.json`
  - `provider-snapshot.json` 以外的本地配置
  - 任何 access token
- ZIP 生成应使用临时文件，然后原子替换。

### 8.5 Manifest 扩展

Final Export manifest 可以增加：

```json
{
  "zip": {
    "created_at": "2026-05-06T00:00:00Z",
    "filename": "final-export.zip",
    "size_bytes": 123456,
    "sha256": "abc...",
    "entry_count": 8
  }
}
```

也可以单独写 `final-export-zip.json`。推荐写入 manifest，方便 Studio 一次展示。

### 8.6 Studio 改动

Final Export tab 增加：

- Build ZIP 按钮。
- ZIP 状态：not built / built / failed。
- ZIP 下载按钮。
- size、sha256 短 hash 展示。

如果 final export 目录未生成，Build ZIP 按钮应禁用或显示 409 友好提示。

### 8.7 测试

新增测试覆盖：

- final-export 目录存在时能生成 zip。
- zip entries 全部是相对路径。
- zip 包含 README、manifest、song-plan、MIDI。
- zip 不包含 `.musicforge/provider.json`。
- symlink 或越界文件不会进入 zip。
- final-export 目录不存在时返回 409。
- GET zip 能下载。
- auth 开启时 zip API 受保护。

## 9. Package E：Project Search / Filter、Release Check 和发布文档

### 9.1 Project Search / Filter

Project 列表现在会越来越长，需要快速定位。

推荐给 `GET /api/projects` 增加 query 参数：

```text
GET /api/projects?q=<text>&status=<status>&variant_type=<type>&hidden=false&include_hidden=false
```

筛选字段：

| 参数 | 说明 |
| --- | --- |
| `q` | 匹配 project name、description、version name |
| `status` | selected/final/gate failed 等简单状态 |
| `variant_type` | original/edit/variation |
| `hidden` | 是否只看隐藏项目 |
| `include_hidden` | 是否包含隐藏项目 |

Studio Projects 工作区增加：

- 搜索框。
- Hidden 开关。
- Status 筛选。
- Variant type 筛选。
- Clear filters 按钮。

不要为了搜索引入数据库，继续基于 `.musicforge/projects/` 本地 JSON 扫描即可。

### 9.2 Release Check 增强

`python -m song_agent.cli release-check` 新增 smoke：

1. 创建 demo project。
2. 创建或读取 built-in preset。
3. 使用 preset 创建 edit version。
4. compare 原始版本和 edit 版本。
5. final export。
6. build final export zip。
7. 检查 zip entry：
   - 无绝对路径。
   - 无 `..`。
   - 包含 manifest / README / MIDI。
8. 检查 secret scan 仍通过。

### 9.3 文档更新

必须更新：

- `README.md`
- `CHANGELOG.md`
- `song_agent/__init__.py` 或项目当前版本来源文件
- 本施工图完成状态

README 至少补：

- Edit Presets 用法。
- Compare 版本对比说明。
- Final Export ZIP 用法。
- Project 搜索筛选说明。
- v1.2.0 本地验证命令。

CHANGELOG 增加：

```md
## v1.2.0 - 2026-05-06
```

## 11. 风险点和 Reviewer 重点

### 11.1 Preset 风险

风险：

- preset payload 绕过 edit intent 校验。
- preset 保存具体 project/version/job，导致跨项目污染。
- user preset JSON 半写时 Studio 读取失败。

Reviewer 检查：

- 保存和应用 preset 都复用 v1.1.1 的 edit 校验。
- preset 不存本地路径。
- built-in 和 user preset 合并逻辑不会互相覆盖。
- 写入使用原子替换。

### 11.2 Compare 风险

风险：

- compare API 因缺失 quality、audio、edit metadata 崩溃。
- 对比结果误导 final 选择。
- 老项目版本兼容性不足。

Reviewer 检查：

- 缺字段时返回 `unknown` 或 `null`，不要 500。
- recommendation 只是建议，不自动改 selected/final。
- 老版本 song-plan 没 quality 时仍能展示基础信息。

### 11.3 ZIP 风险

风险：

- zip 打包时读到 final-export 之外的文件。
- zip entry 出现绝对路径或 `..`。
- symlink/junction 引入敏感文件。
- ZIP 过期但 Studio 仍提示可用。

Reviewer 检查：

- 只遍历 final-export 目录。
- 每个 entry 都做路径边界检查。
- ZIP build 后记录 sha256 和 entry_count。
- final-export 重新生成时旧 zip 要清理或标 stale。

### 11.4 GitHub 发布风险

风险：

- token 写进 remote URL。
- 本机 `.musicforge/*.json` 被误提交。
- release tag 指向错误 commit。

Reviewer 检查：

```powershell
git remote -v
git status
git ls-files .musicforge
git rev-parse HEAD
git rev-parse origin/master
git rev-parse v1.2.0^{}
```

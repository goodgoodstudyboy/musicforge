# v8.6.0 Public Trust Center Acceptance Board 多接收方验收委员会与准出门禁施工图

> 本文是给开发执行的 v8.6.0 施工图。当前稳定基线是 v8.5.1。
>
> v8.5.1 已经完成单个外部接收方对 Distribution Kit 的验收 response、accepted evidence、离线 verifier，并修掉了 reviewer public 字段整体重签伪造的问题。
>
> v8.6.0 的目标，是把“单个外部接收方 accepted evidence”升级成“多接收方 Acceptance Board”：支持多个 reviewer / organization / role 的验收证据汇总、quorum 准出门禁、冲突处理、board package 导出与离线验证。这样 Public Trust Center 才能支持真实业务里的多方确认，而不是只记录一条 accepted response。

---

## 1. 背景

当前 v8.5.1 已经能做到：

1. 为当前 Public Trust Center Distribution Kit 生成外部验收 response template。
2. 导入外部 response。
3. 强制 response 显式绑定当前 Kit：
   - Kit ZIP hash。
   - Kit manifest hash。
   - Kit report/source hash。
   - Kit verification report hash。
4. accepted response 生成 public-safe Accepted Evidence ZIP。
5. Accepted Evidence ZIP verifier 使用导入时落盘的 response verification / binding proof sidecar，阻断 reviewer public 字段整体重签伪造。

但真实交付不会只有一个接收方。常见场景：

- 发行运营同意，但法务要求改 rights 文案。
- 平台接收方 accepted，但客户方 rejected。
- 外部审查团队有多个 reviewer，需要至少 2/3 accepted。
- 必须有某些 role 的 acceptance，例如 `legal`, `distribution_partner`, `executive_owner`。
- 如果任何 `critical` severity 的 needs_changes / rejected 存在，不能准出。
- 多个 response 可能引用不同 Kit 版本，旧 response 不能计入当前 board。
- 需要一个 board-level package，给内部或外部审计方证明“准出判断是如何形成的”。

v8.6.0 就是补这个多接收方准出层。

---

## 2. v8.6.0 定位

一句话：

> v8.6.0 要新增 Public Trust Center Acceptance Board，把多个 Distribution Kit Accepted Evidence 聚合成一个准出报告，支持 role/quorum gate、冲突状态、board signoff draft、board package 和离线 verifier。

它不替代 v8.5：

```text
v8.5: 单个 response -> accepted evidence
v8.6: 多个 accepted evidence / needs_changes / rejected response -> board report -> board package -> verifier
```

---

## 3. 本版不做什么

为了控制范围，本版明确不做：

1. 不接入真实电子签名或 CA。
2. 不自动批准 Change Request。
3. 不自动 revoke / supersede Anchor。
4. 不自动重新生成 Distribution Kit。
5. 不把 board accepted 当成外部法务担保。
6. 不允许 stale response / stale evidence 参与 quorum。
7. 不把 rejected / needs_changes 自动转成 accepted。
8. 不允许 API 读取本机 source_path / local_path / file_path。
9. 不把原始 reviewer private comments、email、phone、本机路径、token 写进 public board package。
10. 不修改 v8.5 Accepted Evidence ZIP 格式，除非确有必要且要保持兼容。

## 11. Quorum 规则

### 11.1 Accepted 计数

计入 quorum 的 participant 必须：

- result 是 `accepted`。
- review_mode 是 `external_manual`。
- response current。
- accepted evidence current。
- accepted evidence verifier passed。
- reviewer public projection proof 通过。

### 11.2 Organization 计数

- 按 public-safe organization 计数。
- 空 organization 不计入 `min_accepted_organizations`。
- 同一个 organization 多个 reviewer 只算一个 organization。

### 11.3 Role 计数

- `required_roles` 每个 role 必须至少有一条 current accepted evidence。
- role 来自 response public reviewer role。
- 如果 role 空，不满足 required role。

### 11.4 Blocking findings

如果 current response 中有：

```json
{"severity": "critical"}
```

且 policy `block_on_critical_findings = true`，则 readiness blocked。

### 11.5 needs_changes / rejected

- `allow_needs_changes=false` 时，任何 current needs_changes 都 blocked。
- `allow_rejected=false` 时，任何 current rejected 都 blocked。
- 即使 quorum 数量满足，blocked conflict 仍优先。

```text

```

### 12.3 Manifest 固定 allow-list

Board verifier 必须固定 allow-list，但 evidence/ 和 response-proofs/ 是动态列表。做法：

- 根文件固定。
- `evidence/<evidence-id>-summary.json` 只允许来自 report participants。
- `response-proofs/<response-id>-binding-proof.json` 只允许来自 report participants。
- `response-proofs/<response-id>-verification-summary.json` 只允许来自 report participants。
- 不允许其它目录或文件。

不要用 manifest.files 自己扩展 allow-list。

## 13. Board Offline Verifier

新增：

```text
song_agent/public_trust_center_acceptance_board_verifier.py
```

CLI：

```powershell
python -m song_agent.cli verify-public-trust-center-acceptance-board-package path\to\public-trust-center-acceptance-board.zip --strict --require-ready --json
```

可选参数：

```powershell
--require-ready
--require-quorum
--require-no-conflicts
--min-accepted-count 2
--min-accepted-organizations 2
--required-role distribution_partner
--required-role legal
--distribution-kit path\to\public-trust-center-distribution-kit.zip
--accepted-evidence-dir path\to\accepted-evidence-zips
--report-out board-verification-report.json
--max-zip-size-mb
--max-uncompressed-size-mb
--max-entry-count
```

### 13.1 必要 checks

ZIP 层：

- `ptcab_zip_open`
- `ptcab_zip_size_limit`
- `ptcab_zip_uncompressed_size_limit`
- `ptcab_zip_entry_count_limit`
- `ptcab_zip_entry_path_safe`
- `ptcab_zip_duplicate_entries`
- `ptcab_zip_required_entries`
- `ptcab_zip_allowed_entries`
- `ptcab_zip_no_internal_entries`

Manifest 层：

- `ptcab_manifest_integrity`
- `ptcab_manifest_package_type`
- `ptcab_manifest_allowed_files`
- `ptcab_manifest_file_hashes`
- `ptcab_manifest_zip_entries_reference_only`

Report 层：

- `ptcab_report_integrity`
- `ptcab_report_source_hash`
- `ptcab_policy_hash`
- `ptcab_conflict_report_integrity`
- `ptcab_board_summary_match`
- `ptcab_response_index_match`
- `ptcab_accepted_evidence_index_match`
- `ptcab_quorum_evidence_match`

Gate 层：

- `ptcab_quorum_status`
- `ptcab_required_roles_status`
- `ptcab_conflict_status`
- `ptcab_no_stale_participants`
- `ptcab_no_blocking_findings`

External 层：

- `ptcab_external_distribution_kit_match`
- `ptcab_external_accepted_evidence_match`

Redaction：

- `ptcab_redaction_scan`

### 13.2 防整体重签

Board verifier 不能只信 `board-report.source`。

必须从 sidecar 反推：

- `response-index.json`
- `accepted-evidence-index.json`
- `quorum-evidence.json`
- `response-proofs/*`
- `evidence/*`

并与 board report 逐项对账。

release-check 必须覆盖：

- 修改 participant reviewer organization。
- 同步重签 board-report / board-summary / response-index / manifest。
- 但不更新对应 response proof 或 evidence proof。
- verifier 必须 failed。

如果攻击者连 response proof 都一起伪造，仍需要外部 Accepted Evidence ZIP 或原始 response 留存才能防；这要在 README 里写清楚边界。

## 24. 风险清单

### R1：Board 把 stale evidence 计入 quorum

要求：

- response stale 或 evidence stale 都不能 counts_for_quorum。
- release-check 覆盖 stale blocked。

### R2：Board verifier 信任 board-report 自证

要求：

- verifier 必须用 response-index、accepted-evidence-index、quorum-evidence、response-proofs/evidence sidecar 反查。
- full resign participant 必须 failed。

### R3：needs_changes/rejected 被 quorum 覆盖

要求：

- blocking conflict 优先级高于 accepted quorum。
- accepted count 满足也不能 ready。

### R4：required role 空值绕过

要求：

- role 空不能满足 required role。
- organization 空不能满足 organization count。

### R5：Board package 暴露 private response

要求：

- package 只输出 public-safe projection。
- 不输出原始 response JSON。
- redaction scan 覆盖所有 JSON/TXT。

### R6：动态目录 allow-list 漏洞

要求：

- evidence/ 和 response-proofs/ 只允许由 participants 派生出的文件名。
- manifest.files 不能自定义新增其它文件。

## 26. 给开发的话

v8.6 不要再做“单条 response 的更多字段”。v8.5.1 已经把单条证据链做稳了，这版要解决真实业务的多方验收问题：谁接受了、谁要求修改、是否满足角色门禁、是否达到 quorum、能不能作为准出依据。

实现时要坚持三点：

1. Board 只能统计 current、external_manual、passed 的 accepted evidence。
2. Board verifier 不能只信 board-report，必须用 index/proof sidecar 反查。
3. needs_changes / rejected 默认阻断 ready，不能被 accepted 数量掩盖。

先把 Store 和 verifier 做硬，再接 API / CLI / Studio。每完成一个可验收块就提交并推 GitHub，避免把大改动攒到最后。

# v7.3.0 Release Portfolio Governance Attestation Registry 公开证明登记册与撤销替换治理施工图

> 本文是给开发执行的 v7.3.0 施工图。当前稳定基线是 v7.2.1。v7.2.1 已经完成 Portfolio Governance Public Attestation，并修复了公开证明包 verifier 的两个关键边界：Evidence Vault 指纹必须反查绑定 `attestation-report.source.evidence_vault_*`，以及 `.musicforge/`、`nested/`、`.zip` 禁止规则必须大小写不敏感。

v7.3.0 不继续扩大证明包内容本身，而是补上“公开证明生命周期治理”：公开证明生成以后，系统要能登记它、标记发布状态、撤销、替换、保留历史、导出公开索引，并且能离线验证这个登记册没有被篡改。

---

## 1. 当前项目状态

项目已经从单首音乐生成，推进到了完整的交付、发行、组合治理和公开证明链路。

关键上下游：

- v6.x：Release Operations、Portfolio Audit、Governance Queue、Governance Signoff、Archive、Audit Ledger、Reviewer Pack。
- v7.0：Final Board 最终委员会签核。
- v7.1：Evidence Vault 证据保险库，支持深度离线复验。
- v7.2：Public Attestation 公开证明包，轻量公开证书，不嵌套 Evidence Vault / Final Board / Audit ZIP。
- v7.2.1：Public Attestation verifier 收紧，避免公开证书与真实 Evidence Vault source 脱钩。

现在缺口：

1. 公开证明 ZIP 生成后，只是一个文件，缺少系统内“发布登记”状态。
2. 如果公开证明需要撤销，当前没有可追溯撤销记录。
3. 如果 Evidence Vault 或 Final Board 重签后生成了新的公开证明，当前没有“替换链”。
4. 外部拿到多个公开证明时，无法用一个轻量索引判断哪个是当前有效、哪个已撤销。
5. 公开证明 verifier 只能验单个 ZIP，不能验一组证明登记册的整体一致性。

---

## 2. v7.3.0 目标

新增 Release Portfolio Governance Attestation Registry。

它是每个 Portfolio 的公开证明登记册，负责记录：

- 哪些 public attestation package 被创建过。
- 哪个证明是 current。
- 哪个证明已 published。
- 哪个证明已 revoked。
- 哪个证明被哪个证明 superseded。
- 每个证明绑定的 Evidence Vault ZIP hash、Vault manifest hash、Vault verification hash、Final Board signoff hash。
- 每次 publish / revoke / supersede / verify 的事件历史。
- 可导出的 Registry Report / Registry Export / Registry ZIP。
- 离线 verifier 能验证 Registry ZIP，且能验证每个声明的 attestation package 摘要与登记册一致。

一句话：

> v7.2 证明“这个组合治理结果可以公开证明”。v7.3 要证明“公开证明的发布、撤销、替换历史没有被篡改”。

## 3. 非目标

必须明确不做：

- 不真正联网发布到网站、GitHub Pages、IPFS、S3、区块链、公证平台。
- 不引入外部数据库。
- 不引入加密签名、公钥证书、PKI。当前仍使用 deterministic hash / integrity hash / source hash。
- 不把 Evidence Vault ZIP 嵌入 Registry ZIP。
- 不把 Public Attestation ZIP 嵌入 Registry ZIP，除非只作为可选 `package-digests` 摘要引用。
- 不让 Registry 反向污染 v7.2 Attestation source hash，避免循环。
- 不让 Registry 自动撤销或自动替换公开证明，所有状态变更必须是显式操作。
- 不允许 registry publish/revoke/supersede 绕过 v7.2 verifier。

## 6. Registry Store 行为

### 6.1 register_current_attestation

用途：把当前 v7.2 Public Attestation ZIP 注册为一个 Registry Entry。

流程：

1. 读取 Attestation ZIP。
2. 调用 `verify_release_portfolio_governance_attestation(..., strict=True, require_vault=True, require_final_board=True)`。
3. verification 必须 passed。
4. 从 Attestation manifest / certificate / report.source 提取：
   - certificate_id。
   - attestation_profile。
   - attestation ZIP sha256 / size。
   - attestation manifest hash。
   - Evidence Vault fingerprints。
   - Final Board signoff hash。
5. 如果 Registry 里已有相同 `attestation_zip_sha256` 的 entry：
   - 默认返回 existing。
   - 不重复创建。
6. 如果当前 entry 已经 published，但新 attestation 指纹不同：
   - 允许创建 draft entry。
   - 不自动 supersede current。
7. 写入 `registry.json` 和 history event。

建议 API 名：

```text
POST /api/release-portfolio-audits/<portfolio-id>/governance-attestation-registry/register-current
```

### 6.2 publish_entry

用途：显式把某个 entry 标记为 published/current。

规则：

1. entry 必须存在。
2. entry verification 必须 current passed。
3. entry 不能 revoked。
4. entry 对应的 Attestation ZIP 仍必须存在并 hash 匹配，或至少有 verification report 绑定同一 ZIP sha256 / manifest hash。
5. 如果已有 current published entry：
   - 新 entry 与旧 entry 不同，必须传 `supersede_current=true`。
   - 旧 entry 状态改为 `superseded`。
   - 旧 entry 写入 `superseded_by_entry_id`。
6. 新 entry 状态改为 `published`。
7. `registry.current_entry_id = entry_id`。
8. 写 history event。

API：

```text
POST /api/release-portfolio-audits/<portfolio-id>/governance-attestation-registry/entries/<entry-id>/publish
```

Payload：

```json
{
  "published_by": "owner",
  "public_url": "",
  "distribution_note": "",
  "supersede_current": true
}
```

### 6.3 revoke_entry

用途：撤销一个公开证明。

规则：

1. entry 必须是 `published` 或 `superseded`。
2. 必须提供 `reason`。
3. 如果 revoke current entry：
   - Registry 进入 `active` 但 `current_entry_id = null`，或者 current 指向最近一个仍 published 且未 revoked 的 entry。
   - 建议 v7.3.0 选择更严格口径：撤销 current 后 `current_entry_id = null`，必须显式 publish 新 entry。
4. revoked entry 不允许再次 publish。
5. 写 history event。

API：

```text
POST /api/release-portfolio-audits/<portfolio-id>/governance-attestation-registry/entries/<entry-id>/revoke
```

Payload：

```json
{
  "revoked_by": "owner",
  "reason": "Evidence Vault was superseded by a new Final Board signoff."
}
```

### 6.4 refresh_report

用途：刷新 Registry Report。

必须检查：

- Registry integrity OK。
- 每个 entry integrity OK。
- current entry 存在时必须是 `published`。
- current entry verification current passed。
- revoked entry 不能是 current。
- superseded entry 必须有 `superseded_by_entry_id`。
- `superseded_by_entry_id` 必须指向存在 entry。
- 不允许两个 `published current`。
- entry 的 attestation manifest/certificate/report source fingerprint 必须一致。
- entry 的 Evidence Vault fingerprint 必须和 v7.2 verifier 报告一致。
- Registry history 最后一条状态事件不能和 `registry.json` 矛盾。

### 6.5 export_registry

导出轻量 Registry Export。

必须包含：

```text
manifest.json
registry.json
registry-report.json
package-index.json
chain-of-custody.json
README.txt
```

不包含：

- Public Attestation ZIP。
- Evidence Vault ZIP。
- Final Board ZIP。
- `.musicforge/`。

### 6.6 build_registry_zip

构建：

```text
governance-attestation-registry.zip
```

不可变规则：

- 如果 Registry Export/ZIP 已经为当前 `registry_hash + current_entry_id + current_entry_hash` 生成过，删除 export/zip 后也不能重建绕过。
- 如果要重新导出，必须先发生新的 registry 状态变化：
  - register 新 entry。
  - publish 新 entry。
  - revoke entry。
  - supersede entry。

这个 immutability 不要求 Change Request，因为 Registry 本身就是公开证明生命周期记录；但不允许同一状态反复重建。

## 8. 离线 Verifier

新增：

```text
python -m song_agent.cli verify-release-portfolio-governance-attestation-registry <zip>
```

参数：

```text
--json
--report-out <path>
--strict
--require-current
--require-published
--require-no-revoked-current
```

Verifier 检查：

### 8.1 ZIP 安全

- ZIP 可打开。
- entry count 上限。
- 总解压大小上限。
- duplicate entry failed。
- raw central directory backslash failed。
- `..`、绝对路径、盘符路径、UNC failed。
- `.musicforge/` 大小写变体 failed。
- `.zip` nested failed。
- `nested/` 大小写变体 failed。
- strict 模式下不允许 manifest.files 之外的 entry。

### 8.2 Manifest

- `package_type == release_portfolio_governance_attestation_registry`。
- `files[]` shape OK。
- 每个 file sha256/size 匹配。
- `manifest.integrity_hash` OK。
- `manifest.registry.integrity_hash == registry.integrity_hash`。
- `manifest.registry_report.integrity_hash == registry-report.integrity_hash`。
- `manifest.source_hash == registry-report.source_hash`。
- `manifest.zip.entries` 不能扩大允许 entry 集合。

### 8.3 Registry

- `registry.integrity_hash` OK。
- 每个 entry integrity OK。
- entry id 唯一。
- certificate_id 可重复但同一 certificate_id 不允许两个不同 attestation_zip_sha。
- current_entry_id 存在时必须指向 published entry。
- revoked entry 不能 current。
- superseded entry 必须有 superseded_by_entry_id。
- superseded_by_entry_id 必须存在。

### 8.4 Registry Report

- `registry-report.integrity_hash` OK。
- `registry-report.source.registry_hash == registry.integrity_hash`。
- summary counts 与 registry entries 实际统计一致。
- blocker/warning 不得被篡改后仍 passed。

### 8.5 Chain of Custody

`chain-of-custody.json` 需要记录 registry history 摘要。

Verifier 要检查：

- chain source hash 与 registry source hash 一致。
- chain event count 与 registry history summary 一致。
- chain latest event 与 registry current state 一致。

### 8.6 Redaction

扫描所有 JSON/TXT/MD：

- 本机路径。
- GitHub token。
- OpenAI key。
- Bearer token。
- `provider-snapshot`。
- `renderer.json`。
- `.musicforge/provider.json`。
- `.musicforge/renderer.json`。
- `api_key`、`token`、`secret`、`password` 等 key。

```text
POST /api/release-portfolio-audits/<portfolio-id>/governance-attestation-registry/verify
GET  /api/release-portfolio-audits/<portfolio-id>/governance-attestation-registry.zip
```

返回语义：

- `200`：读取、刷新成功。
- `202`：如果以后做后台任务，v7.3 暂不需要。
- `400`：payload 缺字段、reason 为空、entry id 非法。
- `404`：portfolio 或 entry 不存在。
- `409`：stale、verification failed、revoked entry publish、current revoke 后未重新 publish、immutability 阻断。

所有写操作继续走已有 auth guard。

## 13. release-check Smoke

新增：

```text
v7.3 public attestation registry smoke
```

必须覆盖：

1. 创建 Portfolio 到 v7.2 Public Attestation。
2. Register current attestation。
3. Publish entry。
4. Refresh registry report -> passed。
5. Export registry。
6. Build registry ZIP。
7. External clean dir verify -> passed。
8. 新建第二个 attestation 后 register，publish supersede current。
9. 旧 entry 变 superseded，新 entry current。
10. Revoke current 后 current_entry_id 清空。
11. 没有 current 时 `--require-current` verifier failed。
12. 重新 publish 新 entry 后 verifier passed。
13. 删除 export/zip 后同一 registry state 不允许重建。
14. 篡改 registry entry hash -> verifier failed。
15. 篡改 manifest package_type -> failed。
16. 增加 duplicate ZIP entry -> failed。
17. 增加 dangerous path -> failed。
18. 增加 raw backslash entry -> failed。
19. 增加 `.MusicForge/internal.json` 并写 manifest -> failed。
20. 增加 nested/fake.zip -> failed。
21. manifest.zip.entries spoof -> warning 或 failed，按 strict 口径 failed。
22. 注入本机路径 / token -> redaction failed。

release-check detail 输出建议：

```text
v7.3 attestation registry smoke: register=ok, publish=ok, supersede=ok, revoke=ok, external_verify=passed, no_current=failed, immutable=409, tamper=failed, duplicate=failed, dangerous=failed, backslash=failed, case_musicforge=failed, nested=failed, redaction=failed
```

## 15. 安全边界

### 15.1 不信任展示字段

Registry Report 不能信 entry.public 里的 summary。所有 gate 必须从：

- registry integrity。
- entry integrity。
- v7.2 attestation verifier report。
- manifest/certificate/report.source binding。

推导。

### 15.2 不信 manifest.zip.entries

和之前 verifier 一样：

- 允许 entry 集合来自 `manifest.files[].path + legal sidecar`。
- `manifest.zip.entries` 只能作为一致性参考，不能放行额外文件。

### 15.3 大小写敏感问题

ZIP path forbidden 检查必须全部 lower-case 后判断：

- `.zip`
- `nested/`
- `.musicforge/`

同时保留 raw central directory name 检查。

### 15.4 撤销不是删除

revoked entry 必须保留。

禁止：

- 删除 revoked entry。
- 覆盖 revoked entry。
- revoked entry 重新 publish。

### 15.5 替换不是自动

register 新证明不能自动 supersede current。必须显式 publish with supersede。

## 18. 风险清单

### P1 风险：Registry entry 与 attestation source 脱钩

必须确保 Registry entry 里的 attestation fingerprint 来自 verifier report / attestation manifest / report.source，不能来自用户 payload。

### P1 风险：撤销后仍被当成 current

`current_entry_id` 必须在 revoke 时清空，或者严格指向另一个 published entry。v7.3 建议清空。

### P1 风险：同一状态删除 ZIP 后重建

必须用 history event 记录 source triple，不能只看文件存在。

### P1 风险：manifest.zip.entries 放行额外文件

禁止。

### P1 风险：大小写路径绕过

`.MusicForge`、`Nested/`、`FAKE.ZIP` 都必须失败。

### P2 风险：Registry 被误认为外部发布系统

README / Studio 文案必须说明它只是本地登记册。

### P2 风险：多 profile 复杂度爆炸

v7.3.0 只做默认 `public_summary`。保留字段，不展开复杂 UI。

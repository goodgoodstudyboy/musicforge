# MusicForge v0.6.0 施工图：安全、鉴权与发布保护

日期：2026-05-05  
角色：reviewer / planner  
目标版本：v0.6.0

## 1. 为什么下一步先做 v0.6.0

v0.5.0 已经把 MusicForge 从“能生成 MIDI”推进到了“能在 Studio 里配置 provider、批量生成、配置 renderer、渲染 WAV、播放音频”的阶段。现在项目已经不是一个单纯的本地脚本，而是一个有写文件、删文件、打开文件夹、调用外部 provider、执行本地渲染器的本地应用。

所以下一阶段不建议继续先堆功能。v0.5.1 可以做 batch audio render，但优先级应低于 v0.6.0。原因很明确：

- Studio 里已经有 provider 配置，虽然 key 已做脱敏，但服务端仍然能读取本地配置。
- Studio 里已经有 renderer 配置，包含本机 SoundFont 路径、FluidSynth 路径等本地环境信息。
- Studio 已经支持 batch、delete、open-folder、render-audio 等会影响本地文件系统或本地进程的操作。
- 现在默认本地使用没有问题，但如果用户把服务绑定到 `0.0.0.0` 或局域网 IP，就必须有访问控制。
- 每次发布到 GitHub 之前，也需要更标准的 release gate，避免 token、本机路径、未忽略配置、错误版本号进入远端。

因此 v0.6.0 的主题是：把 MusicForge 从“本地可用工具”推进到“本地安全可控工具”。

## 2. v0.6.0 总目标

v0.6.0 要交付三件事：

1. Studio 服务访问控制
   - 默认 `127.0.0.1` 本地运行仍然轻量，不强迫用户输入 token。
   - 只要绑定非 loopback 地址，就必须配置 access token。
   - 如果用户在 localhost 模式下主动提供 token，则同样启用鉴权。

2. 敏感信息和危险操作保护
   - API、日志、job state、batch export、snapshot 都不能回显 token、provider key、Authorization header。
   - 所有会读写本地文件、启动任务、删除数据、打开文件夹、保存配置的 API 都必须在鉴权后才能调用。

3. 发布前安全检查
   - 增加本地 release check 命令或脚本。
   - 发布前自动检查测试、版本号、tag、secret scan、remote URL、忽略文件、工作区状态。
   - 形成固定发布流程，开发每完成一个小阶段都先本地验证，再提交和推 GitHub。

## 3. 本阶段不做什么

v0.6.0 不做以下事情，避免范围失控：

- 不做多用户系统。
- 不做账号注册、密码登录、OAuth、GitHub 登录。
- 不做公网部署方案。
- 不做 HTTPS/TLS 证书管理。
- 不做数据库迁移。
- 不做云端任务队列。
- 不做 provider key 的系统级加密保险箱。
- 不做权限角色划分，例如 admin/editor/viewer。

这版只解决本地 Studio 的最重要安全边界：非本机访问必须带 token，敏感信息不能泄露，发布前必须有检查。

## 4. 威胁模型

开发实现前必须先理解这个边界。

如果 Studio 绑定到 `0.0.0.0`、局域网 IP 或其他非本机地址，而没有 access token，同一网络里的其他人可能做到：

- 查看 job 列表和生成产物。
- 下载 MIDI / WAV / JSON。
- 创建大量任务，占用 CPU、磁盘或 provider quota。
- 修改 provider 配置。
- 修改 renderer 配置。
- 触发 FluidSynth 渲染。
- 删除 jobs / batches。
- 调用 open-folder 这类本地行为。
- 通过错误信息或日志推断本机路径。

v0.6.0 的安全目标不是抵抗公网攻击，而是避免“本地工具误绑定到局域网后裸奔”。

## 5. 服务启动规则

### 5.1 loopback 地址定义

以下 host 视为本机地址：

- `127.0.0.1`
- `localhost`
- `::1`

以下 host 视为远程可访问地址：

- `0.0.0.0`
- `::`
- 本机局域网 IP，例如 `192.168.x.x`
- 其他非 loopback host

### 5.2 CLI 参数

在 `python -m song_agent.cli serve` 增加参数：

```powershell
python -m song_agent.cli serve --host 127.0.0.1 --port 8787
python -m song_agent.cli serve --host 0.0.0.0 --port 8787 --access-token <token>
```

新增参数：

- `--access-token <token>`：Studio/API 的访问 token。

新增环境变量：

- `MUSICFORGE_ACCESS_TOKEN`：当 CLI 未传 `--access-token` 时使用。

优先级：

1. CLI `--access-token`
2. 环境变量 `MUSICFORGE_ACCESS_TOKEN`
3. 无 token

### 5.3 启动行为

必须实现以下规则：

- `--host 127.0.0.1` 且没有 token：允许启动，不启用鉴权。
- `--host localhost` 且没有 token：允许启动，不启用鉴权。
- `--host ::1` 且没有 token：允许启动，不启用鉴权。
- `--host 0.0.0.0` 且没有 token：拒绝启动，返回清晰错误。
- `--host ::` 且没有 token：拒绝启动，返回清晰错误。
- `--host 192.168.x.x` 且没有 token：拒绝启动，返回清晰错误。
- 任意 host 只要提供 token：允许启动，并启用鉴权。

错误示例：

```text
error: Access token is required when binding MusicForge Studio to a non-localhost host.
Use --access-token or MUSICFORGE_ACCESS_TOKEN.
```

### 5.4 token 质量要求

token 校验规则：

- 去掉首尾空白后不能为空。
- 不允许包含换行。
- 建议最小长度 16 个字符。
- 错误信息不能回显 token 原文。

不要增加 `--allow-remote-without-token` 这类逃生参数。这会破坏安全边界。

## 6. API 鉴权规则

### 6.1 Header 格式

使用标准 Bearer token：

```http
Authorization: Bearer <token>
```

服务端用 `hmac.compare_digest()` 做 token 比较，避免普通字符串比较。

### 6.2 未授权响应

未提供 token 或 token 错误时：

- HTTP status：`401`
- Header：`WWW-Authenticate: Bearer`
- Body：

```json
{"error":"Unauthorized."}
```

不能返回：

- 收到的 token。
- 正确 token。
- Authorization header 原文。
- provider key。
- renderer 本机敏感路径的额外调试信息。

### 6.3 哪些接口需要鉴权

如果 auth 开启，以下接口必须鉴权：

- Jobs：
  - `GET /api/jobs`
  - `POST /api/jobs`
  - `GET /api/jobs/<id>`
  - `POST /api/jobs/<id>/cancel`
  - `POST /api/jobs/<id>/retry`
  - `POST /api/jobs/<id>/delete`
  - `POST /api/jobs/<id>/hide`
  - `POST /api/jobs/<id>/unhide`
  - `POST /api/jobs/<id>/open-folder`
  - `POST /api/jobs/<id>/render-audio`
  - 所有 job artifacts、logs、timeline、tracks、validator、nodes、audio、midi API

- Provider：
  - `GET /api/provider`
  - `POST /api/provider`
  - `POST /api/provider/reset`
  - `POST /api/provider/test`

- Renderer：
  - `GET /api/renderer`
  - `POST /api/renderer`
  - `POST /api/renderer/reset`
  - `POST /api/renderer/test`

- Batch：
  - `GET /api/batches`
  - `POST /api/batches/import-csv`
  - `GET /api/batches/<id>`
  - `POST /api/batches/<id>/launch`
  - `POST /api/batches/<id>/pause`
  - `POST /api/batches/<id>/resume`
  - `POST /api/batches/<id>/retry-failed`
  - `POST /api/batches/<id>/hide`
  - `POST /api/batches/<id>/unhide`
  - `POST /api/batches/<id>/delete`
  - `POST /api/batches/<id>/open-folder`
  - `GET /api/batches/<id>/export`

### 6.4 可以公开的接口

允许 `GET /api/info` 在无 token 情况下访问，但必须只返回非敏感信息。

`/api/info` 可以包含：

```json
{
  "app": "MusicForge",
  "version": "0.6.0",
  "auth_required": true
}
```

`/api/info` 不允许包含：

- token。
- provider key。
- provider base_url 里的 secret。
- renderer 本机绝对路径。
- job 明细。
- batch 明细。

## 7. Studio 前端改造

### 7.1 Token 输入

如果 `/api/info` 返回 `auth_required: true`，Studio 页面应显示一个简洁的 token 输入区域。

要求：

- token 存在 `sessionStorage`，不要放 `localStorage`。
- 页面刷新后同一个 tab 可以继续用。
- 关闭浏览器 tab 后 token 自动丢失。
- 不把 token 写入 URL。
- 不把 token 写入 DOM 可见文本。
- 不把 token 打到 console。

### 7.2 fetch 封装

现有前端应有统一 API 调用函数。需要在这里注入：

```javascript
Authorization: `Bearer ${token}`
```

要求：

- auth 未开启时，不发送 Authorization header。
- auth 开启但没有 token 时，不请求敏感 API，先显示 token 输入。
- 收到 401 时清掉 sessionStorage 中的 token，并回到 token 输入状态。

### 7.3 UI 要求

页面不要做复杂登录系统，只做本地工具风格的访问口令输入。

建议文案：

```text
Access token
```

按钮：

```text
Unlock
```

不要在页面里解释太多安全概念，也不要展示 token 原文。

## 8. 服务端实现建议

建议新增：

- `song_agent/auth.py`

职责：

- 判断 host 是否 loopback。
- 解析 access token。
- 校验 token 格式。
- 判断 auth 是否 required。
- 校验 Authorization header。
- 提供统一 `AuthConfig`。

可能的数据结构：

```python
@dataclass(frozen=True)
class AuthConfig:
    enabled: bool
    token: str | None = None
```

建议函数：

```python
def is_loopback_host(host: str) -> bool: ...
def resolve_access_token(cli_token: str | None, environ: Mapping[str, str]) -> str | None: ...
def build_auth_config(host: str, cli_token: str | None, environ: Mapping[str, str]) -> AuthConfig: ...
def validate_bearer_header(header_value: str | None, token: str) -> bool: ...
```

在 HTTP server 的 request handler 里增加统一入口：

```python
if self.server.auth_config.enabled and self.path != "/api/info":
    if not authorized:
        return self.write_json(401, {"error": "Unauthorized."}, headers={"WWW-Authenticate": "Bearer"})
```

注意：不要在每个 API 里散落重复鉴权代码。应该在路由分发之前集中判断。

## 9. 日志和脱敏要求

v0.6.0 必须继续保持现有 provider/renderer 脱敏策略，并补充 auth token 保护。

禁止写入以下内容：

- access token 原文。
- Authorization header 原文。
- provider api_key 原文。
- token 文件路径。
- 本机 GitHub token 路径。
- 带 token 的 remote URL。

需要检查以下文件：

- `job-state.json`
- `run-summary.json`
- `provider-snapshot.json`
- `renderer` 相关 snapshot 或 state 文件
- `events.jsonl`
- batch `export.json`
- HTTP error body
- Studio console output

脱敏显示建议：

```text
sk-...abcd
```

或者：

```text
***masked***
```

access token 最好不要显示后四位，统一显示：

```text
***masked***
```

## 10. 发布保护：release check

建议新增命令：

```powershell
python -m song_agent.cli release-check
```

这个命令不负责发布，只负责发布前检查。

### 10.1 release-check 检查项

必须检查：

- `python -m pytest -q` 通过。
- `git status --short --branch` 是干净并且与 `origin/master` 对齐，或者明确提示 ahead/behind。
- `git diff --check` 通过。
- remote URL 不包含 token。
- repo 中没有提交 `.musicforge/provider.json`。
- repo 中没有提交 `.musicforge/renderer.json`。
- repo 中没有明显 secret 模式。
- README、CHANGELOG、包版本号一致。
- 当前版本如果准备发布，tag 不应已存在。

可以检查：

- release notes 是否包含当前版本。
- material 施工图是否提交。
- `runs/` 是否未被 Git 跟踪。
- `__pycache__/` 是否未被 Git 跟踪。
- `.pytest_cache/` 是否未被 Git 跟踪。

### 10.2 secret scan 关键词

至少扫描以下模式：

- `ghp_`
- `github_pat_`
- `sk-`
- `x-access-token`
- `Authorization: Bearer`
- `api_key`
- `access_token`
- 本机 token 文件绝对路径

注意：扫描命中测试用假 key 时不能一刀切失败。可以允许测试 fixture 中的假值，但 release-check 必须清楚输出命中位置，让 reviewer 判断。

## 13. Reviewer 验收清单

开发交付后，reviewer 按这个清单检查：

- `python -m pytest -q` 全绿。
- 默认 localhost Studio 仍然免 token 可用。
- 非 localhost 无 token 无法启动。
- 非 localhost 有 token 可以启动。
- auth 开启后，缺 token 的敏感 API 全部 401。
- auth 开启后，错误 token 的敏感 API 全部 401。
- auth 开启后，正确 token 可以正常生成 job、查看产物、渲染 audio。
- `/api/info` 不泄露敏感信息。
- 401 body 不泄露任何 token。
- Studio 使用 `sessionStorage`，不使用 `localStorage` 保存 token。
- provider key 不出现在 API、job state、snapshot、logs、console。
- renderer 本机路径不会在不必要的公开 API 中泄露。
- open-folder/delete/render-audio/batch launch 等操作都受保护。

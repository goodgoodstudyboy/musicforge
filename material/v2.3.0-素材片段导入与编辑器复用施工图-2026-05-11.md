# v2.3.0 素材片段导入与编辑器复用施工图

日期：2026-05-11

当前基线：v2.2.2

目标版本：v2.3.0

定位：在 v2.2.x 已经稳定的可视化 Project Editor 之上，把系统里已经沉淀的素材能力真正接进编辑器，让用户能把 Asset、Reference MIDI slice、已有 Project Version 里的片段，以可预览、可撤销、可审计、可版本化的方式插入当前歌曲。

---

## 1. 背景

MusicForge 到 v2.2.2 已经具备以下能力：

- 本地生成歌曲、MIDI、WAV、stem、batch、project version、final export。
- Provider、多节点 agent、candidate、prompt A/B、usage report。
- Creative Asset Library，可从 Job、Project Version、Candidate 抽取素材。
- Reference Library，可导入 MIDI / WAV / lyrics text / style note，并对 MIDI 做 slice。
- Library / Context Pack，可搜索和组合资产上下文。
- Project Editor，可在项目版本上进行结构、轨道、音符级编辑。
- Draft view 已经支持不落盘的连续编辑预览，并修过 derived section / track / note 的显示和身份稳定问题。

但当前还有一个关键断点：

用户在系统中沉淀了很多素材，但进入 Project Editor 之后，主要还是手工做 patch。Asset、Reference MIDI slice、已有版本里的好片段，还不能直接变成编辑器里的可插入片段。

v2.3.0 要解决的就是这个断点。

---

## 2. v2.3.0 的一句话目标

把“素材库”和“可视化编辑器”打通：

- 从 Asset 插入 motif / chord / bass / drum pattern。
- 从 Reference MIDI slice 插入外部参考片段。
- 从同一 Project 的旧版本复制 section / track / range。
- 插入前可以 draft 预览。
- 插入后可以进入现有 Preview / Apply / Project Version / Export 链路。
- 所有来源都要有审计 metadata，所有导出都要脱敏。

---

## 3. 这版不做什么

v2.3.0 必须收住范围，避免变成完整 DAW：

- 不做 audio-to-MIDI。
- 不做 MP3 / FLAC 解析。
- 不做实时软音源播放。
- 不做拖拽级复杂 UI，只做可用的选择器和插入面板。
- 不做复杂自动编曲 solver。
- 不做跨小节智能 reharmonization。
- 不做 AI 自动判断最佳插入位置。
- 不做真实音频 waveform 编辑。

这些可以后续 v2.4+ 再做。

---

## 4. 用户价值

当前用户的真实工作流应该变成：

1. 先生成一首歌，进入 Project。
2. 从 Reference MIDI 中切出喜欢的鼓点或旋律。
3. 或从以前的版本、候选、Asset 里找一个 hook。
4. 在 Project Editor 里选择目标 section、track、起始 beat。
5. 点击 Draft Insert，马上看到 Piano Roll / Timeline 变化。
6. 满意后 Preview 生成 MIDI。
7. 再 Apply 成新的 Project Version。
8. 后续还能 Compare、Final Export、Quality Gate。

这才是“素材沉淀 -> 创作复用 -> 版本化”的闭环。

---

## 5. 总体方案

新增一个轻量 Clip 层：

```text
Asset / Reference Slice / Project Version
        |
        v
EditorClip 标准化
        |
        v
Clip Insert Planner
        |
        v
Editor Patch operations
        |
        v
editor-draft / preview / apply
```

v2.3.0 不绕开现有编辑器 patch engine。

正确做法是：

- Clip 只负责抽象“可插入片段”。
- 插入行为最终仍然转成 Editor Patch。
- Draft、Preview、Apply、Project Version 全部复用现有链路。
- 这样可以继承 v2.2.x 已经修好的 identity、validator、summary、MIDI、diff、export。

## 6. 新增核心概念

### 6.1 EditorClip

建议新增文件：

```text
song_agent/editor_clips.py
```

核心结构：

```python
EditorClip
- clip_id: str
- source_type: "asset" | "reference_slice" | "project_version_section" | "project_version_track_range"
- source_id: str
- source_version_id: str | None
- title: str
- kind: "melody" | "chords" | "bass" | "drums" | "lyrics" | "mixed"
- duration_beats: float
- suggested_track_role: str | None
- suggested_key: str | None
- suggested_tempo: int | None
- notes: list[ClipNote]
- lyrics: list[ClipLyricLine]
- metadata: dict
```

### 6.2 ClipNote

```python
ClipNote
- pitch: int | str
- start_beat: float
- duration_beats: float
- velocity: int
- channel: int | None
- role: str | None
```

说明：

- `start_beat` 必须从 0 开始归一化。
- `duration_beats` 必须大于 0。
- `velocity` 限制在 1..127。
- MIDI pitch 建议使用整数 0..127。
- drums 可以保留 channel / role，但插入时仍按目标 track 处理。

### 6.3 ClipInsertRequest

```python
ClipInsertRequest
- clip_ref:
    source_type
    source_id
    slice_id?
    version_id?
    section_id?
    track_id?
- target:
    project_id
    version_id
    track_id
    section_id?
    start_beat?
- options:
    mode: "overlay" | "replace_range"
    transpose_semitones: int
    velocity_scale: float
    quantize_grid: str | None
    fit_to_section: bool
    trim_to_section: bool
```

v2.3.0 默认支持：

- `overlay`
- `replace_range`

`replace_range` 不一定要新增 patch op。后端可以先在 base editor state 中找出目标 track + range 内的 note ids，生成：

1. `delete_notes`
2. 多个 `add_note`

这样可以复用现有 patch engine。

### 6.4 ClipInsertDraft

插入草稿响应建议包含：

```json
{
  "patch": { "...": "..." },
  "draft_view": { "...": "..." },
  "diff": { "...": "..." },
  "clip_summary": { "...": "..." },
  "warnings": []
}
```

前端拿到 `patch` 后，可以把它追加到 Patch Queue。

## 7. 后端模块设计

### 7.1 新增 `song_agent/editor_clips.py`

职责：

- 从不同来源构造 EditorClip。
- 校验 Clip 安全性和大小。
- 生成可执行 Editor Patch。
- 生成脱敏 metadata。

建议函数：

```python
def list_editor_clips(project_id: str, version_id: str, *, stores: Stores) -> dict:
    ...

def build_clip_from_asset(asset_id: str, *, asset_store: AssetStore) -> EditorClip:
    ...

def build_clip_from_reference_slice(reference_id: str, slice_id: str, *, reference_store: ReferenceStore) -> EditorClip:
    ...

def build_clip_from_project_section(project_id: str, version_id: str, section_id: str, *, project_store: ProjectStore) -> EditorClip:
    ...

def build_clip_from_project_track_range(project_id: str, version_id: str, track_id: str, start_beat: float, end_beat: float, *, project_store: ProjectStore) -> EditorClip:
    ...

def build_insert_clip_patch(base_plan: SongPlan, clip: EditorClip, request: ClipInsertRequest) -> dict:
    ...
```

注意：

- 不要把 store 和 HTTP 层强耦合进 Clip model。
- HTTP 层负责解析请求。
- Clip 层负责纯业务校验。

### 7.2 Clip 来源 1：Asset

AssetStore 已经存在，Asset 可能来自：

- Job
- Project Version
- Candidate
- Reference slice 转换

v2.3.0 只要求支持 note-based asset。

必须处理：

- asset 不存在：404。
- asset hidden：默认拒绝，返回 409 或 404，建议 409。
- asset 无 notes：409。
- asset source stale：如果已有 source_hash 机制，需要校验。
- asset 内部 path / provider response 不允许进入响应。

Clip metadata 只保留：

```json
{
  "asset_id": "...",
  "asset_kind": "...",
  "title": "...",
  "source_summary": "...",
  "created_at": "..."
}
```

必须脱敏：

- local path
- token
- api_key
- raw_provider_response
- source content 中可能出现的本机路径

直接复用 `song_agent/redaction.py`。

### 7.3 Clip 来源 2：Reference MIDI Slice

Reference v1.8 已经支持 MIDI analysis 和 slice。

v2.3.0 要支持：

- 已分析的 MIDI reference。
- 已存在的 slice。
- 从 slice 转成 EditorClip。

必须拒绝：

- audio_wav reference slice 插入。
- text / style note 直接当 MIDI 插入。
- stale slice。
- hidden reference。
- slice notes 为空。
- slice 超过大小限制。

建议行为：

- 如果 reference 未 analyze，返回 409，提示先 analyze。
- 如果 slice 未生成，返回 409，提示先 create slices。
- 如果 slice stale，返回 409，提示重新 analyze/slice。

不要在 v2.3.0 自动 analyze，因为：

- 自动 analyze 会让 Draft Insert 变慢。
- 容易把 UI 动作变成隐藏的后台任务。
- 不利于测试和错误边界。

### 7.4 Clip 来源 3：Project Version Section

用于从旧版本复制某一段：

- intro
- verse
- chorus
- bridge
- outro

支持两种：

1. 整个 section 的所有 tracks。
2. 某个 track 在 section 内的 notes。

v2.3.0 建议先落地：

- section + single track。
- section + all note tracks 可以作为 optional。

原因：

- 插入 mixed clip 到多轨会涉及自动找目标轨。
- 初版可以让用户明确选目标 track，更稳定。

如果要支持 mixed clip：

- 返回 Clip 里包含 `notes_by_role`。
- 插入时要求用户选择 role -> target track 映射。

建议 v2.3.0 不做 role mapping，只做单目标 track。

### 7.5 Clip 来源 4：Project Version Track Range

这个是高级一点的复用：

- 从 A 版本的 melody track 复制 8 beats。
- 插入到 B 版本的 chorus melody track。

v2.3.0 可作为 Phase B 或 Phase C。

API 可以先预留，但如果时间紧，先做 section 复制即可。

## 8. 插入逻辑

### 8.1 目标定位

目标可以有两种：

1. `section_id + offset_beat`
2. `start_beat`

建议前端主用：

```json
{
  "track_id": "track-002",
  "section_id": "section-003",
  "offset_beat": 0
}
```

后端换算：

```text
absolute_start = section.start_beat + offset_beat
```

如果只传 `start_beat`，后端直接用 absolute start。

### 8.2 插入模式

#### overlay

不删除旧 notes，只添加新 notes。

适合：

- 加 hook。
- 加 fill。
- 加 counter melody。
- 加鼓花。

#### replace_range

删除目标 track 在插入范围内的 notes，再添加 clip notes。

范围：

```text
[absolute_start, absolute_start + clip.duration_beats)
```

实现：

- 从 base editor state 找出目标 track 中 range 内 note ids。
- 生成 `delete_notes` op。
- 再生成多个 `add_note` op。

注意：

- 不要用 draft view 的 derived note ids 做删除。
- 删除必须基于 base editor state 的稳定 note identity。

### 8.3 transpose

支持：

```json
"transpose_semitones": -12..12
```

限制：

- 插入后 pitch 必须在 0..127。
- drums track 默认不允许 transpose，除非明确 `allow_drum_transpose=true`，v2.3.0 不做这个开关。

### 8.4 velocity scale

支持：

```json
"velocity_scale": 0.2..2.0
```

插入后 clamp 到 1..127。

### 8.5 fit_to_section

v2.3.0 建议只做 `trim_to_section`，暂不做 time-stretch。

原因：

- MIDI time-stretch 会影响音乐性。
- 当前 SongPlan 结构未必有足够表达“拉伸后仍合理”的信息。

如果用户选择 `trim_to_section=true`：

- 超出 section end 的 notes 截断。
- 截断后 duration <= 0 的 notes 丢弃。
- 返回 warning。

### 8.6 quantize

v2.3.0 可支持简单网格：

- `1/4`
- `1/8`
- `1/16`

如果复杂，先只保留 request 字段但不开放 UI。

建议初版：

- 后端支持 `None` 和 `1/16`。
- UI 默认 `None`。

所有 API 继续走现有 Bearer auth。

### 9.1 列出可插入 clip 来源

```http
GET /api/projects/<project_id>/versions/<version_id>/editor-clips
```

返回：

```json
{
  "project_id": "...",
  "version_id": "...",
  "assets": [
    {
      "source_type": "asset",
      "asset_id": "...",
      "title": "...",
      "kind": "melody",
      "duration_beats": 8,
      "note_count": 24,
      "suggested_track_role": "melody",
      "warnings": []
    }
  ],
  "references": [
    {
      "source_type": "reference_slice",
      "reference_id": "...",
      "slice_id": "...",
      "title": "...",
      "duration_beats": 4,
      "note_count": 16,
      "warnings": []
    }
  ],
  "project_versions": [
    {
      "source_type": "project_version_section",
      "version_id": "...",
      "version_name": "...",
      "sections": [
        {
          "section_id": "section-002",
          "name": "verse",
          "duration_beats": 16,
          "tracks": [
            {
              "track_id": "track-001",
              "name": "melody",
              "note_count": 32
            }
          ]
        }
      ]
    }
  ]
}
```

注意：

- 不返回原始本机路径。
- 不返回 raw provider response。
- 不返回 reference 原始文件内容。
- hidden / stale 项默认不列出；也可以列出但标记 disabled。建议初版不列出。

### 9.2 构造插入草稿

```http
POST /api/projects/<project_id>/versions/<version_id>/editor-clip-draft
```

请求：

```json
{
  "clip_ref": {
    "source_type": "asset",
    "asset_id": "asset-..."
  },
  "target": {
    "track_id": "track-002",
    "section_id": "section-003",
    "offset_beat": 0
  },
  "options": {
    "mode": "overlay",
    "transpose_semitones": 0,
    "velocity_scale": 1.0,
    "trim_to_section": true,
    "quantize_grid": null
  }
}
```

返回：

```json
{
  "patch": {
    "operations": [
      {
        "op": "add_note",
        "track_id": "track-002",
        "pitch": 64,
        "start_beat": 48,
        "duration_beats": 1,
        "velocity": 92
      }
    ]
  },
  "draft_view": {},
  "diff": {},
  "clip_summary": {
    "source_type": "asset",
    "title": "Short hook",
    "note_count": 12,
    "duration_beats": 4
  },
  "warnings": []
}
```

这个接口不落盘，不创建 preview，不创建 run，不写 Project event。

它只是给 UI 快速构造 patch 和 draft view。

### 9.3 可选：直接创建 Preview

如果开发觉得 UI 上需要一步 Preview：

```http
POST /api/projects/<project_id>/versions/<version_id>/editor-clip-preview
```

内部可以：

1. build clip patch
2. 调现有 editor-preview
3. 返回 preview_id

但 v2.3.0 更推荐先做 draft，Preview 继续让用户点现有按钮。

这样流程更清晰：

```text
Insert Draft -> Patch Queue -> Preview -> Apply
```

## 10. Studio UI 设计

### 10.1 Project Editor 增加 Clip Browser

在 Project Editor tab 内新增一个区域：

```text
Clip Browser
- Assets
- References
- Project Versions
```

每个 clip item 展示：

- title
- type
- duration
- note count
- suggested role
- disabled reason

### 10.2 Insert 控件

选中 clip 后显示：

- target track selector
- target section selector
- offset beat input
- mode segmented control: Overlay / Replace
- transpose stepper
- velocity scale input
- trim to section checkbox
- Draft Insert button

点击 Draft Insert：

- 调 `/editor-clip-draft`
- 把返回 patch operations 追加到 Patch Queue
- 更新 Draft View
- 在 Piano Roll 中显示新增 derived notes
- 显示 warnings

### 10.3 与现有 Patch Queue 的关系

Clip Insert 不应该绕过 Patch Queue。

用户应该能看到：

```text
add_note x 12
delete_notes x 1
```

如果 operations 太多，UI 可以折叠显示：

```text
Insert clip: Short hook, 12 notes
```

但底层 patch 仍然是普通 operations。

### 10.4 derived note 规则

v2.2.2 已经支持 derived-note 显示。

v2.3.0 继续沿用：

- Draft Insert 产生的新 note 在 Piano Roll 可见。
- 新 note 是 derived，不允许直接继续编辑。
- 用户要继续编辑这些新 note，需要 Preview/Apply 或 Clear 后打开新版本。

这是当前设计的正确约束。

否则 patch identity 会再次变复杂。

## 11. 安全和边界

### 11.1 路径安全

任何 clip 来源都只能来自受管理目录：

- `.musicforge/assets/`
- `.musicforge/references/`
- `.musicforge/projects/`
- `runs/` 中被 Project Version 引用的产物

禁止：

- 用户传入任意本机路径。
- 从 request body 指定文件路径。
- 响应里返回本机绝对路径。

### 11.2 stale 校验

必须处理 stale：

- Reference slice 的 source hash 不匹配：409。
- Asset source hash 不匹配：409。
- Project Version 不存在或隐藏：404 / 409。
- Clip 来源被 delete / hide：409。

### 11.3 大小限制

建议初版限制：

- 单个 clip note 数量 <= 128。
- 单次插入生成 operations <= 160。
- duration <= 64 beats。
- request body <= 256KB。

超过返回 400：

```text
Clip is too large for editor insert. Use a smaller slice or split the source first.
```

### 11.4 音高和时值校验

必须拒绝：

- pitch < 0 或 > 127。
- duration <= 0。
- start_beat < 0。
- 插入后 start_beat 不在 song duration 内。
- velocity 超出范围且无法 clamp 的值。

### 11.5 脱敏

所有以下输出都要脱敏：

- API response clip metadata。
- Project diff / compare 中的 clip source summary。
- Project export。
- Final Export manifest。
- editor metadata。

复用：

```text
song_agent/redaction.py
```

## 12. Project metadata 接入

当用户最终 Apply 一个包含 Clip Insert 的 patch 时，child Project Version 应该记录：

```json
{
  "edit_type": "visual_editor_clip_insert",
  "clip_sources": [
    {
      "source_type": "asset",
      "source_id": "asset-...",
      "title": "Short hook",
      "note_count": 12,
      "duration_beats": 4
    }
  ],
  "target_summary": {
    "track_id": "track-002",
    "section_id": "section-003",
    "mode": "overlay"
  }
}
```

实现方式有两种：

1. 把 clip metadata 附在 patch metadata 里。
2. Apply 时从 patch operations 旁边读取 `clip_insert_summary`。

建议选 1：

```json
{
  "operations": [...],
  "metadata": {
    "clip_inserts": [...]
  }
}
```

这样：

- Project diff 可以展示来源。
- Compare 可以展示来源。
- Final Export 可以说明这个版本用了哪些素材片段。

## 17. 可能风险

### 风险 1：clip 插入产生太多 add_note operations

处理：

- v2.3.0 限制 note 数量。
- 超限提示用户先切更短 slice。
- 后续 v2.4 再考虑 compact patch op。

### 风险 2：derived notes 不能继续编辑

这是当前合理限制。

处理：

- UI 明确只让它们可见，不允许继续点选编辑。
- 用户 Apply 成新版本后再继续编辑。

### 风险 3：Reference slice stale

处理：

- 后端强制 source hash 校验。
- stale 返回 409。
- UI 提示重新 Analyze / Create Slices。

### 风险 4：Project section mixed tracks 插入复杂

处理：

- v2.3.0 优先做 single target track。
- mixed tracks 和 role mapping 放后续版本。

### 风险 5：素材 metadata 泄露本机路径

处理：

- 所有 API / export / final export 二次调用 `redaction.py`。
- release-check 加路径和 token 扫描。

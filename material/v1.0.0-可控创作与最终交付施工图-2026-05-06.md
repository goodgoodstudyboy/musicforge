# MusicForge v1.0.0 施工图：可控创作与最终交付

日期：2026-05-06

基线版本：v0.9.1

## 0. 前置结论

v0.9.1 已经修掉 CLI `--force` 不清理 `stems/` 的残留问题，v0.9.x 的 Project 工作区可以作为 v1.0.0 的稳定基线。

v1.0.0 不应该再只是“多一个按钮”或“多一个 API”。它应该让 MusicForge 从可运行的本地音乐生成工具，进入一个可以持续创作、筛选、定稿、交付的第一稳定版本。

一句话目标：

> v1.0.0 要让用户围绕 Project 的 selected/final version 生成可控变体，执行质量门禁，并把 final version 打包成可交付素材包。

## 1. 当前能力基线

截至 v0.9.1，系统已经具备：

- SongRequest -> SongPlan -> MIDI。
- local / provider generation mode。
- single / multinode pipeline mode。
- Job lifecycle：create / retry / cancel / hide / delete / stalled watchdog。
- Node retry。
- Timeline / Tracks / Nodes / Quality / Validator / SongPlan JSON / Logs / Artifacts。
- FluidSynth 整首 WAV 渲染。
- Stem MIDI / Stem WAV。
- Batch CSV 生产、Batch audio、Batch stems。
- Access token 鉴权。
- Project workspace。
- Project versions。
- selected/final version。
- Project diff/export。
- Batch 自动归档到 Project。
- release-check。

也就是说，MusicForge 已经有“生成”和“管理”。

v1.0.0 应该补“可控创作”和“最终交付”。

## 2. 为什么 v1.0.0 做这三件事

### 2.1 Project Variation

Project 已经能管理多个版本，但用户需要的是基于一个已有版本继续改，而不是每次从空白表单重新填。

典型需求：

- 基于 selected version 生成更短版本。
- 保留歌词和主题，只换风格。
- 保留风格，只调 tempo/key。
- 基于 final candidate 再生成一个更强 hook 版本。
- 记录这个版本是从哪个版本派生出来的。

所以需要 Project variation。

### 2.2 Quality Gate

v0.7 已经有质量分，但目前只是显示。到了 v1.0.0，质量应该变成工作流的一部分：

- 低于阈值的版本不建议定稿。
- final version 必须通过基础质量门禁。
- Project detail 要能显示哪个版本是 keeper。
- Batch / Project export 要带质量结论。

所以需要质量门禁。

### 2.3 Final Export Bundle

现在 Project export 只是 JSON manifest。真实交付时，用户需要一个目录或 zip：

- song-plan.json
- run-summary.json
- song.mid
- song.wav
- stem MIDI
- stem WAV
- quality-report.json
- project-export.json
- README.txt

所以需要 final export bundle。

## 3. v1.0.0 总目标

必须完成：

- Project version lineage：版本能记录 parent_version_id、variant_type、change_summary。
- 从 selected/final/任意 version 创建 variation。
- Variation 创建时复用 parent request，并允许 patch。
- 新 version 自动关联 parent version。
- Project diff 展示 parent/child 关系。
- Quality Gate：Project 级质量门禁配置和评估。
- final version 设置时执行 quality gate。
- Final Export Bundle：把 final version 的核心素材复制到 Project export bundle。
- Studio 支持 Variation、Quality Gate、Final Export。
- README / CHANGELOG / version bump 到 `1.0.0`。
- 发布 tag / GitHub Release。

建议完成：

- Project version notes 支持编辑。
- Project search/filter。
- Final bundle 可选是否包含 stem WAV。
- Final bundle 可选是否自动渲染 missing audio/stems。

暂不做：

- 不做 MIDI piano-roll 编辑器。
- 不做 section/track 局部重写。
- 不做浏览器多轨同步混音台。
- 不做 DAW 工程文件。
- 不做云同步。
- 不做用户账号系统。
- 不做数据库迁移。
- 不做自动调用付费 provider 的无限探索。

## 6. Project Quality Gate

新增模块建议：

- `song_agent/project_quality.py`

### QualityGateConfig

建议字段：

```python
@dataclass
class QualityGateConfig:
    min_overall: int = 75
    min_structure: int = 65
    min_melody: int = 65
    min_harmony: int = 60
    min_arrangement: int = 60
    allow_warnings: bool = True
    max_warnings: int = 5
    require_audio: bool = False
    require_stems: bool = False
```

Project 默认配置：

- 不要求 audio/stems，因为本机可能没有 SoundFont。
- 只要求 quality score。
- 允许 warnings，但数量不能太多。

### QualityGateResult

建议字段：

```python
@dataclass
class QualityGateResult:
    status: str
    score: int | None
    checks: list[dict[str, Any]]
    warnings: list[str]
    evaluated_at: str
```

### Gate 检查规则

必须检查：

- song-plan.json 是否存在。
- SongPlan 是否可解析。
- quality scores 是否存在或可推断。
- overall >= min_overall。
- structure/melody/harmony/arrangement 分数满足最低值。
- warnings 数量是否超过 max_warnings。
- 如果 require_audio=true，则 song.wav 存在。
- 如果 require_stems=true，则 stems manifest 存在且不 stale。

Gate 结果：

- 所有 required checks 通过：`passed`
- 分数通过但 warnings 超限或 artifact 建议项缺失：`warning`
- 分数不达标或 required artifact 缺失：`failed`
- 无 song-plan：`missing_plan`
- 解析错误：`error`

## 7. Project Variation

新增 API：

```text
POST /api/projects/<project-id>/versions/<version-id>/variation
```

Body：

```json
{
  "variant_type": "style_variation",
  "name": "Warmer synth version",
  "note": "Keep lyrics, make arrangement warmer.",
  "change_summary": "style pop -> warm synth pop; tempo unchanged",
  "request_patch": {
    "style": "warm synth pop, softer drums",
    "tempo_bpm": 96
  },
  "generation_mode": "local",
  "pipeline_mode": "multinode"
}
```

行为：

1. 读取 project。
2. 找到 parent version。
3. 找到 parent job。
4. 从 parent version.request 复制原始 request。
5. 合并 request_patch。
6. 校验 SongRequest。
7. 创建新 job。
8. 添加 ProjectVersion：
   - parent_version_id = parent version id
   - variant_type = body.variant_type
   - change_summary = body.change_summary
9. 返回 project + new version + job。

request_patch 允许字段：

- `title`
- `language`
- `style`
- `theme`
- `duration_seconds`
- `vocal_mode`
- `tempo_bpm`
- `key`
- `lyrics`
- `generation_mode`
- `pipeline_mode`

不允许任意字段直接写入 job payload。

### 从 selected/final 创建 variation

可选便捷 API：

```text
POST /api/projects/<project-id>/selected/variation
POST /api/projects/<project-id>/final/variation
```

如果实现成本高，先只做 `/versions/<version-id>/variation`，Studio 可以用 selected/final id 调同一个 API。

## 8. Final Version Gate

修改：

```text
POST /api/projects/<project-id>/final
```

当前只检查 version completed。

v1.0.0 要增加：

- 默认执行 quality gate。
- gate failed 时返回 409。
- body 支持 override：

```json
{
  "version_id": "v003",
  "force": false
}
```

行为：

- `force=false`：gate failed 则不允许 final。
- `force=true`：允许设置 final，但必须记录 event，ProjectVersion gate status 仍为 failed/warning。

建议：

- Studio 设置 final 时，如果 gate failed，显示 gate 结果。
- 如果用户再次确认，可以带 force=true。

## 9. Final Export Bundle

新增模块建议：

- `song_agent/final_export.py`

新增 API：

```text
POST /api/projects/<project-id>/final-export
GET  /api/projects/<project-id>/final-export
GET  /api/projects/<project-id>/final-export/file/<name>
```

为简化 v1.0.0，文件下载可以先只返回 manifest，不做逐文件 API。因为文件都在本机。Studio 可提供 Open Project Folder 或显示路径。

### POST /final-export

Body：

```json
{
  "version_id": "v003",
  "include_audio": true,
  "include_stems": true,
  "include_stem_audio": true,
  "force": false,
  "auto_render_missing": false
}
```

默认：

- version_id 不传则使用 final_version_id。
- include_audio=true。
- include_stems=true。
- include_stem_audio=true。
- auto_render_missing=false。

行为：

1. 找到 Project。
2. 找到目标 version。
3. 找到 job/run。
4. 执行 quality gate。
5. 如果 gate failed 且 force=false，返回 409。
6. 创建/清理 `.musicforge/projects/<id>/final-export/`。
7. 复制核心 JSON。
8. 复制 MIDI。
9. 如果 song.wav 存在，复制。
10. 如果 stem manifest 存在且未 stale，复制 stems。
11. 写 `manifest.json`。
12. 写 `README.txt`。
13. 更新 ProjectVersion.final_export_path。
14. append event。

### final-export manifest

建议：

```json
{
  "project_id": "my-song",
  "version_id": "v003",
  "job_id": "my-song-3",
  "generated_at": "...",
  "quality_gate": {...},
  "files": [
    {"kind": "song_plan", "path": "song-plan.json", "exists": true},
    {"kind": "midi", "path": "song.mid", "exists": true},
    {"kind": "audio", "path": "song.wav", "exists": true},
    {"kind": "stem_manifest", "path": "stems/manifest.json", "exists": true}
  ],
  "source": {
    "run_dir": "runs/my-song-3",
    "song_plan": "runs/my-song-3/data/song-plan.json"
  }
}
```

### README.txt

内容建议：

```text

Project: <name>

Job: <job_id>
Generated: <time>
Tempo: <tempo>
Key: <key>

- song-plan.json
- song.mid
- song.wav
- stems/

<version note>
```

## 12. 安全边界

必须遵守：

- 所有新增 API 走现有 Bearer auth。
- project_id / version_id 继续严格校验。
- final export 只能写 `.musicforge/projects/<project-id>/final-export/`。
- 复制文件时必须验证 source 在 job.output_dir 下面。
- 复制 stems 时必须校验 stem manifest 非 stale。
- 不把 provider key / access token 写入 final export。
- final README 不写本机 token 路径。
- 不允许 request_patch 写任意字段。
- 不允许 final export file API 读取任意路径。

路径安全：

```python
project_root = Path(".musicforge/projects").resolve()
export_dir = project_root / project_id / "final-export"
export_dir.resolve().relative_to(project_root)

run_dir = Path(job.output_dir).resolve()
source.resolve().relative_to(run_dir)
```

## 17. 风险点

### 17.1 范围膨胀

v1.0.0 很容易膨胀成编辑器。必须坚持：

- 不做 MIDI 编辑。
- 不做 section 局部重写。
- 不做 DAW 工程。
- 不做复杂音频混音。

### 17.2 Quality Gate 过严

如果默认 gate 太严，会导致用户无法 final。

建议默认：

- min_overall 75。
- 不强制 audio/stems。
- force=true 允许人工覆盖。

### 17.3 Final Export 路径安全

这是 v1.0.0 最重要的安全点。所有复制源必须限定在 job run_dir 内，所有输出必须限定在 Project final-export 目录内。

### 17.4 Provider 成本

Variation 如果默认 provider，会产生真实调用成本。Studio 应明确显示 generation mode，默认沿用 parent 或当前表单，不自动批量探索。

### 17.5 Stale artifacts

final export 必须复用 v0.8.1 的 stale stem 逻辑。stems manifest stale 时不能复制旧 stems。

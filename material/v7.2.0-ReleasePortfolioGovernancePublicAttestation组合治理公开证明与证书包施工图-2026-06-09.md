## 1. 当前阶段判断

截至 v7.1.1，Portfolio Governance 链路已经非常完整：

- v6.5：Portfolio Audit。
- v6.6：Portfolio Governance Queue。
- v6.7：Governance Signoff / Archive / Change Request。
- v6.8：Governance Audit Ledger。
- v6.9：Governance Reviewer Pack。
- v7.0：Governance Final Board。
- v7.1：Governance Evidence Vault。

v7.1.1 修复了 Evidence Vault verifier 的关键问题：

- `manifest.json`
- `vault-report.json`
- `package-index.json`
- `verification-index.json`
- `chain-of-custody.json`

现在这五份核心 sidecar 必须绑定同一个 `source_hash`。如果只篡改报告摘要并重算 report + manifest，而不更新三份索引，verifier 会 failed。

这意味着 Evidence Vault 已经可以作为“内部/审计方深度复验包”。

但它不适合直接给普通合作方、外部业务方、客户或发行伙伴：

- Evidence Vault 包含 nested packages，体积大。
- 里面有完整审计上下文，信息密度高。
- 外部合作方往往只需要确认：
  - 这个 Portfolio 是否最终准出？
  - 谁签核？
  - 哪个 Final Board / Vault 作为证据？
  - 对应 hash 指纹是什么？
  - 如何在需要时向内部索取完整 Vault？
  - 这份公开证明本身是否可验证？

所以 v7.2.0 要做一个轻量层：

> Public Attestation / Certificate：从已通过验证的 Evidence Vault 生成公开证明包，只携带必要摘要、签核结论、hash 指纹、verifier 状态和可读证书，不携带 nested ZIP。

## 2. v7.2.0 总目标

v7.2.0 实现：

> Release Portfolio Governance Public Attestation：基于当前 Evidence Vault verification，生成一个可公开转交、可离线验证、脱敏、安全、体积小的组合治理证书包。

它要回答：

1. 这个 Portfolio 是否已完成 Final Board 签核？
2. 对应 Evidence Vault 是否通过 strict/deep verification？
3. 这份公开证书绑定的是哪个 Vault ZIP hash？
4. 这份公开证书绑定的是哪个 Final Board signoff hash？
5. 这份公开证书是否能证明“证书内容未被篡改”？
6. 证书是否没有泄露本机路径、token、内部 nested package 内容？
7. 外部拿到证书 ZIP 后，是否能离线验证证书自洽？
8. 证书是否不可在同一个 Vault hash 下静默重建？
9. 如果 Vault 更新或 Final Board reset 后，旧证书是否 stale？
10. 是否能生成面向人看的 `CERTIFICATE.md` / `certificate.html`？

## 3. v7.2 与 v7.1 的关系

Evidence Vault 是完整证据保险库：

- 给内部治理审计。
- 给技术 reviewer。
- 给需要深度复验 nested packages 的场景。
- 可以 `--deep` 验证 Final Board / Reviewer Pack / Governance Audit / Archive / Queue。

Public Attestation 是公开证明：

- 给外部合作方。
- 给业务方看签核结论和 hash 指纹。
- 给不需要完整 nested evidence 的场景。
- 不复制 nested ZIP。
- 不暴露过多内部流程细节。

二者关系：

```text
Final Board -> Evidence Vault -> Public Attestation
```

Public Attestation 必须依赖一个当前、已验证、非 stale 的 Evidence Vault。

Public Attestation 不反向写入 Evidence Vault source hash，避免循环 stale。

## 4. 明确边界

v7.2.0 做：

- Public Attestation Store。
- Attestation Report。
- Attestation Certificate JSON。
- Human-readable `CERTIFICATE.md`。
- Optional static `certificate.html`。
- Attestation Export directory。
- Attestation ZIP。
- Offline verifier。
- API / CLI / Studio。
- release-check smoke。
- README / CHANGELOG / version bump。

v7.2.0 不做：

- 不携带 Evidence Vault nested ZIP。
- 不携带 Final Board Archive ZIP。
- 不携带 Reviewer Pack / Audit / Archive / Queue ZIP。
- 不重新验证 nested packages；nested deep verify 由 Evidence Vault verifier 负责。
- 不自动生成 Evidence Vault。
- 不自动重新签核 Final Board。
- 不自动 approve/reset Change Request。
- 不上传到 GitHub Release asset。
- 不连接外部证书签发机构。
- 不做加密签名或私钥管理。
- 不把 Attestation 写回 Vault / Final Board / Governance Audit source hash。

## 8. Source Hash 规则

Attestation source hash 必须绑定：

- Portfolio ID。
- Portfolio report hash。
- Final Board report hash。
- Final Board signoff hash。
- Final Board signoff status。
- Evidence Vault report hash。
- Evidence Vault source hash。
- Evidence Vault ZIP sha256。
- Evidence Vault ZIP size。
- Evidence Vault manifest hash。
- Evidence Vault verification report hash。
- Evidence Vault verification status。
- Evidence Vault deep verification status。
- signed queue count。
- force signed queue count。
- reviewer response status。
- attestation profile。

不要绑定：

- Attestation manifest hash。
- Attestation ZIP hash。
- Attestation verification report hash。

原因：避免自引用 stale。

## 9. Attestation Profiles

内置 profile：

### 9.1 `public_summary`

默认 profile，面向外部合作方：

- 只输出最终结论。
- 只输出 hash 指纹。
- 不输出 warnings 细节。
- 如果存在 force signoff，显示 `force_signed_queue_count`，但不输出具体 reason。

### 9.2 `partner_due_diligence`

面向更认真审查的合作方：

- 输出更多 coverage summary。
- 输出 warning count。
- 输出 reset count / change request count 的计数，不输出细节。
- 仍不携带 nested ZIP。

### 9.3 `internal_public_preview`

给内部预览公开证书：

- 可显示更详细 summary。
- 仍必须脱敏。
- 仍不输出本机路径或 token。

CLI 参数：

```powershell
--profile public_summary
--profile partner_due_diligence
--profile internal_public_preview
```

## 10. Refresh 规则

`refresh_report(portfolio_id, profile)`：

1. 读取 Portfolio。
2. 读取 Final Board report / signoff。
3. 读取 Evidence Vault report。
4. 读取 Evidence Vault ZIP。
5. 读取 Evidence Vault verification report。
6. 校验 Evidence Vault verification：
   - status == `passed`
   - `summary.deep_verification_status == passed`
   - `zip_sha256` 匹配当前 Vault ZIP
   - `zip_size_bytes` 匹配当前 Vault ZIP
   - `manifest_hash` 匹配 Vault export manifest
7. 校验 Evidence Vault report 非 stale。
8. 校验 Final Board signoff 非 stale。
9. 校验 Final Board signoff hash 与 Vault source 绑定一致。
10. 生成 Attestation Report。
11. 生成 Certificate JSON。
12. 写 history：`report_refreshed`。

失败规则：

- Final Board 未签核：failed。
- Evidence Vault ZIP 缺失：failed。
- Evidence Vault verification 缺失/failed：failed。
- Evidence Vault verification 不是 deep passed：failed。
- Evidence Vault verification 不匹配当前 ZIP/manifest：failed。
- Evidence Vault report stale：failed。
- source redaction failed：failed。
- force signoff：
  - 默认 warning。
  - `--require-no-force` 时 failed。

## 11. Export / ZIP 不可变规则

Attestation 是公开证明，也必须不可静默重建。

不可变绑定对象：

```text
evidence_vault_zip_sha256 + final_board_signoff_hash + attestation_profile
```

一旦 history 里出现：

- `attestation_exported`
- `attestation_zip_built`

且 summary 绑定同一个 triple，后续同一 triple 下再次 export / zip 必须 409。

删除 export 目录或 ZIP 也不能绕过。

要重建：

1. Final Board approved Change Request reset。
2. 重新 Final Board signoff。
3. 重新 Evidence Vault。
4. 重新 Attestation。

如果只是换 profile，可以生成另一份证书，但必须有不同 `profile`，并在 history 里独立记录。

## 13. 离线 Verifier

新增 CLI：

```powershell
python -m song_agent.cli verify-release-portfolio-governance-attestation path\to\portfolio-governance-public-attestation.zip --json --strict --require-vault --require-final-board --report-out attestation-verification-report.json
```

Verifier 检查：

### 13.1 ZIP 安全

- entry path safe。
- raw central directory backslash 检查。
- duplicate entry failed。
- absolute path / drive path / UNC / `..` failed。
- entry count 上限。
- 总解压大小上限。
- 单 entry size 上限。
- manifest extra entries strict failed。
- `manifest.zip.entries` 只作参考，不扩大允许列表。

### 13.2 必需文件

必须有：

```text
manifest.json
attestation-report.json
certificate.json
certificate.md
README.txt
```

`certificate.html` 可选，但如果存在必须被 manifest.files 覆盖。

### 13.3 证书一致性

- manifest integrity OK。
- attestation-report integrity OK。
- certificate payload hash OK。
- manifest.source_hash == attestation-report.source_hash。
- manifest.certificate.payload_hash == certificate.payload_hash。
- manifest.evidence_vault.zip_sha256 == certificate.evidence_vault.zip_sha256。
- manifest.evidence_vault.verification_hash == certificate.evidence_vault.verification_hash。
- certificate.final_board.signoff_hash == report.source.final_board_signoff_hash。
- certificate.evidence_vault.deep_verification_status == `passed` when `--require-vault`。

### 13.4 禁止 nested packages

Verifier 必须检查：

- Attestation ZIP 内不能有 `nested/`。
- Attestation ZIP 内不能有其他 `.zip`，除非未来明确允许。
- Attestation ZIP 内不能有 `.musicforge/` 路径。

命中则 failed。

### 13.5 Redaction

扫描所有 `.json` / `.txt` / `.md` / `.html`：

- `sk-...`
- GitHub token。
- Bearer token。
- Windows 盘符路径。
- UNC 路径。
- `githubkey.txt`
- `api_key`
- `access_token`
- `authorization`

命中 failed。

## 23. 风险清单

### 风险 1：公开证书泄露内部细节

处理：

- certificate 只输出 hash 和计数。
- 不输出 reviewer findings / CR reason / queue action 明细。
- redaction 扫描。

### 风险 2：证书被误当作完整证据包

处理：

- README / certificate.md 明确：完整深度证据请索取 Evidence Vault。
- verifier 只验证证书自洽，不替代 Evidence Vault deep verifier。

### 风险 3：证书和 Vault 不一致

处理：

- source hash 绑定 Vault verification report。
- refresh 时要求 Vault verification current。
- release-check 覆盖 stale Vault。

### 风险 4：同一证书静默重建

处理：

- history guard 绑定 `vault_zip_sha256 + final_board_signoff_hash + profile`。
- 删除 export/zip 后仍 409。

### 风险 5：HTML 引入脚本或外链

处理：

- certificate.html 静态生成。
- verifier 检查 `<script`、`http://`、`https://`、`src=`、`href=` 外链，发现 failed。

# v12.7.0 Unified Release Program Continuity Acceptance Board 项目级连续性交付外部灾备验收委员会施工图

日期：2026-07-08

目标版本：v12.7.0

当前基线：v12.6.0 Continuity Distribution Kit 候选实现完成后发布的稳定基线

## 1. 背景

v12.3 到 v12.6 已经把项目级证据链推进到连续性交付层：

- v12.3：Unified Release Program Evidence Vault，统一项目级证据保险库。
- v12.4：Vault Operations，保险库托管、轮换、签核、交接。
- v12.5：Continuity Recovery，项目级只读恢复演练、连续性恢复签核。
- v12.6：Continuity Distribution Kit，把 Continuity Archive、Vault Operations Archive、Evidence Vault 三个核心包固定打包成外部灾备交付套件。

v12.6 解决的是“交付包能否被离线验证”。但它还不是完整的外部验收闭环：

- 只有单个 receiver receipt，不足以表达多角色、多组织验收。
- receiver receipt 只是一个回执，缺少 Board 决策、quorum、冲突阻断和签核归档。
- Release / GA 可以要求 Continuity Kit，但还不能要求“外部灾备接收方已经完成可信验收”。

v12.7 的目标是补上这一层：把 Continuity Distribution Kit 的接收验收提升为正式的 **Continuity Acceptance Board**。

## 2. 版本目标

新增 **Unified Release Program Continuity Acceptance Board**，用于证明：

1. 当前 Unified Release Program 的 Continuity Distribution Kit 已由外部接收方验收。
2. 验收不是单条自报 receipt，而是多接收方、多组织、多角色的 Board 决策。
3. Board 的 quorum 不能信 payload 自报字段，必须从外部 response verification / binding proof / accepted evidence 反推。
4. `needs_changes` / `rejected` response 默认阻断签核。
5. Board signoff 后生成不可变 Archive ZIP，供 Release signoff / GA readiness / 离线验收使用。

## 3. 非目标

v12.7 不做以下内容：

- 不做 approved Change Request reset。签核后如需改动，必须新建 Board；CR reset 留给 v12.8。
- 不做自动批准 receiver response。
- 不做自动修改 Continuity Kit / Vault / Operations / Program 状态。
- 不做在线第三方签名或 CA 验证。
- 不做人工 UI 的完整体验优化，只接入必要 Studio 控件信号。

## 7. Board Policy

默认 Board policy：

```json
{
  "schema_version": 1,
  "min_accepted_receipts": 2,
  "min_organizations": 2,
  "required_roles": ["recovery_owner", "external_custodian"],
  "block_on_needs_changes": true,
  "block_on_rejected": true,
  "require_current_continuity_distribution_kit": true,
  "require_accepted_evidence": true,
  "allow_synthetic_receiver": false
}
```

规则：

- `accepted` 计入 quorum。
- `needs_changes` 默认 hard block。
- `rejected` 默认 hard block。
- `role` / `organization` 不能从 response payload 自报字段读取，必须从 response binding proof 或 accepted evidence proof 读取。
- `min_organizations` 按外部 proof 里的 organization 去重计算。
- `required_roles` 必须由 accepted evidence proof 覆盖。

## 8. Response 导入

### 8.1 输入要求

外部 response 必须显式包含：

```json
{
  "package_type": "musicforge_unified_release_program_continuity_acceptance_response",
  "program_id": "urp-000001",
  "kit_sha256": "...",
  "kit_manifest_hash": "...",
  "kit_verification_report_hash": "...",
  "receiver_id": "receiver-001",
  "receiver_role": "recovery_owner",
  "organization": "External Recovery Org",
  "decision": "accepted",
  "reviewed_at": "2026-07-08T00:00:00Z",
  "notes": "",
  "findings": []
}
```

禁止导入端自动补：

- `kit_sha256`
- `kit_manifest_hash`
- `kit_verification_report_hash`
- `receiver_role`
- `organization`
- `decision`

如果缺少 source binding 字段，直接 400。

### 8.2 禁止字段

导入 payload 禁止：

```text
source_path
local_path
file_path
absolute_path
token
api_key
authorization
secret
password
raw_provider_response
```

命中后返回 400，不落盘。

### 8.3 Response Verification

导入 response 后生成：

```text
response-000001-verification-report.json
response-000001-binding-summary.json
```

verification report 必须包含：

- response payload hash
- kit zip sha256
- kit manifest hash
- kit verification report hash
- receiver public projection hash
- role / organization / decision proof
- redaction status

binding summary 必须包含：

- `response_id`
- `program_id`
- `receiver_id`
- `receiver_role`
- `organization`
- `decision`
- `payload_hash`
- `kit_sha256`
- `kit_manifest_hash`
- `kit_verification_report_hash`
- `verification_report_hash`
- `integrity_hash`

## 9. Accepted Evidence

只有 `decision == accepted` 且 response verification passed 才能创建 accepted evidence。

accepted evidence 内容：

```text
accepted-evidence.json
original-response-public.json
response-verification-summary.json
response-binding-summary.json
evidence-report.json
```

Board quorum 只使用 accepted evidence 中的 proof，不使用 response payload 自报字段。

必须防止以下攻击：

- 篡改 response payload 的 `receiver_role` 后重签 response。
- 篡改 accepted-evidence 的 `organization` 后重签 evidence。
- 替换 response-verification-summary，但不匹配原始 response binding。
- 替换 response-binding-summary，使角色满足 quorum。

## 12. Signoff

### 12.1 签核输入

```json
{
  "signed_by": "program-chair",
  "role": "program_owner",
  "reason": "Continuity acceptance quorum met"
}
```

签核前必须满足：

- Board `ready_for_signoff`
- 当前 Kit runtime verification passed
- 当前 Kit verification report 与 Kit ZIP 匹配
- receiver response verification 全部 current
- accepted evidence verification 全部 current
- no rejected / needs_changes blocker
- quorum met

### 12.2 Signoff Binding

签核时必须独立落盘：

```text
signoff/continuity-acceptance-signoff-binding-summary.json
```

该 sidecar 不能在 archive/verifier 阶段现算。

必须绑定：

- `signoff_hash`
- `signoff_payload_hash`
- `history_event_hash`
- `board_report_hash`
- `decision_matrix_hash`
- `receiver_index_hash`
- `accepted_evidence_index_hash`
- `source_binding_hash`
- `kit_sha256`
- `kit_manifest_hash`
- `kit_verification_report_hash`

### 12.3 History Hash Chain

`continuity-acceptance-history.jsonl` 每条事件包含：

```json
{
  "event_type": "signoff_created",
  "created_at": "...",
  "payload_hash": "...",
  "previous_event_hash": "...",
  "event_hash": "..."
}
```

Verifier 必须重建 hash chain。

不允许：

- duplicate entry

- trailing data
- 绝对路径
- `..`

## 14. Verifier

新增 CLI：

```powershell
python -m song_agent.cli verify-unified-release-program-continuity-acceptance-package <zip> --strict --deep `
  --continuity-kit <kit.zip> `
  --continuity-kit-verification-report <kit-verification-report.json>
```

Verifier 必须校验：

### 14.1 ZIP Structure

- fixed allow-list
- no duplicate entries
- no dangerous path
- no raw backslash central directory name
- no nested ZIP
- no trailing bytes
- manifest files exact
- file hash / size exact

### 14.2 Source Binding

- Archive source 指向当前 Kit ZIP hash。
- Archive source 指向当前 Kit manifest hash。
- Archive source 指向当前 Kit verification report hash。
- Kit verification report package_type 正确。
- Kit verification report integrity OK。
- Kit verification report runtime matches current Kit ZIP。

### 14.3 Receiver Proof

- 每个 accepted quorum row 都有 response verification。
- 每个 accepted quorum row 都有 response binding summary。
- role / organization / decision 从 proof 重建。
- matrix 和 index 与 proof 重建结果一致。

### 14.4 Signoff Proof

- signoff binding sidecar integrity OK。
- signoff binding sidecar 与 signoff payload 匹配。
- signoff binding sidecar 与 history latest event 匹配。
- history hash chain OK。
- signed_by full-resign failed。

### 14.5 Redaction

扫描所有 JSON / JSONL / TXT / MD：

- OpenAI key
- GitHub token
- bearer token
- api_key
- `C:\Users\...`
- UNC path
- `.musicforge/`

## 27. 给开发的话

v12.7 的关键不是多做一个报告，而是把外部灾备验收做成可信闭环。

最容易出错的地方有三个：

1. **Quorum 不能信 payload**

   receiver response 里的 role / organization / decision 只能作为输入文本。Board 真正用于 quorum 的字段必须来自 response verification 和 accepted evidence proof。

2. **Signoff binding 不能现算**

   `continuity-acceptance-signoff-binding-summary.json` 必须在 signoff 创建时落盘。Archive 和 verifier 只能复制和校验，不能从 signoff JSON 重新计算后当成可信 proof。

3. **外部 Kit 必须 runtime 复验**

   Acceptance Archive 绑定的是某个 Continuity Distribution Kit。Release / GA gate 必须重新验证当前 Kit ZIP 和 Kit verification report，不能只看 Acceptance Archive 里写了什么。

先把 Store + verifier + 攻击回归写硬，再接 CLI/API/UI。不要先做页面。

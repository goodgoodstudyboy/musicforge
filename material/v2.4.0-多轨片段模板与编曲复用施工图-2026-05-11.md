# v2.4.0 多轨片段模板与编曲复用施工图

日期：2026-05-11

当前基线：v2.3.2

目标版本：v2.4.0

定位：在 v2.3.x 已经打通“单轨 Clip 插入 Project Editor”的基础上，把复用能力升级到“多轨编曲片段”和“Section / Track 模板”。这版的核心不是再加一个生成模型，而是让 MusicForge 开始具备真正的编曲积木能力。

---

## 1. 背景

到 v2.3.2，MusicForge 已经具备：

- Project Editor 可视化编辑。
- Editor Draft / Preview / Apply / Project Version 闭环。
- Asset / Reference MIDI slice / Project Version section 可以转为 EditorClip。
- Clip Browser 可以把素材片段插入当前 track。
- `replace_range` 已支持基于当前 Patch Queue 的累计 draft 状态计算删除目标。
- `clip_group_id` 已能区分同一 clip 同一位置但不同 transpose / velocity / replace 参数的审计记录。

这说明“素材 -> Editor Patch -> Draft -> Preview -> Apply -> Export”的主链路已经成立。

但当前 v2.3.2 仍然偏单轨：

- 一个 clip 一次只插到一个目标 track。
- 用户需要自己判断 melody / chords / bass / drums 应该映射到哪条 track。
- Project Version 中好的 section 编曲还不能作为完整模板复用。
- Reference MIDI slice 如果包含多轨信息，目前仍然落到单目标 track，编曲上下文损失较多。
- Studio 还没有“模板库”的概念，用户不能保存常用 intro / chorus / drop / bridge 结构。

v2.4.0 要解决这些问题。

---

## 2. 一句话目标

v2.4.0 要把 MusicForge 从“单轨素材插入器”推进到“编曲模板复用器”：

- 支持 MultiTrackClip：一个片段包含 melody / chords / bass / drums 等多条 lane。
- 支持 role mapping：把 clip lane 映射到当前歌曲的目标 tracks。
- 支持 Section Template：把某个 section 的结构、chords、lyrics、notes、track roles 保存为可复用模板。
- 支持 Track Template：保存常用 track 配置、instrument、role、默认 pattern。
- Studio 提供模板浏览、保存、应用、预览。
- Preview / Apply / Compare / Export / Final Export 保留完整脱敏 provenance。

---

## 3. 不做什么

v2.4.0 必须继续收住边界：

- 不做完整 DAW 拖拽编曲。
- 不做实时播放引擎。
- 不做 audio-to-MIDI。
- 不做 MP3 / FLAC import。
- 不做 AI 自动编曲 solver。
- 不做 provider 自动选择最佳插入位置。
- 不做复杂跨调式 reharmonization。
- 不做多轨混音、音量包络、pan、automation。
- 不做真实音频 waveform 编辑。

这版只做本地、确定性、可测试的模板和多轨复用。

---

## 4. 用户价值

目标用户工作流：

1. 从一个好版本里抽出 chorus 编曲。
2. 保存成 `Chorus Lift Template`。
3. 打开另一首歌的 Project Editor。
4. 在 Clip / Template Browser 里选这个模板。
5. 系统根据 role 自动建议：
   - melody -> lead melody
   - chords -> piano / synth chords
   - bass -> bass
   - drums -> drums
6. 用户确认 mapping 和目标 section。
7. Draft Apply 看到多条 lane 同时变化。
8. Preview 生成 MIDI。
9. Apply 成新的 Project Version。
10. Export 里能看到这个版本用了哪个模板、插入到哪里、映射了哪些轨道。

这会让 MusicForge 从“能生成歌”变成“能积累编曲资产并复用”。

---

## 5. 总体架构

v2.4.0 建议新增一个 Template / MultiTrackClip 层：

```text
Project Version / Asset / Reference Slice
        |
        v
MultiTrackClip / SectionTemplate / TrackTemplate
        |
        v
Role Mapping Planner
        |
        v
Editor Patch operations
        |
        v
Draft / Preview / Apply / Version / Export
```

核心原则：

- 不绕过现有 `song_editor.py` patch engine。
- 不直接写 SongPlan。
- 所有应用行为最终都变成 Editor Patch。
- Draft 不落盘。
- Preview / Apply 继续使用已有审计和版本链路。

## 6. 新增核心概念

### 6.1 MultiTrackClip

建议新增：

```text
song_agent/editor_templates.py
```

或拆分：

```text
song_agent/editor_multitrack_clips.py
song_agent/editor_templates.py
```

如果开发希望更稳，建议先放一个文件，后续再拆。

结构：

```python
MultiTrackClip
- schema_version: int
- clip_id: str
- source_type: "project_section" | "reference_midi" | "asset_bundle" | "template"
- source_id: str
- title: str
- duration_beats: float
- key: str
- tempo_bpm: int | None
- lanes: list[MultiTrackClipLane]
- metadata: dict
```

### 6.2 MultiTrackClipLane

```python
MultiTrackClipLane
- lane_id: str
- role: "melody" | "chords" | "bass" | "drums" | "countermelody" | "pad" | "fx" | "unknown"
- name: str
- instrument: str
- notes: list[ClipNote]
- chords: list[str]
- lyrics: str
- metadata: dict
```

约束：

- 每条 lane 的 notes 都从 0 beat 归一化。
- lane 数量建议上限 8。
- 单 lane note 上限 128。
- 整个 MultiTrackClip note 上限 384。
- duration 上限 64 beats。

### 6.3 Role Mapping

用户选择多轨 clip 后，必须决定每个 lane 应该去哪里：

```json
{
  "lane_mappings": [
    {
      "lane_id": "lane-melody",
      "target_track_id": "track-001",
      "mode": "overlay"
    },
    {
      "lane_id": "lane-bass",
      "target_track_id": "track-003",
      "mode": "replace_range"
    }
  ]
}
```

系统可以建议 mapping，但不能静默决定所有操作。

### 6.4 SectionTemplate

用于复用一个完整段落。

```python
SectionTemplate
- template_id: str
- name: str
- section_name: str
- bars: int
- chords: list[str]
- lyrics_mode: "empty" | "placeholder" | "source_excerpt"
- clip: MultiTrackClip
- source_summary: dict
- tags: list[str]
- hidden: bool
- created_at / updated_at
```

保存目录建议：

```text
.musicforge/editor-templates/section-templates/<template-id>/template.json
```

### 6.5 TrackTemplate

用于复用 track 设置或 pattern：

```python
TrackTemplate
- template_id: str
- name: str
- role: str
- instrument: str
- default_notes: list[ClipNote]
- tags: list[str]
- hidden: bool
- created_at / updated_at
```

保存目录建议：

```text
.musicforge/editor-templates/track-templates/<template-id>/template.json
```

## 7. 后端模块设计

### 7.1 新增 `song_agent/editor_templates.py`

职责：

- 持久化 SectionTemplate / TrackTemplate。
- 从 Project Version section 抽取 SectionTemplate。
- 从 current EditorClip / MultiTrackClip 保存模板。
- 列表、读取、隐藏、删除、导出脱敏 summary。
- 校验 source hash。

建议类：

```python
class EditorTemplateStore:
    def list_section_templates(...)
    def list_track_templates(...)
    def create_section_template_from_project_version(...)
    def create_track_template_from_project_version(...)
    def read_section_template(...)
    def read_track_template(...)
    def hide_template(...)
    def delete_template(...)
```

必须加 `RLock`，参考：

- `ContextPackStore`
- `AssetStore`
- `ReferenceStore`

### 7.2 新增或扩展 `song_agent/editor_clips.py`

v2.3 的 `EditorClip` 是单轨。

v2.4 可以有两种实现方式：

#### 方案 A：新增 MultiTrackClip，不破坏 EditorClip

优点：

- 低风险。
- 兼容 v2.3 API。
- 单轨和多轨逻辑边界清楚。

建议采用方案 A。

#### 方案 B：让 EditorClip 支持 lanes

缺点：

- 容易影响现有单轨测试。
- 需要大量兼容判断。

不建议 v2.4.0 做。

### 7.3 新增 MultiTrackClip builder

建议函数：

```python
def build_multitrack_clip_from_project_section(project_id, version_id, section_id, *, project_store) -> MultiTrackClip:
    ...

def build_multitrack_clip_from_reference_midi(reference_id, slice_id, *, reference_store) -> MultiTrackClip:
    ...

def build_multitrack_clip_from_template(template_id, *, template_store) -> MultiTrackClip:
    ...
```

Project section builder 要做：

- 读取 source version 的 `song-plan.json`。
- 找到 section 范围。
- 对每条 track 抽取此范围内的 notes。
- 每条 track 生成一条 lane。
- lane role 由 track name / instrument / role heuristic 推断。
- note start 归一化为 section 内相对 beat。

Reference MIDI builder 要做：

- 仅支持已分析、fresh 的 MIDI reference。
- 读取 slice manifest。
- 尽量按 track / channel 分 lane。
- 如果分析层暂时无法保留多轨，先按 channel 分。
- drums channel 9 映射为 drums lane。

### 7.4 Role mapping planner

建议函数：

```python
def suggest_lane_mappings(clip: MultiTrackClip, editor_state: dict) -> list[dict]:
    ...
```

规则：

- lane.role 完全匹配 track.role，得分最高。
- track.name 包含 role 关键词，次高。
- instrument 包含关键词，次高。
- 如果无匹配，则 mapping 标记为 `unmapped`。

返回：

```json
{
  "lane_id": "lane-001",
  "lane_role": "bass",
  "suggested_track_id": "track-003",
  "confidence": 0.87,
  "reason": "role match: bass"
}
```

### 7.5 MultiTrack insert patch builder

建议函数：

```python
def build_multitrack_clip_insert_patch(parent_plan, clip, payload, *, current_patch=None) -> tuple[patch, summary, warnings]:
    ...
```

它应该复用 v2.3 的单轨 insert 逻辑，但注意：

- 每个 lane 独立生成 operations。
- 每个 lane 有自己的 `clip_group_id` 或共享一个 `template_group_id`。
- metadata 要记录 lane mapping。
- `replace_range` 按 lane 的 target track 分别计算。
- derived notes 继续不能被删除。

metadata 建议：

```json
{
  "template_inserts": [
    {
      "template_group_id": "template-...",
      "source_type": "section_template",
      "source_id": "section-template-001",
      "title": "Chorus Lift",
      "duration_beats": 16,
      "lane_count": 4,
      "note_count": 96,
      "target": {
        "section_id": "section-003",
        "start_beat": 32
      },
      "lane_mappings": [
        {
          "lane_id": "lane-bass",
          "source_role": "bass",
          "target_track_id": "track-003",
          "mode": "replace_range",
          "inserted_note_count": 24,
          "replaced_note_count": 12
        }
      ]
    }
  ]
}
```

为了兼容，也可以继续写：

```json
"clip_inserts": [...]
```

但更建议新增 `template_inserts`，不要把多轨模板伪装成普通 clip。

## 8. API 设计

所有 API 继续走现有 auth。

### 8.1 模板列表

```http
GET /api/editor-templates
```

返回：

```json
{
  "section_templates": [],
  "track_templates": [],
  "limits": {
    "max_lanes": 8,
    "max_notes": 384
  }
}
```

也可以拆：

```http
GET /api/editor-templates/sections
GET /api/editor-templates/tracks
```

建议初版用一个聚合接口，Studio 简单。

### 8.2 从 Project Version 保存 Section Template

```http
POST /api/projects/<project_id>/versions/<version_id>/section-templates
```

请求：

```json
{
  "section_id": "section-003",
  "name": "Chorus Lift",
  "tags": ["chorus", "lift", "pop"],
  "include_roles": ["melody", "chords", "bass", "drums"]
}
```

返回：

```json
{
  "ok": true,
  "template": {}
}
```

### 8.3 从 Project Version 保存 Track Template

```http
POST /api/projects/<project_id>/versions/<version_id>/track-templates
```

请求：

```json
{
  "track_id": "track-003",
  "name": "Eight note synth bass",
  "range": {
    "start_beat": 32,
    "end_beat": 48
  },
  "tags": ["bass", "synth"]
}
```

### 8.4 MultiTrack Clip Draft

```http
POST /api/projects/<project_id>/versions/<version_id>/editor-multitrack-clip-draft
```

请求：

```json
{
  "source_ref": {
    "source_type": "section_template",
    "template_id": "section-template-001"
  },
  "current_patch": {},
  "target": {
    "section_id": "section-003",
    "start_beat": 32
  },
  "lane_mappings": [
    {
      "lane_id": "lane-melody",
      "target_track_id": "track-001",
      "mode": "overlay"
    },
    {
      "lane_id": "lane-bass",
      "target_track_id": "track-003",
      "mode": "replace_range"
    }
  ],
  "options": {
    "transpose": 0,
    "velocity_scale": 1.0,
    "trim_to_section": true,
    "quantize_grid": null
  }
}
```

返回：

```json
{
  "patch": {},
  "combined_patch": {},
  "draft_view": {},
  "summary": {},
  "template_summary": {},
  "mapping_suggestions": [],
  "warnings": []
}
```

### 8.5 Mapping 建议接口

```http
POST /api/projects/<project_id>/versions/<version_id>/editor-template-mapping
```

请求：

```json
{
  "source_ref": {
    "source_type": "section_template",
    "template_id": "section-template-001"
  }
}
```

返回：

```json
{
  "clip": {},
  "suggestions": []
}
```

这个接口不生成 patch，只给 UI 做预填。

## 10. 安全与边界

### 10.1 路径安全

模板只能来自：

- `.musicforge/editor-templates/`
- `.musicforge/projects/`
- `.musicforge/references/`
- `.musicforge/assets/`

禁止：

- 请求体传本机路径。
- 模板 JSON 内引用任意本机文件。
- API response 暴露绝对路径。

### 10.2 stale 校验

SectionTemplate 必须记录：

```json
{
  "source_project_id": "...",
  "source_version_id": "...",
  "source_plan_hash": "..."
}
```

如果来源仍存在，读取时可以标记：

- `fresh`
- `source_missing`
- `source_changed`

注意：模板一旦保存，应该是可独立复用的快照，不因为 source changed 直接不可用。

区别：

- Reference slice：stale 要拒绝，因为 slice 依赖源文件分析。
- SectionTemplate：source changed 只提示，不拒绝，因为模板已经是独立快照。

### 10.3 大小限制

建议限制：

- max lanes：8
- max notes per lane：128
- max notes total：384
- max generated operations：500
- max template duration：64 beats
- max template JSON：512KB

如果 operations 超过现有 editor patch 上限，需要先扩展 `MAX_EDITOR_OPERATIONS`，但要谨慎。

建议 v2.4.0 不直接把 `MAX_EDITOR_OPERATIONS` 拉太高。

更稳的做法：

- 多轨模板 note 总数先限制在 180 以内。
- 后续 v2.4.1 再评估 compact operation。

### 10.4 冲突规则

必须拒绝：

- lane target track 不存在。
- lane target track 是 derived track。
- lane role 是 drums 但目标 track 明显不是 drums，除非用户明确确认。v2.4.0 可以先 warning，不强拒绝。
- 同一个 lane 映射到多个 tracks。
- 两个 lanes 使用 replace_range 映射到同一个 track 且范围重叠。
- 插入后 note 超出 song 总长度。

### 10.5 脱敏

所有输出都要走：

```text
song_agent/redaction.py
```

必须覆盖：

- template metadata
- template source summary
- project export
- final export manifest
- compare
- edit metadata
- event log

## 15. 风险与处理

### 风险 1：operations 数量过大

处理：

- 初版限制模板 note 总数。
- 超限返回 400，提示拆短模板。
- 不急着扩 `MAX_EDITOR_OPERATIONS`。

### 风险 2：多 lane replace 冲突

处理：

- 检测同 target track overlapping replace range。
- v2.4.0 直接拒绝。
- 后续再做高级合并。

### 风险 3：role mapping 错误

处理：

- mapping 只是建议。
- UI 必须让用户确认。
- 未匹配 lane 默认 skip。

### 风险 4：模板来源变化

处理：

- SectionTemplate 是快照，可继续用。
- 只在 UI 显示 source changed warning。
- Reference slice 仍然按 v2.3 逻辑 stale 拒绝。

### 风险 5：provenance 泄露敏感信息

处理：

- 所有 summary 二次脱敏。
- release-check 加 token/path 扫描。

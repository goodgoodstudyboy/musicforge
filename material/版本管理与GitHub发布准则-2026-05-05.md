# 版本管理与 GitHub 发布准则

日期：2026-05-05

## 目标

本项目以后不能只用 Git commit hash 交流版本，例如 `03fbb5e`。commit hash 适合开发者定位代码，但不适合项目验收、发版、回滚和沟通。

以后项目管理统一使用数字版本号，例如：

```text
v0.1.0
v0.1.1
v0.2.0
```

当前代码状态建议标记为：

```text
v0.1.0 - Local Graph MIDI MVP
```

原因是当前项目已经完成第一个本地可验证闭环：

```text
song_request.json
  -> song-plan.json
  -> song.mid
```

## 两套标识的区别

### Git commit hash

例子：

```text
03fbb5e
```

用途：

- 开发内部定位某一次提交。
- code review 时精确指向代码状态。
- 排查 bug 时追踪变化。

不适合：

- 作为产品版本。
- 作为发布版本。
- 给非开发人员沟通。

### 数字版本号

例子：

```text
v0.1.0
```

用途：

- 阶段验收。
- 发版。
- GitHub Release。
- 回滚。
- 文档说明。
- 给开发排期。

以后对外讨论项目能力时，优先说数字版本。

## 版本号规则

采用语义化版本：

```text
v主版本.次版本.修订版本
```

例如：

```text
v0.1.0
v0.1.1
v0.2.0
v1.0.0
```

含义：

- `主版本`：大架构变化或不兼容变更。
- `次版本`：新增一个明确阶段能力。
- `修订版本`：bug fix、小优化、测试补充、文档修正。

在 `v1.0.0` 之前，项目处于快速迭代期，统一使用：

```text
v0.x.y
```

## 每次发版必须做的事

1. 更新 `pyproject.toml` 里的版本号。
2. 更新 `CHANGELOG.md`。
3. 跑测试。
4. 跑本地 CLI 验收。
5. 提交代码。
6. 打 Git tag。
7. 推送代码和 tag 到 GitHub。
8. 在 GitHub 创建 Release。

## 开发如何推送 GitHub

### 1. 查看当前状态

在项目目录执行：

```powershell
git status
```

如果看到类似：

```text
On branch master
Your branch is up to date with 'origin/master'.
nothing to commit, working tree clean
```

说明当前没有未提交改动。

### 2. 查看远程仓库

```powershell
git remote -v
```

应该看到：

```text
origin  https://github.com/<github-username>/<repo-name>.git (fetch)
origin  https://github.com/<github-username>/<repo-name>.git (push)
```

如果没有 `origin`，添加：

```powershell
git remote add origin https://github.com/<github-username>/<repo-name>.git
```

### 3. 正常提交代码

查看改动：

```powershell
git status
```

添加改动：

```powershell
git add .
```

提交：

```powershell
git commit -m "feat: describe the change"
```

提交信息建议使用这些前缀：

```text
feat: 新功能
fix: bug 修复
docs: 文档
test: 测试
chore: 工程杂项
refactor: 重构
```

例子：

```powershell
git commit -m "docs: add changelog for v0.1.0"
```

### 4. 推送代码

```powershell
git push
```

如果是第一次推送当前分支：

```powershell
git push -u origin master
```

### 5. 如果 GitHub 要求登录

GitHub 现在不支持账号密码推送，需要使用 Personal Access Token。

如果提示用户名：

```text
Username for 'https://github.com':
```

输入 GitHub 用户名：

```text
<github-username>
```

如果提示密码或 token：

```text
Password or token prompt from GitHub
```

不要输入 GitHub 登录密码，要输入 GitHub token。

token 应保存在仓库外的安全位置，例如系统凭据管理器、密码管理器，或本机未被 Git 跟踪的私有文件。

注意：

- 不要把 token 写进代码。
- 不要提交任何保存 token 的本地文件。
- 不要把 token 写进 README、material 或 commit message。
- 不要把远程地址改成带 token 的 URL。

正确 remote URL 应该是：

```text
https://github.com/<github-username>/<repo-name>.git
```

错误做法：

```text
把 token 拼进 remote URL
```

## 如何发布 v0.1.0

### 1. 确认版本号

检查 `pyproject.toml`：

```powershell
Get-Content pyproject.toml
```

应该有：

```toml
version = "0.1.0"
```

如果不是，修改为：

```toml
version = "0.1.0"
```

### 2. 新增或更新 CHANGELOG

新增：

```text
CHANGELOG.md
```

写入 `v0.1.0` 的内容。

### 3. 跑测试

```powershell
python -m pytest -q
```

必须通过。

### 4. 跑本地验收

```powershell
python -m song_agent.cli examples\song_request.json --out runs\release-check --force
```

必须生成：

```text
runs/release-check/data/request.json
runs/release-check/data/song-plan.json
runs/release-check/data/run-summary.json
runs/release-check/logs/events.jsonl
runs/release-check/renders/song.mid
```

### 5. 提交 CHANGELOG

```powershell
git status
git add CHANGELOG.md pyproject.toml
git commit -m "docs: release v0.1.0"
```

如果 `pyproject.toml` 没变化，可以不加它。

### 6. 打 tag

```powershell
git tag -a v0.1.0 -m "v0.1.0 Local Graph MIDI MVP"
```

查看 tag：

```powershell
git tag
```

查看当前 tag 详情：

```powershell
git show v0.1.0
```

### 7. 推送代码和 tag

```powershell
git push
git push origin v0.1.0
```

也可以一次推送所有 tag：

```powershell
git push --tags
```

项目里更建议明确推送单个 tag：

```powershell
git push origin v0.1.0
```

### 8. 在 GitHub 创建 Release

打开：

```text
https://github.com/<github-username>/<repo-name>/releases
```

点击：

```text
Draft a new release
```

填写：

```text
Tag: v0.1.0
Release title: v0.1.0 - Local Graph MIDI MVP
```

Release notes 可以写：

```markdown
## Added
- Local graph runner.
- Deterministic composer.
- SongPlan schema and validator.
- Standard MIDI writer.
- CLI full local generation flow.
- Run artifacts, events log, and run summary.
- Resume guard and force overwrite.
- MIDI semantic tests.

## Verified
- `python -m pytest -q`
- `python -m song_agent.cli examples\song_request.json --out runs\release-check --force`
```

然后点击：

```text
Publish release
```

## Tag 准则

- 每个可验收版本必须有 tag。
- tag 名必须是 `vX.Y.Z` 格式。
- 不要给半成品打正式 tag。
- bug fix 用 `v0.1.1`、`v0.1.2`。
- 新阶段能力用 `v0.2.0`、`v0.3.0`。
- tag 一旦推到 GitHub，原则上不要删除或改写。

如果 tag 打错但还没推送，可以本地删除：

```powershell
git tag -d v0.1.0
```

如果 tag 已经推送到 GitHub，不要自己随便删，先沟通。

## 分支准则

当前阶段保持简单：

```text
master
```

所有稳定提交都进 `master`。

多人协作后再考虑：

```text
master/main      稳定分支
dev              集成分支
feature/*        功能分支
fix/*            修复分支
```

现在不需要过早复杂化。

## 发版验收清单

发版前必须确认：

- `git status` 干净。
- `pyproject.toml` 版本正确。
- `CHANGELOG.md` 已更新。
- `python -m pytest -q` 通过。
- CLI 本地闭环通过。
- `song.mid` 能生成。
- tag 已创建。
- tag 已推送到 GitHub。
- GitHub Release 已创建。

## 1. 当前阶段判断

MusicForge 目前已经不是“能不能生成歌”的阶段，也不是“能不能导出发布包”的阶段。

截至 v6.9.1，系统已经有：

- 单曲生成、编辑、试听、修订、母带、编码格式验收。
- Project / Release / Distribution / Submission 全流程交付。
- 人工听审、Human Review Pack、Acceptance Analytics、Fix Sprint、Knowledge Base。
- Release Operations Dashboard / Runbook / Signoff / Archive / Audit Ledger / Reviewer Pack。
- Release Portfolio Audit。
- Portfolio Governance Queue。
- Portfolio Governance Signoff / Archive / Change Request。
- Portfolio Governance Audit Ledger。
- Portfolio Governance Reviewer Pack。

v6.9.1 已修复 Reviewer Pack 对 Governance Audit verification report 的证据绑定问题：

- Audit verification report 输出 `zip_sha256`、`zip_size_bytes`、`manifest_hash`。
- Reviewer Pack 会拒绝 stale Governance Audit verification。

这意味着 Portfolio 层已经具备：

1. 机器可审计证据链。
2. 人可读审查包。
3. 离线 verifier。
4. 治理队列签核和归档。
5. Change Request reset 机制。

但还缺最后一道“组合治理最终准出”：

> 一个 Portfolio 什么时候可以被正式认定为治理闭环完成？谁签核？依据哪些审查包和 verifier？外部 reviewer 的意见怎么导入？签核后如何归档？签核后如果要改，怎么重开？

v7.0.0 要补这个。

## 2. v7.0.0 总目标

v7.0.0 实现：

> Release Portfolio Governance Final Board：基于 v6.9 Reviewer Pack、v6.8 Audit Ledger、v6.7 Governance Archive、v6.5 Portfolio Audit 的最终组合治理委员会签核、外部审查意见导入、Final Board Archive、离线 verifier 和重开变更控制。

它要回答：

1. 这个 Portfolio 的组合治理是否可以最终准出？
2. 最终准出的依据是什么？
3. Reviewer Pack 是否是当前、已验证、未篡改的？
4. Governance Audit Ledger 是否完整？
5. Governance Archive verification 是否覆盖所有 signed queue？
6. 是否存在 force signoff？如果有，是否允许最终准出？
7. 是否存在 reset？是否有 approved Change Request 因果绑定？
8. 是否收到外部 reviewer 意见？意见是否被处理？
9. 最终签核人是谁？签核原因是什么？
10. 签核后是否禁止静默修改？
11. 需要重开时是否必须走 approved Final Board Change Request？
12. 外部拿到 Final Board Archive ZIP 后，是否能离线验证完整证据链？

## 3. v7.0 为什么是大版本

v7.0.0 是治理链路的一个自然大版本，不是普通 feature release。

前面 v1 到 v5 主要解决：

- 生成。
- 编辑。
- 项目版本。
- 人工听审。
- 音频验收。
- 发行交付。

v6 主要解决：

- Release Operations。
- Portfolio Audit。
- Portfolio Governance。
- Portfolio Governance Audit Ledger。
- Portfolio Governance Reviewer Pack。

v7 开始解决：

> 治理结论本身如何正式准出、归档、被外部审查、被重开、被追责。

因此 v7.0.0 需要比 v6.x 小版本更大一步。

## 8. Final Board Gates

Final Board Report 必须计算 gate。

### 8.1 必需 Gate

```text
portfolio_exists
portfolio_report_current
governance_audit_report_current
governance_audit_report_integrity
governance_audit_ledger_chain
governance_audit_verification_current
governance_reviewer_pack_report_current
governance_reviewer_pack_verification_current
signed_queue_coverage
archive_verification_coverage
reset_change_request_causality
reviewer_response_closed
redaction_scan
```

### 8.2 可选 Gate

配置字段：

```json
{
  "require_no_force": false,
  "require_reviewer_response": false,
  "require_reset_cr_causality": true,
  "require_archives": true,
  "require_reviewer_pack": true,
  "allow_warning_signoff": false
}
```

Gate：

```text
no_force_signoff
external_reviewer_response_required
all_warnings_acknowledged
```

### 8.3 失败口径

- 底层 Audit Report stale：failed。
- Audit verification 不匹配当前 Audit ZIP：failed。
- Reviewer Pack verification 不匹配当前 Reviewer Pack ZIP：failed。
- Governance Archive verification missing：failed。
- Reset 没有 approved/applied CR：failed。
- reviewer response 中存在 unresolved blocker：failed。
- redaction failed：failed。

```json
  },
  "decision": "accepted",
  "findings": [
    {
      "finding_id": "finding-001",
      "severity": "medium",
      "status": "closed",
      "category": "force_signoff",

      "resolution_note": "Accepted for this cycle."
    }
  ],
  "notes": "Reviewer notes.",
  "integrity_hash": "sha..."

```

Import API 只接受 JSON body，不接受 `source_path`。

拒绝字段：

- `source_path`
- `local_path`
- `file_path`
- `raw_file`
- `token`
- `api_key`

Reviewer response 规则：

- 必须绑定当前 Reviewer Pack source hash。
- 必须绑定当前 Reviewer Pack ZIP sha。
- 必须绑定当前 Reviewer Pack verification hash。
- `decision` 支持：
  - `accepted`
  - `accepted_with_notes`
  - `needs_changes`
  - `rejected`
- `needs_changes` / `rejected` 会让 Final Board report failed，直到新增 accepted response 或手动 acknowledge。

## 10. Final Board Signoff

文件：

```text
final-board-signoff.json
```

结构：

```json
{
  "schema_version": 1,
  "signoff_id": "fgs-000001",
  "portfolio_id": "pfa-000001",
  "status": "signed",
  "signed_at": "2026-06-08T00:00:00Z",
  "signed_by": "manager",
  "role": "portfolio_governance_owner",
  "reason": "Portfolio governance evidence reviewed.",
  "force": false,
  "override_reason": null,
  "source": {
    "final_board_report_hash": "sha...",
    "final_board_report_source_hash": "sha...",
    "reviewer_pack_verification_hash": "sha...",
    "reviewer_pack_zip_sha256": "sha...",
    "governance_audit_verification_hash": "sha...",
    "governance_audit_zip_sha256": "sha..."
  },
  "evidence": {
    "report_status": "passed",
    "gate_status": "passed",
    "reviewer_response_status": "accepted",
    "archive_coverage_status": "passed"
  },
  "integrity_hash": "sha..."
}
```

Status：

- `draft`
- `signed`
- `force_signed`
- `reset`

Normal signoff 条件：

- Final Board Report status `passed`。
- Report integrity OK。
- Report source current。
- Reviewer Pack verification current。
- Audit verification current。
- Archive coverage passed。
- reviewer responses closed。
- redaction passed。

Force signoff 条件：

- 只允许 warning，不允许 blocking failed。
- 必须有 `override_reason`，长度建议 >= 20。
- 不能绕过：
  - stale reviewer pack。
  - stale audit verification。
  - failed ledger chain。
  - failed archive verification。
  - redaction failed。
  - unresolved reviewer response blocker。
  - invalid change request causality。

```json
  },
```

## 13. 离线 Verifier

新增：

```text
song_agent/release_portfolio_governance_final_board_verifier.py
```

CLI：

```text
python -m song_agent.cli verify-release-portfolio-governance-final-board-package <zip>
```

参数：

```text
--json
--report-out <path>
--strict
--require-signed
--require-reviewer-pack
--require-audit
--require-archives
--require-reviewer-response
--require-no-force
--require-reset-cr-causality
```

Verifier 必须检查：

ZIP：

- open。
- size limit。
- uncompressed size limit。
- entry count limit。
- duplicate entry。
- raw backslash entry。
- unsafe path。
- required entries。

Manifest：

- package_type。
- manifest integrity。
- files shape。
- file size / sha256。
- manifest.zip.entries 不得放行 extra entry。

Documents：

- final-board-report integrity。
- final-board-signoff integrity。
- reviewer response summary integrity。
- change requests integrity。
- history JSONL parse。
- manifest references match sidecar hash。

Evidence binding：

- signoff source report hash == report integrity hash。
- signoff source reviewer pack verification hash == manifest reviewer pack evidence hash。
- signoff source audit verification hash == manifest audit evidence hash。
- reviewer pack verification report summary passed。
- audit verification report summary passed。
- archive coverage summary passed。

Requirements：

- `--require-signed`：signoff status signed / force_signed。
- `--require-reviewer-pack`：Reviewer Pack evidence passed/current。
- `--require-audit`：Audit evidence passed/current。
- `--require-archives`：archive coverage passed。
- `--require-reviewer-response`：at least one accepted reviewer response current。
- `--require-no-force`：no force signoff。
- `--require-reset-cr-causality`：reset CR causality passed。

Redaction：

- JSON / JSONL / MD / TXT / CSV full scan。
- blocked keys scan。

Verifier report 必须输出：

```json
{
  "zip_sha256": "sha...",
  "zip_size_bytes": 123,
  "manifest_hash": "sha..."
}
```

- reset without approved CR -> 409。
- approved CR reset -> allowed once。

## 21. 安全要求

### 21.1 Path Safety

- 所有路径必须 resolve。
- 写入只能在 `governance-final-board/` 目录下。
- ZIP entry 只允许 POSIX relative path。
- 禁止反斜杠。
- 禁止 `..`。
- 禁止 drive prefix。
- 禁止 symlink。

### 21.2 ZIP Safety

- duplicate entry 构建时拒绝。
- verifier raw central directory name scan。
- ZIP size limit。
- uncompressed size limit。
- entry count limit。

### 21.3 Redaction

扫描：

- JSON。
- JSONL。
- Markdown。
- TXT。
- CSV。

敏感模式：

- token。
- GitHub token。
- API key。
- Bearer。
- Windows drive path。
- UNC path。
- local path。

blocked keys：

```text
api_key
token
access_token
authorization
secret
source_path
local_path
file_path
absolute_path
raw_provider_response
provider_snapshot
```

### 21.4 Source Path 禁止

Reviewer response import 禁止：

```json
{
  "source_path": "C:\\..."
}
```

必须由 JSON body 传入结构化数据。

# v11.8.0 Unified Command Center Release Train Lifecycle Audit 发版列车生命周期审计与证据总账施工图

> 目标读者：开发执行人员、测试验收人员、后续 reviewer  
> 当前稳定基线：v11.7.0  
> 建议下一版：v11.8.0  
> 核心目标：把 v11.6 Release Train 和 v11.7 Change Control 产生的签核、重开、继任签核、archive-history、reset proof、外部 evidence manifest、verification report 统一收敛成一个可离线审计的 Release Train Lifecycle Ledger。它不替代 Train / Change Control，而是作为更高一层的“列车生命周期总账”和准出证据。

---

## 1. 背景

v11.6.1 已经解决：

- Release Train 可以聚合多个 Unified Command Center。
- Train archive 有固定结构 ZIP。
- Train verifier 需要 external evidence manifest。
- `require_signed=true` 必须传外部 `train-signoff-binding-summary.json`，防止 ZIP 内部全量重签伪造 signer。
- Release / GA gate 可以要求当前 signed train。

v11.7.0 又补齐：

- Train Change Request。
- Approved single-use CR。
- Reset proof。
- CR binding report。
- Archive history。
- Reset 后 train 进入非 release-ready 状态。
- 继任 signoff 后重新 signoff / archive / verify。
- Change Control ZIP 和 offline verifier。

现在剩下的问题不是某个单点缺口，而是“证据链太分散”：

1. 当前 train 状态在 Release Train archive / verification report 里。
2. reset 证据在 Change Control package 里。
3. 旧签核和旧 archive 在 archive-history 里。
4. request / approval / reset proof 分散在 change-requests 子目录。
5. Release / GA gate 主要看 current train，Change Control 是独立证明。
6. Reviewer 想复盘一次 train 生命周期时，需要手工拼接很多文件。

v11.8 要把这些分散证据整理成一条可审计、可复验、可交付的生命周期总账：

> 这个 train 从创建到当前签核，中间发生过哪些 reset？每次 reset 是否有 approved single-use CR？旧 archive 是否保留？继任签核是否重新验证？当前 release-ready 状态是否绑定最新 train archive？这些都要能在一个 Lifecycle Audit 包里离线证明。

## 2. 版本定位

### 2.1 建议命名

**Unified Command Center Release Train Lifecycle Audit**

中文名：

**统一总控发版列车生命周期审计与证据总账**

### 2.2 一句话定位

v11.8 是 Release Train 的生命周期审计层：它把 v11.6 的 current train 和 v11.7 的 change-control/reset 历史合成一份固定结构、可离线验证、可接入 Release/GA gate 的 lifecycle ledger。

### 2.3 v11.8 要解决什么

必须解决：

1. 生成 Train Lifecycle Report。
2. 生成 hash-chained Lifecycle Ledger。
3. 生成 Signoff Succession Map。
4. 生成 Change Request / Reset Coverage Matrix。
5. 生成 Archive History Index。
6. 生成 Current Readiness Assertion。
7. 生成 Gap Plan。
8. 导出固定结构 Lifecycle Audit ZIP。
9. 提供 offline verifier。
10. Release signoff / GA readiness 可以要求 lifecycle audit。
11. CLI / API / Studio 接入。
12. release-check 增加 v11.8 smoke。

### 2.4 v11.8 不做什么

不做：

1. 不自动 approve CR。
2. 不自动 reset train。
3. 不自动 signoff train。
4. 不自动修改 child UCC。
5. 不把 Train ZIP、Change Control ZIP、UCC ZIP 嵌进 Lifecycle ZIP。
6. 不做真实 PKI / timestamp / notarization。
7. 不替代 v11.6 train verifier。
8. 不替代 v11.7 change-control verifier。
9. 不做跨仓库在线同步。
10. 不把旧 archive 复制进 Lifecycle ZIP。

## 3. 为什么这版应该做总账，而不是继续加小功能

v11.0 到 v11.7 已经形成了完整顶层治理链：

1. v11.0：Unified Command Center。
2. v11.1：UCC Signoff / Archive / Handoff。
3. v11.2：Continuous Review。
4. v11.3：Drift Response。
5. v11.4：Evidence Review / Replay。
6. v11.5：Reviewer Decision Board。
7. v11.6：Release Train。
8. v11.7：Release Train Change Control。

继续给 train 加更多局部按钮，会让系统越来越碎。v11.8 应该开始把 v11.6 / v11.7 的证据打通：

- 开发人员需要知道当前 train 是否真的“生命周期完整”。
- reviewer 需要一份不依赖 UI 的离线审计包。
- Release/GA gate 需要一个比 current train 更强的证据，尤其是发生过 reset 的 train。
- 用户需要一个清晰答案：这趟发版列车到底可不可以交付？

所以 v11.8 的价值是“收束”和“可审计”，不是再开一个平行工作台。

## 4. 核心原则

### 4.1 Lifecycle Audit 只读，不改业务状态

Lifecycle Audit 不应修改：

- train items
- dependencies
- signoff
- archive
- change requests
- reset proof
- external evidence manifest

它只能读取现有证据、运行 verifier、生成 report / ledger / ZIP。

### 4.2 不信内部自证

Lifecycle ZIP 内的 report / ledger / matrix 不能自证通过。

Verifier 必须从外部证据反推：

- current train archive ZIP
- current train verification report
- current train signoff binding proof
- current external evidence manifest
- Change Control ZIP
- Change Control verification report
- reset proof files
- archive-history entries

然后比较 Lifecycle ZIP 内报告。

### 4.3 发生过 reset 的 train 必须有 Change Control evidence

如果 train history 里出现：

```text
ucc_release_train_signoff_reset
```

那么 Lifecycle Audit 必须要求：

- Change Control ZIP
- Change Control verification report
- relevant reset proof
- archive-history entry

否则 lifecycle status 必须 failed。

### 4.4 current train 必须重新验证

Lifecycle Audit 不允许只读旧 verification report。

`refresh_lifecycle()` 和 verifier 都要重新运行：

```text
verify_unified_command_center_release_train_package(...)
```

并比较：

- zip_sha256
- zip_size_bytes
- manifest_hash
- verification report integrity hash
- signoff binding hash
- external evidence manifest hash

### 4.5 Change Control 也必须运行时验证

如果提供 Change Control ZIP，Lifecycle Audit 必须重新运行：

```text
verify_unified_command_center_release_train_change_control_package(...)
```

参数要带：

- `require_current_train=true`
- `require_reset_applied=true`，当 train 有 reset 时必须启用
- current train archive path
- current train verification report
- train signoff binding
- external evidence manifest
- reset proof path

### 4.6 历史 archive 只能当历史，不能当 current gate

archive-history 中旧 ZIP 只用于审计：

- 它证明旧 signoff 曾经存在。
- 它证明 reset 前的 archive 被保留。

但它不能满足 current Release / GA gate。

### 4.7 签核后删除文件不能绕过

如果未来 v11.8 增加 lifecycle signoff，本版建议先不做。  
v11.8 的 Lifecycle Audit ZIP 是报告包，不做 signoff reset。  
若后续要做 lifecycle signoff，必须单独设计 approved CR reset。

本版重点是 audit，不引入新的可变签核状态，避免再扩一层 reset 复杂度。

## 7. 数据模型

### 7.1 Lifecycle Source

内部构建 source，不一定单独落盘，但 report 必须包含 source hash。

建议字段：

```json
{
  "schema_version": 1,
  "package_type": "musicforge_unified_command_center_release_train_lifecycle_source",
  "train_id": "uct-000001",
  "created_at": "...",
  "train_hash": "...",
  "train_history_tip_hash": "...",
  "current_signoff_state": {
    "status": "signed",
    "signoff_hash": "..."
  },
  "current_train_archive": {
    "zip_sha256": "...",
    "zip_size_bytes": 123,
    "manifest_hash": "...",
    "verification_report_hash": "...",
    "signoff_binding_hash": "...",
    "external_evidence_manifest_hash": "..."
  },
  "change_control": {
    "configured": true,
    "zip_sha256": "...",
    "manifest_hash": "...",
    "verification_report_hash": "...",
    "applied_reset_count": 1
  },
  "reset_proofs": [
    {
      "change_request_id": "tcr-000001",
      "reset_proof_hash": "...",
      "previous_signoff_hash": "...",
      "reset_event_hash": "..."
    }
  ],
  "archive_history_hashes": ["..."]
}
```

`source_hash` 必须排除时间字段，只绑定证据事实。

### 7.2 Lifecycle Report

```json
{
  "schema_version": 1,
  "package_type": "musicforge_unified_command_center_release_train_lifecycle_report",
  "train_id": "uct-000001",
  "created_at": "...",
  "source_hash": "...",
  "status": "passed",
  "summary": {
    "current_state": "signed",
    "current_release_ready": true,
    "signoff_count": 2,
    "reset_count": 1,
    "applied_change_request_count": 1,
    "archive_history_count": 1,
    "current_train_verification_status": "passed",
    "change_control_verification_status": "passed",
    "blocking_gap_count": 0,
    "manual_action_count": 0
  },
  "blockers": [],
  "warnings": []
}
```

状态建议：

- `passed`
- `warning`
- `failed`
- `not_configured`

### 7.3 Lifecycle Ledger

从 train history + change request history 生成统一 ledger。

JSONL，每行一个事件：

```json
{
  "event_id": "tle-000001",
  "event_type": "train_created",
  "created_at": "...",
  "source": "release_train_history",
  "train_id": "uct-000001",
  "signoff_hash": null,
  "change_request_id": null,
  "payload_hash": "...",
  "previous_event_hash": "",
  "event_hash": "..."
}
```

必须覆盖事件类型：

- `train_created`
- `train_refreshed`
- `train_signoff_created`
- `train_archive_exported`
- `train_archive_built`
- `train_archive_verified`
- `train_change_request_submitted`
- `train_change_request_approved`
- `train_signoff_reset`
- `train_change_request_reset_applied`
- `train_successor_signoff_created`

如果原始 history 没有某类事件，不要伪造，只生成实际存在事件。

## 8. Store API

新增类：

```python
class UnifiedCommandCenterReleaseTrainLifecycleStore:
    def refresh_report(self, train_id: str, payload: dict | None = None) -> dict: ...
    def read_report(self, train_id: str) -> dict: ...
    def export_package(self, train_id: str) -> dict: ...
    def build_zip(self, train_id: str) -> dict: ...
    def verify_package(self, train_id: str, payload: dict | None = None) -> dict: ...
    def gate(self, train_id: str, *, required: bool = False, **payload) -> dict: ...
```

### 8.1 refresh_report()

输入 payload 支持：

```json
{
  "external_evidence_manifest": "...",
  "train_archive": "...",
  "train_archive_verification_report": "...",
  "train_signoff_binding": "...",
  "change_control_zip": "...",
  "change_control_verification_report": "...",
  "reset_proofs": ["..."]
}
```

要求：

- 读取 current train state。
- Runtime verify current train。
- 如果 history 有 reset，runtime verify Change Control。
- 生成 lifecycle report / ledger / maps / gap plan。

### 8.2 export_package()

要求：

- 如果 report stale，返回 409。
- 如果 current source hash 变化，返回 409。
- 固定导出结构。
- 不嵌套外部 ZIP。

### 8.3 build_zip()

要求：

- 如果 export stale，返回 409。
- ZIP 固定 entry allow-list。
- manifest.files[] 必须与 allow-list 一致。

### 8.4 verify_package()

调用 offline verifier，并把 verification report 写到：

```text
lifecycle/export/unified-command-center-release-train-lifecycle-verification-report.json
```

### 8.5 gate()

Release / GA gate 使用。

必须支持：

```python
gate(
  train_id,
  required=True,
  lifecycle_zip_path=...,
  verification_report_path=...,
  external_evidence_manifest_path=...,
  train_archive_path=...,
  train_archive_verification_report_path=...,
  train_signoff_binding_path=...,
  change_control_zip_path=...,
  change_control_verification_report_path=...,
  reset_proof_paths=[...],
)
```

失败条件：

- lifecycle ZIP 缺失。
- lifecycle verification report 缺失。
- report integrity 失败。
- runtime verifier 失败。
- verification report 与 current ZIP 不匹配。
- current train gate 失败。
- reset history 未被 Change Control 覆盖。
- reset proof 缺失。
- open approved CR 存在。

## 9. Offline Verifier

新增：

```text
song_agent/unified_command_center_release_train_lifecycle_verifier.py
```

CLI：

```powershell
python -m song_agent.cli verify-unified-command-center-release-train-lifecycle-package `
  .musicforge/unified-command-trains/<train-id>/lifecycle/export/unified-command-center-release-train-lifecycle.zip `
  --strict `
  --require-current-train `
  --train-archive .musicforge/unified-command-trains/<train-id>/archive/unified-command-center-release-train.zip `
  --train-archive-verification-report .musicforge/unified-command-trains/<train-id>/archive/unified-command-center-release-train-verification-report.json `
  --train-signoff-binding .musicforge/unified-command-trains/<train-id>/train-signoff-binding-summary.json `
  --external-evidence-manifest train-external-evidence.json `
  --change-control-zip .musicforge/unified-command-trains/<train-id>/change-control/export/unified-command-center-release-train-change-control.zip `
  --change-control-verification-report .musicforge/unified-command-trains/<train-id>/change-control/export/unified-command-center-release-train-change-control-verification-report.json `
  --reset-proof .musicforge/unified-command-trains/<train-id>/change-control/change-requests/tcr-000001/reset-proof.json `
  --json
```

### 9.1 Required entries

固定 entries：

```text
manifest.json
lifecycle-report.json
lifecycle-ledger.jsonl
signoff-succession-map.json
change-reset-coverage.json
archive-history-ledger.json
current-readiness-assertion.json
gap-plan.json
evidence-fingerprint-index.json
REVIEWER_GUIDE.md
README.txt
```

任何额外 entry 都 failed。

### 9.2 必查项

Verifier 必须检查：

- ZIP exists。
- ZIP size / uncompressed size / entry count。
- duplicate entries。
- path traversal。
- backslash entries。
- `.musicforge/` 变体。
- nested ZIP。
- manifest package_type。
- manifest integrity。
- manifest.files[] 固定结构。
- file hash / size。
- report integrity。
- ledger hash chain。
- ledger event semantics。
- signoff succession semantics。
- change reset coverage semantics。
- current train runtime verification。
- external current train verification report binding。
- external signoff binding proof。
- external evidence manifest。
- Change Control runtime verification when reset_count > 0。
- reset proof binding。
- redaction scan。

### 9.3 Verifier 不允许的自证

不得只信：

- lifecycle-report.status。
- change-reset-coverage.status。
- signoff-succession-map.current。
- evidence-fingerprint-index 中的 hash。

必须用外部 Train / Change Control evidence 反推。

### 9.4 Full-resign 攻击回归

必须加回归：

1. 修改 lifecycle-report，把 reset_count 改成 0。
2. 同步重算 report / matrix / manifest hash。
3. 不修改外部 Change Control ZIP / reset proof。
4. Verifier 必须 failed。

Blocker 建议：

```text
ucc_train_lifecycle_reset_semantics_match
```

再加：

1. 修改 signoff-succession-map，把旧 signer 改成另一个人。
2. 同步重签 lifecycle ZIP。
3. 外部 train signoff binding 不变。
4. Verifier 必须 failed。

Blocker 建议：

```text
ucc_train_lifecycle_signoff_succession_external_binding
```

## 22. 给开发的话

这版不是为了再加一个“看起来很完整”的报表，而是为了把 v11.6/v11.7 已经产生的证据链做成可审计总账。

请按这条主线实现：

1. 不改 train 状态，只读现有证据。
2. 不信 lifecycle ZIP 自证，必须用外部 Train / Change Control 证据反推。
3. reset 发生过，就必须证明每次 reset 有 approved single-use CR、reset proof 和 archive-history。
4. current train 仍必须通过 v11.6 verifier。
5. 旧 archive 只做历史，不做当前准出。
6. Release / GA gate 只接受 current lifecycle passed。

如果实现过程中遇到“为了方便直接读 report.status”的地方，先停一下。v11 的一贯原则是：report 只能作为展示，gate/verifier 必须回到外部证据和 runtime verifier。

# MusicForge v2.0.0 施工图：可视化编曲编辑与版本化收口

> 基线版本：v1.9.1  
> 当前目标：在已经具备生成、项目版本、素材库、引用库、候选、编辑、导出能力之后，新增一个本地可验证的可视化 SongPlan 编辑工作台。  
> 执行原则：全部先本地化验证；每完成一个边界清晰的功能包，测试通过后提交并推送 GitHub；最终再 tag / Release。  
> 范围判断：v2.0.0 不做完整 DAW，不做实时音频引擎，不做音频扒谱，先把 SongPlan 的结构、段落、轨道、音符做到可视化编辑、可预览、可保存为 Project 新版本。

---

## 1. 背景

v1.9.1 之后，MusicForge 已经具备：

- 本地 deterministic 生成。
- Provider-backed 生成和编辑。
- 多 Agent multinode pipeline。
- Studio 操作面板。
- Job / Batch / Project / Version 管理。
- Quality Layer。
- Stem MIDI/WAV 导出。
- Final Export Bundle 和 ZIP。
- Local Edit / Provider Edit / Candidate / Prompt A/B。
- Creative Asset Library。
- Reference Library。
- Reference Analysis 和 MIDI slice 资产化。
- Library Search / Recommend / Context Pack。

这说明系统已经能从“生成一首歌”走到“管理项目、多版本、多素材、多候选、最终交付”。

但现在还有一个关键短板：

> 用户看到 Timeline、Tracks、Quality、SongPlan JSON，但不能直接在 Studio 里改这首歌。  
> 当前 edit 主要是表单式、意图式、provider patch 式；缺少面向音乐结构本身的可视化编辑器。

所以 v2.0.0 应该做“可视化编曲编辑与版本化收口”。

这版的核心不是继续增加生成能力，而是让用户能在 Studio 里对已有 Project Version 做明确、局部、可回滚的手工编辑：

- 改段落和弦。
- 改段落歌词。
- 改轨道乐器。
- 增删改音符。
- 批量移调。
- 批量量化。
- 批量调 velocity。
- 预览 MIDI。
- 保存为 Project 新版本。

这一步完成后，MusicForge 才真正具备“生成 -> 选择 -> 修改 -> 对比 -> 定稿”的闭环。

---

## 2. 一句话目标

v2.0.0 的一句话目标：

> 新增一个基于 SongPlan patch 的可视化编曲编辑器，让用户可以在 Studio 里安全编辑 Project Version，并把编辑结果保存为新的可审计版本。

落地后，用户应能做到：

1. 打开任意 Project Version 的 Editor。
2. 看到 section timeline、track lanes、notes grid。
3. 选择 section，修改 chords / lyrics。
4. 选择 track，修改 instrument。
5. 选择 notes，移动、移调、量化、调 velocity。
6. 添加 note、删除 note、修改 note pitch/start/duration/velocity。
7. Preview patch，不覆盖 parent version。
8. Preview 成功后下载 MIDI。
9. 配置 renderer 后可渲染 WAV 试听。
10. Apply patch，生成一个新的 Project Version。
11. 新版本写入 editor patch metadata。
12. 新版本重新生成 song.mid、validator、quality、summary。
13. Parent version 保持不变。
14. Project Compare 能看到 editor edit 的摘要。
15. Project Export / Final Export 能写入脱敏 patch summary。
16. release-check 覆盖 v2.0 editor 主链路。

---

## 3. 非目标

v2.0.0 不做以下事情：

- 不做完整 DAW。
- 不做实时播放头和低延迟音频引擎。
- 不做浏览器内合成器。
- 不做录音。
- 不做 audio-to-MIDI。
- 不做 MP3/FLAC 导入。
- 不做音频扒旋律、扒和弦、扒鼓点。
- 不做 MIDI 文件完整导入到当前 SongPlan 的交互式合并。
- 不做复杂 section 重新编排求解。
- 不做跨版本自动 merge。
- 不做多人协同编辑。
- 不做无限 undo/redo 持久化。
- 不引入大型前端框架。

原因：

- 当前 Studio 是标准库 HTTP + 单页 UI，v2.0.0 应保持低依赖和可测试。
- 现在最需要的是“对 SongPlan 的安全可视化 patch”，不是完整音乐制作软件。
- 一旦 SongPlan patch 层稳定，后续 v2.1 / v2.2 再做更复杂的 arranger 和 piano-roll 体验。

## 4. 核心设计

新增一个编辑器领域层：

```text
song_agent/
  song_editor.py
```

新增 Project 内的 editor preview 持久化目录：

```text
.musicforge/
  projects/
    project-001/
      editor-previews/
        preview-001/
          preview.json
          patch.json
          song-plan.json
          validator-report.json
          quality.json
          song.mid
          song.wav
          events.jsonl
```

新增 run 产物：

```text
runs/
  <editor-job-id>/
    data/
      request.json
      editor-patch.json
      edit-metadata.json
      song-plan.json
      validator-report.json
      run-summary.json
    renders/
      song.mid
      song.wav
    logs/
      events.jsonl
```

关键原则：

1. Parent Version 永远不被覆盖。
2. Preview 不创建正式 Project Version。
3. Apply 才创建正式 Project Version。
4. Patch 必须绑定 `base_plan_hash`。
5. Base plan 变化时，preview/apply 返回 409。
6. Patch 操作必须有数量、范围、音高、时值、velocity 限制。
7. 每次 apply 后都重新 validate、quality、render MIDI。
8. 新版本不复用 parent 的 audio/stems/final-export，避免陈旧产物污染。
9. Studio 只调用 API，不直接改文件。

## 5. Editor State

### 5.1 API

新增：

```text
GET /api/projects/<project-id>/versions/<version-id>/editor-state
```

返回：

```json
{
  "ok": true,
  "project_id": "project-001",
  "version_id": "v003",
  "base_plan_hash": "sha256...",
  "song": {
    "title": "Rain Street",
    "key": "C",
    "tempo_bpm": 118,
    "meter": "4/4",
    "total_bars": 64,
    "beats_per_bar": 4
  },
  "sections": [
    {
      "section_id": "section-001",
      "name": "verse",
      "start_bar": 5,
      "bars": 8,
      "start_beat": 16,
      "end_beat": 48,
      "chords": ["Am7", "Fmaj7", "Cmaj7", "G7"],
      "lyrics": "..."
    }
  ],
  "tracks": [
    {
      "track_id": "track-001",
      "name": "melody",
      "instrument": "lead synth",
      "role": "melody",
      "note_count": 32,
      "pitch_min": 60,
      "pitch_max": 76,
      "notes": [
        {
          "note_id": "note-track-001-0001-a1b2c3d4",
          "pitch": 64,
          "start_beat": 16,
          "duration_beats": 1,
          "velocity": 90
        }
      ]
    }
  ],
  "quality": {},
  "warnings": []
}
```

### 5.2 Stable IDs

SongPlan 当前的 NoteEvent 没有 id。Editor State 必须生成稳定 id。

建议：

```text
section_id = section-<index>
track_id   = track-<index>
note_id    = note-<track_id>-<note_index>-<hash>
```

`hash` 来源：

```text
track_name + note_index + pitch + start_beat + duration_beats + velocity
```

注意：

- `note_id` 只在某个 `base_plan_hash` 下稳定。
- patch 必须带 `base_plan_hash`。
- 如果 base hash 不匹配，拒绝 patch。

### 5.3 Editor State 限制

为了避免前端一次性拿到过大的对象：

- track 数最多展示 32。
- 每 track notes 最多展示 4096。
- 如果超过限制，返回 409，提示 plan too large for visual editor。

当前生成器不会接近这个限制，但必须先有保护。

## 6. Editor Patch Schema

### 6.1 Patch 顶层结构

```json
{
  "schema_version": 1,
  "base_plan_hash": "sha256...",
  "label": "Make chorus brighter",
  "operations": [
    {
      "op": "set_section_chords",
      "section_id": "section-003",
      "chords": ["Cmaj7", "G7", "Am7", "Fmaj7"]
    }
  ]
}
```

### 6.2 支持的操作

v2.0.0 支持这些安全操作：

```text
set_section_chords
set_section_lyrics
set_track_instrument
add_note
update_note
delete_notes
move_notes
transpose_notes
quantize_notes
scale_velocity
```

不支持：

```text
add_track
delete_track
reorder_track
add_section
delete_section
reorder_section
resize_section
change_tempo_map
change_meter
```

这些留给 v2.1。

### 6.3 set_section_chords

```json
{
  "op": "set_section_chords",
  "section_id": "section-003",
  "chords": ["Cmaj7", "G7", "Am7", "Fmaj7"]
}
```

限制：

- `section_id` 必须存在。
- `chords` 不能为空。
- `chords` 最多 16 个。
- chords 必须在当前 MIDI renderer 支持的白名单内。

建议复用 v1.1.1 的安全和弦集合：

```text
Am7, Cmaj7, Dm7, E7, Fmaj7, G7
```

如果后续要扩大和弦表，必须单独测试 MIDI renderer。

### 6.4 set_section_lyrics

```json
{
  "op": "set_section_lyrics",
  "section_id": "section-002",
  "lyrics": "new lyric line"
}
```

限制：

- lyrics 最多 2000 字符。
- 走 `sanitize_sensitive_text`。
- 不允许控制字符。

### 6.5 set_track_instrument

```json
{
  "op": "set_track_instrument",
  "track_id": "track-001",
  "instrument": "warm lead synth"
}
```

限制：

- instrument 最多 80 字符。
- 走脱敏。
- 不改变 track name。

### 6.6 add_note

```json
{
  "op": "add_note",
  "track_id": "track-001",
  "note": {
    "pitch": 64,
    "start_beat": 48,
    "duration_beats": 1,
    "velocity": 90
  }
}
```

限制：

- pitch 0..127。
- velocity 1..127。
- start_beat >= 0。
- duration_beats > 0。
- note end 不超过 plan total beats。
- 单个 patch 最多新增 512 个 notes。

### 6.7 update_note

```json
{
  "op": "update_note",
  "track_id": "track-001",
  "note_id": "note-track-001-0001-a1b2c3d4",
  "patch": {
    "pitch": 67,
    "start_beat": 49,
    "duration_beats": 0.5,
    "velocity": 96
  }
}
```

限制：

- `note_id` 必须存在于 base editor state。
- patch 只能包含 `pitch/start_beat/duration_beats/velocity`。
- 更新后仍必须合法。

### 6.8 delete_notes

```json
{
  "op": "delete_notes",
  "track_id": "track-001",
  "note_ids": ["note-track-001-0001-a1b2c3d4"]
}
```

限制：

- note_ids 最多 512。
- 不允许删除不存在 note。
- 删除后 track 可以为空，但 validator 会给 warning。

### 6.9 move_notes

```json
{
  "op": "move_notes",
  "track_id": "track-001",
  "note_ids": ["note-track-001-0001-a1b2c3d4"],
  "delta_beats": 0.5
}
```

限制：

- note_ids 最多 512。
- delta_beats 范围 -64..64。
- 移动后不能小于 0，不能超过 total beats。

### 6.10 transpose_notes

```json
{
  "op": "transpose_notes",
  "track_id": "track-001",
  "note_ids": ["note-track-001-0001-a1b2c3d4"],
  "semitones": 2
}
```

也支持 range：

```json
{
  "op": "transpose_notes",
  "track_id": "track-001",
  "range": {
    "start_beat": 48,
    "end_beat": 80
  },
  "semitones": -12
}
```

限制：

- semitones -24..24。
- 必须提供 `note_ids` 或 `range` 之一。
- 更新后 pitch 仍在 0..127。

### 6.11 quantize_notes

```json
{
  "op": "quantize_notes",
  "track_id": "track-001",
  "range": {
    "start_beat": 48,
    "end_beat": 80
  },
  "grid": 0.25
}
```

限制：

- grid 只允许：`0.125, 0.25, 0.5, 1.0`。
- 只调整 start_beat。
- 不自动改变 duration。

### 6.12 scale_velocity

```json
{
  "op": "scale_velocity",
  "track_id": "track-001",
  "range": {
    "start_beat": 48,
    "end_beat": 80
  },
  "factor": 1.1
}
```

限制：

- factor 0.25..2.0。
- 结果 clamp 到 1..127。

## 7. Patch 限制

全局限制：

```text
MAX_EDITOR_PATCH_BYTES = 256 KB
MAX_EDITOR_OPERATIONS = 200
MAX_NOTE_IDS_PER_OPERATION = 512
MAX_ADDED_NOTES_PER_PATCH = 512
MAX_TRACK_NOTES_AFTER_PATCH = 4096
MAX_TOTAL_NOTES_AFTER_PATCH = 16000
```

如果超限：

- API 返回 400。
- 不写 preview。
- 不写 run。

Patch apply 后必须：

1. 重新排序 notes。
2. clamp / validate notes。
3. `SongPlan.validate()`。
4. `attach_quality()`。
5. 写 validator report。
6. 渲染 MIDI。

## 9. Apply API

新增：

```text
POST /api/projects/<project-id>/editor-previews/<preview-id>/apply
```

请求：

```json
{
  "version_name": "Chorus polish",
  "version_note": "manual visual editor patch"
}
```

行为：

1. 读取 preview。
2. 校验 preview status completed。
3. 校验 parent version 仍存在。
4. 校验 parent song-plan hash 仍等于 preview.base_plan_hash。
5. 创建新的 run 目录。
6. 写 `editor-patch.json`。
7. 写 `edit-metadata.json`。
8. 写 `song-plan.json`。
9. 写 `validator-report.json`。
10. 写 `run-summary.json`。
11. 渲染 `song.mid`。
12. 新增 Project Version。

返回：

```json
{
  "ok": true,
  "version": {
    "version_id": "v004",
    "name": "Chorus polish",
    "parent_version_id": "v003",
    "variant_type": "manual_editor_edit",
    "job_id": "job-..."
  }
}
```

### 9.1 Apply 幂等性

v2.0.0 可以先不做严格幂等。

但必须防止同一个 preview 被重复 apply 导致用户误操作：

- preview metadata 增加 `applied_version_id`。
- 已 apply 的 preview 再 apply 返回 409。

### 9.2 Apply 并发

同一个 preview 并发 apply：

- 只能成功一次。
- 另一个返回 409。

必须加测试。

## 11. Studio UI

### 11.1 新增 Project Editor tab

在 Project detail 中新增：

```text
Editor
```

入口：

- 选择 parent version。
- 点击 Open Editor。

布局建议：

```text
Top toolbar:
  Version select | Grid | Snap | Zoom | Preview | Apply as Version | Download MIDI

Main:
  Section strip
  Track lanes / note grid

Right inspector:
  Selected section
  Selected track
  Selected notes
  Patch summary
  Quality preview
```

不要做营销页，不要在页面里写大段说明。

### 11.2 Section strip

显示：

- section name。
- start bar。
- bars。
- chords。
- energy / tension / hook marker。

操作：

- 点击选中 section。
- Inspector 修改 chords。
- Inspector 修改 lyrics。

v2.0.0 不支持拖动 section 或改 bars。

### 11.3 Track lanes

显示：

- track name。
- instrument。
- note count。
- pitch range。
- notes grid。

操作：

- 选择 track。
- 修改 instrument。
- notes 点击选择。
- shift/ctrl 多选可以先不做，v2.0.0 可用 checkbox/select list 简化。

### 11.4 Notes grid

v2.0.0 不需要完整 piano roll。

可接受实现：

- 横轴 beat。
- 纵轴 pitch。
- note 用绝对定位 div。
- 支持点击选中。
- 支持 Inspector 修改 pitch/start/duration/velocity。
- 支持 Add Note 表单。
- 支持 Delete Selected。
- 支持 Transpose。
- 支持 Quantize。
- 支持 Velocity Scale。

如果拖拽实现复杂，v2.0.0 可以先不做拖拽。

### 11.5 Patch summary

Studio 维护一个前端 patch draft：

```json
{
  "operations": []
}
```

每次用户修改，追加 operation。

前端需要提供：

- Clear Patch。
- Preview Patch。
- Apply Preview as Version。

v2.0.0 可以不做 undo/redo，但 Clear Patch 必须有。

### 11.6 Preview 状态

Preview 后显示：

- changed_sections。
- changed_tracks。
- operation_count。
- validator status。
- quality overall。
- warnings。
- MIDI 下载。
- WAV 播放器，如果 render-audio 成功。

### 11.7 视觉要求

Studio 是操作工具，不做 landing page。

UI 要求：

- 信息密度高。
- 控件清楚。
- 文本不溢出。
- 编辑器轨道和 note grid 尺寸稳定。
- 不使用大面积装饰渐变。
- 不用卡片套卡片。
- 移动端可以降级为 section/track/inspector 列表，不强行显示完整 grid。

## 13. release-check 增强

新增 smoke：

```text
v2.0 visual editor smoke
```

流程：

1. 创建临时 root。
2. 创建 Project。
3. 生成 parent SongPlan。
4. add Project Version v001。
5. 调 `build_editor_state()`。
6. 创建 patch：
   - 改 chorus chords。
   - melody chorus 移调 +2。
   - 添加一个 note。
   - quantize melody。
7. 创建 editor preview。
8. 确认 preview song-plan 和 parent 不同。
9. 确认 parent song-plan 未变。
10. 渲染 preview MIDI。
11. apply preview。
12. 创建 v002。
13. Project Compare 有 changed tracks/sections。
14. Project Export 有 editor edit summary。
15. Final Export manifest 有 editor edit summary。
16. 重复 apply 返回 409。
17. 序列化输出不包含敏感值。

输出示例：

```text
v2.0 visual editor smoke: ok
  preview=preview-001, version=v002, operations=4, changed_tracks=1, changed_sections=1
```

## 17. reviewer 重点检查点

### P1：Preview 是否覆盖 parent

复现：

1. 创建 parent version。
2. 预览 patch。
3. 读取 parent run 的 `song-plan.json`。

预期：

- parent 文件完全不变。

### P1：base hash stale 是否被拒绝

复现：

1. 获取 editor-state。
2. 修改 parent `song-plan.json`。
3. 用旧 base hash preview。

预期：

- 返回 409。
- 不写 preview。

### P1：重复 apply 是否创建多个版本

复现：

1. preview。
2. 并发 apply 10 次。

预期：

- 只成功一次。
- 只创建一个 version。
- 其他返回 409。

### P1：非法 note 是否能进 SongPlan

污染 patch：

```json
{"pitch": 128}
{"velocity": 999}
{"duration_beats": 0}
{"start_beat": -1}
```

预期：

- 返回 400。
- 不写 run。

### P1：路径下载是否越界

复现：

- 修改 preview metadata 里的 midi path 指向其他文件。

预期：

- 下载 API 不信任 metadata path。
- 只从固定 preview 目录读固定文件。

### P1：Final Export 是否泄露 patch 污染文本

污染 label / lyrics / instrument：

```text
sk-secret
Authorization: Bearer token
D:\Music\private.mid
\\server\share\file.wav
raw_provider_response
local_path
```

预期：

- Project Export 没有。
- Final Export manifest 没有。
- ZIP 没有。

### P2：UI 大 patch 是否卡死

复现：

- 200 operations。
- 多轨多 note。

预期：

- API 有限制。
- UI 不无限追加 DOM。
- Preview 有 loading / error 状态。

### P2：质量分是否重新计算

复现：

- patch 后改 melody。

预期：

- 新版本 quality 不是直接复用 parent。

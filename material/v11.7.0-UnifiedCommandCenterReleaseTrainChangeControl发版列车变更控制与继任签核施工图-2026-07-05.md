# v11.7.0 Unified Command Center Release Train Change Control 发版列车变更控制与继任签核施工图

> 目标读者：开发执行人员、测试验收人员、后续 reviewer  
> 当前稳定基线：v11.6.1  
> 建议下一版：v11.7.0  
> 核心目标：补齐 v11.6 Release Train 签核后的受控变更能力。已签核 train 不能被静默修改；任何变更必须通过 approved Change Request、reset/reopen、重新 refresh/signoff/archive/verify，并保留旧签核与旧 archive 的可追溯证据。

---

## 1. 背景

v11.6.1 已经把多个 Unified Command Center 组合成 Release Train，并补上了外部 signoff binding proof：

- Train 可以聚合多个 UCC。
- Train 有 external evidence manifest。
- Train signoff 后有 history hash chain。
- Train archive ZIP 固定结构。
- `require_signed=True` 必须传外部 `train-signoff-binding-summary.json` proof。
- Release signoff / GA gate 可以要求 current Release Train。

但 v11.6 明确不做 reset。现实流程里这会马上遇到问题：

1. 某个 UCC 在 train 签核后修了 hotfix。
2. 某个 UCC archive verification 过期或重新生成。
3. 某个 item 要从本轮 train 移出并 defer 到下一轮。
4. 某个 dependency 要调整 wave / lane。
5. reviewer 要求补充一个 UCC Reviewer Decision Board。
6. Release signoff 前发现 train 不是当前证据。

v11.7 的目的不是放松 v11.6 的不可变性，而是给不可变性增加合法的变更通道：

> signed train 仍不可静默改写；只有 approved single-use Train Change Request 可以 reset/reopen train。旧签核、旧 binding、旧 archive 都必须保留，新签核必须重新生成完整 evidence 和 binding。

## 2. 版本定位

### 2.1 v11.7 要解决什么

v11.7 要实现：

- Train Change Request
- Change impact report
- Approved reset / reopen
- Rebuild / re-sign / re-archive
- Supersession summary
- Change-control fixed ZIP
- Offline verifier
- Release / GA gate currentness
- CLI / API / Studio
- release-check v11.7 smoke

### 2.2 v11.7 不做什么

不做：

1. 不自动修改 child UCC。
2. 不自动 approve Change Request。
3. 不自动 signoff train。
4. 不删除旧 archive。
5. 不把旧 ZIP 嵌入新 ZIP。
6. 不把外部 UCC ZIP 嵌入 Change Control ZIP。
7. 不做跨机器 CR 协同。
8. 不做真实 PKI / timestamp / notarization。
9. 不做 provider 调用。
10. 不跳过 v11.6 的 external evidence manifest 和 signoff binding proof。

## 3. 核心原则

### 3.1 Reset 不是删除签核

`reset_train_signoff()` 不能删除：

- `train-signoff.json`
- `train-signoff-binding-summary.json`
- `train-history.jsonl`
- old archive manifest
- old ZIP

Reset 只能追加 history event：

- `ucc_release_train_signoff_reset`

并写入 change-control proof：

- `train-change-request.json`
- `change-request-approval.json`
- `change-request-binding-report.json`
- `reset-proof.json`

latest state 的判断必须来自 history chain：

- latest signed event 且未被 reset -> `signed`
- latest signed event 后有 reset event -> `reset`
- reset 后新 signoff event -> `signed`

### 3.2 Change Request 必须一次性使用

每个 approved CR 只能 reset 一次。

Reset 成功后 CR 必须标记：

- `status=applied`
- `applied_at`
- `applied_train_id`
- `applied_previous_signoff_hash`
- `applied_reset_event_hash`

第二次使用同一个 CR 必须 409。

### 3.3 CR 必须绑定当前签核状态

CR approval 不能是泛化许可。它必须绑定：

- train_id
- current signoff hash
- current signoff binding hash
- current archive ZIP sha256
- current archive manifest hash
- current verification report hash
- current external evidence manifest hash
- requested change set hash

如果签核后有任何证据变化，旧 approved CR 不能再 reset。

### 3.4 Reset 后必须重新走 v11.6 完整链路

Reset 之后，train 进入 `reset` / `draft` 状态，但不是 release-ready。

必须重新：

1. 修改 item/dependency/policy。
2. refresh。
3. signoff。
4. export archive。
5. build ZIP。
6. verify archive ZIP with:
   - external evidence manifest
   - external signoff binding proof
7. Release / GA gate 再通过。

### 3.5 旧 archive 必须保留

旧 archive 不得覆盖。

建议目录：

```text
.musicforge/unified-command-trains/<train-id>/archive-history/<signoff-hash>/
  manifest.json
  unified-command-center-release-train.zip
  verification-report.json
  train-signoff-binding-summary.json
```

当前 archive 目录只代表 latest signed train。

Reset 时如果当前 archive 存在，必须复制或索引到 archive-history。不能直接删除。

### 3.6 Gate 只认 current signed train

Release signoff / GA readiness 的 train gate 必须：

- 拒绝 reset 状态。
- 拒绝 superseded 状态。
- 拒绝有 open approved-but-unapplied CR。
- 拒绝 current archive 和 latest signoff 不匹配。
- 拒绝 verification report 与 current archive 不匹配。
- 拒绝 signoff binding proof 与 current signoff 不匹配。

## 7. 状态机

### 7.1 Train state

```text
draft
  -> ready
  -> signed
  -> reset
  -> ready
  -> signed
```

规则：

- `signed`：只读，除 CR 创建/审批之外不能变更。
- `reset`：可以改 item / dependency / external evidence，但不能作为 Release / GA gate 证据。
- reset 后必须重新 signoff。
- 每次 signoff 生成新的 signoff hash 和 binding sidecar。
- 每次 archive build 生成新的 current archive。
- 旧 archive 进入 archive-history。

### 7.2 CR state

```text
draft
  -> approved
  -> applied
```

或：

```text
draft
  -> rejected
draft
  -> cancelled
```

限制：

- 只有 approved CR 可以 reset。
- rejected / cancelled 不能 reset。
- applied 不能复用。
- approved CR 如果 current binding stale，reset 必须 409。

### 8.1 create_change_request

必须：

- 允许 signed train 创建 CR。
- 拒绝 unsigned train 创建 reset CR，除非 `allow_unsigned=true` 且只做 draft impact。
- 读取 current signoff state。
- 读取 current archive ZIP / manifest / verification report / external binding proof。
- 保存 current binding snapshot。
- 对 reason / requested_by / note 做脱敏。
- 写 `train-change-request.json`。
- 立即写 `change-impact-report.json`。

### 8.2 approve_change_request

必须：

- 重新校验 CR integrity。
- 重新校验 impact report。
- 重新校验 current binding 未变化。
- 拒绝 high-risk blocker。
- 写 `approval.json`。
- 写 history event `train_change_request_approved`。

### 8.3 apply_reset

必须：

- 要求 CR status approved。
- 要求 approval integrity OK。
- 要求 CR 未 applied。
- 重新校验 current signoff / binding / archive / verification report。
- 要求 current binding 与 CR approval 绑定一致。
- 把 current archive 记录到 archive-history。
- 追加 train history event `ucc_release_train_signoff_reset`。
- 写 `reset-proof.json`。
- 写 `change-request-binding-report.json`。
- 标记 CR status applied。
- 把 train status 改成 `reset`。
- 删除或标记 current archive as stale，但不得删除 archive-history。

不能：

- 自动 refresh。
- 自动修改 external evidence manifest。
- 自动 signoff。
- 自动 build ZIP。

## 9. Release Train Store 需要改的点

v11.7 不是完全独立模块，必须收紧 v11.6 的 Train Store。

### 9.1 latest_signoff_state()

必须从 `train-history.jsonl` 重建：

- latest signoff event
- latest reset event
- latest archive exported event
- latest archive built event

如果 latest reset event 晚于 latest signoff event：

```json
{
  "status": "reset",
  "previous_signoff_hash": "...",
  "reset_event_hash": "..."
}
```

### 9.2 ensure_unsigned()

当前逻辑可能只区分 signed / unsigned。

v11.7 后应：

- signed -> 阻断 mutation。
- reset -> 允许 mutation。
- draft / no_go / ready -> 允许 mutation。

### 9.3 signoff()

reset 后重新 signoff 必须：

- 生成新的 signoff hash。
- 生成新的 signoff binding sidecar。
- 追加新的 signoff history event。
- 不能覆盖 reset proof。
- 不能覆盖 archive-history。

### 9.4 export_archive() / build_zip()

必须：

- current signed 才允许。
- reset 状态 409。
- 如果旧 archive 已存在但 signoff hash 不同，必须先 archive-history 归档旧 archive，再生成 current archive。
- 如果同一 signoff hash 已经 build 过 ZIP，则仍保持 v11.6 逻辑：不能静默重建。

```text

- 本机绝对路径
- token / API key / bearer

### 10.3 必须检查

ZIP 层：

- fixed allow-list
- manifest files exactly match entries
- file hash / size
- zip size / uncompressed size
- redaction

CR 层：

- change request integrity
- impact report integrity
- approval integrity
- reset proof integrity
- CR history hash chain
- binding report integrity
- approval binds CR + impact + current binding
- reset proof binds approval + previous signoff + reset event
- CR status applied 时必须有 reset proof
- applied CR 不能重复

外部证据层：

- current train archive ZIP exists
- train archive verification report exists
- current train signoff binding proof exists
- external evidence manifest exists
- current train archive verifier passed
- current train latest state is signed if `require_current_resigned=true`
- current train signoff hash differs from previous reset signoff hash
- current train source hash differs if requested changes actually changed evidence

### 10.4 防 full-resign

必须覆盖这些攻击：

1. 改 `approval.approved_by` 并重算 approval / manifest。
2. 改 `reset-proof.previous_signoff_hash` 并重算 proof / manifest。
3. 改 `change-request-binding-report.source` 并重算 report / manifest。
4. 改 CR status from draft to approved 并重算所有 ZIP 内文件。
5. 改 old archive fingerprint，让 CR 看起来绑定另一个 signoff。

Verifier 必须通过外部 current train archive / signoff binding / verification report 反查，而不是信 Change Control ZIP 自身。

### Unified Command Center Release Train Change Control

Signed Release Trains are immutable. v11.7 adds a controlled Change Request workflow for reopening a signed train after a child UCC or external evidence changes. A reset requires an approved single-use Train Change Request bound to the current signoff hash, signoff binding proof, archive ZIP hash, manifest hash, verification report hash, and external evidence manifest hash.

Reset never deletes old archives. It appends a hash-chained reset event, records reset proof, moves previous archive fingerprints into archive history, and leaves the train non-release-ready until it is refreshed, signed, archived, and verified again.
```

## 23. 给开发的话

这版的核心不是“让 signed train 可以改”，而是“让 signed train 只能在可审计的 CR 证明下被重新打开”。

你实现时要守住六条：

1. reset 不能删除历史，只能追加 history event。
2. reset 必须绑定 approved single-use CR。
3. CR 必须绑定 current signoff / binding / archive / verification / manifest。
4. reset 后 train 不是 release-ready，必须重新 signoff + archive + verify。
5. old archive 只能作为历史证据，不能冒充 current gate。
6. verifier 必须依赖外部 current train archive 和 signoff binding proof，不信 Change Control ZIP 内部自证。

做到这六条，v11.7 才算真正补上 v11.6 留下的签核后变更缺口。

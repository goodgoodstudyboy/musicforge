# MusicForge v1.6.0 施工图：创作资产库与素材复用层

> 基线版本：v1.5.1  
> 当前目标：把 MusicForge 从“能生成、能编辑、能试听、能比较”推进到“能沉淀好素材、能检索好素材、能复用好素材”。  
> 执行原则：全部先本地化验证；每完成一个边界清晰的功能包，测试通过后提交并推送 GitHub；最终再 tag / Release。

---

## 1. 背景

v1.5.1 之后，系统已经具备这些能力：

- 本地 deterministic 生成。
- provider-backed SongPlan / Project edit。
- 多节点 pipeline。
- Project 版本管理。
- 局部 edit、preset、preview、candidate group。
- Candidate MIDI/WAV 试听。
- Prompt A/B。
- Quality、Quality Gate、Final Export。
- Stem 导出与试听。
- Provider usage/cost report。

这已经能支撑“单首歌从生成到交付”的闭环。

但当前还有一个明显短板：

> 好的旋律、和弦、鼓型、bass pattern、歌词 hook、结构套路，只存在某一次生成结果里。  
> 用户不能把它们沉淀成素材库，也不能在下一首歌里明确复用。

这会导致两个问题：

1. **创作积累断层**
   - 每次生成都像从零开始。
   - 好用片段只能靠人工记忆和手工复制。
   - 多个 Project 之间无法共享创作资产。

2. **生成控制不够稳定**
   - 用户可以说“参考之前那个副歌”，但系统没有结构化入口。
   - Provider prompt 可以描述风格，但没有可靠的本地素材上下文。
   - Candidate A/B 能比较结果，但不能把胜出的部分沉淀成 reusable building block。

所以 v1.6.0 应该做“创作资产库与素材复用层”。

---

## 2. v1.6.0 总目标

v1.6.0 的一句话目标：

> 从 Project / Version / Candidate / Job 中抽取可复用音乐素材，形成本地资产库，并允许后续生成、编辑、候选生成时引用这些资产。

落地后，用户应能做到：

1. 在 Studio 里从某个 Project Version 保存一个旋律 motif。
2. 从某个候选保存一个和弦套路。
3. 从某个完成 job 保存鼓型或 bass pattern。
4. 在资产库里按类型、标签、风格、质量分筛选。
5. 预览资产 MIDI，配置 renderer 后试听 WAV。
6. 创建新版本或 candidate group 时选择若干资产作为参考。
7. Project / Job / Candidate 的 metadata 能追溯使用过哪些资产。
8. Final Export / Project export 能体现资产引用关系，但不泄露本地绝对路径或敏感信息。

---

## 3. 非目标

v1.6.0 不做以下事情，避免版本失控：

- 不做真实音频文件导入分析，比如从 MP3/WAV 自动扒谱。
- 不做向量数据库、embedding 检索、相似旋律搜索。
- 不做云端协作资产库。
- 不做版权授权系统。
- 不做 DAW 插件。
- 不做复杂的 automatic arrangement reuse。
- 不把资产强行塞进 `SongPlan` 主 schema。
- 不要求 provider 必须严格复用资产，只提供结构化上下文和本地可验证 fallback。

这些可以放到 v1.7.0 之后。

---

## 4. 核心概念

### 4.1 Asset

Asset 是一个可复用创作素材，不等同于 Project Version。

Project Version 是一整首歌的版本；Asset 是从一整首歌中提炼出来的局部素材或模板。

Asset 可以来自：

- completed job。
- Project version。
- Provider edit preview。
- Candidate group candidate。
- Stem / track。
- 人工创建。

Asset 应该是本地快照，而不是只引用源文件。

原因：

- 源 Project 可能被删除。
- Candidate group 可能被删除。
- run 目录可能被清理。
- 资产库应保持独立可用。

### 4.2 Asset Types

v1.6.0 建议先支持这些类型：

| Type | 中文 | 来源 | 主要用途 |
| --- | --- | --- | --- |
| `motif` | 旋律动机 | melody/lead track、quality.primary_motif | 新歌旋律参考、variation |
| `chord_progression` | 和弦进行 | section.chords | 生成和声骨架、section_harmony |
| `drum_pattern` | 鼓型 | drums track | 复用节奏律动 |
| `bass_pattern` | Bass pattern | bass track | 复用低频走向 |
| `section_template` | 段落模板 | section + quality.section_intent | 复用 verse/chorus/bridge 结构 |
| `arrangement_template` | 编排模板 | sections + tracks roles | 复用整首结构大纲 |
| `lyric_hook` | 歌词 hook | section.lyrics | 复用副歌 hook 或 slogan |

v1.6.0 可以先把 `motif`、`chord_progression`、`drum_pattern`、`bass_pattern` 做扎实。

`section_template`、`arrangement_template`、`lyric_hook` 可以作为支持但轻量的类型，不要过度智能化。

## 5. 存储设计

### 5.1 根目录

新增本地资产库：

```text
.musicforge/
  assets/
    asset-001/
      asset.json
      source-fragment.json
      preview.mid
      preview.wav
      render-report.json
      audio-render-report.json
      events.jsonl
    asset-002/
      asset.json
```

不要用一个大 JSON 保存所有资产。

原因：

- 资产数量会增长。
- 单文件并发写风险高。
- 删除、隐藏、渲染、更新 metadata 都更适合独立目录。
- 后续做 asset pack export 更方便。

### 5.2 `asset.json`

建议 schema：

```json
{
  "schema_version": 1,
  "asset_id": "asset-001",
  "asset_type": "motif",
  "name": "bright chorus motif",
  "description": "A rising hook motif extracted from v003 chorus.",
  "tags": ["chorus", "hook", "synth-pop"],
  "style": "synth pop",
  "mood": "uplifting",
  "key": "C",
  "tempo_bpm": 118,
  "meter": "4/4",
  "duration_beats": 8.0,
  "quality_score": 88,
  "favorite": false,
  "hidden": false,
  "usage_count": 0,
  "created_at": "2026-05-07T00:00:00Z",
  "updated_at": "2026-05-07T00:00:00Z",
  "source": {
    "source_type": "project_version",
    "project_id": "my-song",
    "version_id": "v003",
    "job_id": "job-abc",
    "candidate_group_id": null,
    "candidate_id": null,
    "section_name": "chorus",
    "track_name": "melody",
    "song_plan_sha256": "..."
  },
  "content": {
    "kind": "motif",
    "rhythm_pattern": [1.0, 1.0, 0.5, 0.5],
    "pitch_intervals": [0, 3, 5, 7],
    "anchor_pitch": 64,
    "notes": [
      {"pitch": 64, "start_beat": 0.0, "duration_beats": 1.0, "velocity": 90}
    ]
  },
  "preview": {
    "midi_status": "completed",
    "midi_size_bytes": 512,
    "midi_url": "/api/assets/asset-001/midi",
    "audio_status": "not_started",
    "audio_size_bytes": 0,
    "audio_url": null,
    "error": null
  }
}
```

### 5.3 `source-fragment.json`

保存从源 SongPlan 抽出的局部片段，便于 review 和后续兼容：

```json
{
  "schema_version": 1,
  "asset_id": "asset-001",
  "source_type": "project_version",
  "section": {
    "name": "chorus",
    "start_bar": 9,
    "bars": 8,
    "chords": ["F", "G", "C", "Am"]
  },
  "track": {
    "name": "melody",
    "instrument": "lead synth",
    "notes": []
  },
  "quality": {},
  "extracted_at": "2026-05-07T00:00:00Z"
}
```

### 5.4 路径规则

必须坚持现有安全习惯：

- `asset_id` 必须正则校验，建议 `^asset-[0-9]{3,6}$`。
- 任何 API 传入的 asset id 不允许包含路径分隔符。
- 删除目录前必须 `resolve()` 后确认在 `.musicforge/assets/` 内。
- 拒绝删除 symlink。
- 下载 MIDI/WAV 时只能读取固定路径：
  - `asset_dir / "preview.mid"`
  - `asset_dir / "preview.wav"`
- 不信任 `asset.json` 里的路径字段作为下载路径。
- API 返回值不暴露本地绝对路径，必要时只返回 URL。

## 6. Package A：Asset Schema 与 AssetStore

### 6.1 新增模块

建议新增：

```text
song_agent/assets.py
```

职责：

- Asset dataclass。
- Asset content 校验。
- AssetStore。
- asset id 分配。
- list/read/write/update/hide/unhide/delete。
- render MIDI / render WAV。
- search/filter。

### 6.2 Asset dataclass

核心类：

```python
@dataclass(frozen=True)
class CreativeAsset:
    schema_version: int
    asset_id: str
    asset_type: str
    name: str
    description: str
    tags: list[str]
    style: str
    mood: str
    key: str
    tempo_bpm: int
    meter: str
    duration_beats: float
    quality_score: int | None
    favorite: bool
    hidden: bool
    usage_count: int
    source: dict[str, Any]
    content: dict[str, Any]
    preview: dict[str, Any]
    created_at: str
    updated_at: str
```

### 6.3 校验规则

必须校验：

- `asset_type` 属于允许列表。
- `name` 不超过 120 字符。
- `description` 不超过 1000 字符。
- `tags` 最多 32 个，每个不超过 48 字符。
- `tempo_bpm` 在 40 到 240。
- `duration_beats` 大于 0，小于等于 256。
- `quality_score` 为空或 0 到 100。
- `content` 不允许出现：
  - `api_key`
  - `secret`
  - `token`
  - `password`
  - `credential`
  - `absolute_path`
  - `local_path`
  - `file`
  - `path`
- `notes` 数量建议上限 1024。
- 单个 asset JSON 大小建议上限 128KB。

### 6.4 AssetStore API

Python 层方法建议：

```python
class AssetStore:
    def list_assets(self, include_hidden: bool = False, filters: AssetFilters | None = None) -> list[CreativeAsset]: ...
    def read_asset(self, asset_id: str) -> CreativeAsset: ...
    def create_asset(self, payload: dict[str, Any], now: str | None = None) -> CreativeAsset: ...
    def update_asset(self, asset_id: str, patch: dict[str, Any]) -> CreativeAsset: ...
    def hide_asset(self, asset_id: str) -> CreativeAsset: ...
    def unhide_asset(self, asset_id: str) -> CreativeAsset: ...
    def delete_asset(self, asset_id: str) -> None: ...
    def render_asset_midi(self, asset_id: str) -> CreativeAsset: ...
    def render_asset_audio(self, asset_id: str, config: RendererConfig) -> CreativeAsset: ...
    def mark_used(self, asset_ids: list[str]) -> None: ...
```

新增：

## 7. Package B：从 SongPlan / Project / Candidate 抽取资产

### 7.1 抽取入口

新增抽取函数：

```python
extract_assets_from_song_plan(
    plan: SongPlan,
    source: dict[str, Any],
    request: AssetExtractionRequest,
) -> list[CreativeAssetPayload]
```

### 7.2 抽取类型规则

#### motif

来源优先级：

1. `plan.quality.primary_motif`
2. hook section 的 melody track notes
3. melody track 前 8 到 16 beats

输出：

- rhythm_pattern。
- pitch_intervals。
- anchor_pitch。
- notes snapshot。
- source section / track。

#### chord_progression

来源：

- 指定 section 的 chords。
- 未指定时优先 hook section。
- 没有 hook 时优先 chorus。
- 没有 chorus 时取最长 section。

输出：

- chords。
- section_name。
- bars。
- harmonic_rhythm。
- key。

#### drum_pattern

来源：

- track name 或 instrument 包含 drum / drums。
- 截取指定 section。
- 没指定 section 时取前 4 到 8 bars。

输出：

- normalized notes。
- duration_beats。
- meter。
- drum map 保持 MIDI pitch，不做复杂语义分类。

#### bass_pattern

来源：

- track name 或 instrument 包含 bass。
- 截取指定 section。

输出：

- notes。
- root_motion 简单从 pitch class 推断。
- rhythm_density。

#### section_template

来源：

- section + quality.section_intent。

输出：

- role。
- bars。
- energy。
- tension。
- density。
- transition。
- hook。
- chords 可选。

#### arrangement_template

来源：

- whole SongPlan sections + track role summary。

输出：

- section roles。
- bars。
- energy/tension/density。
- track roles。
- total duration estimate。

#### lyric_hook

来源：

- hook section lyrics。
- 或指定 section lyrics。

输出：

- text。
- language。
- section_name。
- syllable_count 简单估计。

### 7.3 从 Project Version 抽取

API payload 需要能指定：

```json
{
  "project_id": "demo",
  "version_id": "v003",
  "asset_types": ["motif", "chord_progression"],
  "section_name": "chorus",
  "track_name": "melody",
  "name_prefix": "demo chorus",
  "tags": ["demo", "chorus"],
  "favorite": true

```

抽取时记录 source：

```json
{
  "source_type": "project_version",
  "project_id": "...",
  "version_id": "...",
  "job_id": "...",
  "section_name": "...",
  "track_name": "...",
  "song_plan_sha256": "..."
}
```

### 7.4 从 Candidate 抽取

Candidate group 已经有 `candidate-song-plan.json`。

从候选抽取时记录：

```json
{
  "source_type": "candidate",
  "project_id": "...",
  "version_id": "parent version",
  "job_id": "parent job",
```

对非 Project job 也要支持：

```json

  "job_id": "...",

```

这样用户可以先在 Jobs 里试生成，再把好片段保存到资产库。

### 8.4 `POST /api/assets/<asset-id>`

只允许更新 metadata：

- name
- description
- tags
- style
- mood
- favorite

不要允许直接改 `source`、`content`、`preview`。

如果后面需要编辑 content，应做新的 `revision` 机制，不能直接覆盖。

### 8.5 MIDI 预览

Asset MIDI 不是完整歌曲，只是片段预览。

规则：

- motif：生成一个短 melody track。
- chord_progression：生成 chord track。
- drum_pattern：生成 drum track。
- bass_pattern：生成 bass track。
- section_template：生成简单 chord + guide rhythm。
- arrangement_template：可以返回 409 “not renderable yet”，不强求。
- lyric_hook：返回 409 “lyric assets do not have MIDI preview”。

### 8.6 WAV 预览

复用现有 renderer config。

失败规则：

- renderer 未配置：400。
- MIDI 未生成：先自动生成 MIDI。
- 不可渲染 asset：409。

所有 `/api/assets` 路由必须受现有 Bearer auth 保护。

补 `tests/test_server_auth.py`：

- POST `/api/assets`

- download routes
- delete/hide routes

## 9. Package D：资产复用接入生成、编辑、候选

### 9.1 新增 payload 字段

多个入口可以接受：

```json
{
  "asset_refs": [
    {
      "asset_id": "asset-001",
      "role": "motif_reference",
      "strength": 0.7
    },
    {
      "asset_id": "asset-002",
      "role": "chord_reference",
      "strength": 0.5
    }
  ]
}
```

### 9.2 支持入口

v1.6.0 建议支持：

- `POST /api/jobs`
- `POST /api/projects/<project-id>/versions`
- `POST /api/projects/<project-id>/versions/<version-id>/variation`
- `POST /api/projects/<project-id>/versions/<version-id>/edit`
- `POST /api/projects/<project-id>/versions/<version-id>/edit-preview`
- `POST /api/projects/<project-id>/versions/<version-id>/edit-candidates`
- `POST /api/projects/<project-id>/versions/<version-id>/edit-candidates/ab`

如果时间不够，至少支持：

- Project new version。
- Project variation。
- Provider candidate generation。

### 9.3 资产引用快照

每次使用 asset，都要把快照写入 job metadata：

```text
runs/<job-id>/data/asset-refs.json
```

内容：

```json
{
  "schema_version": 1,
  "asset_refs": [
    {
      "asset_id": "asset-001",
      "asset_type": "motif",
      "name": "bright chorus motif",
      "role": "motif_reference",
      "strength": 0.7,
      "source": {
        "project_id": "...",
        "version_id": "..."
      },
      "content_summary": {
        "duration_beats": 8.0,
        "note_count": 8,
        "chord_count": 0
      }
    }
  ],
  "captured_at": "2026-05-07T00:00:00Z"
}
```

不要把完整 notes 全部写入每个 job metadata，避免 metadata 膨胀。

完整内容仍在 `.musicforge/assets/<asset-id>/asset.json`。

### 9.4 本地 deterministic 复用规则

本地 composer 可先实现轻量规则：

#### motif

- 读取 pitch_intervals。
- 从当前 key 的 anchor pitch 推导 melody。
- strength 越高，越多使用 asset intervals。
- strength 低时只影响 hook section。

#### chord_progression

- 应用到 chorus 或 hook section。
- 如果没有 hook section，应用到第一个非 intro/outro section。
- 保留 SongPlan validator 支持的和弦。

#### drum_pattern

- 替换 drums track 的前 4 到 8 bars pattern，然后循环。

#### bass_pattern

- 替换 bass track 的 rhythm shape。
- pitch 需要按当前 key/和弦做安全转调，不要直接照搬绝对 pitch。

### 9.5 Provider prompt 上下文

Provider 只接收 sanitized asset summaries：

```json
{
  "asset_references": [
    {
      "asset_id": "asset-001",
      "asset_type": "motif",
      "name": "bright chorus motif",
      "tags": ["chorus", "hook"],
      "role": "motif_reference",
      "strength": 0.7,
      "content": {
        "rhythm_pattern": [1.0, 1.0, 0.5, 0.5],
        "pitch_intervals": [0, 3, 5, 7]
      }
    }
  ]
}
```

禁止传：

- 本地绝对路径。
- API key。
- raw provider response。
- 过长 lyrics 全文。
- 超过限制的 notes 数组。

### 9.6 Candidate group 资产引用

Candidate group 需要记录：

```json
{
  "asset_refs": [
    {"asset_id": "asset-001", "role": "motif_reference", "strength": 0.7}
  ]
}
```

应用 candidate 后，child edit metadata 也要保留 asset references。

这样 Project diff / Compare 可以解释：

> 这个候选来自 prompt template A，并参考了 asset-001 motif。

### 9.7 usage_count

成功创建 job、preview、candidate group 时：

- 对引用的 asset 增加 `usage_count`。
- 写 asset event：

```json
{
  "type": "asset_used",
  "job_id": "...",
  "project_id": "...",
  "version_id": "...",
  "usage_type": "candidate_generation"
}
```

注意：

- 如果请求失败，不增加 usage_count。
- Prompt A/B 部分失败并 rollback 时，已回滚 group 对应的 asset usage 也要避免被永久计入。最简单做法：A/B 创建只有全部成功后才统一 `mark_used()`。

### 9.8 测试

新增：

```text

```

覆盖：

- local generation 使用 motif asset 后 melody 与 asset intervals 有明显关系。
- chord_progression asset 被应用到 hook/chorus。
- invalid asset id 返回 400/404。
- hidden asset 默认不可用于 generation，除非显式 `include_hidden_assets`，建议 v1.6.0 不支持 include hidden。
- provider candidate prompt 中包含 asset summary，但不包含路径和 secret。
- asset usage_count 成功后增加。
- failed request 不增加 usage_count。
- Prompt A/B rollback 不留下 usage_count。

## 14. Reviewer 重点检查点

### 14.1 数据安全

必须检查：

- asset content 是否能塞入 `api_key`、`secret`、`path`。
- download 是否只读固定 preview 文件。
- delete 是否拒绝 symlink。
- API 是否暴露本地绝对路径。
- provider prompt 是否包含本地路径或过长 raw content。

### 14.2 复用正确性

必须检查：

- motif asset 是否真的影响 melody。
- chord_progression 是否真的影响 section chords。
- asset_refs 是否写入 job metadata。
- Project diff / Compare 是否能展示 asset source。
- candidate apply 后是否保留 asset_refs。

### 14.3 失败状态

必须检查：

- invalid asset id。
- missing asset。
- hidden asset。
- renderer 未配置。
- asset 不可 MIDI 渲染。
- Prompt A/B 中 asset 使用失败是否没有错误增加 usage_count。

### 14.4 并发和路径

必须检查：

- 并发创建 asset id 不冲突。
- 删除 asset 时不会删除 `.musicforge/assets/` 外部目录。
- asset render 失败不会污染已有成功 preview。
- atomic write 仍然使用 `write_json()`。

## 19. v1.7.0 候选方向

v1.6.0 稳定后，v1.7.0 可以考虑：

- Reference Audio Import：导入 WAV/MP3 后做人声/节奏/和弦粗分析。
- Asset Similarity Search：基于 melody interval / rhythm hash 的相似素材检索。
- Asset Packs：把一组素材导出成可分享包。
- Style Profile：从多个 assets 生成某种风格 profile。
- Arrangement Reuse：让 arrangement_template 更深地影响多节点 pipeline。
- Provider asset ranking：让 provider 解释为什么选择某个 asset。
- Batch asset_refs：CSV 批量任务引用素材库。

不要在 v1.6.0 做这些。v1.6.0 的核心是：

> 能保存素材，能搜素材，能听素材，能在新创作里复用素材。

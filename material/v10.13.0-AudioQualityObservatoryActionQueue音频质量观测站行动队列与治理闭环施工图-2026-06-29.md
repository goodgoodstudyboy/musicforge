# v10.13.0 Audio Quality Observatory Action Queue 音频质量观测站行动队列与治理闭环施工图

## 1. 版本定位

v10.12.0 已经完成 Release Audio Quality Observatory：

- 聚合 Certification / Timeline / Campaign / Regression / Baseline evidence。
- 输出跨发行趋势、问题热区、baseline drift、remediation cost、risk register、recommendations。
- 支持固定结构 ZIP、offline verifier、Release signoff gate、GA gate。

但 v10.12 仍然停在“看见风险”。v10.13.0 要往前推进一步：把 Observatory 的 risks / recommendations 变成可审计、可执行、可复盘的治理队列。

v10.13.0 的目标不是自动改音乐，而是做一个 deterministic 的 Audio Quality Observatory Action Queue：

- 从 Observatory 风险生成治理行动队列。
- 区分 safe action、manual action、blocked action。
- 安全动作只允许刷新、导出、验证、创建草稿，不允许自动签核、自动 reset、自动改音乐、自动切换 baseline。
- 人工动作必须保留 manual_required item 和证据。
- 队列执行结果可以导出 ZIP，并有离线 verifier。
- Release signoff / GA readiness 可以要求指定 Observatory Queue 已完成或无 critical blocking。

一句话：v10.12 是“趋势预警”，v10.13 是“预警之后怎么处置，并留下可验证证据”。

## 3. 为什么 v10.13 做 Action Queue

现在系统已经有很长的音频治理链：

- v10.2 Audio Lab：真实音频环境、人工试听 session、marker。
- v10.3 Audio Fix Sprint：marker -> candidate -> A/B -> recheck -> closeout。
- v10.4 Audio Campaign：发行候选批量真实听审。
- v10.5 Audio Campaign Governance：Campaign 签核、归档、趋势。
- v10.6 Release-driven Campaign：从 Release tracks 自动创建 Campaign。
- v10.7 Campaign Remediation：Campaign 问题修复编排。
- v10.8 Audio Certification：发行音频准出证书。
- v10.9 Audio Timeline：音频证据时间线。
- v10.10 Regression Guard：当前 release 相对 baseline 的回归检测。
- v10.11 Baseline Governance / Regression Response：基线治理与回归响应。
- v10.12 Quality Observatory：跨发行趋势、风险、recommendations。

但业务上的下一步是：

> 系统发现过去 3 个发行里都出现 mix_balance 问题，或者最新 release rating 下降，或者某个 baseline 已不适合了，那应该怎么转成任务？谁处理？哪些动作可以系统自动准备？哪些必须人工确认？处理完怎么证明？

如果没有 Action Queue，Observatory 的 recommendation 只是报告文本；开发和业务仍然要人工复制粘贴，容易漏项，也没有统一审计。

v10.13 要让 Observatory 进入“治理工作流”：

- 每条 risk 可以转成 queue item。
- 每条 recommendation 可以转成 queue item。
- queue 绑定 Observatory source hash，源数据变了就 stale。
- queue 执行 safe actions 后输出 action result。
- manual actions 不自动执行，只生成明确的 manual_required。
- queue 完成后能作为 Release / GA 的外部 evidence。

## 4. 非目标

v10.13 不做这些事：

- 不自动修改音乐。
- 不自动 apply Audio Fix Sprint candidate。
- 不自动 approve / signoff / reset。
- 不自动替换 active baseline。
- 不自动关闭 Regression Response。
- 不调用 provider 生成主观音质判断。
- 不把 synthetic / fake WAV 视为 release-ready。
- 不做云端遥测，不上传任何证据。
- 不引入数据库，继续使用 `.musicforge/` 本地文件存储。
- 不支持并发多 worker 分布式执行。

## 8. Action 类型

### 8.1 safe actions

这些可以由 `run-safe` 执行：

1. `refresh_observatory`
   - 重新运行 Observatory refresh / verify。
   - 注意：如果 source hash 改变，当前 queue 应该 stale，不应继续执行旧 queue。

2. `create_audio_quality_review_task`
   - 创建本地 review task draft 或 lightweight issue draft。
   - 不自动进入 accepted / resolved。

3. `create_audio_fix_sprint_draft`
   - 只创建 draft，不自动生成候选，不自动 apply。

4. `create_regression_response_plan_draft`
   - 只创建 response plan draft。
   - 不自动 closeout / signoff。

5. `create_baseline_review_request`
   - 创建 baseline review request。
   - 不自动 approve / activate / revoke baseline。

6. `export_observatory`
   - 重新导出 Observatory ZIP。
   - 仅当 Observatory 未 stale 且 verifier passed。

7. `verify_observatory`
   - 重新验证 Observatory ZIP。

### 8.2 manual actions

这些永远不能自动执行：

- `manual_audio_lead_review`
- `approve_baseline_change`
- `activate_baseline`
- `waive_regression`
- `signoff_release`
- `reset_signoff`
- `apply_audio_fix`
- `close_regression_response`
- `close_audio_fix_sprint`
- `provider_generate_recommendation`

执行时只生成 manual action 记录。

### 8.3 blocked actions

这些应该被拒绝或标 blocked：

- source Observatory stale。
- Observatory verifier failed。
- risk source id 不存在。
- recommendation source id 不存在。
- critical risk 被降级但外部 Observatory 反推不一致。
- action target release 不在 Observatory source release_ids 中。
- 试图自动执行 mutating action。

## 9. 由 Observatory risk/recommendation 生成 Action Item 的规则

### 9.1 risk -> action

| risk check_id | severity | action_type | execution_mode |
|---|---:|---|---|
| `audio_evidence_not_current` | critical | `refresh_observatory` + `verify_observatory` | safe |
| `manual_rating_floor` | critical | `create_audio_quality_review_task` | safe |
| `quality_trend_decline` | high | `create_audio_quality_review_task` | safe |
| `critical_issue_hotspot` | critical | `create_audio_fix_sprint_draft` | safe |
| `needs_fix_backlog` | high | `create_audio_fix_sprint_draft` | safe |
| `baseline_drift_detected` | high/critical | `create_baseline_review_request` | manual_required |
| unknown | any | `manual_audio_lead_review` | manual_required |

### 9.2 recommendation -> action

| recommendation.action | action_type | execution_mode |
|---|---|---|
| `refresh_audio_evidence` | `refresh_observatory` / `verify_observatory` | safe |
| `open_audio_quality_review` | `create_audio_quality_review_task` | safe |
| `review_baseline_policy` | `create_baseline_review_request` | manual_required |
| `open_regression_response` | `create_regression_response_plan_draft` | safe |
| unknown | `manual_audio_lead_review` | manual_required |

### 9.3 去重规则

同一个 queue 内不能重复创建同一 action：

```text
fingerprint = stable_hash({
  source_type,
  source_id,
  action_type,
  target.release_id,
  target.track_id,
  target.issue_type
})
```

如果重复，保留第一条，后续记录到 `deduplicated_source_ids`。

## 10. Stale 与 Source Guard

Queue 创建时必须记录：

- Observatory ZIP sha256。
- Observatory ZIP size。
- Observatory manifest hash。
- Observatory verification report hash。
- Observatory source hash。
- risk_register hash。
- recommendation_report hash。

后续所有关键动作前必须重新验证：

- `run-safe`
- `export`
- `zip`
- `verify`
- `Release signoff gate`
- `GA readiness gate`

如果 Observatory 当前验证结果或 source hash 不匹配：

```json
{
  "status": "failed",
  "error": "Audio Quality Action Queue source is stale. Refresh Observatory and create a new queue."
}
```

必须 409，不允许 force 绕过。

新增类：

```python
    def run_safe(self, queue_id: str) -> dict: ...
    def export_package(self, queue_id: str) -> dict: ...
    def build_zip(self, queue_id: str) -> dict: ...
    def verify_zip(self, queue_id: str, **kwargs) -> dict: ...
    def gate(self, release_id: str, *, queue_id: str | None, required: bool, require_no_blocking: bool = True) -> dict: ...
```

### 11.1 `create_from_observatory`

流程：

1. 读取 Observatory config / summary / risk / recommendations。
2. 调用 Observatory verifier：
   - `strict=True`
   - `require_current_evidence=True`
   - `require_no_critical_risk=False`
3. 如果 verifier failed，拒绝创建。
4. 生成 source binding。
5. 生成 action items。
6. 写 history：`queue_created`。

### 11.2 `run_safe`

流程：

1. 检查 source binding 当前有效。
2. 读取 action items。
3. 对每条 item：
   - manual item -> 写 manual_required。
   - safe item -> 执行。
   - mutating/provider/signoff/reset item -> blocked。
4. 写 action-results。
5. 写 queue-summary。
6. 写 history：`queue_run_safe_completed`。

### 11.3 `export_package`

必须先：

- 检查 source 不 stale。
- 检查 queue summary integrity。
- 检查 history chain。

签核概念 v10.13 暂不做；所以没有 immutable signoff guard。后续 v10.14 可做 Action Queue signoff/archive。

### 11.4 `verify_zip`

必须写 `verification-report.json`，供 Release/GA gate 引用。

## 12. Offline Verifier

新增：

```python
verify_release_audio_quality_action_queue_package(
    zip_path,
    *,
    strict=False,
    require_current_observatory=False,
    observatory_zip_path=None,
    observatory_verification_report_path=None,
    evidence_root=None,
    require_no_blocking=True,
)
```

### 12.1 固定 ZIP allow-list

必需 entries：

```text
manifest.json
action-queue.json
source-binding.json
action-items.json
action-results.json
manual-actions.json
queue-summary.json
README.txt
```

可选：

```text
queue-history.jsonl
```

任何额外 entry 都 failed。

### 12.2 ZIP 安全检查

必须覆盖：

- duplicate entry。
- dangerous path。
- backslash path。
- absolute path。
- drive path。
- `.musicforge/` 任意大小写变体。
- nested zip。
- manifest spoof。
- manifest.files declared extra。
- file hash mismatch。
- zip bomb：
  - max zip size。
  - max uncompressed size。
  - max entry count。
- redaction：
  - `sk-...`
  - GitHub token。
  - Bearer token。
  - `api_key=...`
  - Windows path。
  - UNC path。
  - local `.musicforge` path。

### 12.3 内部一致性

校验：

- `manifest.package_type == release_audio_quality_action_queue`
- 所有 document integrity_hash。
- 所有 document source_hash 一致。
- summary.document_hashes 绑定所有核心文档。
- manifest 绑定所有核心文档 hash。
- history hash-chain。
- action result 必须引用存在的 item_id。
- manual action 必须引用存在的 item_id。
- completed / failed / blocked / manual_required count 与 summary 一致。

### 12.4 外部 Observatory 绑定

如果 `require_current_observatory=True`：

必须提供：

- Observatory ZIP。
- Observatory verification report。
- evidence root。

校验：

- Observatory ZIP 当前 verifier passed。
- Observatory verification report integrity ok。
- Observatory verification report 绑定当前 Observatory ZIP sha256 / size / manifest hash。
- Queue source-binding 里的 Observatory fingerprint 与外部 Observatory 一致。
- Queue item source ids 必须存在于外部 Observatory risk/recommendation。
- Queue summary 反推结果与 external Observatory 风险一致。

不能只信 queue ZIP 内部复制的 Observatory source-binding。

## 16. Release Signoff Gate

在 Release signoff payload 中新增：

```json
{
  "require_release_audio_quality_action_queue": true,
  "release_audio_quality_action_queue_id": "aqa-000001",
  "require_no_blocking_audio_quality_actions": true
}
```

Gate 逻辑：

1. required false：不阻断。
2. required true：必须有 queue。
3. queue 必须 verify passed。
4. queue 必须 source current。
5. queue source Observatory 必须覆盖当前 Release。
6. 如果 `require_no_blocking_audio_quality_actions=true`：
   - `blocked_count == 0`
   - `failed_count == 0`
   - `critical_unhandled_count == 0`
7. manual_required 可以允许通过，但必须进入 signoff evidence：
   - 因为 v10.13 的目标是行动队列，不是完成所有人工动作。
   - 如果业务后续要求 manual 必须清零，可在 v10.14 做 Action Queue Signoff。

`force=true` 不能绕过 stale/current/integrity failed。

## 23. P1 风险清单

### P1-1：Action Queue 自证

风险：Queue ZIP 内部 source-binding 被同步重签后通过。

要求：verifier 必须能用外部 Observatory ZIP + verification report + evidence root 重建 source，不信内部 source-binding 自证。

### P1-2：自动执行越权

风险：run-safe 自动 close/signoff/reset/apply。

要求：safe action allow-list 固定，所有 mutating/signoff/reset/provider 自动 blocked 或 manual_required。

### P1-3：stale Observatory 继续执行

风险：Observatory 更新后，旧 queue 还能 run/export/zip/signoff。

要求：source hash / zip hash / manifest hash / verification hash 必须当前匹配。force 不可绕过。

### P1-4：critical risk 被人为降级

风险：risk_register 全量重签，把 critical 改 warning。

要求：external Observatory verifier 必须反推风险，Action Queue verifier 必须比对 external risk/recommendation。

### P1-5：Release gate 只看 queue status

风险：queue status passed，但不覆盖当前 Release。

要求：Release gate 必须确认 queue source Observatory release_ids 覆盖当前 release。

### P1-6：manual actions 被误当完成

风险：manual_required 被当 completed，导致 gate 误过。

要求：summary 明确 manual_required_count。v10.13 可以允许 manual_required 通过，但必须作为 evidence 写入 signoff；如果 require_no_manual=true 后续再做。

### P1-7：fake/test WAV 间接进入质量治理

风险：Observatory 源数据如果未过滤 test/fake，Action Queue 会基于假证据。

要求：依赖 Observatory 的 current evidence verifier；同时 action summary 不得声称 release-ready audio，除非源 Certification/Timeline 已真实音频 passed。

## 25. 给开发的话

这版不要做成“又一个报表”。v10.12 已经能看见问题，v10.13 要解决的是“问题出现后怎么被纳入治理流程”。

你实现时要始终守住三条线：

1. 只自动做安全准备动作，不自动改音乐、不自动签核、不自动 reset。
2. Queue 的所有判断都必须能从外部 Observatory evidence 反推，不能靠 queue ZIP 自证。
3. 每完成一个可运行阶段就本地验证、提交、推 GitHub，不要一口气堆到最后。

如果你发现某个 action 需要改变音乐、改变 baseline、改变 signoff 状态，那它不是 v10.13 的 safe action，只能生成 manual_required 或 blocked。

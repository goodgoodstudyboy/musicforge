# v14.2.7 MusicForge Explicit Any 派生不确定绑定传播安全修复施工图

## 1. 定位

v14.2.7 是 v14.2.6 的安全热修复，不扩展业务功能。它修复 Explicit
Any collector schema 9 中 `uncertain` 绑定经过一次复合 RHS 后被降级为
`other` 的绕过。

稳定基线在本版发布前仍是 v14.1.2；已公开的 v14.2.6 tag 不移动、不删除，
待 v14.2.7 完整发布后仅将 Release 标记为 superseded。

## 2. 攻击面

以下三类 class-global 间接目标在运行时都能把模块 `Alias` 变成
`typing.Any`：

- `for Alias in ((typing.Any,),)` 后执行 `Alias = Alias[0]`。
- `with nullcontext((typing.Any,)) as Alias` 后执行 `Alias = Alias[0]`。
- `match (typing.Any,)` 捕获 `Alias` 后执行 `Alias = (Alias,)[0]`。

schema 9 只保留直接 `Name` 的 uncertain 状态，复合表达式会被错误洗成
`other`，导致后续 100 个注解计数为零。

## 3. 安全不变量

1. 整个 RHS AST 依赖 uncertain 时，结果继续是 uncertain。
2. 下标、属性、容器、调用、条件、布尔和多级赋值都不能洗白。
3. 仅在注解消费 uncertain 时产生 hard blocker 和计数。
4. 普通未进入注解的运行时值不产生无关 blocker。
5. schema 9 的总量、层级、文件、复杂度和 recovery ceiling 不得提高。
6. collector schema 升级必须有独立 migration record 和 ADR。

## 4. 实施步骤

### Phase 1: Collector

- `_expression_binding_kind()` 在直接类型识别前后检查完整 RHS 依赖。
- 任意 `ast.Name` 解析为 uncertain 时，复合表达式结果保持 uncertain。
- 保留注解消费点的 `uncertain_annotation_binding:<name>` blocker。

### Phase 2: Tests

- 三种攻击均验证 runtime、100 annotations、Ruff、strict mypy。
- collector 必须 count=100 并产生 scope-flow blocker。
- total、layer、file 三层 ratchet 必须失败。
- 额外覆盖 subscript、attribute、container、call、if-expression、Boolean
  expression 和多级赋值。
- 未被注解消费的普通值必须保持无 blocker。

### Phase 3: Policy And Release Gate

- schema 升到 10。
- 新增 ADR-022 和 9-to-10 migration record。
- 新增 `v1427.explicit_any_derived_uncertain_scope_smoke`，进入 v14、latest、
  GA、security 和 full profiles。
- policy updater 必须拒绝任何 ceiling 增长。

### Phase 4: Release

- 跑定向测试、全仓 Ruff、全 active-tree mypy、完整 pytest 和 legacy
  partition。
- 跑 v14、latest、security、GA、full profiles。
- 自审实际 diff，修完 P0/P1/P2 后提交并在干净工作区复跑 GA。
- 推送 master，创建 annotated `v14.2.7` tag。
- 最终 SHA 的 Quality 与 Nightly LTS 必须通过。
- 构建 17 文件 Reviewer Package，公开下载后独立 `--require-final` 复验。
- 发布 v14.2.7 并将 v14.2.6 Release 标记为 superseded。

## 5. Stop Conditions

以下任一情况立即停止发布：

- 三种攻击任一 collector count 不是 100。
- active tree 出现新的 scope-flow blocker。
- 任一 ceiling 被提高或固定 hash 改变。
- Ruff、mypy、完整 pytest、release-check、Quality 或 Nightly 状态不确定。
- Reviewer Package 不是 17 个唯一安全 entry 或外部下载 hash 不一致。

## 6. 准确口径

v14.2.7 只关闭已知的 derived uncertain propagation 绕过。它不宣称手写
collector 已覆盖全部 Python 语义，也不关闭 ARCH-014 或 TYPE-003。

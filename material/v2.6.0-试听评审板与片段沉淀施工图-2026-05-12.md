# v2.6.0 试听评审板与片段沉淀施工图

日期：2026-05-12

当前基线：v2.5.1

目标版本：v2.6.0

定位：在 v2.5.1 已经打通 Preview / Parent / Audition 试听可信链路之后，把“听完之后如何判断、标注、筛选、复用”补成正式工作流。v2.6.0 不继续堆编辑操作，而是让试听结果可评价、可标记、可排序、可沉淀为 Asset / Clip / Template，为后续更强的创作闭环打基础。

---

## 1. 背景

到 v2.5.1，MusicForge 已经具备：

- Project Editor 可构造 patch。
- Editor Preview 可生成候选。
- Preview WAV 会从父版本 SongPlan + preview patch 重新计算，不信任缓存。
- Parent WAV 可用于 A/B。
- Editor Audition 支持：
  - `source=preview|parent`
  - `range=full_song|section|changed_sections|custom`
  - `track_mode=all|solo|mute`
  - MIDI 下载
  - 可选 WAV 渲染
- Audition summary 已进入 Apply metadata、Compare、Project Export、Final Export summary。

这说明“生成试听产物”的链路已经稳定。

但现在还有几个业务短板：

- 用户听完 audition 后，不能给它打分。
- 用户不能写“这个 chorus hook 好，但 bass 太满”这类评审备注。
- 用户不能在试听上标记关键时间点，比如 hook、drop、问题点、待修复点。
- Preview History / Audition 列表还只是文件列表，不是可排序的评审板。
- 好的试听片段不能一键沉淀为 Asset，后面无法在 Library / Clip Browser / Context Pack 里复用。
- 用户做了很多试听后，很难知道哪个 audition 最值得 Apply。

v2.6.0 要解决这个问题。

---

## 2. 一句话目标

v2.6.0 要把 MusicForge 从“能试听”推进到“能评审试听并沉淀素材”：

- 每个 audition 可评分、收藏、写备注。
- 每个 audition 可打 marker，标注 beat 位置和类型。
- Studio 提供 Audition Review Board，可按评分、来源、范围、track mode、时间排序和筛选。
- Preview 可计算 review summary，辅助用户决定 Apply。
- 可从 audition 片段保存为 Creative Asset。
- 可从 audition 片段生成 EditorClip 引用，后续能插回 Project Editor。
- Apply / Compare / Export 只写脱敏 review summary，不复制临时音频。

---

## 3. 不做什么

v2.6.0 必须继续收住边界：

- 不做实时 DAW 播放引擎。
- 不做 waveform 编辑。
- 不做浏览器 Web Audio 混音。
- 不做自动 AI 评审。
- 不做 provider 根据评分自动改歌。
- 不做多人协作评论。
- 不做 cloud sync。
- 不做 MP3 / FLAC。
- 不做音频切割和淡入淡出。
- 不把 audition WAV 默认放进 Final Export。
- 不把 review notes 里的本机路径、token、key 原样导出。

这版只做本地、确定性、可审计的评审和素材沉淀。

---

## 4. 用户价值

目标用户工作流：

1. 用户在 Project Editor 里做多个 Preview / Audition。
2. 听 `preview full song`、`chorus solo melody`、`mute drums` 等试听。
3. 给每个 audition 打分：
   - 5 分：可用
   - 3 分：有潜力
   - 1 分：丢弃
4. 写备注：
   - “hook 不错，第二遍能量可以更高”
   - “bass 和 kick 打架”
5. 在关键 beat 加 marker：
   - `hook`
   - `issue`
   - `drop`
   - `keep`
   - `fix`
6. 在 Review Board 里筛选评分最高的 audition。
7. 把好的 melody / bass / drum 片段保存为 Asset。
8. 后续在 Clip Browser / Library / Context Pack 中复用。

这样用户的创作过程开始形成积累，不再只是一次性生成。

## 5. 核心设计原则

### 5.1 Review 是元数据，不改音乐内容

评分、备注、marker 都只写入 audition manifest 或独立 review 文件。

不能因为用户评分而改：

- preview patch
- preview song-plan
- audition song-plan
- parent version
- Project Version

### 5.2 Asset 化必须重新生成安全内容

从 audition 保存 Asset 时，不能复制任意文件路径。

必须：

- 读取 audition `song-plan.json`
- 根据 range / track 重新抽取 notes
- 生成标准 Creative Asset payload
- 通过 `AssetStore.create_asset()` 写入

不能：

- 直接复制 audition manifest 中的 path
- 直接把 WAV 当成 asset content
- 把本机路径写入 asset source

### 5.3 Review 需要脱敏

用户备注可能写入：

- token
- api key
- 本机路径
- provider 原始返回

必须复用 `song_agent/redaction.py`，所有 review notes / marker labels / export summary 都要脱敏。

### 5.4 Audition 仍然是缓存

Audition review 是有价值的，但 audition 本体仍然是 Preview 下面的候选缓存。

- 删除 preview 会删除 audition 和 review。
- Applied preview 仍受保护，不被 cleanup 删除。
- 如果 audition 被删除，其生成的 Asset 不能被删除；Asset 是独立沉淀。
- Asset source 应记录 audition 摘要和 hash，不依赖 audition 目录存在。

## 7. 数据模型

### 7.1 Audition Review 字段

建议直接扩展 `EditorAuditionManifest`，避免多文件状态不同步。

新增字段：

```json
{
  "review": {
    "rating": 0,
    "favorite": false,
    "status": "unreviewed",
    "notes": "",
    "tags": [],
    "markers": [],
    "updated_at": null
  }
}
```

### 7.2 rating

规则：

- 整数，0 到 5。
- `0` 表示未评分。
- `1..5` 表示用户评分。

### 7.3 status

支持：

- `unreviewed`
- `keep`
- `maybe`
- `reject`
- `needs_fix`

规则：

- 默认 `unreviewed`
- 如果 `favorite=true` 但 status 还是 `reject`，允许，但 UI 应明显展示。

### 7.4 notes

规则：

- 最大 2000 字符。
- 控制字符清理。
- 敏感值脱敏。
- export 时二次脱敏。

### 7.5 tags

规则：

- 最多 20 个。
- 每个最多 40 字符。
- 清理控制字符。
- 去重。
- 全部脱敏。

### 7.6 markers

Marker 结构：

```json
{
  "marker_id": "marker-001",
  "beat": 16.0,
  "kind": "hook",
  "label": "chorus hook",
  "severity": "info",
  "created_at": "..."
}
```

`kind` 支持：

- `hook`
- `drop`
- `issue`
- `keep`
- `fix`
- `note`

`severity` 支持：

- `info`
- `warning`
- `critical`

规则：

- marker beat 必须在 audition `0 <= beat <= duration_beats` 范围内。
- marker_id 服务端分配，不接受客户端指定。
- 最多 100 个 marker。
- label 最多 160 字符，脱敏。

### Phase 2：Review Board API

新增 API：

```text
GET  /api/projects/<project-id>/audition-reviews
GET  /api/projects/<project-id>/editor-previews/<preview-id>/audition-reviews
POST /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/review
POST /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/markers
POST /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/markers/<marker-id>
POST /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/markers/<marker-id>/delete
```

说明：

- `GET /audition-reviews` 返回 Project 级 review board。
- `GET /editor-previews/<id>/audition-reviews` 返回单 preview 的 review board。
- 所有 POST 仍使用 POST，保持当前项目风格，避免浏览器/本地环境 method 兼容问题。

`GET audition-reviews` 支持 query：

- `source=preview|parent`
- `status=keep|maybe|reject|needs_fix|unreviewed`
- `favorite=true|false`
- `min_rating=0..5`
- `track_mode=all|solo|mute`
- `range_mode=full_song|section|changed_sections|custom`
- `sort=rating|updated|created|note_count|duration`
- `order=asc|desc`
- `limit=1..500`

返回：

```json
{
  "ok": true,
  "project_id": "project-001",
  "summary": {
    "audition_count": 12,
    "reviewed_count": 8,
    "favorite_count": 3,
    "average_rating": 3.75,
    "status_counts": {
      "keep": 2,
      "maybe": 4,
      "reject": 1,
      "needs_fix": 1
    }
  },
  "auditions": []
}
```

### Phase 3：从 Audition 保存为 Asset

新增 API：

```text
POST /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/create-asset
```

Payload：

```json
{
  "name": "Chorus hook from preview 001",
  "asset_type": "motif",
  "track_id": "track-001",
  "tags": ["hook", "chorus"],
  "description": "Good hook from audition",
  "favorite": true
}
```

支持 asset_type：

- `motif`
- `bass_pattern`
- `drum_pattern`
- `chord_progression`

暂不支持：

- `audio_wav`
- 多轨 asset
- 直接保存 WAV

生成逻辑：

1. 读取 audition plan。
2. 如果指定 `track_id`：
   - 从 audition editor state 找 track。
   - 抽取该 track 的 notes。
3. 如果未指定：
   - 按 asset_type 自动选择：
     - `motif` -> melody
     - `bass_pattern` -> bass
     - `drum_pattern` -> drums
     - `chord_progression` -> sections chords
4. 构造标准 Asset payload。
5. source 写脱敏摘要：

```json
{
  "source_type": "editor_audition",
  "project_id": "project-001",
  "preview_id": "preview-001",
  "audition_id": "audition-001",
  "source": "preview",
  "range": {"mode": "section"},
  "track_mode": "solo",
  "source_plan_hash": "..."
}
```

6. 调用 `AssetStore.create_asset()`。
7. 写 project event：
   - `editor_audition_asset_created`

错误规则：

- audition 不存在：404
- track 不存在：400
- track 无 notes：409
- asset_type 不支持：400
- payload 过大：400
- 脱敏后空 name 用默认名

### Phase 4：EditorClip 接入 Audition Source

让 Clip Browser 能直接看到或引用 audition 生成的片段。

有两种实现方式：

推荐 v2.6.0 先做轻量方式：

- 从 audition create-asset 后，Asset 自动进入现有 Library / Clip Browser。
- 不直接让 `EditorClip` 从 audition path 读取。

可选增强：

- `source_type=editor_audition`
- `clip_ref` 支持：

```json
{
  "source_type": "editor_audition",
  "project_id": "project-001",
  "preview_id": "preview-001",
  "audition_id": "audition-001",
  "track_id": "track-001"
}
```

如果开发时间有限，v2.6.0 做 create-asset 即可，把直接 audition clip ref 放 v2.6.1 或 v2.7.0。

### Phase 5：Apply / Compare / Export Summary

Apply 时已有 audition summary。

v2.6.0 扩展 summary：

```json
{
  "audition_summary": {
    "audition_count": 3,
    "reviewed_count": 2,
    "favorite_count": 1,
    "best_rating": 5,
    "average_rating": 4.0,
    "status_counts": {"keep": 1, "maybe": 1},
    "marker_count": 4,
    "asset_count": 1

```

要求：

- Project Export 带脱敏 summary。
- Final Export manifest 带脱敏 summary。
- 不导出完整 notes 原文，除非 reviewer 认为必要；建议只导出 summary。
- 不复制 audition MIDI/WAV。

## 10. 安全与边界

### 10.1 Review 文本脱敏

以下字段必须脱敏：

- notes
- tags
- marker label
- asset description
- asset source summary

必须覆盖：

- `sk-...`
- GitHub token
- Bearer token
- Windows 盘符路径
- UNC 路径
- Unix 路径
- renderer path
- SoundFont path

### 10.2 Marker 边界

- beat 不能小于 0。
- beat 不能超过 audition duration。
- marker 数量最多 100。
- kind / severity 只接受白名单。
- label 不能包含控制字符。

### 10.3 Asset 化边界

- 不接受客户端传入 notes。
- 不接受客户端传入 source path。
- 不读取 manifest path。
- 只读取 store 解析出的 audition plan。
- 生成 Asset 前要确认 audition plan 有 notes 或 chords。
- Asset payload 仍走 `AssetStore.create_asset()`，复用已有大小和 schema 校验。

### 10.4 并发

需要考虑：

- 同一个 audition 并发 update review。
- 并发 add marker。
- 并发 create asset。
- delete audition 与 update review 同时发生。

最低要求：

- `EditorAuditionStore` 继续使用 project-level RLock。
- marker id 分配在 lock 内。
- manifest 写入使用 `write_json`。
- create asset 成功后再写 audition review 的 asset reference summary；如果写 review 失败，不要删除已创建 asset，但要记录 project event。

  - `HEAD = origin/master`
  - `v2.6.0^{}` 指向发布 commit
  - GitHub Release latest 是 `v2.6.0`

- 不写 token 到配置。

## 14. 验收标准

v2.6.0 完成时，必须满足：

- Audition 可评分。
- Audition 可 favorite。
- Audition 可设置 status。
- Audition 可写脱敏 notes。
- Audition 可添加、更新、删除 marker。
- Project 级 Review Board 可筛选和排序。
- Preview 级 Review Board 可筛选和排序。
- Studio 可完成 rating / marker / create asset。
- Audition 可保存为 motif / bass_pattern / drum_pattern / chord_progression asset。
- Asset source 不泄露本地路径。
- Apply metadata 包含 review summary。
- Compare / Project Export / Final Export 包含脱敏 review summary。
- Final Export 不复制 audition WAV。
- release-check 包含 v2.6 smoke。
- 全量测试通过。
- GitHub master/tag/release 对齐。

## 15. Reviewer 重点检查清单

开发完成后，reviewer 应重点看：

- 旧 audition manifest 没有 review 字段是否兼容。
- review notes / tags / marker label 是否脱敏。
- marker beat 边界是否正确。
- marker_id 是否服务端分配。
- review update 是否会覆盖其他字段。
- Review Board sort/filter 是否 deterministic。
- create asset 是否只从 audition plan 抽取内容。
- create asset 是否拒绝客户端 notes/path。
- Asset source 是否无本机路径。
- Apply 是否只写 review summary，不信任 review 改音乐。
- Project Export / Final Export 是否二次脱敏。
- delete preview 是否正常带走 auditions/reviews。
- applied preview cleanup 保护是否仍有效。
- release-check 是否不依赖真实 SoundFont。

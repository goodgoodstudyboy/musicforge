# v7.4.0 Release Portfolio Governance Attestation Portal Snapshot 公开证明静态门户快照与离线发布验收施工图

> 本文是给开发执行的 v7.4.0 施工图。当前稳定基线是 v7.3.1。v7.3.1 已经完成 Public Attestation Registry，并修复了 Registry ZIP verifier 对 `registry-report.source`、`package-index.json.items`、`chain-of-custody.json` 的反查绑定问题。

v7.4.0 的目标是把单个 Public Attestation 和 Attestation Registry 组织成一个可携带、可离线打开、可离线验证的静态门户快照。

这不是联网发布，不是网站托管，也不是外部认证。它是一个本地生成的、可以给外部审计方打开的静态 snapshot 包。

---

## 1. 背景

v7.2 做了 Public Attestation：

- 公开证明 ZIP。
- 公开证书 JSON / Markdown / HTML。
- 不包含 Evidence Vault / Final Board 等嵌套包。
- verifier 能检查公开证书是否绑定当前 Evidence Vault 和 Final Board signoff。

v7.3 做了 Attestation Registry：

- 登记 Public Attestation。
- publish / revoke / supersede。
- 生成 Registry ZIP。
- verifier 能检查公开证明生命周期没有被篡改。

当前缺口：

1. 单个 Public Attestation ZIP 适合机器验收，但给人读不够直观。
2. Registry ZIP 能证明生命周期，但没有一个清晰的公开页面告诉外部方：
   - 当前有效证明是哪一个？
   - 哪些证明被撤销？
   - 哪些证明被替换？
   - 如何运行 verifier？
   - 公开证明、登记册、Vault 指纹之间如何对应？
3. 如果把 HTML 页面单独发出去，当前没有验证 HTML 是否与 Registry / Attestation hash 一致。
4. 外部审计方需要一个 “打开 index.html 先看，再跑 verifier 深验” 的入口。

---

## 2. v7.4.0 目标

新增 Release Portfolio Governance Attestation Portal Snapshot。

它负责从当前 Attestation Registry 和 Public Attestation 生成一个静态门户快照：

- `index.html`：总览页。
- `current.html`：当前公开证明页。
- `registry.html`：登记册生命周期页。
- `revocations.html`：撤销/替换历史页。
- `verify.html`：离线验证说明页。
- `data/portal-summary.json`：门户摘要。
- `data/registry-summary.json`：登记册摘要。
- `data/current-attestation-summary.json`：当前证明摘要。
- `portal-manifest.json`：文件 hash 和 source hash。
- `portal-verification-report.json`：本地 verifier 输出。
- `governance-attestation-portal.zip`：可携带 ZIP。

一句话：

> v7.4 要让外部方无需进入 `.musicforge/`，只拿到一个静态门户快照，就能看懂公开证明状态，并用离线 verifier 验证快照没有被篡改。

## 3. 非目标

必须明确不做：

- 不发布到公网。
- 不接 GitHub Pages / S3 / IPFS / Cloudflare。
- 不引入外部 JS / CSS / 字体 / 图片。
- 不允许 `<script>`。
- 不允许 `http://` / `https://` 外链。
- 不做二维码。
- 不嵌入 Public Attestation ZIP。
- 不嵌入 Registry ZIP。
- 不嵌入 Evidence Vault ZIP。
- 不让 Portal Snapshot 反向污染 Public Attestation / Registry source hash。
- 不让 Portal Snapshot 自动 publish / revoke Registry entry。

## 6. Store 行为

### 6.1 refresh_report

流程：

1. 确认 Portfolio 存在。
2. 读取 Attestation Registry ZIP。
3. 调用：

```text
verify_release_portfolio_governance_attestation_registry(
  zip_path,
  strict=True,
  require_current=True,
  require_published=True,
  require_no_revoked_current=True
)
```

4. Registry verification 必须 `passed`。
5. 读取 Registry ZIP 中的 `registry.json`、`registry-report.json`、`portal` 需要的 summary。
6. 找 current entry。
7. 读取 current entry source。
8. 读取当前 Public Attestation ZIP，并调用：

```text
verify_release_portfolio_governance_attestation(
  attestation_zip,
  strict=True,
  require_vault=True,
  require_final_board=True
)
```

9. Public Attestation verification 必须 `passed`。
10. 构建 Portal Source。
11. 计算 blockers / warnings。
12. 写 `portal-report.json`。
13. 写 history event：`portal_report_refreshed`。

必要 blockers：

- Registry ZIP missing。
- Registry verifier failed。
- Registry current entry missing。
- Registry current entry revoked。
- Registry current entry not published。
- Public Attestation ZIP missing。
- Public Attestation verifier failed。
- current entry source 与 attestation verification 不一致。
- Registry source 与 Attestation source 不一致。
- redaction failed。

### 6.2 export_portal

流程：

1. 读取 `portal-report.json`。
2. 确认 report integrity OK。
3. 确认 report source 当前，不 stale。
4. 删除旧 export 目录前做路径边界检查。
5. 写 HTML 页面。
6. 写 data JSON。
7. 写 `README.txt`。
8. 写 `portal-manifest.json`。
9. 写 history event：`portal_exported`。

不可变规则：

- 对同一 `source_hash + current_entry_hash + registry_zip_sha256`，已经 export 过后，不允许删除目录后重建。
- 要重建必须 Registry 状态变化或当前 Attestation 变化。

### 6.3 build_portal_zip

流程：

1. 如果 export 缺失且同 state 已经 export 过，返回 409。
2. 如果 ZIP 已存在且 manifest state 一致，返回 409。
3. 写 ZIP。
4. 写 history event：`portal_zip_built`。

不可变规则同 export。

### 6.4 verify_portal_zip

Store 可提供 convenience method：

```text
verify_release_portfolio_governance_attestation_portal(zip_path, strict=True, require_current=True)
```

并写 `portal-verification-report.json`。

## 9. Portal ZIP Verifier

新增：

```text
python -m song_agent.cli verify-release-portfolio-governance-attestation-portal <zip>
```

参数：

```text
--json
--report-out <path>
--strict
--require-current
--require-registry
--require-attestation
```

### 9.1 ZIP 检查

- ZIP exists。
- ZIP size limit。
- total uncompressed size limit。
- entry count limit。
- duplicate entry failed。
- raw central directory backslash failed。
- unsafe path failed。
- `.musicforge/` 大小写变体 failed。
- `nested/` 大小写变体 failed。
- `.zip` nested failed。
- strict 下 extra entry failed。

### 9.2 Manifest 检查

- `package_type == release_portfolio_governance_attestation_portal`。
- manifest integrity OK。
- `files[]` shape OK。
- file hash/size match。
- `manifest.source_hash == portal-report.source_hash`。
- `manifest.portal_report.integrity_hash == portal-report.integrity_hash`。
- `manifest.registry.*` 与 portal-report.source / registry-summary 一致。
- `manifest.current_attestation.*` 与 portal-report.source / current-attestation-summary 一致。
- `manifest.pages[]` path 必须存在且 hash match。

### 9.3 Report 检查

- report integrity OK。
- report source hash OK。
- report source 必须能从 data JSON 反查。
- summary counts 必须能从 registry-summary 反查。

### 9.4 HTML 检查

每个 HTML 页面：

- UTF-8 parse。
- hash match manifest。
- no script。
- no iframe/object/embed。
- no inline event handler。
- no http/https。
- no `url(`。
- no local path。
- no sensitive value。
- no blocked keys。

### 9.5 Data JSON 检查

- JSON parse。
- no blocked keys。
- no sensitive values。
- portal-summary 与 report summary 一致。
- registry-summary 与 report source / manifest registry 一致。
- current-attestation-summary 与 report source / manifest current_attestation 一致。
- verification-commands 不含本机绝对路径。

## 15. 安全边界

### 15.1 不信 HTML

HTML 只是展示层。Verifier 不能因为 HTML 内容自洽就通过，必须回到 manifest / report / data JSON。

### 15.2 不信 data JSON

Data JSON 也只是派生层。Verifier 必须反查到 Portal Report source。

### 15.3 不信 manifest.zip.entries

与之前所有 ZIP verifier 一致：

- allowed set 来自 `manifest.files[] + legal sidecars`。
- `manifest.zip.entries` 只能做参考。

### 15.4 不联网

任何 `http://` / `https://` 都失败。即使只是链接也失败。

### 15.5 不含嵌套包

Portal ZIP 不含：

- Attestation ZIP。
- Registry ZIP。
- Evidence Vault ZIP。
- `.musicforge/`。

### 15.6 不暴露本机路径

所有 page/data/readme 都要 redaction scan。

## 19. 风险清单

### P1：HTML 页面与数据源脱钩

必须让 verifier 检查 HTML 内容 hash 和 manifest page hash，同时 data/report 反查。不要求 verifier 语义解析完整 HTML，但至少要保证页面不是被替换成另一份内容。

### P1：Data JSON 整体重签绕过

必须把 data JSON 反查到 Portal Report source。不要只检查 data JSON 自己 hash。

### P1：Portal Report 整体重签绕过

Portal Report source 必须能从 Registry verifier + Attestation verifier 结果派生。

### P1：同 state 删除重建

必须用 history event 做不可变保护，不能只看文件是否存在。

### P1：外链和脚本

任何 HTML 外链和脚本都必须 failed。Portal 是离线 snapshot。

### P2：生成范围过大

不要做真实发布，不要接外部平台。v7.4 只做本地静态快照。

### P2：release-check 超时

现在完整 release-check 已经多次接近或超过 30 分钟。v7.4 开始必须在发布说明里明确 full release-check 是否完成；如果没完成，要补足定向集合。

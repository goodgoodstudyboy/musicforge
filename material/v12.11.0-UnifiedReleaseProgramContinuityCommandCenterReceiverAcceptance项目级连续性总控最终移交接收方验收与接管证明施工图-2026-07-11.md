# v12.11.0 Unified Release Program Continuity Command Center Receiver Acceptance 施工图

日期：2026-07-11

目标版本：v12.11.0

当前稳定基线：v12.10.0 提交候选，核心 P1 已复核通过，但仍需提交后跑干净 GA。

本文目标：在 v12.10 的 Continuity Command Center Signoff / Archive / Final Handoff 之上，补齐“接收方验收与运营接管证明”闭环。v12.10 证明内部总控已经签核并生成最终移交包，v12.11 需要证明接收方确实基于当前包完成 review、acceptance、quorum decision，并且该验收不能被 response payload 自报、包内自洽、旧 verification report 或删除历史文件绕过。

---

## 1. 背景

v12.10 已经完成：

- Continuity Command Center Signoff。
- 独立 signoff binding sidecar。
- signoff history hash-chain。
- approved single-use CR reset。
- Signoff Archive ZIP。
- Final Handoff ZIP。
- Release signoff gate。
- GA readiness / verify-ga-readiness-report gate。

但 v12.10 仍然停留在“项目侧已经完成最终移交包”的状态。它还没有证明：

- 外部接收方确实拿到了当前 Final Handoff。
- 接收方 review response 显式绑定当前 handoff / archive / command center source。
- accepted response 经过独立 verification / binding proof。
- 多角色接收方 quorum 达标。
- rejected / needs_changes / critical finding 会阻断最终接管。
- 接收方验收签核 archive 不能被全量重签或删除 history 绕过。

v12.11 要做的是把 v12.10 的内部签核推进到接收方接管层。

---

## 2. 版本定位

版本名称：

`Unified Release Program Continuity Command Center Receiver Acceptance`

一句话定义：

把 v12.10 的 signed Command Center Final Handoff 交给接收方，收集外部 response，生成 accepted evidence，形成 Receiver Acceptance Board，完成不可变签核归档，并接入 Release / GA gate。

推荐模块名：

- `song_agent/unified_release_program_continuity_command_center_acceptance.py`
- `song_agent/unified_release_program_continuity_command_center_acceptance_verifier.py`

推荐短存储目录：

- `.musicforge/urpccca/`

说明：

`urpccca` = Unified Release Program Continuity Command Center Acceptance。路径短，避免 Windows 深层临时目录下测试失败。

---

## 3. 非目标

v12.11 不做这些事：

- 不自动 approve reset。
- 不自动修改 v12.10 Command Center / Signoff / Handoff。
- 不把 needs_changes 或 rejected response 自动变成 accepted。
- 不允许导入端补 response source binding。
- 不依赖 reviewer payload 自报 role / organization / decision 作为 quorum 可信来源。
- 不做第三方 CA 或真实公钥体系。
- 不做长期公开门户发布；如果需要，后续 v12.12 或 v13 做 Receiver Acceptance Publication。
- 不做签核 reset。签核后如需改动，本版策略是新建 acceptance run；v12.12 可以单独设计 approved CR reset。

## 4. 核心对象

### 4.1 Handoff Review Pack

用于发给接收方 review 的固定结构 ZIP。

来源：

- v12.10 Signoff Archive ZIP。
- v12.10 Signoff Archive verification report。
- v12.10 Final Handoff ZIP。
- v12.10 Final Handoff verification report。
- v12.10 signoff binding summary。
- v12.9 Command Center ZIP。
- v12.9 Command Center verification report。
- v12.9 external evidence manifest。

Review Pack 必须运行时复验所有底层证据。

Review Pack 可以包含两个 nested ZIP，但必须固定 allow-list：

- `packages/command-center-signoff-archive.zip`
- `packages/command-center-final-handoff.zip`

不允许任何其他 nested ZIP。

### 4.2 Receiver Response

接收方返回的 response JSON 或 response ZIP。

必须由外部 response 自带 source binding。导入端不能补。

必需字段：

- `response_id`
- `review_pack_id`
- `review_pack_source_hash`
- `review_pack_zip_sha256`
- `review_pack_manifest_hash`
- `review_pack_verification_report_hash`
- `command_center_signoff_archive_zip_sha256`
- `command_center_signoff_archive_manifest_hash`
- `command_center_signoff_archive_verification_report_hash`
- `command_center_final_handoff_zip_sha256`
- `command_center_final_handoff_manifest_hash`
- `command_center_final_handoff_verification_report_hash`
- `command_center_signoff_binding_hash`
- `reviewer`
- `organization`
- `role`
- `decision`
- `findings`
- `created_at`

允许的 `decision`：

- `accepted`
- `needs_changes`
- `rejected`

API 导入只接受 base64，不接受：

- `source_path`
- `local_path`
- `file_path`
- `path`

CLI 可以读取本地 response 文件，但 Store 不得持久化原始本机路径。

### 4.3 Response Verification Report

Response Verification Report 必须由接收方侧随 response 一起提供。导入端只能验证并原样落盘，不能从 response payload 现场生成一份“passed”报告，也不能替导入端补 binding。

导入时必须同时提供三份外部材料：

- response 原文。
- response verification report。
- response binding summary。

三者任一缺失、package type 错误、integrity 错误、payload hash 不一致或 source binding 不匹配时直接拒绝导入。

报告字段：

- `package_type = musicforge_unified_release_program_continuity_command_center_acceptance_response_verification`
- `response_sha256`
- `response_payload_hash`
- `review_pack_source_hash`
- `review_pack_zip_sha256`
- `review_pack_manifest_hash`
- `review_pack_verification_report_hash`
- `status`
- `blockers`
- `integrity_hash`

### 4.4 Response Binding Summary

独立 sidecar，用于后续 accepted evidence 和 board 反查。

字段：

- `package_type = musicforge_unified_release_program_continuity_command_center_acceptance_response_binding`
- `program_id`
- `response_id`
- `response_sha256`
- `response_payload_hash`
- `response_verification_report_hash`
- `review_pack_source_hash`
- `review_pack_zip_sha256`
- `review_pack_manifest_hash`
- `review_pack_verification_report_hash`
- `signoff_archive_zip_sha256`
- `signoff_archive_manifest_hash`
- `signoff_archive_verification_report_hash`
- `final_handoff_zip_sha256`
- `final_handoff_manifest_hash`
- `final_handoff_verification_report_hash`
- `signoff_binding_hash`
- `reviewer_identity_hash`
- `decision_hash`
- `integrity_hash`

### 4.5 Accepted Evidence

只有 `decision == accepted` 且 response verification passed 才能创建。

Accepted Evidence 是 board 可引用的可信输入，但它自身也不能自证。

Accepted Evidence ZIP 固定结构：

- `manifest.json`
- `accepted-evidence.json`
- `original-response-public.json`
- `response-verification-summary.json`
- `response-binding-summary.json`
- `README.txt`

Verifier 必须使用外部 response verification / binding proof 反查 accepted evidence。

### 4.6 Receiver Acceptance Board

聚合 accepted evidence 和所有 response 状态。

默认 policy：

```json
{
  "min_accepted_count": 2,
  "min_organization_count": 2,
  "required_roles": ["continuity_owner", "operations_owner"],
  "block_on_rejected": true,
  "block_on_needs_changes": true,
  "block_on_critical_findings": true
}
```

Policy 可以在未签核前显式 refresh，但 signoff payload 不能覆盖 policy。

Board 输出：

- `receiver-acceptance-board-report.json`
- `receiver-decision-matrix.json`
- `receiver-quorum-report.json`
- `receiver-findings-register.json`
- `accepted-evidence-index.json`
- `response-proof-index.json`

### 4.7 Receiver Acceptance Signoff

Board ready 后由项目负责人签核。

必须生成：

- `receiver-acceptance-signoff.json`
- `receiver-acceptance-signoff-binding-summary.json`
- `receiver-acceptance-history.jsonl`
- `receiver-acceptance-state.json`
- `receiver-acceptance-policy.json`

signoff binding 必须在签核时独立落盘，archive/verifier 只能复制，不能现算。

### 4.8 Receiver Acceptance Archive

不可变 archive ZIP。

固定结构：

- `manifest.json`
- `receiver-acceptance-signoff.json`
- `receiver-acceptance-signoff-binding-summary.json`
- `receiver-acceptance-history.jsonl`
- `receiver-acceptance-state.json`
- `receiver-acceptance-policy.json`
- `receiver-acceptance-board-report.json`
- `receiver-decision-matrix.json`
- `receiver-quorum-report.json`
- `receiver-findings-register.json`
- `accepted-evidence-index.json`
- `response-proof-index.json`
- `source-handoff-summary.json`
- `source-signoff-archive-summary.json`
- `README.txt`

Archive 不内嵌 response 原文，不内嵌 accepted evidence ZIP，不内嵌 v12.10 handoff ZIP。Verifier 通过外部 evidence manifest 和外部 paths 反查。

## 10. Verifier 规则

### 10.1 Review Pack verifier

必须检查：

- 固定 allow-list。
- duplicate entry。
- raw backslash entry。
- dangerous path。
- `.MusicForge` / `.musicforge` case-insensitive 禁止。
- nested ZIP 只允许固定两份。
- manifest package_type。
- manifest.files 等于固定结构。
- package-index 等于固定结构。
- signoff archive runtime verification passed。
- final handoff runtime verification passed。
- external verification report 与 nested ZIP hash/size/manifest 绑定。
- signoff binding 和 handoff source 一致。
- no redaction leak。

### 10.2 Response verifier

必须检查：

- response 自带 binding 字段齐全。
- 不允许导入端补 binding。
- verification report / binding summary 必须由导入 payload 显式提供，Store 不得现场生成。
- response hash / payload hash。
- review_pack_id/source_hash 匹配当前 review pack。
- review pack ZIP / manifest / verification report hash 匹配当前文件。
- handoff/archive/signoff binding 指纹匹配当前 v12.10 source。
- `decision in accepted/needs_changes/rejected`。
- findings severity 合法。
- reviewer/organization/role 经过敏感信息脱敏。

### 10.3 Accepted Evidence verifier

必须检查：

- ZIP 固定 allow-list。
- public projection 不含敏感路径/token。
- public projection 必须反查 original response hash。
- response-verification-summary 必须反查外部 verification report。
- response-binding-summary 必须反查外部 binding summary。
- reviewer role / organization / decision 只能来自 verified response binding，不信 payload 自报。

### 10.4 Board verifier

必须检查：

- Board report / matrix / quorum / findings / indexes integrity。
- Board status 从 accepted evidence 外部 proof 重建。
- rejected / needs_changes response 阻断。
- critical finding 阻断。
- quorum count 和 organization count 从 accepted evidence proof 推导。
- required_roles 从 accepted evidence proof 推导。
- role forge full-resign 必须 failed。

### 10.5 Signoff Archive verifier

必须检查：

- 固定 allow-list。
- no extra entry。
- no trailing data。
- manifest files 等于固定结构。
- signoff integrity。
- binding integrity。
- history hash-chain。
- binding 与 signoff/history/source 一致。
- require_signed 时必须传外部 signoff binding。
- external signoff binding 必须和 ZIP 内 binding 完全一致。
- current review pack / accepted evidence / handoff/archive runtime source 必须匹配 signoff source。
- accepted evidence 通过 `accepted_evidence_dir` 按 evidence id 匹配；response proof 通过 sibling `responses/` 或显式 `response_proof_dir` 按 response id 匹配，不依赖命令行参数顺序。

## 11. 签核不可变规则

签核后禁止：

- import response。
- create accepted evidence。
- refresh board。
- signoff again。
- export archive 重算。
- build archive ZIP 重算。

允许：

- verify archive。
- read status。
- download existing immutable ZIP。

如果签核后删除：

- signoff JSON。
- signoff binding。
- history JSONL。
- state JSON。
- archive export dir。
- archive ZIP。

都不能降级为 unsigned 或 silently rebuild。必须返回 409。

v12.11 不提供 reset。需要改动时，新建 receiver acceptance run，或等 v12.12 单独做 approved CR reset。

```json
  "unified_release_program_continuity_command_center_acceptance_archive": "...",
  "unified_release_program_continuity_command_center_acceptance_verification_report": "...",
  "unified_release_program_continuity_command_center_acceptance_signoff_binding": "...",
  "unified_release_program_continuity_command_center_acceptance_review_pack": "...",
  "unified_release_program_continuity_command_center_acceptance_review_pack_verification_report": "...",
  "unified_release_program_continuity_command_center_acceptance_accepted_evidence_dir": "...",
  "unified_release_program_continuity_command_center_signoff_archive": "...",
  "unified_release_program_continuity_command_center_signoff_verification_report": "...",
  "unified_release_program_continuity_command_center_final_handoff": "...",
  "unified_release_program_continuity_command_center_final_handoff_verification_report": "..."

```

Gate 规则：

- required=false 时不阻断。
- required=true 时缺任一外部证据直接 409。
- force=true 不能绕过 failed / stale / missing / unsigned。
- archive verification report 必须绑定当前 archive ZIP。
- verifier 必须以 require_signed + external binding + current source paths 运行。

## 15. 必测回归

### 15.1 Happy path

- create review pack。
- verify review pack passed。
- import two accepted responses。
- create accepted evidence。
- refresh board ready。
- signoff signed。
- archive verify passed。
- Release gate passed。
- GA gate passed。

### 15.2 Missing binding

- verifier require_signed 但不传 external signoff binding。
- 预期 failed。

### 15.3 Role forge

- response payload 把 `technical_reviewer` 伪造成 `continuity_owner`。
- 重算 response/public evidence。
- Board 必须仍按外部 binding proof 判定。
- 预期 board blocked 或 verifier failed。

### 15.4 Rejected / needs_changes

- 导入 `rejected`。
- Board status blocked。
- signoff 409。

### 15.5 Stale review pack

- response accepted 后污染 v12.10 final handoff ZIP 或 review pack source。
- Board refresh blocked。
- signoff 409。

### 15.6 Signed full-resign

- 签核 archive 后同步篡改 signoff signed_by、history、manifest。
- 外部 binding 不变。
- verifier failed。

### 15.7 Delete history

- 签核后删除 `receiver-acceptance-history.jsonl`。
- signoff 409。
- export 409。
- zip 409。
- gate failed。

### 15.8 Declared extra

## 19. 给开发的话

v12.11 的关键不是多做一个 board，而是把 v12.10 的最终移交包变成“接收方已经验收并可接管”的证据。实现时先做 Store 和 verifier，不要先铺 API/UI。所有 quorum、role、decision 都必须从外部 response verification / binding / accepted evidence proof 推导，不能信 response payload 或 archive 内部 JSON 自洽。

重点防三类老问题：

1. 导入端补 binding。
2. 签核后删除 history 或 signoff 文件重新签。
3. 全量重签 archive 内部文件后绕过 external proof。

只要这三类挡住，v12.11 才算真正把接收方验收闭环收住。

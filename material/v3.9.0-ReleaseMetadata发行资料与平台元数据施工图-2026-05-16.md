# v3.9.0 Release Metadata 发行资料与平台元数据施工图

日期：2026-05-16

当前稳定基线：v3.8.1

目标版本：v3.9.0

定位：v3.8.1 已经让 Release ZIP 可以离开当前 `.musicforge/` 工作区独立验收。v3.9.0 要继续向“真实交付前准备”推进：新增 Release Metadata Sheet，把一个已验收 Release 的曲目资料、署名、歌词、credits、rights notes、平台字段、UPC/ISRC 手填字段、导出 CSV/JSON、Metadata QA 和 Studio 面板做完整。v3.9.0 仍不上传任何平台，只做本地资料准备和验收。

---

## 1. 背景

MusicForge 现在已经有三层交付能力：

```text
Project Final Export
  -> Project Delivery QA / Signoff
  -> Release Workspace
  -> Release Export / ZIP / Signoff
  -> verify-release 外部验收
```

这条链路能证明：

- 单曲 Project 的最终版本可交付。
- 多曲目 Release ZIP 可组装。
- Release ZIP 可离开本机独立验证。
- ZIP 内 manifest、track、signoff、hash、redaction、entry safety 都可验收。

但一个真实发行前包还缺“资料层”：

- Release 标题、艺人、厂牌、语言是否完整。
- 每首 track 的 display title、artist、version subtitle 是否完整。
- 词曲作者、制作人、编曲、混音、母带、演唱等 credits 是否完整。
- 歌词是否存在、是否标记 explicit。
- UPC / ISRC 是否人工填写并格式可校验。
- rights / license / copyright notes 是否明确。
- 平台要求的 CSV/JSON 是否可导出。
- Metadata 是否和 Release tracklist 一致。
- Metadata 是否不泄露本机路径、token 或 raw provider 内容。

v3.9.0 要补的是“发行资料工作台”。

---

## 2. 一句话目标

v3.9.0 要让一个已通过 v3.8.1 验收的 Release ZIP，进一步具备可交付给发行人员或平台后台录入人员的 metadata package：

```text
Release Workspace
  -> Release Metadata Sheet
  -> Track Credits / Lyrics / Rights
  -> Metadata QA
  -> Platform CSV / JSON Export
  -> Release Export / ZIP / verify-release summary update
```

最低成功标准：

```text
一个 2-track Release
  -> 填写 release-level metadata
  -> 填写 track-level metadata
  -> Metadata QA passed/warning
  -> 导出 release-metadata.json
  -> 导出 platform-metadata.csv
  -> Release Export/ZIP 包含脱敏 metadata summary
  -> verify-release 仍 passed
```

## 4. 核心原则

### 4.1 Metadata 是人工确认资料，不是自动事实

系统可以从 Release / Project / SongPlan 初始化建议值，但最终 metadata 是人工确认资料。

必须能区分：

- inferred。
- user_confirmed。
- missing。

### 4.2 Metadata QA 是准出检查，不是法律审查

Metadata QA 只做格式、完整性、一致性、安全检查。

它不判断：

- 版权是否真实。
- ISRC 是否已经注册。
- UPC 是否属于用户。
- credits 是否法律有效。

### 4.3 不破坏 v3.8.1 的可移植验收

Metadata 加入 Release ZIP 后，`verify-release` 仍必须能在外部目录独立验证：

- metadata files 存在。
- metadata files hash 匹配。
- metadata 不泄露路径/secret。
- metadata 与 tracklist 一致。

### 4.4 所有敏感信息都要二次脱敏

Metadata 是人工输入，最容易被粘贴进：

- 本机路径。
- token。
- API key。
- 私密备注。
- provider raw response。

写入 export/ZIP 前必须二次脱敏。

## 7. Metadata 初始化

新增 API：

```text
POST /api/releases/<release-id>/metadata/init
```

初始化来源：

- ReleaseDocument。
- tracklist。
- each track song-plan.json。
- project-export summary。

规则：

- 如果 `metadata.json` 不存在，创建完整 metadata。
- 如果已存在，默认不覆盖用户字段。
- `force=true` 才重建。
- `merge=true` 可以补缺失字段。

初始化字段：

- release title <- Release name。
- primary_artist <- Release primary_artist。
- track title <- ReleaseTrack title。
- language <- release language or SongPlan language。
- lyrics <- SongPlan lyrics if present。
- tempo/key/duration 只作为 source_summary，不作为平台字段。

## 8. Metadata QA

新增：

```text
song_agent/release_metadata_qa.py
```

### 8.1 Release-level checks

| check_id | 说明 | 级别 |
| --- | --- | --- |
| metadata_exists | metadata.json 存在 | blocking |
| release_title | title 必填 | blocking |
| release_artist | display_artist/primary_artist 必填 | blocking |
| release_type | release_type 合法 | blocking |
| release_date_format | YYYY-MM-DD | warning |
| upc_format | 12/13/14 位数字 | warning |
| copyright_present | copyright 建议填写 | warning |
| phonographic_copyright_present | P-line 建议填写 | warning |
| release_confirmed | release metadata confirmed | warning |
| redaction_scan | 无敏感值 | blocking |

### 8.2 Track-level checks

| check_id | 说明 | 级别 |
| --- | --- | --- |
| track_count_match | metadata tracks 与 release tracks 一致 | blocking |
| track_id_match | track_id 都存在 | blocking |
| track_title | title 必填 | blocking |
| track_artist | display_artist 必填 | blocking |
| isrc_format | ISRC 格式 | warning |
| isrc_unique | ISRC 不重复 | blocking |
| lyrics_presence | 非 instrumental 建议有 lyrics | warning |
| instrumental_lyrics_conflict | instrumental 但有 lyrics | warning |
| explicit_flag_consistency | lyrics 有敏感词但 explicit=false | warning |
| credits_present | composer/producer 建议填写 | warning |
| track_confirmed | track metadata confirmed | warning |

### 8.3 Status 规则

- 有 blocking failed -> `failed`。
- 无 blocking，但有 warning -> `warning`。
- 无 warning -> `passed`。


### 9.1 保存 metadata

`POST /metadata`：

- body 是完整 document 或 patch。
- 保存前 sanitize。
- 写 history event。
- 标记 Release export stale。

### 9.2 Metadata QA

`POST /metadata/qa/refresh`：

- 重新读取 Release。
- 重新读取 metadata。
- 检查一致性。
- 写 `metadata-qa.json`。

### 9.3 Metadata Export

`POST /metadata/export`：

- 必须 metadata QA 不 failed。
- 写入 release-export 下 metadata files。
- 更新 release export manifest。
- 标记 ZIP stale 或要求重新 build Release ZIP。

v3.9.0 要扩展 `release_verifier.py`：

新增检查：

- metadata manifest summary。
- `release-metadata.json` parse。
- `platform-metadata.csv` exists / UTF-8。

- metadata track_count 与 tracklist 一致。

- 如果 manifest 没有 metadata summary：warning。

## 18. 风险清单

### P1：metadata 污染进入可携带 ZIP

必须让 Metadata QA 和 verify-release 双层阻断。

### P1：metadata export 后 ZIP 没重建

必须让 metadata export 标记 Release ZIP stale，或者自动重建并更新 manifest。

### P1：metadata tracklist 与 Release tracklist 不一致

必须 blocking failed。

### P2：字段太多导致 UI 不可用

先做表格和 textarea，不做复杂表单引擎。

### P2：平台字段差异过大

v3.9.0 只做通用 CSV/JSON，不做各平台上传模板。

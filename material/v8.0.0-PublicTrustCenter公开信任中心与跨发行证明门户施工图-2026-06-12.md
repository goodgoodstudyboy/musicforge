# v8.0.0 Public Trust Center 公开信任中心与跨发行证明门户施工图

> 本文是给开发执行的 v8.0.0 施工图。当前稳定基线是 v7.9.1。v7.9.1 已修复 Acknowledgement Evidence ZIP 全量重签伪造问题：Evidence export 会写入 `response-verification-summary.json` 和 `original-response-binding-summary.json`，offline verifier 必须把 evidence public summary 反查到原始 accepted response，而不是只验证 evidence 自身自洽。

v8.0.0 的目标是跨一个更大的步子：把 v7 已经做完的公开证明链路，从“单个 Portfolio Audit 的证明包集合”升级为“可交付给外部合作方的 Public Trust Center 公开信任中心”。

一句话：

> v8.0.0 要把 Release / Distribution / Submission / Operations / Portfolio Governance / Public Attestation / Registry / Portal / Transparency / Acknowledgement 等公开安全摘要，聚合成一个跨发行、可离线验证、可静态浏览、可导出 ZIP、可被外部方审计的 Public Trust Center。它不是把所有内部证据打包出去，而是建立一个公开可携带的信任入口，让外部方一次性判断哪些 release 已签核、哪些证明当前有效、哪些门户被接受、哪些透明度变更已有回执。

---

## 1. 背景

MusicForge 目前已经从“自动生成音乐”走到了完整的本地生产、验收、交付、证明链：

### 1.1 生产和质量链

- SongPlan / MIDI 生成。
- Provider / multinode agent。
- Project version / edit / visual editor。
- Stems / audio render / mastering / encoded formats。
- Human acceptance / regression songbook / manual review。
- Audio revision / mix / mastering QA。

### 1.2 交付链

- Final Export。
- Release Workspace。
- Distribution Prep。
- Submission Workspace。
- Submission Evidence Archive。
- Release Operations Dashboard。
- Release Operations Runbook / Signoff / Archive / Audit / Reviewer Pack。

### 1.3 Portfolio Governance 链

- Portfolio Audit。
- Governance Action Queue。
- Governance Signoff / Archive / Audit / Reviewer Pack。
- Final Board。
- Evidence Vault。
- Public Attestation。
- Attestation Registry。
- Attestation Portal Snapshot。
- Portal Review Response。
- Accepted Evidence。
- Transparency Feed。
- Transparency Acknowledgement。

v7 解决了一个非常关键的问题：公开证明链路的每个包都能离线验证，而且不断修掉了“公开摘要可伪造”“全量重签自洽但语义错误”“旧 verification report 被重放”等问题。

现在的主要缺口变成了“入口割裂”：

1. 外部方需要分别拿到 Portal ZIP、Registry ZIP、Attestation ZIP、Transparency ZIP、Acknowledgement Evidence ZIP。
2. 内部运营人员需要在 Studio 的多个面板之间切换才能判断一批 release 的公开证明状态。
3. 对合作方来说，单个包是可验证的，但缺少一个面向人的、公开安全的总入口。
4. 对审计来说，跨 release / portfolio 的状态趋势、当前有效证明、最近变更、已接受回执，没有一个统一索引。
5. 现有 Public Attestation Portal 是单 Portfolio 的静态快照，不是跨发行公共信任中心。

v8.0 要补的就是这个总入口。

## 2. v8.0 的业务定位

### 2.1 它是什么

Public Trust Center 是一个本地生成、可导出 ZIP、可离线验证、可静态浏览的公开信任中心。

它聚合：

- Releases 的公开交付状态。
- Distribution targets 的公开提交状态。
- Submission / accepted 状态。
- Release Operations signoff / audit / archive 摘要。
- Portfolio Governance signoff / audit / Final Board 摘要。
- Evidence Vault / Public Attestation / Registry / Portal / Transparency / Acknowledgement 当前证明状态。
- Accepted Evidence / external review / acknowledgement evidence 的公开摘要。
- 风险与缺口索引。

### 2.2 它不是什么

Public Trust Center 不是：

- 不是公网托管服务。
- 不是 SaaS 后端。
- 不是区块链。
- 不是法律电子签名。
- 不是把 `.musicforge/` 内部证据全部公开。
- 不是嵌套所有 ZIP 的超级包。
- 不是替代 Evidence Vault。
- 不是替代 Registry。
- 不是替代 Portal。
- 不是自动发布或自动通知外部方。

### 2.3 目标用户

- 外部合作方：查看当前 release 证明是否有效。
- 发行负责人：查看所有发行准备、提交、验收、公开证明状态。
- 法务/审计：查看跨发行证明链是否完整。
- 内部 reviewer：快速发现哪些 release 还缺 acceptance、rights、audio review、public acknowledgement。
- 开发：用 offline verifier 验证 Trust Center 是否可携带、不可伪造、不可泄密。

## 3. v8.0 的核心目标

新增 Public Trust Center。

核心能力：

1. 建立 Trust Center Store。
2. 支持跨 release / portfolio 聚合公开安全摘要。
3. 生成 Trust Center Report。
4. 生成 Trust Center Static Portal。
5. 生成 Trust Center Export。
6. 生成 Trust Center ZIP。
7. 新增离线 verifier：`verify-public-trust-center-package`。
8. Trust Center 不嵌套任何内部 ZIP。
9. Trust Center 可选择引用外部包 fingerprint，但不复制内部包内容。
10. Trust Center 支持 profile：
    - `public_summary`
    - `partner_due_diligence`
    - `internal_preview`
11. Trust Center 支持 publish snapshot / archive snapshot / supersede snapshot。
12. Trust Center 支持 external acknowledgement summary，但不导入新的外部 response。
13. Trust Center 支持 risk register 和 readiness index。
14. Studio 增加顶层 `Trust Center` 工作区。
15. CLI / API 接入。
16. release-check matrix 新增 `v80.public_trust_center_smoke`。
17. README / CHANGELOG / version bump 到 `8.0.0`。

---

## 4. 版本边界

v8.0 是 major version，不只是 v7.10。

理由：

1. v7 已经完成公开证明链路的最后外部确认闭环。
2. v8.0 开始面向“多 release / 多 portfolio 的公共入口”。
3. 数据模型会横跨 Release / Distribution / Submission / Operations / Portfolio Governance / Public Attestation 多条链。
4. Studio 会新增顶层 Trust Center 工作区，而不只是 Portfolio 页面子面板。
5. 离线 verifier 会验证一个更高层级的门户包。

---

## 5. 非目标

v8.0 不做：

- 不做公网部署。
- 不做 GitHub Pages 自动发布。
- 不做 S3 / OSS / IPFS 上传。
- 不做邮件通知。
- 不做 webhook。
- 不做多用户权限。
- 不做真实电子签章。
- 不自动创建 Release / Portfolio / Attestation。
- 不自动 signoff。
- 不自动 reset / approve Change Request。
- 不自动导入 external reviewer response。
- 不嵌套 Release ZIP / Evidence Vault ZIP / Portal ZIP / Transparency ZIP / Acknowledgement ZIP。
- 不公开 reviewer 私密 comments 原文。
- 不公开 audio files。
- 不公开 full lyrics / stems / source assets。
- 不公开本机路径、provider key、GitHub token、renderer config、SoundFont path。

## 12. Verifier 设计

新增：

```text
song_agent/public_trust_center_verifier.py
```

### 12.1 基础 ZIP 检查

必须检查：

- ZIP 可打开。
- raw central directory entry name。
- duplicate entries。
- backslash entry。
- dangerous path。
- absolute path。
- drive letter。
- UNC path。
- `.musicforge/` 大小写变体。
- nested `.zip`。
- entry count。
- total uncompressed size。
- per-entry size。

检查项：

```text
ptc_zip_open
ptc_zip_entry_path_safe
ptc_zip_duplicate_entries
ptc_zip_no_nested_packages
ptc_zip_size_limits
```

### 12.2 Manifest 检查

必须：

- `package_type == musicforge_public_trust_center`
- required entries 存在。
- manifest integrity hash 正确。
- files hash/size 匹配。
- extra entry 在 strict 下 failed。
- 不信 `manifest.zip.entries` 放行 entry。

检查项：

```text
ptc_manifest_package_type
ptc_manifest_integrity
ptc_manifest_file_hashes
ptc_manifest_files_match_zip
ptc_manifest_zip_entries_reference_only
```

### 12.3 Report / Data 绑定

必须：

- report.source_hash == manifest.source_hash。
- report.integrity_hash 正确。
- data/trust-center-data.json source_hash == report.source_hash。
- release-index / portfolio-index / package-index / verification-index 都 source_hash 一致。
- report summary 能从 data 反推。
- risk register 能从 data 反推。
- readiness index 能从 data 反推。

检查项：

```text
ptc_report_source_hash
ptc_report_integrity
ptc_data_source_hash
ptc_summary_semantics_match
ptc_risk_register_semantics_match
ptc_readiness_index_semantics_match
```

### 12.4 HTML 安全

必须：

- 不允许 remote script。
- 不允许 remote stylesheet。
- 不允许 `javascript:` URL。
- 不允许 form action 指向外部。
- 不允许 base64 blob 内嵌可执行 HTML。
- HTML 展示 summary 必须与 data sidecar 一致。

检查项：

```text
ptc_html_static_safe
ptc_html_summary_matches_data
```

### 12.5 Public Package Fingerprint 绑定

Trust Center 不嵌套 public packages，但会引用 fingerprint。Verifier 必须确认 package-index 与 report/data 一致：

```text
ptc_package_index_matches_report
ptc_verification_index_matches_package_index
```

如果 `--require-public-attestation`：

- 每个 included portfolio 必须有 public attestation status passed。

如果 `--require-registry-current`：

- 每个 included portfolio 必须有 current registry entry。

如果 `--require-portal-current`：

- 每个 included portfolio 必须有 current portal summary。

如果 `--require-transparency-current`：

- 每个 included portfolio 必须有 current transparency feed。

如果 `--require-acknowledgement-current`：

- 每个 included portfolio 必须有 current accepted transparency acknowledgement evidence。

### 12.6 Redaction

扫描所有 `.json/.txt/.html/.md/.csv`：

- token。
- key。
- Windows path。
- UNC path。
- `.musicforge`。
- `provider-snapshot`。
- `renderer.json`。
- `githubkey`。
- `source_path` / `local_path` / `file_path`。

检查项：

```text
ptc_redaction_scan
```

### 12.7 全量重签攻击

必须补回归：

1. 改 report summary，重算 report/manifest，但不改 data。
   - `ptc_summary_semantics_match` failed。
2. 改 data trust-center-data，重算 data/report/manifest，但不改 package-index。
   - `ptc_package_index_matches_report` 或 data semantics failed。
3. 改 HTML 展示 status，重算 manifest。
   - `ptc_html_summary_matches_data` failed。
4. 加 extra entry 并写进 `manifest.zip.entries`。
   - strict 下 failed。

## 19. 安全边界

### 19.1 不嵌套 ZIP

Public Trust Center 只能引用 public package fingerprint，不复制 ZIP。

如果发现 ZIP entry：

```text
*.zip
nested/*
```

verifier failed。

### 19.2 不信 manifest.zip.entries

Verifier 的 allowed entries 来自：

- required entries。
- manifest.files[].path。

`manifest.zip.entries` 只做一致性参考。

### 19.3 不信 HTML

HTML 是展示副本。

Verifier 必须从 data JSON 反推 summary，再检查 HTML 是否匹配。

### 19.4 不信 report 自身

Report summary 必须从 data/trust-center-data.json 反推。

### 19.5 不信 data 自身

data/trust-center-data.json 必须和 package-index / verification-index / release-index / portfolio-index 互相校验。

### 19.6 不泄漏内部路径

Trust Center 是公开入口，任何路径泄漏都应 failed。

## 27. 给开发的交接说明

开发同学请先读这一段，再开始写代码。

v8.0.0 不是一个“小面板”或“小 ZIP”。它是 MusicForge 进入 v8 的第一版，目标是把前面 v1 到 v7 做出来的生产、验收、发行、运营、组合治理、公开证明链路，收束成一个外部可读、可携带、可离线验证的 Public Trust Center。

你要把它当成一个“公开信任中心交付物”来做，而不是当成一个内部 dashboard。

关键原则：

1. Trust Center 只能读底层状态，不允许自动修改 Release / Distribution / Submission / Operations / Portfolio / Registry / Portal / Transparency / Acknowledgement。
2. Trust Center ZIP 只能包含公开安全摘要，不允许嵌套任何内部 ZIP。
3. Trust Center verifier 必须能在离开 `.musicforge/` 的干净目录里独立验证。
4. HTML 只是展示层，不能成为证据来源。
5. Report 不能只自证，必须能从 data sidecar 反推。
6. data sidecar 也不能只自证，必须和 package-index / verification-index / release-index / portfolio-index 互相绑定。
7. 每完成一个稳定阶段就提交一次，不要一口气堆完。
8. 每个阶段都要跑对应定向测试，通过后再进入下一阶段。

开发前先确认当前基线：


```text
ptc_html_summary_matches_data failed
```

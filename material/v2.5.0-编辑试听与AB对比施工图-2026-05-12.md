# v2.5.0 编辑试听与 A/B 对比施工图

日期：2026-05-12

当前基线：v2.4.1

目标版本：v2.5.0

定位：在 v2.4.x 已经具备 Project Editor、Clip Insert、MultiTrack Template Insert、Preview / Apply / Export 审计链路的基础上，把“编辑后能不能听、怎么听、怎么和父版本对比”补成正式能力。v2.5.0 的核心不是继续增加编辑类型，而是让每一次编辑、clip 插入、template 插入都可以在不 Apply 的情况下完成可靠试听和 A/B 判断。

---

## 1. 背景

到 v2.4.1，MusicForge 已经具备：

- Project Version 管理。
- Visual Editor Patch。
- Editor Draft / Preview / Apply。
- Section / Track 结构编辑。
- Piano Roll 交互视图。
- 单轨 Clip 插入。
- 多轨 Section Template / Track Template 保存和插入。
- `clip_inserts` / `template_inserts` provenance 贯通到 Preview Apply、Compare、Project Export、Final Export。
- Editor Preview 已能生成 MIDI，后端也已有基础 `render-audio` / `audio` 路由。

但当前体验还有一个明显短板：

- 用户能“构造编辑”，但不能高效“听出编辑是否正确”。
- Studio Preview 面板主要展示 JSON / MIDI 下载，音频试听入口不完整。
- 父版本和 Preview 之间缺少明确的 A/B 对比。
- 用户想听某个 section、某几条 track、solo/mute 效果时，需要 Apply 成版本或手动下载 MIDI 到外部软件。
- Preview History 虽然存在，但还不是一个真正可复用的 audition 面板。
- 当前 audio render 状态没有形成统一 manifest，失败、大小、路径、安全边界和 cleanup 行为需要收紧。

v2.5.0 要补齐这层“试听判断能力”。这一步做完后，用户才能在 Studio 里形成完整工作流：

编辑 -> Draft 看结构 -> Preview 固化候选 -> A/B 试听 -> 局部试听 -> 决定 Apply 或丢弃。

---

## 2. 一句话目标

v2.5.0 要把 Project Editor 从“能预览数据”推进到“能听着做决定”：

- Preview 后可直接试听 Preview WAV。
- 可一键渲染并试听父版本 WAV。
- 可在 Studio 中 A/B 切换父版本与 Preview。
- 可创建局部试听片段：全曲、当前 section、changed sections、自定义 beat range。
- 可创建 track audition：all / solo / mute。
- 所有试听产物都有本地 manifest、状态、错误信息、路径边界保护和 cleanup 行为。
- Preview Apply 继续只信任 patch 重新计算结果，不信任试听产物。
- release-check 覆盖 v2.5 audition 主链路，但不能依赖真实 SoundFont。

---

## 3. 不做什么

v2.5.0 必须继续收住边界：

- 不做实时 DAW 播放引擎。
- 不做 Web Audio 多轨混音器。
- 不做 waveform 编辑。
- 不做音频剪切、淡入淡出、压缩、EQ、混响等混音能力。
- 不做 MP3 / FLAC 导入导出。
- 不做 VST / AU 插件。
- 不做 streaming audio。
- 不做复杂 loop arranger。
- 不做多人协作。
- 不把 audition 产物当成正式 Project Version。
- 不让 Final Export 默认带上临时 audition WAV。

这版只做“本地确定性试听产物”和“Studio A/B 判断界面”。

---

## 4. 用户价值

目标用户工作流：

1. 用户打开一个 Project Version。
2. 在 Project Editor 里做手工编辑、插入 Clip、插入 Section Template。
3. 点击 Preview，生成 `preview-001`。
4. 点击 Render Preview Audio，得到 Preview WAV。
5. 点击 Render Parent Audio，得到父版本 WAV。
6. 在 Studio 里用 A/B 按钮切换听父版本和 Preview。
7. 只听 chorus 或当前编辑 section。
8. solo melody / mute drums 检查局部编曲。
9. 如果满意，再 Apply 成新 Project Version。
10. 如果不满意，删除 Preview 或继续编辑，不污染正式版本历史。

这会显著减少“为了听效果而反复 Apply”的脏版本。

---

## 5. 核心设计原则

### 5.1 Preview 是候选，不是正式版本

Preview 可以有 MIDI、WAV、audition variants，但它们都只是候选产物。

Apply 时仍然必须：

- 读取父版本 SongPlan。
- 读取 Preview patch。
- 从父版本 + patch 重新计算 result plan。
- 用 result plan 写新 job / version。
- 不信任 preview 目录里的 `song-plan.json`、audition MIDI、audition WAV。

v2.0.1 已经修过类似问题，v2.5.0 不能倒退。

### 5.2 Audition 是可删除缓存

Audition 产物可以重建，不应该成为最终交付核心数据。

建议默认放在：

```text
.musicforge/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/
```

其中：

```text
audition.json
song-plan.json
song.mid
song.wav
render-report.json
events.jsonl
```

`song-plan.json` 是试听用裁剪/过滤后的计划，不是正式 Project Version。

### 5.3 所有路径必须从 store 解析

任何下载、删除、渲染都不能信任客户端传入路径。

必须通过：

- `project_id`
- `preview_id`
- `audition_id`
- `source`
- `track_ids`
- `range`

重新解析到受控目录。

禁止把 manifest 里的任意路径拿来复制或下载。

### 5.4 release-check 不能依赖真实 SoundFont

很多本地机器没有 FluidSynth / SoundFont。

因此：

- 单测中用 fake renderer / fake audio runner 覆盖 WAV 渲染。
- release-check 必须覆盖 MIDI audition 主链路。
- release-check 可以检查未配置 renderer 时返回清晰错误。
- 如果本机 renderer 已配置，可以额外跑可选 WAV smoke，但不能作为必过前提。

## 7. 数据模型

### 7.1 EditorAuditionManifest

建议字段：

```json
{
  "schema_version": 1,
  "audition_id": "audition-001",
  "project_id": "project-001",
  "preview_id": "preview-001",
  "source": "preview",
  "parent_version_id": "v001",
  "base_plan_hash": "...",
  "source_plan_hash": "...",
  "created_at": "...",
  "updated_at": "...",
  "status": "completed",
  "label": "Preview chorus solo melody",
  "range": {
    "mode": "section",
    "section_id": "section-003",
    "start_beat": 32,
    "end_beat": 48
  },
  "track_mode": "solo",
  "track_ids": ["track-001"],
  "note_count": 24,
  "track_count": 1,
  "duration_beats": 16,
  "midi": {
    "exists": true,
    "size_bytes": 3200,
    "url": "/api/projects/project-001/editor-previews/preview-001/auditions/audition-001/midi"
  },
  "audio": {
    "status": "not_started",
    "exists": false,
    "size_bytes": 0,
    "url": null,
    "error": null
  },
  "warnings": []
}
```

### 7.2 source

支持：

- `preview`：试听 Preview 结果。
- `parent`：试听 Preview 对应的父版本。

不要在 v2.5.0 做任意 Project Version 之间的 audition。先围绕 Editor Preview A/B 解决核心工作流。

### 7.3 range

支持：

- `full_song`
- `section`
- `changed_sections`
- `custom`

字段规则：

- `full_song`：不需要 `start_beat/end_beat`。
- `section`：需要 `section_id`，服务端根据 SongPlan 解析。
- `changed_sections`：根据 preview summary 自动取 changed sections 的最小覆盖区间。
- `custom`：需要 `start_beat/end_beat`。

限制：

- `start_beat >= 0`
- `end_beat > start_beat`
- `end_beat <= total_beats`
- 最短长度建议 `>= 0.25 beat`
- 最大长度可以允许全曲，但要受 SongPlan 总长度限制。

### 7.4 track_mode

支持：

- `all`
- `solo`
- `mute`

规则：

- `all`：忽略 `track_ids`。
- `solo`：只保留 `track_ids` 中的 tracks。
- `mute`：排除 `track_ids` 中的 tracks。
- `track_ids` 必须存在于对应 source plan。
- 禁止 derived-only UI id 传入后端，后端只接受真实 `track-xxx`。
- 如果过滤后没有任何有音符 track，返回 `409 Audition produced no notes.`

## 8. 后端任务

### Phase 1：Editor Audition Core

新增 `song_agent/editor_audition.py`。

需要实现：

- `EditorAuditionError`
- `EditorAuditionUnavailableError`
- `EditorAuditionManifest`
- `EditorAuditionStore`
- `create_audition(...)`
- `render_audition_midi(...)`
- `render_audition_audio(...)`
- `build_audition_plan(...)`

核心逻辑：

1. 根据 `source=preview|parent` 读取 source plan。
2. 解析 range。
3. 根据 track_mode 过滤 tracks。
4. 裁剪 notes：
   - note 与 range 无交集：丢弃。
   - note 跨 range 边界：裁剪 duration。
   - 裁剪后的 note start 建议 rebased 到 0，便于试听片段从开头播放。
5. 裁剪 sections：
   - 保留与 range 有交集的 sections。
   - section start/end rebased。
   - lyrics/chords 保留。
6. 重新计算 `total_bars` 或保证 song plan validator 接受。
7. attach quality 或保留基本 quality summary。
8. render MIDI。
9. 写 manifest。

注意：

- 不要改父版本。
- 不要改 preview patch。
- 不要把 audition plan 写回 preview `song-plan.json`。
- Audition manifest 写入必须原子化，沿用 `write_json`。
- Store id 分配必须在 lock 内完成，并用 `mkdir(..., exist_ok=False)` 原子占位。

### Phase 2：Preview Audio 状态收紧

当前 `EditorPreview` 有 `audio_url`，但没有完整状态。

建议扩展：

```python
audio_status: str = "not_started"
audio_error: str | None = None
audio_size_bytes: int = 0
audio_updated_at: str | None = None
```

行为：

- Preview 创建时：`audio_status=not_started`
- Render Preview Audio 成功：`completed`
- Render Preview Audio 失败：`failed` + 脱敏 error
- Renderer 未配置：返回 400，preview 可记录 failed 或保持 not_started。建议记录 failed，方便 UI 展示。

必须补兼容：

- 旧 preview.json 没有这些字段时，from_dict 默认不报错。
- Preview History 读取旧 preview 不崩。

### Phase 3：API

新增或补强 API。

#### 8.3.1 Preview Audio 已有路由补强

现有：

```text
POST /api/projects/<project-id>/editor-previews/<preview-id>/render-audio
GET  /api/projects/<project-id>/editor-previews/<preview-id>/audio
```

需要补：

- `GET audio` 在 WAV 不存在时返回 404，不要泄露路径。
- `POST render-audio` 返回 preview audio status/report。
- Renderer 错误返回 400，错误文本脱敏。
- 写 project event：`editor_preview_audio_rendered` / `editor_preview_audio_failed`

#### 8.3.2 Parent Version Audio

为了 A/B 对比，Studio 需要能渲染父版本。

新增：

```text
POST /api/projects/<project-id>/versions/<version-id>/render-audio
GET  /api/projects/<project-id>/versions/<version-id>/audio
```

实现可以复用现有 Job audio render：

- 通过 Project Version 找到 `job_id` / `output_dir`
- 调用现有 job audio renderer 或同等逻辑
- 不要让客户端传 run path

返回：

```json
{
  "ok": true,
  "version_id": "v001",
  "job_id": "job-001",
  "audio_status": "completed",
  "audio_url": "/api/projects/project-001/versions/v001/audio",
  "audio": {
    "exists": true,
    "size_bytes": 12345
  }
}
```

#### 8.3.3 Audition API

新增：

```text
GET  /api/projects/<project-id>/editor-previews/<preview-id>/auditions
POST /api/projects/<project-id>/editor-previews/<preview-id>/auditions
GET  /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>
GET  /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/midi
GET  /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/audio
POST /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/render-audio
POST /api/projects/<project-id>/editor-previews/<preview-id>/auditions/<audition-id>/delete
```

`POST auditions` payload：

```json
{
  "source": "preview",
  "label": "Chorus melody solo",
  "range": {
    "mode": "section",
    "section_id": "section-003"
  },
  "track_mode": "solo",
  "track_ids": ["track-001"],
  "render_audio": false
}
```

响应：

```json
{
  "ok": true,
  "audition": {
    "audition_id": "audition-001",
    "status": "completed",
    "midi": {
      "url": "/api/projects/project-001/editor-previews/preview-001/auditions/audition-001/midi"
    },
    "audio": {
      "status": "not_started"
    }
  }
}
```

错误规则：

- unknown preview：404
- unknown source：400
- unknown section：400
- invalid range：400
- unknown track：400
- no notes after filter：409
- renderer missing：400
- path boundary issue：500 或 400，但必须记录并不泄露本地路径

## 10. 安全与边界

开发必须重点检查：

### 10.1 路径安全

- `project_id`、`preview_id`、`audition_id` 都必须 validate。
- 下载 MIDI/WAV 时必须从 store path 解析。
- `audition.json` 里的 URL/path 不能作为真实文件路径来源。
- 删除 audition 时拒绝 symlink。
- cleanup 时拒绝 symlink。

### 10.2 数据污染

Apply 不能信任：

- preview `song-plan.json`
- audition `song-plan.json`
- audition `song.mid`
- audition `song.wav`
- audition manifest

Apply 只能信任：

- 父版本 SongPlan
- preview patch
- 当前 patch engine 重新计算结果

### 10.3 脱敏

错误和 metadata 不得暴露：

- API key
- Bearer token
- GitHub token
- 本机路径
- SoundFont 绝对路径
- renderer executable path

复用 `song_agent/redaction.py`。

### 10.4 并发

需要考虑：

- 同一个 preview 并发创建 audition。
- 同一个 audition 并发 render audio。
- preview cleanup 和 audition render 同时发生。
- delete audition 和 download 同时发生。

最低要求：

- Store 使用 `RLock`。
- ID 分配在 lock 内完成。
- 目录用 `mkdir(..., exist_ok=False)` 原子占位。
- 写 JSON 用现有原子写。

## 13. 版本和推送准则

继续执行当前项目准则：

- 每完成一个可独立验证的阶段，就提交一次。
- 每个阶段测试通过后推 GitHub。
- 不要把所有内容堆到最后一个巨大提交。
- 不要提交 `.musicforge/` 本地运行数据。
- 不要提交 provider key、renderer path、SoundFont path。
- 不要把 token 写入 remote URL。
- 版本号只在准备发布时升到 `2.5.0`。
- 发布前必须确认：
  - `HEAD = origin/master`
  - `v2.5.0^{}` 指向发布 commit
  - GitHub Release latest 是 `v2.5.0`

如果普通 `git push` 因 GitHub 443 网络问题失败，可以沿用之前的安全处理方式：

- 不改 remote URL。
- 不把 token 写入文档或配置。
- 用一次性 Git 网络参数或 GitHub API 完成远端同步。
- 完成后必须把本地 master 和本地 tag 对齐到远端。

## 14. 验收标准

v2.5.0 完成时，必须满足：

- 用户可以在 Studio 对 Editor Preview 渲染并试听 WAV。
- 用户可以在 Studio 对父版本渲染并试听 WAV。
- 用户可以在同一面板做 Parent / Preview A/B。
- 用户可以创建至少三类 audition：
  - full song
  - section / changed_sections
  - solo / mute track
- Audition MIDI 下载可用。
- Audition WAV 在 renderer 配置后可用。
- Renderer 未配置时错误清晰，不影响 MIDI audition。
- Preview Apply 不信任 audition 产物。
- Project Export 只写脱敏 audition summary。
- Final Export 默认不复制 audition WAV。
- Preview cleanup 删除未保护 preview 时会带走 audition 子目录。
- Applied preview 仍受保护。
- 所有 API 受现有 auth 保护。
- 所有下载路径都有边界保护。
- 全量测试通过。
- release-check 通过。
- GitHub master/tag/release 对齐。

## 15. Reviewer 重点检查清单

开发完成后，reviewer 应重点看：

- `EditorPreviewStore` 扩字段是否兼容旧 preview。
- Audition Store 是否有锁和原子目录占位。
- `audition_id` 是否 validate。
- 下载接口是否只从 store path 取文件。
- 删除接口是否拒绝 symlink。
- `source=parent` 是否通过 Project Version 解析，不允许客户端传路径。
- range 裁剪是否会产生负 duration。
- note rebasing 后 MIDI 是否仍可渲染。
- solo/mute 后没有 notes 时是否返回 409。
- renderer error 是否脱敏。
- Studio A/B 播放是否会同时响两个 audio。
- Apply 是否仍从父版本 + patch 重算。
- Export / Final Export 是否没有本机路径。
- release-check 是否不依赖真实 SoundFont。

## 16. v2.5.1 预留修复方向

v2.5.0 发布后，如果 reviewer 发现以下问题，优先发 v2.5.1 收紧，不要急着进 v2.6.0：

- Audition manifest path 可被污染。
- Apply 间接信任 preview/audition 文件。
- parent/preview A/B 使用了错误父版本。
- range 裁剪导致 MIDI note_off 不配对。
- concurrent render 覆盖音频文件。
- cleanup 删除了 applied preview 的 audition。
- renderer error 泄露本机路径。
- Studio 在 audio 缺失时无限轮询或按钮状态错误。

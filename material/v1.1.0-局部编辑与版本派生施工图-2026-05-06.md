# MusicForge v1.1.0 施工图：局部编辑与版本派生

日期：2026-05-06

基线版本：v1.0.2

当前 v1.0.2 已经完成 Project Variation、Quality Gate、Final Export，并修复了 v1.0.0/v1.0.1 发现的 stem 边界和门禁覆盖问题。v1.0.x 可以作为稳定基线。

v1.1.0 的主题不再是继续堆“生成一次”的能力，而是开始做真正的可控修改：

> 用户应该能选中一个 Project version，对某个 section、track 或歌词局部发起编辑，系统生成一个新的 child version，并保留旧版本、变更说明、质量门禁和最终交付链路。

这版必须坚持非破坏式编辑：所有 edit 都创建新 job / new version，不直接覆盖父版本的 `song-plan.json`、MIDI、stems、audio 或 final export。

## 1. 为什么 v1.1.0 做局部编辑

v1.0.x 已经把 MusicForge 做成了可以本地运行、生成、筛选、定稿、交付的系统。现在主要缺口是：用户听完之后，通常不是想重新生成整首歌，而是想局部调整。

典型需求：

- 副歌更强一点。
- 主歌少一点鼓。
- 只换 chorus 和弦。
- 只改 verse 歌词。
- 保留结构和音色，只重写 melody。
- 保留 selected/final version，派生一个小修改版本对比。

如果仍然只靠 v1.0.0 的 `request_patch`，用户只能改 style/theme/tempo/key/lyrics 这类输入字段，不能表达“改哪一段、改哪一轨、怎么改”。这会导致生成不稳定、版本差异过大，也不利于本地验证。

所以 v1.1.0 要补一个中间层：Edit Intent。

Edit Intent 不等于 DAW，不等于 piano roll。它是结构化的“局部修改请求”，让后端能安全地把修改限定在 SongPlan 的一部分。

## 2. v1.1.0 总目标

v1.1.0 完成后应该具备：

- Project version 支持创建 edit-derived version。
- 编辑范围支持 section、track、lyrics 三类最小可用场景。
- 后端能基于父版本 `song-plan.json` 生成新的 edited SongPlan。
- edited SongPlan 必须重新 validate、重新 render MIDI、清理 stale stems/audio。
- edited job 必须写入 edit metadata，便于 Project diff 和 Studio 展示。
- Studio Project Detail 增加 Edit Version 工作区。
- Quality Gate、Final Export、Project lineage 继续可用。
- 所有功能先本地验证，真实 provider edit 可以预留但不作为 v1.1.0 强依赖。

一句话：

> v1.1.0 要把 Project version 从“生成历史”推进到“可控编辑历史”。

## 3. 不做什么

v1.1.0 不做以下内容：

- 不做浏览器 piano-roll 编辑器。
- 不做音频波形编辑。
- 不做 VST、DAW 工程导出。
- 不做真实混音台 automation。
- 不做 arbitrary JSON patch。
- 不允许前端传任意文件路径。
- 不直接覆盖父版本 run 目录。
- 不把 edited SongPlan 直接写回 old job。
- 不要求 provider 真的能做复杂音乐编辑。

v1.1.0 的编辑是“结构化意图 + 后端可控生成/变换”，不是自由文件编辑器。

## 4. 核心概念

### 4.1 Edit Intent

Edit Intent 是一次局部编辑请求的结构化描述。

建议新增文件：

```text
song_agent/edits.py
```

建议 schema：

```python
@dataclass(frozen=True)
class EditIntent:
    edit_type: str
    target: EditTarget
    instruction: str
    preserve: list[str]
    strength: int
    provider_mode: str
```

其中：

```python
@dataclass(frozen=True)
class EditTarget:
    section_name: str | None = None
    track_name: str | None = None
    field: str | None = None
```

字段解释：

- `edit_type`：`section_energy`、`section_harmony`、`track_density`、`lyrics_rewrite`、`melody_variation`、`arrangement_variation`。
- `target.section_name`：例如 `chorus`、`verse`、`intro`。
- `target.track_name`：例如 `melody`、`chords`、`bass`、`drums`。
- `target.field`：例如 `lyrics`、`chords`、`notes`、`instrument`。
- `instruction`：人类可读的修改意图。
- `preserve`：要求保留的部分，例如 `["tempo", "key", "structure", "lyrics"]`。
- `strength`：1..10，表示修改强度，默认 5。
- `provider_mode`：`local` 或 `provider`。v1.1.0 默认 local。

### 4.2 Edit Job

Edit Job 是一种普通 job，但它不是从 `SongRequest` 重新生成，而是从父版本 `SongPlan` 派生。

可以有两种实现路线：

路线 A：复用 `JobState`，在 `input_payload` 里增加 edit metadata。

路线 B：新增 `edit-metadata.json`，JobState 仍尽量不扩字段。

建议 v1.1.0 采用路线 B，降低兼容成本。

每个 edit job 写入：

```text
runs/<job-id>/data/edit-metadata.json
```

建议内容：

```json
{
  "schema_version": 1,
  "project_id": "demo",
  "parent_version_id": "v001",
  "parent_job_id": "old-job",
  "edit_type": "section_energy",
  "target": {
    "section_name": "chorus",
    "track_name": null,
    "field": null
  },
  "instruction": "Make the chorus more energetic without changing the key.",
  "preserve": ["tempo", "key", "structure"],
  "strength": 6,
  "created_at": "..."
}
```

### 4.3 Edit-Derived ProjectVersion

`ProjectVersion.variant_type` 已有 `manual`、`arrangement_variation`、`lyrics_variation`、`quality_repair` 等类型。

v1.1.0 建议在 `song_agent/projects.py` 的 `VARIANT_TYPES` 中新增：

- `section_edit`
- `track_edit`
- `lyrics_edit`
- `melody_edit`
- `arrangement_edit`

不建议继续复用 `manual`。原因是 Studio 和 Project diff 需要直观看出版本来源。

`edit_type` 到 `variant_type` 的建议映射：

```text
section_energy      -> section_edit
section_harmony     -> section_edit
track_density       -> track_edit
lyrics_rewrite      -> lyrics_edit
melody_variation    -> melody_edit
arrangement_variation -> arrangement_edit
```

ProjectVersion 继续使用：

- `parent_version_id`
- `variant_type`
- `change_summary`

不用新增太多字段；详细 edit 信息放在 job 的 `edit-metadata.json`。

## 5. 后端能力设计

## 5.1 新增 Edit Engine

新增：

```text
song_agent/edits.py
```

职责：

- 解析和验证 EditIntent。
- 校验目标 section / track 是否存在。
- 从父 SongPlan 生成 edited SongPlan。
- 返回 edit summary。
- 不读写 Project 文件，不直接操作 HTTP。

建议核心函数：

```python
def apply_edit_intent(parent_plan: SongPlan, intent: EditIntent) -> EditedSongPlanResult:
    ...
```

返回：

```python
@dataclass(frozen=True)
class EditedSongPlanResult:
    plan: SongPlan
    summary: dict[str, Any]
    warnings: list[str]
```

### 本地 deterministic edit 规则

v1.1.0 本地规则要足够可验证，不追求音乐创作极致。

#### section_energy

目标：调整某个 section 的能量。

规则：

- 找到目标 section 的 beat range。
- 如果 strength >= 6：
  - 目标 section 内 melody velocity +8，最多 127。
  - drums 在目标 section 内增加稳定 backbeat 或提高 velocity。
  - quality.section_intents 中对应 section 的 energy +1..2，最多 10。
- 如果 strength <= 4：
  - 目标 section 内非 melody 轨 velocity -8，最低 1。
  - drums 可减少部分 note，保持节拍不空。
  - energy -1..2，最低 0。

必须保持：

- tempo 不变。
- key 不变。
- section 数量不变。
- section start_bar/bars 不变。
- 所有 note 仍在歌曲总长度内。

#### section_harmony

目标：替换某个 section 的 chords。

本地规则：

- 从 intent 中解析简单 chord list。
- 如果无法解析，使用安全替换：
  - major key 默认 `["Cmaj7", "Am7", "Fmaj7", "G7"]`
  - minor key 默认 `["Am7", "Fmaj7", "Dm7", "E7"]`
- 更新目标 SongSection.chords。
- 重新生成目标 section 内 chords track 和 bass track 的 notes。
- melody track 先保留。

必须避免：

- 修改其他 section chords。
- 让 chords 为空。
- 让 bass/chords note 超出 section 范围。

#### track_density

目标：调整某一 track 在某一 section 的密度。

规则：

- target.track_name 必填。
- section 可选；没有 section 表示全曲。
- strength >= 6：复制部分节奏骨架增加 note，但不能爆炸式增长。
- strength <= 4：按 deterministic 规则删除一部分非关键 note。
- drums 特殊处理：优先保留 kick/snare 骨架。
- bass 特殊处理：保留 root motion。
- melody 特殊处理：保留首拍和 phrase anchor。

#### lyrics_rewrite

目标：只改某个 section 的 lyrics。

本地规则：

- target.section_name 必填。
- target.field 必须是 `lyrics` 或为空。
- 如果 payload 中提供 `lyrics`，直接替换。
- 如果没有提供 lyrics，本地生成占位式简短歌词，不调用 provider。

建议 EditIntent 可扩展字段：

```python
payload: dict[str, Any] = field(default_factory=dict)
```

lyrics rewrite 使用：

```json
{
  "payload": {
    "lyrics": "..."
  }
}
```

#### melody_variation

目标：只改某 section 的 melody。

v1.1.0 简化：

- 不做复杂 melody AI。
- 对目标 section 的 melody notes 做小幅 deterministic 变体：
  - 偶数 phrase 上移 1 或 2 scale step。
  - 保持 rhythm。
  - pitch clamp 0..127。
  - 不改变 note 数量太多。

#### arrangement_variation

目标：对 section 或全曲做轻微编曲变化。

v1.1.0 建议先不做复杂；可以只支持：

- 改 instrument。
- 改 section_behavior metadata。
- 调整 velocity/density。

## 5.2 Provider-backed Edit 预留

v1.1.0 不强制做真实 provider edit，但接口要留好位置。

建议：

```text
song_agent/prompts/edit_song_plan.md
```

Provider 输入：

```json
{
  "parent_song_plan": {},
  "edit_intent": {},
  "constraints": {
    "must_preserve": ["tempo", "key", "structure"],
    "output_schema": "SongPlan"
  }
}
```

Provider 输出仍必须转成 SongPlan，并通过：

- `SongPlan.from_dict()`
- `plan.validate()`
- `attach_quality()` 或 `analyze_song_quality()`
- MIDI render

如果 provider 输出失败，job failed，不要 fallback 静默改成本地 edit。因为用户选择 provider 时，需要知道 provider 是否可靠。

## 5.3 Edit Job Runner

建议在 `JobStore` 增加：

```python
def create_edit_job(
    self,
    project_id: str,
    parent_version: ProjectVersion,
    intent: EditIntent,
    *,
    start_immediately: bool = True,
) -> JobState:
    ...
```

也可以先不把函数放进 JobStore，而是在 server route 内创建 run_dir/job，然后调用一个 `_run_edit_job`。但为了和普通 job 一致，建议放进 JobStore。

Edit job 的执行步骤：

1. 读取 parent version 的 `data/song-plan.json`。
2. 校验 parent job status 是 `completed`。
3. 校验 parent plan 存在且合法。
4. 写入当前 run 的：
   - `data/request.json`：可以写 parent request + edit 标识。
   - `data/edit-metadata.json`
   - `logs/events.jsonl`
   - `data/job-state.json`
5. 应用 edit intent 得到 edited plan。
6. `plan.validate()`。
7. 重新计算 quality。
8. 写 `data/song-plan.json`。
9. render `renders/song.mid`。
10. 写 `data/validator-report.json`。
11. 写 `data/run-summary.json`。
12. 清理或不创建 stems/audio。
13. job completed。
14. 自动添加 ProjectVersion，parent_version_id 指向父版本。

注意：

- 新 job 的 `generation_mode` 可以是 `local` 或 `provider`，由 EditIntent 的 `provider_mode` 映射而来。
- 新 job 的 `pipeline_mode` 建议使用 `edit` 或沿用 parent 的 pipeline_mode。
- 当前 `pipeline_mode` 只有 `single|multinode`。为减少改动，可以沿用 parent pipeline_mode，同时在 `edit-metadata.json` 标记它是 edit job。
- 不要调用 `generate_request()` 重新全量生成，否则无法保证局部编辑。

## 6. API 设计

## 6.1 创建局部编辑版本

新增：

```text
POST /api/projects/<project-id>/versions/<version-id>/edit
```

请求：

```json
{
  "edit_type": "section_energy",
  "target": {
    "section_name": "chorus",
    "track_name": null,
    "field": null
  },
  "instruction": "Make chorus more energetic but keep tempo and key.",
  "preserve": ["tempo", "key", "structure"],
  "strength": 7,
  "payload": {},
  "name": "Chorus energy edit",
  "note": "Raise chorus impact",
  "start_immediately": true
}
```

响应：

```json
{
  "ok": true,
  "project": {},
  "versions": [],
  "version": {},
  "job": {},
  "edit": {
    "edit_type": "section_energy",
    "target": {},
    "summary": {}
  }
}
```

状态码：

- 202：edit job 已创建。
- 400：intent 无效。
- 404：project/version/job 不存在。
- 409：父版本未 completed 或父 plan 不存在。

## 6.2 获取版本 edit metadata

新增：

```text
GET /api/projects/<project-id>/versions/<version-id>/edit
```

响应：

```json
{
  "version_id": "v002",
  "edit": {
    "schema_version": 1,
    "parent_version_id": "v001",
    "edit_type": "section_energy",
    "target": {},
    "instruction": "...",
    "summary": {},
    "warnings": []
  }
}
```

如果不是 edit-derived version：

- 返回 404 或 `{ "edit": null }`。
- 建议返回 404，语义更清楚。

## 6.3 预览可编辑目标

新增：

```text
GET /api/projects/<project-id>/versions/<version-id>/edit-targets
```

返回：


## 8. Project diff 增强

当前 Project diff 已能比较 request、summary、lineage、quality、artifacts。v1.1.0 应增强：

```json
"changed": {
  "edit": {
    "left": null,
    "right": {
      "edit_type": "section_energy",
      "target": {"section_name": "chorus"},
      "summary": {}
    }
  },
  "sections": {},
  "tracks": {}
}
```

最小可用要求：

- diff 返回 parent/child lineage。
- 如果 right version 是 edit job，diff 包含 edit metadata。
- section diff 至少能显示 chords/lyrics 是否变化。
- tracks diff 至少能显示 note_count、instrument 是否变化。

不要求做 note-by-note diff。

## 9. Studio 设计

Studio Project Detail 增加一个 `Edit` tab 或在已有 Project Detail 中新增区域。

### 9.1 Edit Version 区域

控件：

- Parent version selector。
- Edit type selector。
- Section selector。
- Track selector。
- Field selector。
- Strength slider 1..10。
- Preserve checkboxes：
  - tempo
  - key
  - structure
  - lyrics
  - harmony
  - melody
  - arrangement
- Instruction textarea。
- Payload textarea 或按 edit type 展示专用字段。
- Create Edit Version 按钮。

原则：

- 默认 parent 使用 selected version；没有 selected 时使用 latest version。
- edit type 决定显示哪些 target 控件。
- section/track 选项来自 `/edit-targets`。
- 提交后创建新 version，并能跳到新 job。
- 新 job 完成后 Project version table 更新。

### 9.2 Version Table 增强

版本表新增或复用：

- Parent。
- Variant Type。
- Edit Type。
- Target。
- Gate。
- Quality。

如果空间不够，Edit Type/Target 可以折叠到 detail panel。

### 9.3 Job Detail 增加 Edit tab

如果 job 是 edit job：

- 显示 parent project/version/job。
- 显示 edit_type、target、instruction、preserve、strength。
- 显示 summary/warnings。

非 edit job 时不显示或显示 empty state。

### 9.4 UI 边界

不要把 v1.1.0 做成复杂编辑器。

必须避免：

- 可拖拽 MIDI note。
- 大型 piano roll。
- 任意 JSON patch 编辑框作为主路径。
- 复杂 modal 嵌套。

## 10. 后端安全和一致性要求

### 10.1 目标校验

Edit target 必须从父 SongPlan 中验证：

- section_name 必须存在。
- track_name 必须存在。
- field 必须在白名单中。
- edit_type 必须在白名单中。
- strength 必须 1..10。
- preserve 必须是白名单值。

### 10.2 路径边界

edit 不应读取任意路径。只允许：

- parent version output_dir 下的 `data/song-plan.json`。
- 新 edit job output_dir。

不要让请求传文件路径。

### 10.3 父版本保护

绝对不能修改：

- parent run `data/song-plan.json`
- parent run `renders/song.mid`
- parent run `stems/`
- parent project final-export

所有输出写入新的 run。

### 10.4 Artifact 生命周期

edit job 生成后：

- 新 run 没有旧 stems。
- 新 run 没有旧 audio。
- 如果用户要 stems/audio，需要重新 render。
- final export 只能基于新 version 重新生成。

### 10.5 Quality 重新计算

edited plan 必须重新：

- `attach_quality` 或 `analyze_song_quality`
- `validate_song_plan`
- validator-report
- run-summary

不要继承父版本 quality 分数。

## 11. 分阶段施工包

每完成一个施工包都要：

- 本地跑对应测试。
- `git status --short --branch` 干净。
- commit。
- push 到 GitHub master。
- 如果达到可发布节点，再 tag / Release。

不要等 v1.1.0 全部写完才第一次推。

### Package A：Edit Intent schema 与 deterministic edit engine

目标：

- 新增 `song_agent/edits.py`。
- 实现 EditIntent / EditTarget / EditedSongPlanResult。
- 实现 `apply_edit_intent()`。
- 支持：
  - `section_energy`
  - `section_harmony`
  - `track_density`
  - `lyrics_rewrite`
  - `melody_variation`
- 输出 plan 通过 SongPlan validate。

测试：

- valid intent round trip。
- unknown edit_type rejected。
- missing section rejected。
- missing track rejected。
- invalid strength rejected。
- section_energy 只改目标 section beat range。
- lyrics_rewrite 只改目标 section lyrics。
- section_harmony 更新 chords 且重建 chords/bass 目标 section notes。
- parent plan 不被 mutate。

建议提交：

```text
git add song_agent/edits.py tests/test_edits.py
git commit -m "feat: add local song edit engine"
git push origin master
```

### Package B：Edit job runner

目标：

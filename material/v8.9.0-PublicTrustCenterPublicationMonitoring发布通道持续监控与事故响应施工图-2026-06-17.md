# v8.9.0 Public Trust Center Publication Monitoring 发布通道持续监控与事故响应施工图

> 当前稳定基线：v8.8.1  
> 当前核心能力：Public Trust Center Publication Channels 已经可以生成发布通道、Publication ZIP、静态 Mirror，并通过外部 `publication-channel-state.json` 阻断 revoke/supersede 后旧 ZIP 自证通过。  
> v8.9.0 的目标，是从“发布包可验证”推进到“发布后可持续巡检、可发现漂移、可记录事故、可导出监控证据包”。

---

## 0. 给开发的话

你接手这一版时，不要把它理解成“再加一个 ZIP 导出”。v8.9.0 要解决的是发布后的运营问题：

1. v8.8 已经能把 Public Trust Center 发布成一个通道快照。
2. 但发布出去以后，文件可能被误删、替换、追加、撤回、supersede、镜像目录复制不完整，或者外部接收方拿到旧包。
3. v8.9 要提供一个本地监控工作台，定期或手动对 Publication ZIP / Mirror / Channel State 做复验。
4. 监控发现问题后，不自动修复、不自动撤回、不自动 supersede，只生成 Drift Report / Incident / Manual Action。
5. 所有报告、事故、导出包都必须可离线验证，并且不能只靠包内自证。

这版最重要的 reviewer 红线：

- `--require-current` / `--require-no-revoked` 这类门禁必须绑定外部 `publication-channel-state.json`。
- Monitoring ZIP 里的 `channel-state-snapshot.json` 只能作为当时快照，不能作为“当前状态”的唯一证据。
- 旧 Monitoring ZIP 在 channel state 后续 revoke/supersede 后，离线 verifier 必须失败。
- Incident / Drift Report 不能被全量重签伪造为 resolved / passed。
- 不允许监控逻辑自动调用 revoke/supersede/signoff/reset。

## 3. 不做什么

v8.9.0 必须继续本地优先，不能扩大到真实公网运营：

- 不做后台 daemon。
- 不做定时任务服务。
- 不访问真实公网 URL。
- 不爬 GitHub Pages / CDN / OSS / S3。
- 不发邮件、短信、Webhook、Slack。
- 不自动 revoke publication。
- 不自动 supersede publication。
- 不自动 rebuild publication ZIP。
- 不自动修改 mirror 内容。
- 不自动 approve / signoff / reset。
- 不引入数据库。
- 不引入外部依赖。
- 不做真实 PKI / CA 签名。

允许做：

- 本地目录巡检。
- 本地 ZIP 复验。
- 本地 mirror 目录复验。
- 本地 channel state 比对。
- 本地 incident 记录。
- 本地 monitoring ZIP 导出与离线验证。

## 4. 核心设计原则

### 4.1 外部状态优先

Publication ZIP / Monitoring ZIP 都可能是旧文件，因此：

- 当前状态必须来自外部 `publication-channel-state.json`。
- Verifier 在 `--require-current` 或 `--require-no-revoked` 下必须要求外部 state。
- 包内 `channel-state-snapshot.json` 只能用于审计当时状态，不能替代外部 state。

### 4.2 Probe 是事实，Drift 是解释，Incident 是处理

拆三层：

```text
Probe Result: 某个目标验出来是什么状态
Drift Report: 和期望相比哪里漂移
Incident: 对漂移/失败的人工处理记录
```

不要把这三类混在一个 JSON 里。

### 4.3 Monitoring 不修复生产证据

Monitoring 只能产生观察和建议：

- 可以提示：需要重新 publish。
- 可以提示：需要 supersede。
- 可以提示：mirror 缺文件。
- 可以提示：旧 ZIP 已被 revoke。
- 可以生成 manual action。

但不能直接执行这些动作。

### 4.4 所有包都固定 allow-list

Monitoring ZIP 也必须遵守 v8 以来的固定包结构：

- ZIP entry 固定 allow-list。
- `manifest.files[]` 必须匹配 allow-list。
- `file-index.json` 必须匹配 allow-list。
- 禁止未声明 extra 文件。
- 禁止 duplicate entry。
- 禁止 path traversal。
- 禁止 backslash entry。
- 禁止 `.musicforge/` / `.MusicForge/` 变体。
- 禁止 nested ZIP，除非显式 allow-list。
- 全文 redaction scan。

### 4.5 Incident 不能自证 solved

事故处理必须有事件链：

- open
- acknowledge
- resolve
- waive
- reopen

`incident-report.json` 里的最终状态必须能从 `incident-events.jsonl` 推导出来。  
不能只改 summary/status 然后重算 hash 就通过 verifier。

## 8. Store 行为

新增 `PublicTrustCenterPublicationMonitoringStore`。

### 8.1 create_monitor()

Input:

```python
create_monitor(center_id, channel_id, payload)
```

Must:

- validate center/channel exists.
- validate mirror path if provided.
- reject absolute paths in persisted public fields unless they are redacted or stored as local-only internal path.
- write `monitor.json` atomically.
- append `monitor_created` event.

### 8.2 run_monitor()

Input:

```python
run_monitor(center_id, channel_id, monitor_id, payload=None)
```

Must:

- resolve selected publication.
- require `publication-channel-state.json` if monitor requirements need current/no revoked.
- call existing `verify_public_trust_center_publication_package()`.
- call existing `verify_public_trust_center_publication_mirror()` when mirror enabled.
- write `channel-state-snapshot.json`.
- write `probe-results.json`.
- build `drift-report.json`.
- open or update incidents for blocking drift.
- write `monitor-run.json`.
- append `monitor_run_completed` event.

Must not:

- call `revoke_publication()`.
- call `supersede_publication()`.
- rebuild publication ZIP automatically.
- modify mirror content.

### 8.3 open / acknowledge / resolve / waive incident

APIs:

```python
acknowledge_incident(center_id, channel_id, monitor_id, incident_id, payload)
resolve_incident(center_id, channel_id, monitor_id, incident_id, payload)
waive_incident(center_id, channel_id, monitor_id, incident_id, payload)
reopen_incident(center_id, channel_id, monitor_id, incident_id, payload)
```

Must:

- append event to `incident-events.jsonl`.
- rebuild `incident.json` from event chain.
- preserve history.
- never hard-delete incident.

### 8.4 export_monitoring_run()

Input:

```python
export_monitoring_run(center_id, channel_id, monitor_id, run_id)
```

Must:

- refuse export if run artifacts are missing/integrity failed.
- copy sanitized run artifacts into fixed export layout.
- include verification reports.
- include incident summary.
- include `channel-state-snapshot.json`.
- write `monitoring-manifest.json`.
- write `file-index.json`.
- write checksums.
- run redaction scan before returning success.

### 8.5 build_monitoring_zip()

Input:

```python
build_monitoring_zip(center_id, channel_id, monitor_id, run_id)
```

Must:

- only package fixed allow-list.
- refuse if export is stale or missing.
- write deterministic ZIP order.
- no absolute local paths in ZIP.
- no hidden local `.musicforge` contents.

## 11. Offline Verifier

新增：

```text
song_agent/public_trust_center_publication_monitoring_verifier.py
```

CLI:

```text
python -m song_agent.cli verify-public-trust-center-publication-monitoring-package <zip>
```

Flags:

```text
--strict
--json
--report-out <path>
--require-current
--require-no-revoked
--require-ready
--require-no-drift
--require-no-open-critical-incidents
--allow-waived-incidents
--publication-channel-state <path>
```

### 11.1 Verifier 必须检查

ZIP:

- parseable ZIP.
- no duplicate entries.
- no path traversal.
- no backslash raw names.
- no absolute paths.
- no `.musicforge/` or `.MusicForge/`.
- no nested ZIP.
- exact allow-list.
- manifest.files exact match.
- file-index exact match.
- checksum exact match.

JSON:

- all JSON parse.
- schema/package_type correct.
- integrity hashes match.
- manifest source matches sidecar files.
- drift report source matches probe results.
- monitor run source matches monitor/probe/drift.
- incident report status derived from event chain.

Current state:

- If `--require-current` or `--require-no-revoked`, `--publication-channel-state` is mandatory.
- external channel state integrity OK.
- external channel state channel_id matches.
- publication row present.
- publication row zip_sha256 matches manifest source when package verifier is checking a ZIP-derived run.
- publication row manifest/source/report hash match.
- status not revoked/superseded.
- latest event hash is compatible with monitor run source unless run is explicitly historical and verifier is not requiring current.

Requirements:

- `--require-ready`: drift report status must be passed and publication verifier report ready.
- `--require-no-drift`: no critical/high drift.
- `--require-no-open-critical-incidents`: incident report cannot contain open critical/high incidents.
- `--allow-waived-incidents`: optional, but waived incidents must be visible in output as warnings.

Redaction:

- scan all text JSON/TXT.
- fail on API keys, GitHub token patterns, Bearer tokens, Windows paths, UNC paths, `.musicforge` internals, raw provider responses.

## 17. 安全与 reviewer 风险清单

### P1 风险 1：Monitoring ZIP 自证 current

错误做法：

```text
Monitoring ZIP 里有 channel-state-snapshot.json，所以 require-current 通过。
```

正确做法：

```text
require-current 必须额外传外部 publication-channel-state.json。
```

必须有回归：

- build monitoring ZIP。
- revoke publication。
- 用旧 ZIP + 新 external state verify。
- 必须 failed。

### P1 风险 2：Incident summary 可全量重签

错误做法：

```text
改 incident-report.json status=resolved，然后重算 integrity_hash，verifier passed。
```

正确做法：

```text
incident status 必须从 incident-events.jsonl 推导。
```

必须有回归：

- tamper incident summary resolved。
- event chain 仍是 open。
- verifier failed。

### P1 风险 3：Mirror verifier 只看 manifest

错误做法：

```text
只检查 mirror manifest hash，不检查文件实际 hash。
```

正确做法：

```text
复用 v8.8 mirror verifier，逐文件检查。
```

### P1 风险 4：Waive 事故绕过

错误做法：

```text
waived critical incident 默认当通过。
```

正确做法：

```text
默认阻断；只有 verifier 明确 --allow-waived-incidents 才允许，并输出 warning。
```

### P1 风险 5：监控自动修复

错误做法：

```text
monitor run 发现 revoked，自动 supersede。
```

正确做法：

```text
只生成 manual_required action。
```

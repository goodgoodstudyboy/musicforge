# v11.6.0 Unified Command Center Release Train 统一总控发版列车与跨中心准出编排施工图

> 目标读者：开发执行人员、测试验收人员、后续 reviewer  
> 当前稳定基线：v11.5.2  
> 建议下一版：v11.6.0  
> 核心目标：把 v11.0-v11.5 的“单个 Unified Command Center 准出链”提升为“多个 UCC 的发版列车”，让多个 Release / UCC / 审查决策可以在同一个发版窗口里被统一编排、统一验收、统一签核和统一归档。

---

## 1. 背景

v11.0 到 v11.5 已经完成了单个 Unified Command Center 的完整闭环：

- v11.0：Unified Command Center 聚合全产品准出证据。
- v11.1：UCC Signoff / Archive / Final Handoff。
- v11.2：UCC Continuous Review。
- v11.3：UCC Drift Response。
- v11.4：UCC Evidence Review / Replay。
- v11.5：UCC Reviewer Decision Board，多 reviewer quorum 和决策签核。

现在的问题不是单条链路缺一个包，而是整体流程已经很长：

1. 单个 release 的证据链已经足够严谨，但多个 release 同期发版时，缺少统一窗口。
2. 每个 UCC 都能证明自己 ready，但没有一个 train-level 视图判断“这一批能不能一起发”。
3. 多个 UCC 之间可能存在依赖：同一 album、多平台交付、同一 public trust center、同一 audio baseline、同一 operations handoff。
4. 当前 reviewer 需要逐个打开多个 UCC archive / handoff / decision board；缺少跨中心 evidence inventory 和 go/no-go matrix。
5. 如果某个 UCC 延迟、被 revoke、需要 drift response，缺少 train-level 变更控制。

v11.6 要解决这个问题：建立 `Unified Command Center Release Train`。

一句话：

> v11.6 不再继续堆单中心证明包，而是做“跨 UCC 发版列车”：把多个中心加入同一个 train，按 lane / wave / dependency 做准出编排，生成统一 Go/No-Go 决策、不可变 Train Signoff Archive 和离线 verifier。

---

## 2. 非目标

v11.6 必须收住边界，避免把所有后续能力一次做爆。

不做：

1. 不自动发布 GitHub Release。
2. 不自动 submit distribution/submission。
3. 不自动 signoff 单个 UCC。
4. 不自动 reset 单个 UCC。
5. 不替代 UCC Reviewer Decision Board。
6. 不把所有 nested ZIP 复制进 Train ZIP。
7. 不做真实外部 PKI、公证链或第三方时间戳。
8. 不做跨机器同步数据库。
9. 不做 provider 调用。
10. 不做音乐重新生成、音频修复、distribution rebuild。

v11.6 只做本地确定性编排、验证、签核和归档。

## 3. 设计原则

### 3.1 Train 不信内部 summary

Release Train 不能只读取 UCC report 里的 `status=ready`。

它必须运行或核验：

- UCC ZIP runtime verifier。
- UCC Archive verifier。
- UCC Final Handoff verifier。
- UCC Continuous Review verifier。
- UCC Evidence Review verifier。
- UCC Reviewer Decision Board verifier。
- 每个 external verification report 的 package_type / integrity_hash / zip hash / manifest hash。

### 3.2 Train ZIP 不嵌套 UCC ZIP

Train ZIP 只放 train 自己的固定结构文件：

- train manifest
- train report
- item index
- evidence inventory
- readiness matrix
- dependency graph
- wave plan
- go/no-go report
- safe runbook
- signoff
- history
- reviewer guide

外部 UCC ZIP / Archive / Handoff / Decision Board ZIP 由 verifier 参数传入。

原因：

- 避免 nested ZIP 攻击面。
- 避免一个 train ZIP 变成巨型包。
- 避免复制旧 UCC 包造成 stale 混淆。

### 3.3 Train 只执行 safe action

Train Runbook 允许：

- refresh train report
- refresh train readiness
- verify item evidence
- generate manual-required signoff/archive actions
- verify existing train archive zip if already built

Train Runbook 不允许：

- signoff UCC
- reset UCC
- signoff train
- export train archive
- build train archive zip
- approve external response
- apply drift response
- sign Release
- submit distribution
- mutate evidence source

### 3.4 签核后不可变

v11.6 明确采用这一种时序，开发不能再二选一：

1. `signoff()` 发生在 archive export/zip 之前。
2. `signoff()` 会冻结当前 train docs，并写入独立的 `train-signoff-binding-summary.json`。
3. signoff 之后只允许第一次 immutable archive export / ZIP build，且只能复制签核时冻结的 docs。
4. archive export / ZIP build 不允许 refresh、不允许重新计算 train source、不允许重新生成 signoff binding。
5. 如果 archive 已存在且内容与签核冻结 hash 不一致，直接 409。

这样 Train ZIP 可以固定包含 signoff 文件，同时不会出现“签核后重新计算证据”的歧义。

Train signoff 后必须阻断：

- refresh blocked
- item add/remove blocked
- dependency edit blocked
- run-safe blocked
- direct export blocked
- direct zip rebuild blocked

但允许：

- `export_archive()`：仅第一次复制 frozen docs 到 archive/export 目录。
- `build_archive_zip()`：仅第一次基于 archive/export 目录生成固定 ZIP。
- `verify_archive_zip()`：只读验证。

`export_archive()` 和 `build_archive_zip()` 必须先检查 history 里的 latest signed event，而不是只看 `train-signoff.json` 是否存在。删除 signoff 文件不能解锁 train。

除非 v11.7 以后做 approved Change Request reset。v11.6 暂不做 reset。

如果实现 reset，必须另开版本，因为 reset 需要完整 CR proof 和 history causality。

签核后如需改动，只能：

- 新建一个新的 train。
- 或等 v11.7 单独设计 Train Change Request reset。

不能靠删除 `train-signoff.json`、删除 export 目录、删除 ZIP 或改本地 JSON 重新打开。

## 7. Train 状态机

```text
draft
  -> ready
  -> signed
  -> archived

draft / ready
  -> blocked

blocked
  -> ready after refresh and blockers clear

signed
  -> immutable
```

v11.6 不做 reset。

签核后任何下列动作必须 409：

- add item
- remove item
- update item
- update dependency
- refresh
- run-safe
- export
- build zip
- signoff again

如果需要修改，后续 v11.7 做 Train Change Request reset。

```text
python -m song_agent.cli unified-command-train export <train-id>

python -m song_agent.cli unified-command-train verify <train-id>
python -m song_agent.cli verify-unified-command-train-package <zip> ...
```

命令名可以沿用 `export` / `zip`，但实现语义必须是 immutable archive：

- unsigned train：`export` / `zip` 必须 409，提示先 refresh/go/signoff。
- signed train：`export` 只复制 signoff 时冻结的 docs。
- signed train：`zip` 只打包 archive/export 固定文件。
- 两者都不能调用 refresh 或重算 source docs。

### 9.1 verify CLI

```powershell
python -m song_agent.cli verify-unified-command-train-package `
  .musicforge\unified-command-trains\ucct-000001\unified-command-train.zip `
  --strict `
  --require-signed `
  --require-go `
  --external-evidence-manifest .musicforge\unified-command-trains\ucct-000001\external-evidence.json `
  --json
```

`--external-evidence-manifest` 是 verifier / gate 的主入口。重复 CLI 参数只允许作为便捷输入，由 CLI 在进入 store/verifier 前转换成同一份 canonical manifest；store/verifier 不得依赖参数顺序。

必须支持：

```json
{
  "schema_version": 1,
  "package_type": "musicforge_unified_command_center_release_train_external_evidence_manifest",
  "train_id": "ucct-000001",
  "items": [
    {
      "item_id": "item-000001",
      "center_id": "ucc-000001",
      "evidence": [
        {
          "evidence_type": "ucc",
          "package_path": "...",
          "verification_report_path": "..."
        },
        {
          "evidence_type": "ucc_archive",
          "package_path": "...",
          "verification_report_path": "..."
        },
        {
          "evidence_type": "ucc_handoff",
          "package_path": "...",
          "verification_report_path": "..."
        },
        {
          "evidence_type": "reviewer_decision_board",
          "package_path": "...",
          "verification_report_path": "..."
        }
      ]
    }
  ],
  "manifest_hash": "stable hash of manifest payload without manifest_hash"
}
```

Verifier 必须：

- 以 `item_id + center_id + evidence_type` 匹配，不按数组顺序匹配。
- 校验 manifest 中的 item set 与 Train ZIP 内部 `train-items.json` 完全一致。
- 拒绝重复 evidence key。
- 拒绝缺失 required evidence。
- 拒绝多余 unknown evidence_type。
- 拒绝 manifest hash 不匹配。
- 将 manifest hash 写入 `train-source.json`、`go-no-go-report.json`、`train-signoff.json` 和 verification report。

CLI repeat 参数如果保留，只能生成临时 canonical manifest，并打印 manifest path / hash，方便 reviewer 复现。

- no duplicate entries
- raw paths safe
- no backslash
- no absolute path
- no `..`
- no drive letter
- no `.musicforge/`
- no nested zip
- fixed allow-list
- manifest.files exactly match fixed entries
- manifest file hashes match
- uncompressed size cap
- entry count cap
- redaction scan

文档层：

- train source integrity
- train items integrity
- evidence inventory integrity
- readiness matrix integrity
- dependency graph integrity
- wave plan integrity
- go/no-go report integrity
- safe runbook integrity
- safe runbook result integrity
- signoff integrity if present
- history hash chain
- signoff binding summary

外部证据层：

- `external_evidence_manifest_path` 在 `require_signed` / `require_go` / Release gate / GA gate 下必须提供。
- verifier 必须先读取 canonical manifest，再用 `item_id + center_id + evidence_type` 建立索引。
- CLI repeat 参数生成的临时 manifest 必须和显式 manifest 走同一代码路径。
- 每个 required item 必须有 external evidence。
- external evidence 的 `center_id` 必须匹配。
- external evidence 的 `item_id` 必须匹配。
- external evidence type 必须在 allow-list 中。
- 同一个 `item_id + center_id + evidence_type` 出现两次直接 failed。
- external UCC verification report package_type 必须正确。
- external UCC ZIP runtime verification 必须 passed。
- external report 的 zip_sha256 / manifest_hash 必须等于 runtime result。
- Train inventory 中记录的 fingerprint 必须等于 external runtime result。
- Reviewer Decision Board 必须带 external verifier report。
- 如果 policy require decision board，则缺 decision board 直接 failed。
- external manifest hash 必须等于 `train-source.json` / `go-no-go-report.json` / `train-signoff.json` / verification report 里的绑定值。

语义层：

- dependency graph 必须 acyclic。
- blocked dependency 会导致 downstream item blocked。
- required wave blocked 会导致 train no_go。
- require_go 时 go-no-go-report.status 必须 `go`。
- require_signed 时 train-signoff.status 必须 `signed`。
- signed train 的 signoff hash 必须存在于 history chain。

## 11. Store API

建议类：

```python
class UnifiedCommandCenterReleaseTrainStore:
    def create_train(self, payload: dict[str, Any]) -> dict[str, Any]: ...
    def list_trains(self) -> list[dict[str, Any]]: ...
    def get_train(self, train_id: str) -> dict[str, Any]: ...
    def add_item(self, train_id: str, payload: dict[str, Any]) -> dict[str, Any]: ...
    def remove_item(self, train_id: str, item_id: str) -> dict[str, Any]: ...
    def refresh(self, train_id: str) -> dict[str, Any]: ...
    def run_safe(self, train_id: str) -> dict[str, Any]: ...
    def signoff(self, train_id: str, payload: dict[str, Any]) -> dict[str, Any]: ...
    def export_archive(self, train_id: str) -> dict[str, Any]: ...
    def build_archive_zip(self, train_id: str) -> dict[str, Any]: ...
    def verify_archive_zip(self, train_id: str, *, external_evidence_manifest_path: Path | str | None = None) -> dict[str, Any]: ...
    def gate(self, train_id: str | None = None, *, required: bool = False, ...) -> dict[str, Any]: ...
```

### 11.1 add_item guard

`add_item()` 必须：

- 拒绝 signed train。
- 校验 item_id 唯一。
- 默认校验 center_id 唯一；只有显式 `allow_duplicate_center=true` 才允许同一个 center_id 多次加入。
- 立即运行基础 path 存在检查。
- 不把本地路径写入 export docs。
- 对 payload 文本做 `sanitize_metadata()`。

### 11.2 refresh guard

`refresh()` 必须：

- 拒绝 signed train。
- 重新运行每个 item 的外部 verifier。
- 重新计算 inventory / readiness / go-no-go。
- 不使用旧 verification report 自证。
- 如果外部 evidence 缺失，item status = missing。
- 如果 external report 和 runtime 不一致，item status = stale。

### 11.3 signoff guard

`signoff()` 必须：

- 拒绝非 ready/go train。
- 重新运行 refresh 或至少 runtime verifier。
- 使用 external evidence manifest 重新跑当前 runtime verifier。
- 绑定当前所有 frozen docs hash。
- 绑定 external evidence manifest hash。
- 写入 `train-signoff.json`。
- 在签核时写入独立 `train-signoff-binding-summary.json`。
- 写入 `train-history.jsonl` hash chain。
- 标记 train 为 signed。

签核时必须冻结这些 docs：

- `train-source.json`
- `train-items.json`
- `evidence-inventory.json`
- `readiness-matrix.json`
- `dependency-graph.json`
- `wave-plan.json`
- `go-no-go-report.json`
- `safe-runbook.json`
- `safe-runbook-result.json`
- `train-signoff.json`
- `train-signoff-binding-summary.json`
- `train-history.jsonl`

签核后：

- `refresh()` / `run_safe()` / `add_item()` / `remove_item()` / dependency edit 必须 409。
- `export_archive()` 只允许复制 frozen docs，不允许调用 refresh。
- `build_archive_zip()` 只允许读取 archive/export 固定文件，不允许重算 docs。
- 如果 export/zip 已存在且 hash 与 frozen docs 不一致，必须 409。
- 如果 history 显示已签核，即使 `train-signoff.json` 被删除，也必须保持 signed/immutable。

### 12.3 signoff-binding-summary.json

- `signoff()` 生成一次。

## 24. 给开发的话

这版不要再把重点放在“多写一个证明包”。你要做的是一个跨 UCC 的发版窗口。

实现时记住五条：

1. Train 是协调层，不是信任源。所有 ready / signed / go 都要反查外部 UCC、Archive、Handoff、Evidence Review、Decision Board 的真实 verifier。
2. Train ZIP 不能嵌套外部 ZIP。只保存 train 自己的固定结构证据和 fingerprint，外部包通过 verifier 参数传入。
3. External evidence manifest 是主入口。按 `item_id + center_id + evidence_type` 匹配，不要靠 CLI repeat 参数顺序。
4. `signoff()` 先冻结 docs，并在签核时生成 `train-signoff-binding-summary.json`。archive/export/zip 只能复制，不能重算。
5. 签核后不可变。只要 history 里有 signed event，即使用户删了 signoff 文件，也不能 refresh/run-safe/direct export/direct zip；只能做 immutable archive build。

如果这五条做到，v11.6 才算真正把 v11 线从“单中心证明链”推进到“跨中心准出编排”。

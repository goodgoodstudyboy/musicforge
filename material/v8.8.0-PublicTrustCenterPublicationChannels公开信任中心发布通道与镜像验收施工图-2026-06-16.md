# v8.8.0 Public Trust Center Publication Channels 公开信任中心发布通道与镜像验收施工图

> v8.7.2 已经把 Acceptance Board Signoff Archive 接入 Public Trust Center / Distribution Kit 顶层门禁，并收紧了 archive-only 降级路径。  
> v8.8.0 的目标，是从“本地包可验证”推进到“本地可模拟公开发布、可生成发布通道快照、可验证镜像、可记录撤回和替换”。  
> 这一步仍然坚持本地优先，不做真实联网发布；但要把将来发布到 GitHub Pages、对象存储、网盘、官网静态目录之前的本地验收链路一次性搭起来。

---

## 0. 当前稳定基线

当前稳定基线：

```text
v8.7.2
commit: 16fd374cd2ed74a921658b9d3d4b3fcceeba1d83
```

v8.7.2 已具备：

- Public Trust Center ZIP。
- Distribution Kit ZIP。
- Anchor Registry ZIP。
- Anchor Transparency ZIP + checkpoint。
- Distribution Kit Acceptance Evidence。
- Acceptance Board ZIP。
- Acceptance Board Signoff Archive ZIP。
- Top-level PTC / Distribution Kit verifier 可强制要求 Acceptance Board Signoff。
- v8 release-check matrix 能覆盖 v8.0 到 v8.7 smoke。

v8.7.2 留下的自然缺口：

- 这些公开证据包仍然只是“本地生成的一堆 ZIP”。
- 没有一个面向外部查看者的发布目录结构。
- 没有 Publication Manifest，不能说明本次公开发布包含哪些包、对应哪个中心、哪个 Board Signoff、哪个 Anchor。
- 没有 mirror snapshot 验证，无法证明“复制到另一个目录后仍完整、没有缺包、没有替换”。
- 没有发布记录历史，无法审计某次公开发布、撤回、替换、再发布。
- 没有通道概念，无法区分 internal_preview / public_release / partner_handoff / archive_mirror。
- 没有 release-check 覆盖“公开发布包被复制到外部目录后仍可验”。

## 1. v8.8.0 一句话目标

新增 Public Trust Center Publication Channels：

```text
PTC + Distribution Kit + Anchor Registry + Anchor Transparency + Acceptance Board Signoff
  -> Publication Channel
  -> Publication Snapshot
  -> Publication Bundle ZIP
  -> Mirror Directory Verification
  -> Publication Event Ledger
  -> Revoke / Supersede / Re-publish Audit
```

业务上要能回答：

> 我准备公开给外部合作方看的信任中心材料是哪一版？包含哪些包？复制出去以后是否还完整？如果后来撤回或替换，是否有明确原因和审计记录？

## 2. 不做什么

本版必须收住边界：

- 不做真实网络发布。
- 不调用 GitHub Pages API。
- 不上传 S3 / OSS / COS / 网盘。
- 不发邮件。
- 不做 DNS / HTTPS / CDN。
- 不做第三方 CA 证书。
- 不做区块链上链。
- 不把本地 deterministic signature 冒充法律签名。
- 不自动撤销 Anchor Registry。
- 不自动修改 Acceptance Board Signoff。
- 不自动修改 Distribution Kit Accepted Evidence。
- 不自动 approve 外部 response。
- 不让发布通道绕过已有 verifier。

也就是说，v8.8.0 做的是：

```text
本地发布目录 + 本地镜像验收 + 本地发布审计
```

不是：

```text
真正公网托管服务
```

---

## 3. 为什么这一步必须做

现在 v8.x 已经有很多强 verifier：

- PTC verifier。
- Anchor Registry verifier。
- Anchor Transparency verifier。
- Distribution Kit verifier。
- Distribution Kit Acceptance Evidence verifier。
- Acceptance Board verifier。
- Acceptance Board Signoff Archive verifier。

但是真实交付时，人不会一个一个文件解释：

```text
这个 ZIP 是 PTC
这个 ZIP 是 Anchor Registry
这个 ZIP 是 Transparency
这个 JSON 是 checkpoint
这个 ZIP 是 Acceptance Board Signoff
这个目录是 Accepted Evidence
...
```

外部接收方需要的是一个清晰的发布入口：

```text
publication/
  README.txt
  publication-manifest.json
  index.html
  packages/...
  verification-reports/...
  checksums/SHA256SUMS.txt
```

并且我们自己需要能证明：

- 这个发布目录来自当前 v8.7.2 证据链。
- 目录内没有多余文件。
- 文件复制到其他位置后 hash 不变。
- ZIP 没有路径穿越、反斜杠、重复 entry。
- Manifest 没有自证伪造。
- 撤回和替换有记录。

这就是 v8.8.0。

## 9. 数据结构：Publication Manifest

`publication-manifest.json`：

```json
{
  "schema_version": 1,
  "package_type": "musicforge_public_trust_center_publication",
  "publication_id": "ptc-pub-000001",
  "channel_id": "ptc-channel-000001",
  "center_id": "ptc-default",
  "created_at": "2026-06-16T00:00:00Z",
  "files": [
    {
      "path": "README.txt",
      "size_bytes": 1234,
      "sha256": "<sha256>"
    }
  ],
  "zip": {
    "name": "public-trust-center-publication.zip",
    "size_bytes": 123456,
    "sha256": "<sha256>",
    "entries": []
  },
  "report_hash": "<publication-report integrity_hash>",
  "source_hash": "<publication-report source_hash>",
  "integrity_hash": "<stable-hash>"
}
```

Manifest 不允许自证：

- verifier 不能只信 `manifest.files[]`。
- verifier 必须固定 allow-list 或从 package-index + policy 推导 allow-list。
- verifier 必须重新计算 ZIP 实际 entries。
- `manifest.zip.entries` 只能作为一致性参考，不能用于放行。

## 15. Channel 创建规则

`create_channel()`：

输入：

```json
{
  "name": "Public Release",
  "channel_type": "public_release",
  "description": "Main public trust center channel.",
  "policy": {
    "require_acceptance_board_signoff": true
  }
}
```

规则：

- `channel_id` 自动分配：`ptc-channel-000001`。
- 同一 center 下 name 可重复，但 channel_id 不重复。
- channel policy 合并默认值。
- 写 `channel.json`。
- 写 `events.jsonl`。
- 返回 masked/safe channel。

不允许：

- `channel_type` 非白名单。
- policy 里出现未知 dangerous key。
- description 含 token/path。

## 16. Publication refresh 规则

`refresh_publication()`：

负责读取当前证据链并生成 report。

必须检查：

- PTC ZIP 存在。
- PTC verification report 存在且 passed。
- Distribution Kit ZIP 存在。
- Distribution Kit verification report 存在且 passed。
- Anchor Registry ZIP 存在且 verification passed。
- Anchor Transparency ZIP 存在且 verification passed。
- checkpoint 存在。
- Acceptance Board ZIP 存在且 verification passed。
- Acceptance Board Signoff Archive ZIP 存在且 verification passed。
- Accepted Evidence 数量满足 Board signoff source。

如果 channel policy 要求 strict：

- 任一缺失 -> report `status=blocked`。
- 任一 stale -> report `status=blocked`。
- 任一 verifier failed -> report `status=blocked`。

如果 channel_type 是 `internal_preview`：

- 缺失可 warning，但不能显示 `ready_for_publication=true`。

## 17. Publication export 规则

`export_publication()`：

必须先确认 report：

- `status=ready`
- `source_hash` 当前
- channel 未 revoked / inactive

导出固定结构：

```text
README.txt
VERIFY.txt
publication-report.json
publication-manifest.json
package-index.json
verification-index.json
mirror-policy.json
checksum/SHA256SUMS.txt
checksum/SHA256SUMS.json
site/index.html
site/trust-center.html
site/packages.html
site/verification.html
packages/*.zip
verification-reports/*.json
anchors/*.json
```

导出时必须：

- 复制文件后重新 sha256。
- 写 package-index。
- 写 verification-index。
- 写 checksum 文件。
- 写 manifest。
- 写 event。

不得：

- 复制 `.musicforge/`。
- 复制任何 provider snapshot。
- 复制任何本机绝对路径。
- 复制未脱敏 JSON。

## 18. Publication ZIP 规则

`build_publication_zip()`：

必须先：

- `export_publication()` 已完成。
- export manifest 当前。
- publication 未 revoked。

ZIP 规则：

- entry 使用 `/`。
- 禁止 `\`。
- 禁止 `..`。
- 禁止绝对路径。
- 禁止 drive path。
- 禁止 UNC path。
- 禁止 duplicate entry。
- 禁止 `.musicforge/` 任意大小写。
- nested ZIP 只允许 `packages/*.zip` 固定列表。
- ZIP 写完后更新 manifest zip metadata。
- 不能把 zip 自己放进自己。

## 19. Mirror Directory 规则

新增 mirror verification：

```text
verify mirror dir
```

输入：

```json
{
  "mirror_dir": "D:/somewhere/publication-copy",
  "strict": true
}
```

这里不是复制动作，而是验收动作。

开发可以提供一个 helper：

```python
copy_publication_to_mirror(source_export_dir, mirror_dir)
```

但公开 API 不要自动复制到任意路径，避免滥用本机写入。

Mirror verifier 必须：

- 读取 mirror 下 `publication-manifest.json`。
- 读取 mirror 下所有 required files。
- 重新 sha256。
- 检查没有 extra files。
- 检查 nested ZIP allow-list。
- 检查 redaction。
- 可选 deep verify nested packages。

Mirror report：

```json
{
  "schema_version": 1,
  "status": "passed",
  "publication_id": "ptc-pub-000001",
  "mirror_root_name": "publication-copy",
  "manifest_hash": "<hash>",
  "file_count": 20,
  "blockers": [],
  "warnings": [],
  "integrity_hash": "<hash>"
}
```

不要在 report 里写本机绝对 mirror path。

## 20. Offline verifier

新增 CLI verifier：

```text
python -m song_agent.cli verify-public-trust-center-publication-package <zip>
```

参数：

```text
--strict
--deep
--require-ready
--require-acceptance-board-signoff
--require-anchor-current
--require-no-revoked
--report-out <path>
--json
```

函数：

```python
verify_public_trust_center_publication_package(
    zip_path: Path,
    *,
    strict: bool = False,
    deep: bool = False,
    require_ready: bool = False,
    require_acceptance_board_signoff: bool = False,
    require_anchor_current: bool = False,
    require_no_revoked: bool = False,
    max_zip_size_mb: int = 512,
    max_uncompressed_size_mb: int = 2048,
    max_entry_count: int = 256,
) -> dict
```

Verifier 必须检查：

## 21. Deep verify 规则

`--deep` 时，publication verifier 需要调用：

```text
verify-public-trust-center-package
verify-public-trust-center-distribution-kit-package
verify-public-trust-center-anchor-registry-package
verify-public-trust-center-anchor-transparency-package
verify-public-trust-center-acceptance-board-package
verify-public-trust-center-acceptance-board-signoff-archive-package
```

必须使用 publication 内部文件：

- `packages/*.zip`
- `verification-reports/*.json`
- `anchors/*.json`

不要依赖当前 workspace。

deep verify 输出要写 summary：

```json
{
  "deep_verification": {
    "public_trust_center": "passed",
    "distribution_kit": "passed",
    "anchor_registry": "passed",
    "anchor_transparency": "passed",
    "acceptance_board": "passed",
    "acceptance_board_signoff_archive": "passed"
  }
}
```

如果某个 nested package verifier 需要外部 evidence dir，但 publication 没有携带 accepted evidence 原包，则本版有两种选择：

推荐选择 A：

- Publication 只携带 accepted evidence summary，不携带每个 accepted evidence ZIP。
- deep verify Acceptance Board Signoff Archive 使用 signoff archive 内已固化 summary，不做 external accepted evidence dir current 校验。
- 但 verifier 必须标记 warning：`accepted_evidence_external_current_not_available`。

更强选择 B：

- Publication 携带 accepted evidence ZIP allow-list。
- deep verify 使用这些 ZIP 做 full current 校验。

建议 v8.8.0 采用 B，因为 v8.7.2 已经把 Accepted Evidence 作为强绑定证据。

如果采用 B，Publication packages 里增加：

```text
accepted-evidence/<evidence-id>/accepted-evidence.zip
accepted-evidence/<evidence-id>/accepted-evidence-verification-report.json
```

并更新 mirror-policy allow-list。

## 25. Revoke / Supersede

新增 publication 状态：

```text
ready
published
revoked
superseded
archived
```

注意：这里的 `published` 是本地发布记录，不代表已经真实公网发布。

`revoke_publication()`：

输入：

```json
{
  "reason": "External partner reported wrong package link.",
  "revoked_by": "local"
}
```

规则：

- publication 必须存在。
- 已 revoked 不可重复 revoke。
- 写 event。
- current-publication 如果指向该 publication，则清空或标 revoked。
- 不删除旧 ZIP。

`supersede_publication()`：

输入：

```json
{
  "reason": "Replace with current Acceptance Board signoff.",
  "superseded_by_publication_id": "ptc-pub-000002"
}
```

规则：

- old publication 标 superseded。
- new publication 必须 ready / published。
- 写双向关系。
- 不删除旧包。

## 32. 安全边界

必须避免：

- path traversal。
- symlink file read。
- arbitrary source_path copy。
- local absolute path leak。
- raw provider response leak。
- token leak。
- ZIP bomb。
- duplicate ZIP entry。
- manifest declared extra bypass。
- `.musicforge` internal file inclusion。
- nested ZIP unbounded recursion。

所有 file copy 必须：

- 源路径来自 Store 内部已知 path。
- 目标路径固定在 export dir 下。
- 目标 resolved path 必须在 export dir 内。

## 40. 给开发的话

这版不要急着写 UI。先把 Store 和 verifier 写扎实。

# v14.3.3 MusicForge Call Binding and Lambda Effect Closure

## Goal

Close the schema 14 Explicit Any gaps in local function argument binding and
lambda closure effects without increasing any existing quality ceiling.

## Required Changes

1. Persist positional-only, keyword-only, variadic, and definition-time
   default bindings in local callable summaries.
2. Bind direct arguments and literal `*`/`**` expansions according to Python
   call semantics.
3. Route incomplete or dynamic bindings through the generic may-alias call
   effect rather than trusting a partial summary.
4. Analyze lambdas with the named-function effect machinery and retain closure
   provenance through factory returns.
5. Preserve original callable identities across compacted data-flow
   components.
6. Treat function and lambda free-variable rebinding as an unknown late-bound
   capture that fails closed when consumed by an annotation.
7. Upgrade the collector to schema 15 and record the 14-to-15 migration while
   retaining all total, layer, file, complexity, and recovery ceilings.

## Mandatory Attack Corpus

- positional default
- keyword-only default
- `*args`
- `**kwargs`
- literal starred positional expansion
- literal expanded keyword mapping
- dynamic starred positional expansion
- dynamic expanded keyword mapping
- direct lambda closure
- lambda default binding
- lambda factory return
- named-function late-bound closure rebind
- lambda late-bound closure rebind

Each case must execute to 100 runtime Any annotations, pass project Ruff and
strict mypy, be counted as 100 by the collector, and trigger scope, total,
layer, and per-file blockers under a 99 ceiling.

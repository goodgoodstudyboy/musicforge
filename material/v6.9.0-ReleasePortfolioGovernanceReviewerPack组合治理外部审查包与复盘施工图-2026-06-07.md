v6.9.0 实现：

7. 当前组合治理的主要风险是什么？
8. reviewer 应该重点审什么？
9. 团队下一轮应该改进什么？

## 5. 核心原则

### 5.1 只读

Reviewer Pack 不能改变任何底层状态。Refresh / Export / ZIP / Verify 只能写入：

`.musicforge/portfolios/<portfolio-id>/governance-reviewer-pack/`

不能写：

- portfolio report。
- governance queue。
- governance signoff。
- governance archive。
- governance audit ledger。
- release evidence。
- distribution evidence。

### 5.2 Source Hash 绑定

Reviewer Pack 必须绑定 v6.8 Audit Report / Ledger 的当前状态。

source hash 应至少包含：

- `portfolio_id`
- Portfolio record hash。
- Portfolio Audit report hash。
- Portfolio Governance Audit report integrity hash。
- Portfolio Governance Audit ledger hash。
- Portfolio Governance Audit export manifest hash，如果存在。
- Portfolio Governance Audit verification report hash，如果存在。
- Governance Queue summaries。
- Governance Signoff summaries。
- Governance Archive verification summaries。
- Change Request ledger summary。

如果底层 Audit Ledger refresh 后发生变化，旧 Reviewer Pack 必须 stale。

### 5.3 证据不循环

Portfolio Governance Reviewer Pack 不能纳入 Portfolio Governance Audit Ledger 的 source。

理由：

- Audit Ledger 是机器底层证据。
- Reviewer Pack 是人读摘要。
- 如果互相引用，会造成每次生成 Reviewer Pack 都让 Audit Ledger stale。

### 5.4 外部可携带

Reviewer Pack ZIP 必须能离开 `.musicforge/` 后独立校验。

Verifier 只读 ZIP，不依赖本地 workspace。

### 5.5 脱敏优先

所有 JSON / TXT / MD / CSV 都必须扫描：

- token。
- api key。
- Bearer。
- GitHub token。
- Windows drive path。
- UNC path。
- local path。
- blocked key，例如 `api_key`、`token`、`local_path`、`source_path`、`raw_provider_response`。

### 5.6 不把 warning 伪装成 passed

Reviewer Pack 可以生成 warning 状态，但不能把底层 audit failed / stale 说成 passed。

如果 v6.8 Audit report 是 failed，Reviewer Pack report 必须 failed。

## 12. Refresh 行为

`refresh(portfolio_id)` 做这些事：

1. 读取 Portfolio。
2. 读取 Portfolio Audit report。
3. 读取 Portfolio Governance Audit report。
4. 读取 Portfolio Governance Audit ledger。
5. 读取 Governance Audit verification report，如果存在。
6. 判断 source current。
7. 构造 reviewer report。
8. 构造 retrospective report。
9. 构造 evidence index。
10. 构造 timeline。
11. 运行 redaction scan。
12. 写入四个 sidecar。

如果底层 Governance Audit report 不存在：

- reviewer report status = `failed`
- blocker = `governance_audit_missing`
- 可以写 report，但不能 export 为 passed。

如果底层 Governance Audit report stale：

- reviewer report status = `failed`
- blocker = `governance_audit_stale`
- export/zip 应阻断，除非只是导出 failed report？建议阻断 export，避免外部误用。

建议口径：

- `refresh` 永远可以生成 failed report。
- `export_pack` 和 `build_zip` 遇到 stale / integrity failed 直接 409。

## 15. Offline Verifier

新增：

```text
song_agent/release_portfolio_governance_reviewer_pack_verifier.py
```

CLI：

```text
python -m song_agent.cli verify-release-portfolio-governance-reviewer-pack <zip>
```

参数：

```text
--json
--report-out <path>
--strict
--require-audit
--require-signed
--require-archives
--require-no-force
--require-reset-cr-causality
```

Verifier 只读 ZIP。

### 15.1 必须检查

ZIP：

- 文件存在。
- 可打开。
- ZIP size limit。
- total uncompressed size limit。
- entry count limit。
- raw central directory entry name。
- unsafe path。
- duplicate entry。
- required entries。

Manifest：

- `package_type == "release_portfolio_governance_reviewer_pack"`。
- manifest integrity。
- manifest.files shape。
- file size / sha256 对账。
- extra entry。
- manifest.zip.entries spoof。

Documents：

- reviewer report parse。
- reviewer report integrity。
- retrospective integrity。
- evidence index integrity。
- timeline integrity。
- manifest references match sidecar integrity hash。

Source：

- reviewer report `source_hash` == manifest `source_hash`。
- retrospective / evidence / timeline source hash 和 report source hash 一致，或明确 derived_source_hash。

Audit requirement：

- 如果 `--require-audit`，必须有 audit_summary.status passed。
- 如果有 Audit verification summary，必须 passed。
- Audit ledger hash 必须存在。

Signed requirement：

- 如果 `--require-signed`，report summary 中 queue_count > 0 且 signed_queue_count >= queue_count。

Archive requirement：

- 如果 `--require-archives`，archive_verified_count >= signed_queue_count。

No-force requirement：

- 如果 `--require-no-force`，force_signed_queue_count == 0。

Reset causality：

- 如果 `--require-reset-cr-causality`，reset_count > 0 时必须有 passed causality evidence。

Redaction：

- 扫描全部 JSON / JSONL / TXT / MD / CSV。

### 15.2 Verifier 输出

```json
{
  "schema_version": 1,
  "generated_at": "...",
  "status": "passed",
  "zip_path": "portfolio-governance-reviewer-pack.zip",
  "zip_sha256": "sha...",
  "zip_size_bytes": 12345,
  "manifest_hash": "sha...",
  "summary": {
    "portfolio_id": "pf-000001",
    "reviewer_report_status": "passed",
    "queue_count": 2,
    "signed_queue_count": 2,
    "archive_verified_count": 2,
    "blocker_count": 0,
    "warning_count": 1
  },
  "checks": [],
  "blockers": [],
  "warnings": [],
  "redaction_findings": []
}
```

重要：和 v6.7/v6.8 一样，verifier report 必须输出：

- `zip_sha256`
- `zip_size_bytes`
- `manifest_hash`

后续如果 v7.0 要签核 Reviewer Pack，这些字段可直接用于证据绑定。

## 23. 安全边界

### 23.1 Path Safety

所有 export / zip 操作：

- resolve 路径。
- 确保在 `governance-reviewer-pack/` 内。
- ZIP entry 只使用 POSIX `/`。
- 禁止反斜杠。
- 禁止 `..`。
- 禁止 drive prefix。
- 禁止绝对路径。

### 23.2 Duplicate ZIP

构建时：

- `_zip_entries()` 必须发现重复 entry 直接报错。

Verifier：

- 读取 `archive.infolist()` 检查 duplicate。
- 读取 central directory raw name 检查 raw backslash。

### 23.3 ZIP Bomb

Verifier 限制：

- 最大 ZIP 文件大小，例如 100MB。
- 最大 entry count，例如 1000。
- 最大 total uncompressed size，例如 250MB。

不需要解压全部内容，只用 `ZipInfo.file_size` 汇总。

### 23.4 Redaction

复用 `song_agent/redaction.py`。

扫描：

- JSON。
- JSONL。
- TXT。
- MD。
- CSV。

blocked keys：

```text
api_key
token
access_token
authorization
secret
provider_snapshot
raw_provider_response
source_path
local_path
file_path
absolute_path
```

### 23.5 No Raw Local Paths

Evidence Index 里不能写：

```text
C:\...
D:\...
\\server\share\...
//server/share/...
```

只允许写抽象 path hint：

```text
portfolio governance audit report
governance archive verification report
```

## 27. 预期风险

### 风险 1：循环 source hash

如果把 Reviewer Pack summary 写回 Governance Audit source，会造成循环 stale。

处理：

- Reviewer Pack 只读 Audit Ledger。
- Audit Ledger 不读 Reviewer Pack。

### 风险 2：只信 summary，不信底层 hash

如果 verifier 只看 summary，可能被篡改 summary 放行。

处理：

- summary 必须受 report integrity hash 保护。
- manifest 必须引用 report integrity hash。
- verifier 必须校验。

### 风险 3：Reviewer Pack 被当成签核证据

v6.9 不做 Reviewer Pack signoff。

处理：

- 只生成 reviewer pack verification report。
- 不新增签核 gate。
- 如需签核，放 v7.0。

### 风险 4：外部包误带本机路径

处理：

- export 前 sanitize。
- verifier raw redaction scan。
- release-check 注入路径污染。

### 风险 5：和 v6.4 Release Reviewer Pack 混淆

处理：

- package_type 必须是 `release_portfolio_governance_reviewer_pack`。
- CLI 名称必须包含 `portfolio-governance`。
- README 解释区别。

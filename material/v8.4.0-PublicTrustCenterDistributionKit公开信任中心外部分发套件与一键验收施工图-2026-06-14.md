# v8.4.0 Public Trust Center Distribution Kit 公开信任中心外部分发套件与一键验收施工图

> 本文是给开发执行的 v8.4.0 施工图。当前稳定基线是 v8.3.1。
>
> v8.3.1 已经把 Public Trust Center 的信任链做到了：PTC ZIP、delivery anchor、Anchor Registry、Anchor Transparency、external checkpoint 可以互相绑定，并且 stale registry 会阻断 transparency export / ZIP。  
> v8.4.0 的目标，是把这些文件从“开发者手动凑齐的一组包”升级为“可交付给外部方的一体化 Distribution Kit”，并提供一条命令离线验收全套证据。

---

## 1. 背景

v8.0 到 v8.3 已经完成了 Public Trust Center 的核心信任结构：

1. `public-trust-center.zip`
   - 公开信任中心主包。
   - 包含 HTML、data、manifest、公开交付摘要。
   - 可通过 `verify-public-trust-center-package` 验证。

2. `public-trust-center.delivery-anchor.json`
   - PTC ZIP 外部锚点。
   - 绑定 ZIP hash、manifest hash、source hash、delivery fingerprint sidecar。

3. `public-trust-center-anchor-registry.zip`
   - Anchor Registry 包。
   - 管理 current / published / revoked / superseded anchor。
   - 可通过 `verify-public-trust-center-anchor-registry-package` 验证。

4. `public-trust-center-anchor-transparency.zip`
   - Anchor Transparency 包。
   - 记录 Anchor Registry 状态的 append-only ledger。
   - 绑定 checkpoint。
   - 可通过 `verify-public-trust-center-anchor-transparency-package` 验证。

5. `ptc-anchor-checkpoint-current.json`
   - 外部留存 checkpoint。
   - 用于发现 PTC / anchor / registry / transparency 整体替换。

这些能力已经很强，但对外交付时仍有一个实际问题：

> 外部方需要同时拿到多个文件，并且必须知道正确的验证命令和参数。只要少传一个文件、传错一个路径，验收就可能降级或失败。

v8.4.0 要解决这个交付体验和审计问题。

---

## 2. v8.4.0 定位

一句话：

> v8.4.0 要把 Public Trust Center 主包、delivery anchor、Anchor Registry、Anchor Transparency、checkpoint 和验证说明打成一个外部分发套件，并新增 Distribution Kit verifier，一条命令完成整套离线验收。

它不是替代 v8.0-v8.3 的各个 verifier，而是把它们编排起来，形成外部交付入口。

---

## 3. 本版不做什么

为了避免发散，本版明确不做：

1. 不接入真实 CA / PGP / X.509。
2. 不做在线发布平台。
3. 不自动上传 GitHub Release assets。
4. 不改变 PTC / Anchor Registry / Anchor Transparency 的内部包格式。
5. 不把 `.musicforge/` 内部目录打进套件。
6. 不把 token、本机路径、provider 原始响应写进套件。
7. 不允许 Distribution Kit verifier 信任 kit manifest 自证。
8. 不自动 revoke、supersede、publish anchor。
9. 不要求联网才能验证。

## 9. Export 规则

`export_kit()` 必须：

1. 重新读取当前 PTC ZIP / anchor / registry / transparency / checkpoint。
2. 重新运行或读取当前底层 verification report。
3. 如果底层 report 缺失或 stale，必须刷新 verifier report 或直接 409。
4. 如果任一底层 verifier failed，kit report failed，export 阻断。
5. 复制文件到 `export/`。
6. 写 `file-index.json`。
7. 写 `verification-index.json`。
8. 写 `chain-of-custody.json`。
9. 写 `VERIFY.txt`。
10. 写 manifest。

不允许：

- 复制 `.musicforge/`。
- 复制任意本机路径。
- 信任用户传入的 source_path。
- 把 private config、provider key、renderer path、GitHub token 打包。

---

## 10. Kit ZIP 规则

`build_zip()` 必须：

- 只打包 `export/` 内文件。
- ZIP entry 必须全是 POSIX relative path。
- 不允许 duplicate entry。
- 不允许 nested `.zip` 以外的内部套件？这里要明确：本版 Distribution Kit 必须包含底层 ZIP，所以允许：
  - `packages/public-trust-center.zip`
  - `packages/public-trust-center-anchor-registry.zip`
  - `packages/public-trust-center-anchor-transparency.zip`
- 但不允许其他 `.zip`。
- 需要 verifier 对这三个 allowed nested ZIP 做深度验证。

这是 v8.4 和之前公开包不同的地方：它是“套件包”，必须允许指定的 nested ZIP。禁止规则不能照抄 PTC / Transparency verifier 的 no nested zip。


```python
    require_anchor_transparency_current: bool = True,
```

必须检查：

1. Kit ZIP 可打开。
2. ZIP size / uncompressed size / entry count 限制。
3. raw central directory 反斜杠。
4. duplicate entries。
5. required entries。
6. package_type。
7. manifest integrity。
8. manifest files hash。
9. no extra entries。
10. nested zip allow-list。
11. report integrity。
12. file-index 与 manifest/files 一致。
13. verification-index 与实际 verification reports 一致。
14. delivery anchor hash 与 PTC ZIP 一致。
15. checkpoint hash 与 Anchor Transparency 一致。
16. deep 模式重新跑：
    - `verify-public-trust-center-package`
    - `verify-public-trust-center-anchor-registry-package`
    - `verify-public-trust-center-anchor-transparency-package`
17. deep 模式必须使用 kit 内相对文件，不允许引用本地外部路径。
18. redaction scan。
19. manifest spoof 检测。
20. allowed nested ZIP 之外的 `.zip` failed。

## 17. 安全重点

v8.4 的风险点和之前不同：它必须允许三个指定 nested ZIP。开发要非常小心：

- 只允许 `packages/public-trust-center.zip`。
- 只允许 `packages/public-trust-center-anchor-registry.zip`。
- 只允许 `packages/public-trust-center-anchor-transparency.zip`。
- 其他 `.zip` 一律 failed。
- deep verifier 必须从 kit 解出的临时安全目录读取 nested ZIP，不允许读本机路径。
- 不允许 path traversal。
- 不允许反斜杠 entry。
- 不允许 symlink。
- 不允许 manifest.zip.entries 扩大 allow-list。
- 不允许 report/source 自证。
- 不允许把 old verification report 当 current。

## 23. 给开发的话

这版的关键不是再造一个证明包，而是减少外部交付的人为错误。外部方拿到一个 Distribution Kit ZIP 后，应该可以只运行一条 verifier 命令，就知道 PTC ZIP、delivery anchor、Anchor Registry、Anchor Transparency、checkpoint 是否彼此匹配。

实现时请特别注意 nested ZIP allow-list：v8.4 必须允许三个指定底层 ZIP，但不能因此放开所有 ZIP。这个点最容易写成安全漏洞。先把 Store、Verifier 和 release-check smoke 做扎实，再接 Studio。

# v9.0.0 Trust Operations Hub 统一信任运营中枢与跨链路准出施工图

> 当前稳定基线：v8.9.1
> v8 系列已经把 Public Trust Center 从“可生成包”推进到“可发布、可验收、可签核、可监控、可发现事故”。
> v9.0.0 的目标，是把 Release / Distribution / Submission / Operations / Public Trust Center / Publication / Monitoring 这些分散证据链收束成一个统一的本地运营中枢，提供跨链路 readiness、阻断项、手动动作、证据导出、签核和离线验证。

---

## 0. 给开发的话

这版是一个大跨步，但不能大到失控。你要把 v9.0.0 理解成：

```text
不是再做一个单点 ZIP
而是做一个统一运营总控面板和总控证据包
```

到 v8.9.1 为止，我们已经有很多强模块：

- Release QA / Final Export / Release Export。
- Distribution Prep / Distribution ZIP / Submission Workspace。
- Submission Evidence Archive。
- Release Operations Dashboard / Runbook / Signoff / Archive / Audit / Reviewer Pack。
- Portfolio Governance / Final Board / Evidence Vault / Public Attestation。
- Public Trust Center。
- PTC Anchor Registry / Transparency。
- PTC Distribution Kit / Acceptance Board / Board Signoff。
- PTC Publication Channel / Publication Monitoring。

问题是：这些能力非常强，但散在不同页面、不同 CLI、不同 ZIP、不同 verifier 里。
v9.0.0 要建立一个 Trust Operations Hub：

- 汇总所有关键链路状态。
- 明确什么可以 release-ready，什么阻断。
- 明确每个阻断项对应哪个 manual action。
- 明确每个 ready 判断来自哪个底层 verification report。
- 生成一个可交给 reviewer 的 Hub ZIP。
- Hub ZIP 可离线验证。
- Hub 签核必须绑定当前底层证据。

这版最重要的 reviewer 红线：

- Hub 不能只信各模块 summary 自证。
- Hub 必须绑定底层 package ZIP hash、manifest hash、verification report hash。
- Hub 必须能发现底层证据后续 stale / revoke / supersede / reset / new incident。
- Hub signoff 不能用旧 Hub report 签当前状态。
- Hub export/zip/signoff 不能在已签核后静默重建。
- Hub verifier 必须有 full-resign 回归。

## 2. 为什么 v9.0.0 是必要的

现在项目已经进入一个典型问题：

```text
每条链路都可验
但缺一个“总控验收口径”
```

例如业务问：

> 这个 release 现在到底能不能对外发布？

现在需要分别看：

- Release Signoff。
- Distribution Target Signoff。
- Submission accepted。
- Submission Evidence signed。
- Release Operations signed/archived/audited。
- Reviewer Pack。
- Portfolio Governance。
- Public Trust Center。
- Distribution Kit。
- Acceptance Board Signoff。
- Publication Channel。
- Publication Monitoring。

这对开发、reviewer、业务都太散。

v9.0.0 要提供一个统一回答：

```text
Trust Operations Hub status = ready / blocked / warning / stale
```

并且能说明：

```text
为什么 ready？
为什么 blocked？
证据来自哪个包？
哪个 verifier 证明过？
现在是否 current？
谁签核过？
后续 manual actions 是什么？
```

## 4. 不做什么

v9.0.0 必须收住：

- 不做真实公网发布。
- 不做真实后台定时任务。
- 不调用外部 API。
- 不发送 Webhook / 邮件 / Slack。
- 不自动 approve / signoff / reset。
- 不自动 revoke / supersede publication。
- 不自动修改 Release / Distribution / Submission 状态。
- 不自动生成新的 Acceptance Board response。
- 不自动创建 GitHub Release。
- 不引入数据库。
- 不引入外部依赖。
- 不把 deterministic signature 冒充法律签名。

允许做：

- 聚合本地证据。
- 读取已有 verification reports。
- 运行本地 verifier。
- 生成 readiness matrix。
- 生成 manual action queue。
- 生成 Hub package。
- Hub signoff / reset。
- 离线 verifier。

- `--publication-channel-state`
- `--publication-monitoring-verification`
- `--public-trust-center-verification`

后续版本再扩展更多显式 external proof 参数。

### 19.1 Verifier 必查

ZIP:

- parseable。
- no duplicate entries。
- no path traversal。
- no raw backslash entry。
- no absolute path。
- no `.musicforge` / `.MusicForge`。
- no nested ZIP。
- exact allow-list。
- manifest.files exact match。
- file-index/checksum exact match。
- zip bomb limits。

JSON:

- package_type。
- integrity_hash。
- manifest source binding。
- hub report source binding。
- readiness matrix summary derived from rows。
- blocker register summary derived from rows。
- manual action queue summary derived from actions。
- evidence binding summary derived from evidence rows。
- verification summary derived from verification rows。

Semantics:

- `hub-report.readiness` must derive from readiness matrix。
- blockers must derive from readiness matrix failed rows。
- manual actions must map to blockers。
- `overall_status=ready` impossible if blocker_count > 0。
- `not_configured` under explicit requirement is blocked。
- stale evidence under explicit requirement is blocked。
- waived high/critical blockers blocked unless explicit allowed in future; v9.0 不提供 allow flag。

External current:

- if `--require-current`, external state required for publication channel。
- external publication channel state must match source-state and evidence binding。
- revoked/superseded publication causes failed。
- external verification report hash must match evidence binding if provided。

Redaction:

- scan JSON/TXT/MD。
- fail on keys/tokens/local paths/UNC paths/raw provider response。

create_hub(payload)

- validate scope。
- write `hub.json`。

### 20.2 refresh_report()

```python
refresh_report(hub_id, payload=None)
```

Must:

- collect source state。
- run/read required bottom verifications。
- build readiness matrix。
- build blocker register。
- build manual action queue。
- build evidence binding index。
- build verification summary index。
- write hub report。
- update current-report pointer。

Must not:

- mutate bottom modules。
- auto signoff。
- auto reset。
- auto revoke/supersede。

```python
export_report(hub_id, report_id)
```

Must:

- refuse if report stale。
- refuse if signed and no approved CR reset。
- write fixed export structure。

### 20.6 signoff()

## 27. P1 Reviewer 风险清单

### P1-1 Hub summary 自证

错误：

```text
hub-report overall_status=ready
verifier 直接相信
```

正确：

```text
overall_status 必须从 readiness-matrix rows 推导
readiness-matrix 必须从 evidence-binding-index / verification-summary-index 推导
```

必须回归：

- 改 hub-report ready，其他不变 -> failed。

### P1-2 Blocker register 被清空

错误：

```text
blocker-register.json 清空，重算 hash -> passed
```

正确：

```text
blocker register 必须从 readiness matrix failed/blocking rows 推导
```

必须回归：

- 清空 blockers + 重签 -> failed。

### P1-3 Evidence binding 被替换

错误：

```text
把 evidence-binding-index 指向另一个 ZIP hash，重签 -> passed
```

正确：

```text
external verification report / external state 必须能反查 binding
```

必须回归：

- evidence zip_sha256 tamper -> failed。

### P1-4 旧 Hub ZIP 在 publication revoke 后仍通过

错误：

```text
Hub ZIP 里 source-state 仍是旧 published，于是 current passed
```

正确：

```text
--require-current 必须读外部 publication-channel-state
```

必须回归：

- build Hub ZIP -> revoke publication -> verify old Hub with external state -> failed。

### P1-5 signed Hub 静默重建

错误：

```text
signoff 后删除 export/zip，再 export/zip 成功
```

正确：

```text
signoff history 阻断重建，必须 approved CR reset
```

必须回归：

- signoff -> delete export/zip -> export/zip 409。

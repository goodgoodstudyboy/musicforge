# v7.6.0 Release Portfolio Governance Attestation Portal Review Response 公开证明门户外部审查响应闭环施工图

> 本文是给开发执行的 v7.6.0 施工图。当前稳定基线是 v7.5.1。v7.5.1 已经把 Release Check Verification Matrix 修稳：空检查集不再假绿，`release-check` 支持 profile/group/since/only/list/json/report/timing，v7 链路可以独立复验。

v7.6.0 的目标是把 v7.4 的 Public Attestation Portal Snapshot 从“单向展示证明”升级成“可接收外部审查响应、可离线验证、可导入治理闭环”的系统。

一句话：

> v7.6.0 要让外部审查方拿到 Portal Snapshot 后，可以给出结构化 response；系统能验证 response 确实针对当前 Portal / Registry / Public Attestation，并把 accepted / needs_changes / rejected 进入后续治理流程。

---

## 1. 背景

v7.1 到 v7.5 已经完成了公开证明链路的主体：

- v7.1：Evidence Vault，深度证据保险库。
- v7.2：Public Attestation，公开证明证书包。
- v7.3：Attestation Registry，公开证明登记册，支持 publish / revoke / supersede。
- v7.4：Attestation Portal Snapshot，静态门户快照，给外部方打开查看。
- v7.5：Release Check Verification Matrix，让本地发布验证可拆分、可计时、可复验。

当前缺口：

1. Portal Snapshot 只能“我们生成、我们验证、外部查看”。
2. 外部审查方看完 Portal 后，没有结构化方式把结论带回系统。
3. 如果审查方说 accepted，目前没有可验证的 response 包。
4. 如果审查方说 needs_changes / rejected，目前不能直接形成后续治理动作。
5. 外部 response 如果只是一份手写 JSON，很容易被伪造为针对另一个 Portal 或旧 Portal。
6. 当前 Final Board / Registry / Portal 证明链路缺少“外部审查回执”的安全归档。

v7.6 要解决这个闭环：

```text
Evidence Vault
  -> Public Attestation
  -> Attestation Registry
  -> Portal Snapshot
  -> Portal Review Pack
  -> External Reviewer Response
  -> Import / Verify
  -> accepted evidence 或 needs_changes / rejected governance work
```

---

## 2. v7.6.0 目标

新增 Public Attestation Portal Review Response。

核心能力：

1. 从当前 Portal Snapshot 生成 Portal Review Pack。
2. Review Pack 可打 ZIP，可离线验证。
3. 外部审查方基于 Review Pack 填写 Reviewer Response。
4. 系统导入 Response 时必须校验它绑定当前 Portal source。
5. Response 支持三种结论：
   - `accepted`
   - `needs_changes`
   - `rejected`
6. `accepted` 可作为后续公开证明/组合治理外部审查证据。
7. `needs_changes` / `rejected` 可生成 Governance Change Request 或 Follow-up work item。
8. 新增离线 verifier：
   - `verify-release-portfolio-governance-attestation-portal-review-pack`
   - `verify-release-portfolio-governance-attestation-portal-response`
9. Studio 增加 Portal Review Response 控件。
10. `release-check --profile latest` 和 `release-check --profile v7` 接入 v7.6 smoke。

- 不做在线评论系统。
- 不接邮件。

- 不允许 rejected 自动 revoke attestation。

```json

  "portfolio_id": "portfolio-000001",
  "portal_zip_sha256": "...",
  "portal_zip_size_bytes": 12345,
  "portal_manifest_hash": "...",
  "portal_verification_hash": "...",
  "portal_verification_status": "passed",
  "portal_source_hash": "...",
  "registry_zip_sha256": "...",
  "registry_manifest_hash": "...",
  "registry_verification_hash": "...",
  "registry_current_entry_id": "...",
  "attestation_zip_sha256": "...",
  "attestation_manifest_hash": "...",
  "attestation_verification_hash": "...",
  "evidence_vault_zip_sha256": "...",
  "final_board_signoff_hash": "...",
  "generated_at": "2026-06-10T00:00:00+00:00"
```

```text
review_pack_source_hash = stable_hash({
  portal_zip_sha256,
```

- `generated_at` 不参与 source hash。
- reviewer guide 文案不参与 source hash。

## 7. 决策语义

### 7.1 accepted

含义：

- 外部 reviewer 认可当前 Portal Snapshot 所代表的公开证明状态。
- 可以作为后续 Registry / Portfolio Governance 的外部审查 evidence。

要求：

- findings 里不能有 `high` / `critical` unresolved。
- response verifier passed。
- response source 绑定当前 Review Pack source。
- response 没有 redaction failure。

### 7.2 needs_changes

含义：

- 外部 reviewer 认为当前 Portal 可以修正后再审。

效果：

- 导入成功。
- 生成 follow-up work item。
- 可选生成 Governance Change Request draft。
- 不自动 reset / revoke / supersede。

### 7.3 rejected

含义：

- 外部 reviewer 拒绝当前 Portal / Public Attestation 状态。

效果：

- 导入成功。
- 标记 response decision 为 rejected。
- 生成 high-priority follow-up work item。
- 可选生成 Governance Change Request draft。
- 不自动 revoke Registry entry。
- 后续人工决定是否 revoke / supersede。

## 11. Verifier 要求

### 11.1 Review Pack Verifier

必须检查：

- ZIP path safe。
- raw central directory entry safe。
- no duplicate entry。
- no nested ZIP。
- no `.musicforge/`，大小写不敏感。
- `package_type == release_portfolio_governance_attestation_portal_review_pack`。
- manifest files hash。
- `review-pack.json.source_hash` 与 manifest source 一致。
- Portal verification summary hash 一致。
- Registry verification summary hash 一致。
- Attestation verification summary hash 一致。
- redaction scan passed。
- reviewer guide 不含脚本/远程链接。

### 11.2 Response Verifier

必须检查：

- ZIP path safe。
- no duplicate entry。
- no nested ZIP。
- no `.musicforge/`，大小写不敏感。
- package_type 正确。
- response manifest hash。
- `review_pack_source_hash` 与 response 内 source summary 一致。
- `portal_zip_sha256` / `portal_manifest_hash` / `portal_verification_hash` 与 review pack source 一致。
- response_payload_hash 正确。
- decision 合法。
- accepted 不能带 unresolved high/critical finding。
- notes / findings / reviewer 字段脱敏。
- attachments 只允许摘要，不允许 source_path。

Verifier 输出状态：

```text
passed
failed
warning
```

任何 source mismatch 都必须 failed。

## 12. Stale Guard

Review Pack stale 条件：

- Portal ZIP 变化。
- Portal manifest hash 变化。
- Portal verification report 变化。
- Registry verification summary 变化。
- Attestation verification summary 变化。
- Evidence Vault 指纹变化。
- Final Board signoff hash 变化。

Response stale 条件：

- response 绑定的 review_pack_source_hash 不等于当前 Review Pack source hash。
- response 绑定的 portal verification hash 不等于当前 Portal verification hash。
- response 绑定的 registry current entry 不等于当前 Registry current entry。
- response verifier report 不是当前 response ZIP / manifest 生成。

导入 response 时：

- 可以导入旧 response，但状态必须标 `stale`。
- stale response 不能作为 accepted evidence。
- stale response 不能创建 accepted summary。
- stale needs_changes / rejected 可以保留为历史记录，但不能驱动当前 Change Request，除非用户明确重新导入针对当前 pack 的 response。

## 13. Governance Change Request / Follow-up

v7.6 不自动执行治理动作，只创建草案。

needs_changes / rejected 后建议生成：

```json
{
  "source_type": "attestation_portal_review_response",
  "response_id": "aprr-000001",
  "decision": "needs_changes",
  "severity": "high",
  "recommended_actions": [
    "Update verifier instructions",
    "Regenerate portal snapshot",
    "Re-run registry verification"
  ],
  "status": "draft"
}
```

如果已有 open Change Request 来自同一个 response：

- 返回 existing。
- 不重复创建。

如果 response 是 stale：

- 返回 409。

Smoke detail 建议：


## 21. 安全要求

必须满足：

1. response 不允许 source_path。
2. response 不允许 local_path。
3. response 不允许嵌入 token。
4. response 不允许嵌入本机绝对路径。
5. response 不允许嵌入 nested ZIP。
6. Review Pack ZIP 不允许 nested ZIP。
7. ZIP verifier 必须检查 raw central directory entry。
8. `.musicforge/` 禁止规则大小写不敏感。
9. `\` 反斜杠 entry 必须 failed。
10. duplicate entry 必须 failed。
11. accepted response 必须 current。
12. stale accepted response 不能作为 evidence。
13. needs_changes / rejected 不能自动执行 destructive 动作。
14. Change Request draft 必须可追溯到 response hash。
15. 所有 JSON report 必须脱敏。

# MusicForge v0.7.0 施工图：音乐质量升级

日期：2026-05-06  
角色：reviewer / planner  
目标版本：v0.7.0  
前置版本：v0.6.2

## 1. 当前项目状态

MusicForge 到 v0.6.2 为止，工程基础已经基本成型：

- 单 job 生成链路可用。
- Studio 面板可用。
- provider 配置和 mock / OpenAI-compatible provider 可用。
- multinode agent pipeline 可用。
- node retry 可用。
- batch CSV 生产可用。
- MIDI 渲染可用。
- WAV 渲染可用。
- batch audio render 可用。
- access token 鉴权和 release-check 已完成。

现在的问题不是“系统能不能跑”，而是“生成出来的歌是否更像一首经过规划的歌”。当前 SongPlan 仍偏工程最小可用格式：`sections + chords + tracks`。它能渲染 MIDI，但缺少音乐创作层面的可解释结构，例如 motif、hook、段落张力、旋律轮廓、和声功能、编曲密度、歌词和旋律关系。

v0.7.0 的重点应该从工程外壳转向音乐质量。

## 2. v0.7.0 总目标

v0.7.0 要交付一个“可解释、可检查、可逐步提升”的音乐质量层。

具体目标：

1. SongPlan 增加兼容式 quality metadata
   - 不破坏现有 MIDI renderer。
   - 不破坏旧 `song-plan.json` 读取。
   - 给每首歌增加可选的音乐意图、motif、hook、张力曲线、段落角色、质量评分。

2. multinode pipeline 输出更有音乐意图
   - structure 不只是 bars 和 energy，还要有 tension / role / transition intent。
   - melody 不只是音符列表，还要有 motif 和 phrase contour。
   - arrangement 不只是四轨，还要有 density / mute-intent / section dynamics。
   - critic 不只检查硬错误，还要检查音乐性问题。

3. validator 和 Studio 能展示质量
   - Studio 增加 Quality tab 或增强 Validator tab。
   - 展示总分、维度分、问题列表、建议修复项。
   - Timeline 能显示 energy / tension / section role。

4. provider prompt 升级
   - provider 节点输出必须包含质量意图字段。
   - mock provider 和本地 deterministic 模式也要能生成这些字段，保证本地可验证。

5. 保持本地优先
   - 所有能力必须先在 local deterministic 和 mock provider 下跑通。
   - 不依赖真实 provider 才能通过测试。
   - 不引入重型音乐理论库，先用轻量规则和现有 schema 推进。

## 3. 本阶段不做什么

v0.7.0 不做这些事情：

- 不做真实 AI 音频生成。
- 不做人声合成。
- 不做混音母带。
- 不做 DAW 工程文件导出。
- 不做复杂乐理引擎或第三方音乐理论依赖。
- 不做多版本 A/B 评分系统。
- 不做可视化钢琴卷帘编辑器。
- 不做 stem 独立 WAV 导出。这个放 v0.8.0。
- 不强制真实 provider 接入才能验收。

v0.7.0 是“音乐结构和质量评价层”，不是“音频生产大跃迁”。

## 4. 核心设计原则

### 4.1 兼容优先

SongPlan 现有字段必须保持：

```json
{
  "title": "...",
  "key": "...",
  "tempo_bpm": 120,
  "meter": "4/4",
  "sections": [],
  "tracks": []
}
```

新增字段必须是可选字段。旧计划没有这些字段时也能：

- `SongPlan.from_dict()` 成功。
- `validate_song_plan()` 成功。
- MIDI renderer 成功。
- Runtime views 成功。

### 4.2 质量字段服务于后续编排

不要为了“看起来高级”加字段。每个字段都要满足至少一个用途：

- 能帮助 provider 生成更好结果。
- 能帮助 deterministic composer 生成更有结构的 MIDI。
- 能帮助 validator 发现问题。
- 能帮助 Studio 解释这首歌。
- 能帮助后续 v0.8.0 stem / v0.9.0 edit workflow。

### 4.3 先做可测规则，再做主观质量

质量评价里有大量主观问题。v0.7.0 先做可测的基础项：

- 段落是否有合理张力变化。
- chorus energy 是否高于 verse。
- hook 是否存在。
- melody 是否全程机械重复。
- melody 音域是否过窄或过宽。
- tracks 是否和 section 长度一致。
- chord / bass / section 是否一致。
- drums density 是否随 energy 有变化。
- 是否存在过多空白小节。

先把这些做稳，再谈更深的审美。

## 5. 新增数据结构建议

### 5.1 SongPlan 新增可选字段

在 `song_agent/schemas/song.py` 增加可选 dataclass。

建议新增：

```python
@dataclass(frozen=True)
class MotifPlan:
    name: str
    description: str
    rhythm_pattern: list[float] = field(default_factory=list)
    pitch_intervals: list[int] = field(default_factory=list)
    anchor_section: str | None = None

@dataclass(frozen=True)
class SectionIntent:
    section_name: str
    role: str
    energy: int
    tension: int
    density: int
    transition: str = ""
    hook: bool = False

@dataclass(frozen=True)
class QualityScores:
    overall: int
    structure: int
    melody: int
    harmony: int
    arrangement: int
    lyric_fit: int = 0

@dataclass(frozen=True)
class SongQualityMeta:
    summary: str = ""
    primary_motif: MotifPlan | None = None
    section_intents: list[SectionIntent] = field(default_factory=list)
    hook_sections: list[str] = field(default_factory=list)
    scores: QualityScores | None = None
    warnings: list[str] = field(default_factory=list)
```

`SongPlan` 增加：

```python
quality: SongQualityMeta | None = None
```

### 5.2 JSON 示例

示例：

```json
{
  "title": "Rainy Convenience Store",
  "key": "C",
  "tempo_bpm": 96,
  "meter": "4/4",
  "sections": [
    {
      "name": "intro",
      "start_bar": 1,
      "bars": 4,
      "chords": ["Cmaj7", "Am7", "Dm7", "G7"],
      "lyrics": null
    }
  ],
  "tracks": [],
  "quality": {
    "summary": "Warm city-pop cue with a simple rising hook and restrained verse-to-chorus lift.",
    "primary_motif": {
      "name": "rain-window hook",
      "description": "A two-bar rising-falling phrase used in intro and chorus.",
      "rhythm_pattern": [1.0, 1.0, 0.5, 0.5, 1.0],
      "pitch_intervals": [0, 3, 2, -2, -3],
      "anchor_section": "chorus"
    },
    "section_intents": [
      {
        "section_name": "intro",
        "role": "establish",
        "energy": 2,
        "tension": 2,
        "density": 2,
        "transition": "open into verse with light pickup",
        "hook": false
      }
    ],
    "hook_sections": ["chorus"],
    "scores": {
      "overall": 82,
      "structure": 85,
      "melody": 80,
      "harmony": 78,
      "arrangement": 84,
      "lyric_fit": 75
    },
    "warnings": []
  }
}
```

### 5.3 兼容要求

必须满足：

- 旧 JSON 没有 `quality`，能读取。
- 新 JSON 有 `quality`，能读取。
- `to_dict()` 会输出 `quality`。
- `quality=None` 时输出可以是 `null` 或省略，建议保留 `quality: null` 也可以，但要统一测试。
- validator 不应该因为没有 `quality` 直接失败，只给 warning。

## 6. Agent node schema 升级

当前 `song_agent/schemas/agent_nodes.py` 已有：

- `SongBrief`
- `SonicPalette`
- `StructureSectionPlan`
- `StructurePlan`
- `LyricPlan`
- `HarmonyPlan`
- `MelodyPlan`
- `ArrangementPlan`
- `CriticReport`
- `RepairPlan`

v0.7.0 建议扩展这些节点，而不是马上新增大量节点。

### 6.1 StructureSectionPlan 扩展

当前：

```python
class StructureSectionPlan:
    name: str
    start_bar: int
    bars: int
    energy: int
    purpose: str
```

建议增加可选字段：

```python
tension: int = 0
density: int = 0
role: str = ""
transition: str = ""
hook_candidate: bool = False
```

规则：

- `energy/tension/density` 范围 0..10。
- 如果旧 provider 输出没有这些字段，用默认值推导。
- `role` 可为 `intro/verse/pre_chorus/chorus/bridge/outro/fill/transition` 之一，也可以先允许自由字符串，但 validator 给 warning。

### 6.2 MelodyPhrase 扩展

当前：

```python
class MelodyPhrase:
    section_name: str
    notes: list[NoteEvent]
```

建议增加：

```python
motif_name: str | None = None
contour: str = ""
phrase_role: str = ""
```

`contour` 建议值：

- `rising`
- `falling`
- `arch`
- `inverted_arch`
- `flat`
- `mixed`

### 6.3 MelodyPlan 扩展

当前：

```python
class MelodyPlan:
    lead_instrument: str
    phrases: list[MelodyPhrase]
```

建议增加：

```python
primary_motif: MotifPlan | None = None
hook_phrase_section: str | None = None
```

注意：如果 `MotifPlan` 放在 `schemas/song.py`，`agent_nodes.py` 可以复用它，避免重复定义。

### 6.4 ArrangementTrack 扩展

当前：

```python
class ArrangementTrack:
    name: str
    instrument: str
    role: str
    notes: list[NoteEvent]
```

建议增加：

```python
density: int = 0
section_behavior: dict[str, str] = field(default_factory=dict)
```

示例：

```json
{
  "name": "drums",
  "instrument": "gm drums",
  "role": "drums",
  "density": 6,
  "section_behavior": {
    "intro": "kick only",
    "verse": "closed hat groove",
    "chorus": "full backbeat with crash"
  },
  "notes": []
}
```

### 6.5 CriticReport 扩展

当前：

```python
class CriticReport:
    passed: bool
    score: int
    issues: list[CriticIssue]
```

建议增加：

```python
dimension_scores: dict[str, int] = field(default_factory=dict)
summary: str = ""
```

维度：

- `structure`
- `melody`
- `harmony`
- `arrangement`
- `lyric_fit`
- `renderability`

## 7. 新增 quality analyzer

建议新增文件：

- `song_agent/music_quality.py`

职责：

- 从 SongPlan 计算音乐质量指标。
- 生成 `SongQualityMeta`。
- 生成 critic issues。
- 给 Runtime / Studio 提供统一数据。

建议函数：

```python
def analyze_song_quality(plan: SongPlan) -> SongQualityMeta: ...
def quality_issues_for_plan(plan: SongPlan) -> list[CriticIssue]: ...
def score_song_plan(plan: SongPlan) -> QualityScores: ...
def melody_range_by_track(plan: SongPlan) -> dict[str, tuple[int, int]]: ...
def track_density_by_section(plan: SongPlan) -> dict[str, dict[str, float]]: ...
def detect_repetition(plan: SongPlan) -> list[CriticIssue]: ...
def detect_section_energy_shape(plan: SongPlan) -> list[CriticIssue]: ...
```

### 7.1 质量评分初版规则

总分 `overall` 由 5 个维度组成：

- structure：20%
- melody：25%
- harmony：20%
- arrangement：25%
- lyric_fit：10%

如果 instrumental：

- lyric_fit 不参与总分。
- 其他维度重新归一化。

### 7.2 structure 评分

检查：

- section 数量是否 >= 3。
- 总 bars 是否和 duration 大致匹配。
- start_bar 是否连续。
- chorus energy 是否高于 verse。
- outro energy 是否低于 chorus。
- 是否至少存在一个 hook section。

### 7.3 melody 评分

检查：

- melody track 是否存在。
- melody 音域是否合理，建议 5..24 semitones。
- melody 是否有重复 motif，但不能完全机械重复。
- 每个主要 section 是否有 melody。
- hook section 是否有更高或更集中的 melodic contour。
- note duration 是否过碎或过长。

### 7.4 harmony 评分

检查：

- chords 是否为空。
- section chords 是否数量合理。
- bass root 是否大致跟 chord root 对齐。
- 是否全歌完全同一组 chord 且无变化。如果是，可 warning，不直接 fail。
- chord 名称是否可被当前 `_chord_pitches()` / `_bass_pitch()` 支持。当前不支持的可以 warning。

### 7.5 arrangement 评分

检查：

- 必需四轨是否齐全。
- drums density 是否随 section energy 有变化。
- bass 和 chords 是否覆盖主要 section。
- 是否存在长时间全轨空白。
- velocity 是否有基础变化。
- chorus 是否比 verse 更满。

### 7.6 lyric_fit 评分

初版只做轻量检查：

- vocal_mode 是 instrumental 时跳过。
- 有 lyrics 的 section 是否存在 melody notes。
- lyrics 过长但 melody 太少时 warning。
- language 不一致不做强校验。

## 8. deterministic composer 升级

当前 local deterministic composer 的旋律 motif 非常固定。v0.7.0 要让本地生成也体现质量升级。

建议改动：

- 根据 `SongRequest.style` 选择不同 groove density。
- 根据 `tempo_bpm` 和 `duration_seconds` 推导 section 长度，先保持 `intro/verse/chorus/outro` 结构也可以。
- verse 使用较低音域和更少音符。
- chorus 使用更高音区、更强 velocity、更明确 hook。
- drums 在 intro/verse/chorus/outro 有不同密度。
- bass 在 chorus 加 octave 或更密集节奏。
- chords 在 chorus 提高 velocity 或增加 offbeat。

验收标准：

- local single pipeline 生成的 MIDI 仍然可渲染。
- local multinode pipeline 的 `SongPlan.quality` 不为空。
- `quality.scores.overall >= 70`。
- chorus 的 section intent energy 高于 verse。
- melody track 在 chorus 的平均 pitch 高于 verse 或 velocity 高于 verse。

## 9. multinode pipeline 升级

### 9.1 build_structure_plan

当前固定输出：

- intro 4 bars
- verse 8 bars
- chorus 8 bars
- outro 4 bars

v0.7.0 可以先继续固定结构，但要补质量意图：

- intro：energy 2，tension 2，density 2，role establish。
- verse：energy 4，tension 4，density 4，role narrative。
- chorus：energy 7，tension 6，density 7，role hook。
- outro：energy 3，tension 2，density 3，role resolve。

### 9.2 build_melody_plan

需要生成：

- `primary_motif`
- phrase contour
- hook phrase section

本地确定性策略：

- motif 使用 interval pattern，而不是只写死 pitch 序列。
- verse phrase：motif 轻微下行或平稳。
- chorus phrase：motif 上移 3..5 semitones，velocity 更高。
- outro phrase：回到 intro/verse 的简化版。

### 9.3 build_arrangement_plan

需要把 section energy 传进去。当前函数签名：

```python
build_arrangement_plan(palette, sections, melody)
```

建议变为：

```python
build_arrangement_plan(palette, structure, sections, melody)
```

这样 drums/bass/chords 能根据 `StructureSectionPlan.energy/density` 生成不同密度。

注意 node retry 依赖：

- 如果 structure 改了，melody、arrangement、critic、repair、song_plan_builder 都应重跑。
- 如果 harmony 改了，arrangement、critic、repair、song_plan_builder 要重跑。
- 如果 melody 改了，arrangement、critic、repair、song_plan_builder 要重跑。

当前 `node_graph.py` 里 arrangement 已依赖 harmony 和 melody，这条是对的。若新增 quality 节点，需要更新依赖。

### 9.4 critic_report_for_plan

把 `quality_issues_for_plan(plan)` 接入 critic。

错误级别建议：

- `error`：会导致渲染失败或结构不合法。
- `warning`：音乐质量明显弱，但仍可渲染。
- `info`：可优化建议。

评分：

- `CriticReport.score` 使用 `QualityScores.overall`。
- `dimension_scores` 写入各维度。

### 9.5 repair_song_plan

v0.7.0 不要求修复所有音乐性问题，但至少要新增几个低风险修复：

- 缺 `quality` 时自动补 `SongQualityMeta`。
- 缺 hook section 时把 chorus 标记为 hook。
- chorus energy 不高于 verse 时调整 section intent。
- melody 音域过窄时 chorus melody 上移少量音程。
- 完全空 drums/chords/bass 继续按现有逻辑补。

不要做风险太高的修复：

- 不自动重写复杂和弦。
- 不自动大规模重排全部 melody。
- 不根据歌词硬切音节。

## 10. provider prompts 升级

需要更新：

- `song_agent/prompts/provider_song_plan.md`
- `song_agent/prompts/nodes/structure_planner.md`
- `song_agent/prompts/nodes/harmony_planner.md`
- `song_agent/prompts/nodes/lyric_planner.md`

- `song_agent/prompts/nodes/melody_planner.md`

Prompt 必须明确：

- 输出 JSON only。
- 必填字段和可选字段。
- `energy/tension/density` 范围 0..10。
- chorus/hook 要有更明确的 section intent。
- 不要输出 markdown。
- 不要输出解释文字。

# v7.5.0 Release Check Verification Matrix 发布验证矩阵与回归检查编排施工图

> 本文是给开发执行的 v7.5.0 施工图。当前稳定基线是 v7.4.1。v7.4.1 已经修复 Public Attestation Portal Snapshot 的关键证明链路问题：Portal report / data / manifest / HTML 即使被整体重签，也不能伪造 Registry 和 Public Attestation verification summary 指纹。

v7.5.0 的目标不是继续新增公开证明业务功能，而是先把发布验证体系收紧。当前项目已经走到 v7.4.1，功能面非常大，`release-check` 已经多次在 20-30 分钟内跑不完。继续堆功能会让每次发布越来越难判断“到底安全不安全、到底哪里慢、到底哪里失败”。v7.5.0 要把这件事系统化。

一句话：

> v7.5.0 要把 `python -m song_agent.cli release-check` 从一个线性大脚本，升级成可分组、可计时、可复跑、可输出 JSON 报告、可定位慢项和失败项的 Release Verification Matrix。

---

## 1. 背景

从 v0.1 到 v7.4，项目已经从本地 MIDI MVP 演进到完整的音乐生成、人工听审、音频交付、发行、提交、运营、组合治理、公开证明链路。

尤其是 v6 到 v7：

- v6.0：Release Operations Dashboard。
- v6.1：Operations Runbook。
- v6.2：Operations Signoff / Archive / Change Request。
- v6.3：Operations Audit Ledger。
- v6.4：Operations Reviewer Pack。
- v6.5：Release Portfolio Audit。
- v6.6：Portfolio Governance Queue。
- v6.7：Portfolio Governance Signoff / Archive。
- v6.8：Portfolio Governance Audit。
- v6.9：Portfolio Governance Reviewer Pack。
- v7.0：Final Board。
- v7.1：Evidence Vault。
- v7.2：Public Attestation。
- v7.3：Attestation Registry。
- v7.4：Attestation Portal Snapshot。

这些版本都把自己的 smoke 加进了 `song_agent/release_checks.py`。目前 `release-check` 仍然是一个大函数顺序执行：

```text
run pytest -q
git diff --check
git status
remote token check
config ignore check
version consistency
secret scan
final export smoke
edit smoke
v1.2 smoke
...
v7.4 smoke
```

这个结构的问题已经很明显：

1. 全量 release-check 变得很慢。
2. 某个 smoke 变慢时没有清晰耗时报告。
3. 失败时很难只复跑失败项。
4. 最新版本 hotfix 经常只能跑定向集合，缺少统一机器可读证据。
5. 旧版本 smoke、全量 pytest、最新证明链路 smoke 的风险等级没有区分。
6. duplicate ZIP warning 等预期 warning 混在输出里，影响判断。
7. GitHub 网络核验不稳定时，缺少“网络失败”和“代码失败”的清晰分类。

v7.5.0 必须先解决这些工程问题，否则后面的 v7.6、v7.7 再继续做外部门户、公开索引、审查响应，只会让验证成本继续失控。

---

## 2. v7.5.0 目标

新增 Release Check Verification Matrix。

目标能力：

1. `release-check` 支持 profile / group / since / only 选择。
2. 每个检查项都有稳定 ID、分组、风险等级、版本标签、默认 timeout、预期 warning 说明。
3. 每个检查项记录耗时、状态、失败原因、输出尾部。
4. 支持 JSON 报告输出，方便 reviewer 和开发留档。
5. 支持列出所有检查项，不执行。
6. 支持复跑失败项。
7. 保留原来的默认 full release-check 语义，不降低发布门槛。
8. 最新版本的 critical smoke 可以独立快速跑完。
9. GitHub remote/tag/release 核验作为独立 check，网络失败必须和代码失败区分。
10. release-check 自己也要有单元测试和 smoke 测试。

---

## 3. 非目标

v7.5.0 不做以下事情：

- 不删除旧版本 smoke。
- 不降低 `python -m song_agent.cli release-check` 的默认严格度。
- 不把失败项改成 warning 来“让发布通过”。
- 不引入外部 CI 服务。
- 不依赖 GitHub Actions。
- 不引入 pytest-xdist 等新依赖。
- 不改变业务模块的 verifier 语义。
- 不重写所有历史 smoke 的业务逻辑。
- 不把 `release-check` 变成只跑最新版本。
- 不把 GitHub token 写进 remote URL、日志、报告或文档。

v7.5.0 是本地化验证体系重构，不是云端 CI 建设。

## 6. 数据结构设计

### 6.1 Check Definition

每个检查项用结构化定义表示。

建议 dataclass：

```python
@dataclass(frozen=True)
class ReleaseCheckDefinition:
    check_id: str
    name: str
    group: str
    version: str | None
    kind: str
    risk: str
    timeout_seconds: int
    callable_name: str | None = None
    command: list[str] | None = None
    expected_warnings: list[str] = field(default_factory=list)
    description: str = ""
```

字段说明：

- `check_id`：稳定机器 ID，例如 `v74.attestation_portal_smoke`。
- `name`：人类可读名称，例如 `v7.4 release portfolio governance attestation portal smoke`。
- `group`：分组，例如 `core`、`git`、`security`、`v7`、`governance`、`portal`、`audio`。
- `version`：关联版本，例如 `7.4`，基础检查可为空。
- `kind`：`pytest`、`smoke`、`git`、`security`、`remote`、`meta`。
- `risk`：`critical`、`high`、`normal`、`diagnostic`。
- `timeout_seconds`：单项超时时间。
- `callable_name`：历史 smoke 函数名。
- `command`：外部命令，例如 `python -m pytest -q`。
- `expected_warnings`：预期 warning 模式，例如 duplicate ZIP entry。
- `description`：简短说明。

### 6.2 Check Result

建议结果结构：

```python
@dataclass
class ReleaseCheckRunResult:
    check_id: str
    name: str
    group: str
    version: str | None
    kind: str
    risk: str
    status: str
    ok: bool
    duration_ms: int
    detail: str = ""
    stdout_tail: str = ""
    stderr_tail: str = ""
    warnings: list[str] = field(default_factory=list)
    expected_warning_matches: list[str] = field(default_factory=list)
    started_at: str = ""
    finished_at: str = ""
```

`status` 允许：

```text
passed
failed
warning
skipped
timed_out
network_error
not_selected
```

注意：

- `network_error` 只能用于 remote 类检查。
- `warning` 不能替代 failed。
- `critical` / `high` 的 `warning` 是否阻断，由 profile 决定。

### 6.3 Report Schema

JSON 报告建议：

```json
{
  "schema_version": 1,
  "app_version": "7.5.0",
  "profile": "latest",
  "groups": ["v7", "portal"],
  "repo_root": "...",
  "started_at": "2026-06-10T00:00:00+08:00",
  "finished_at": "2026-06-10T00:05:00+08:00",
  "duration_ms": 300000,
  "ok": true,
  "summary": {
    "total": 8,
    "passed": 8,
    "failed": 0,
    "timed_out": 0,
    "network_error": 0,
    "skipped": 0,
    "slowest": [
      {"check_id": "v74.attestation_portal_smoke", "duration_ms": 168000}
    ]
  },
  "environment": {
    "python": "3.x.x",
    "platform": "Windows",
    "git_head": "...",
    "git_branch_status": "## master...origin/master"
  },
  "results": []
}
```

报告必须脱敏：

- remote URL token。
- GitHub token。
- OpenAI / provider key。
- 本机 token 文件路径。
- `C:\Users\...\Documents\projects\githubkey.txt`。

## 7. CLI 设计

### 7.1 保留旧命令

必须继续支持：

```powershell
python -m song_agent.cli release-check
```

默认行为：

- 等价于 `--profile full`。
- 仍然跑全量 pytest。
- 仍然检查 git status。
- 仍然检查 secret scan。
- 仍然跑所有历史 smoke。
- 失败退出码 1。

### 7.2 新增参数

建议：

```powershell
python -m song_agent.cli release-check --profile latest
python -m song_agent.cli release-check --profile v7
python -m song_agent.cli release-check --profile quick
python -m song_agent.cli release-check --group portal
python -m song_agent.cli release-check --since 7.0
python -m song_agent.cli release-check --only v74.attestation_portal_smoke
python -m song_agent.cli release-check --list
python -m song_agent.cli release-check --json
python -m song_agent.cli release-check --report-out runs\release-check-v750.json
python -m song_agent.cli release-check --timing-out runs\release-check-timing.json
python -m song_agent.cli release-check --fail-fast
python -m song_agent.cli release-check --timeout-seconds 900
```

参数语义：

- `--profile full`：默认全量。
- `--profile latest`：当前版本核心检查，v7.5 发布时应包含基础 meta + v7.4 + v7.5。
- `--profile v7`：v7.0 到当前版本所有 v7 smoke。
- `--profile quick`：不跑全量 pytest，只跑版本一致、git 状态、secret scan、最新 smoke。
- `--profile publish`：发布前推荐组合，包含 full 或可配置为 full + remote。
- `--group <name>`：按分组筛选。
- `--since <version>`：从某版本开始筛选，例如 `--since 6.5`。
- `--only <check_id>`：只跑一个或多个检查项，可逗号分隔。
- `--list`：列出检查项，不执行。
- `--json`：stdout 输出 JSON。
- `--report-out <path>`：写 JSON 报告。
- `--timing-out <path>`：写轻量 timing report。
- `--fail-fast`：第一项失败立即停止。
- `--timeout-seconds <n>`：覆盖单项默认 timeout，但不能低于 10 秒。

### 7.3 不建议第一版做的 CLI

暂不做：

```powershell
--parallel
--retry
--rerun-failed-from
--baseline-report
```

原因：

- 并行会影响临时目录、HTTP server、端口和全局 `.musicforge` 测试隔离，风险较高。
- 自动 retry 容易掩盖真实 flake。
- baseline diff 后面可以做 v7.5.1 或 v7.6。

## 8. Profile 设计

### 8.1 full

用于最终发布前。

包含：

- `pytest.full`
- `git.diff_check`
- `git.status`
- `git.remote_token`
- `git.musicforge_configs_untracked`
- `git.musicforge_configs_ignored`
- `meta.version_consistency`
- `security.secret_scan`
- 所有历史 smoke。

等价旧版 release-check。

### 8.2 quick

用于开发日常自测。

包含：

- `git.diff_check`
- `meta.version_consistency`
- `security.secret_scan`
- `smoke.final_export`
- `smoke.edit`
- 最新版本 smoke。

不包含：

- 全量 pytest。
- 所有历史 smoke。
- remote check。

### 8.3 latest

用于 hotfix 或当前版本 reviewer 验收。

v7.5.0 时包含：

- `meta.version_consistency`
- `security.secret_scan`
- `git.diff_check`
- `v74.attestation_portal_smoke`
- `v75.release_check_matrix_smoke`
- v7.4.1 回归对应定向 pytest。

### 8.4 v7

用于公开证明链路回归。

包含：

- v7.0 Final Board。
- v7.1 Evidence Vault。
- v7.2 Public Attestation。
- v7.3 Attestation Registry。
- v7.4 Portal Snapshot。
- v7.5 Release Check Matrix。

### 8.5 publish

用于正式发布。

建议初版等价 `full`，后续可追加 remote/tag/release check：

- full。
- `remote.origin_master_match_head`。
- `remote.tag_exists`。
- `remote.latest_release_matches_tag`。

remote 类检查失败时要区分：

- `network_error`：GitHub 连接失败。
- `failed`：远端确实不一致。

发布前如果 remote 是 `network_error`，开发必须说明使用了哪种替代核验方式，例如 GitHub API 或 `curloptResolve`。

## 10. release_checks.py 改造方案

### 10.1 当前问题

现在 `run_release_checks()` 是线性硬编码：

```python
report.add("pytest", ...)
report.add("git diff --check", ...)
...
report.add("v7.4 release portfolio governance attestation portal smoke", *_v74_release_portfolio_governance_attestation_portal_smoke(root))
```

v7.5 不建议删除这些函数。改造方式：

1. 保留所有 `_vXX_..._smoke(root)` 函数。
2. 新增 `CHECK_DEFINITIONS`，把每个 smoke 映射为定义。
3. `run_release_checks()` 委托 runner。
4. `print_release_check_report()` 保持兼容，但新增 duration 输出。

### 10.2 兼容旧测试

现有测试里直接 import：

```python
from song_agent.release_checks import ReleaseCheckReport, print_release_check_report
```

不能破坏。

建议：

- `ReleaseCheckReport` 可以扩字段，但保留 `.results` 和 `.ok`。
- `CheckResult` 可以扩字段，但保留 `name`、`ok`、`detail`。
- `print_release_check_report(report)` 继续可用。

### 10.3 新 runner

建议函数：

```python
def run_release_check_matrix(
    *,
    repo_root: Path | None = None,
    profile: str = "full",
    groups: list[str] | None = None,
    since: str | None = None,
    only: list[str] | None = None,
    run_tests: bool | None = None,
    fail_fast: bool = False,
    timeout_seconds: int | None = None,
) -> ReleaseCheckReport:
    ...
```

旧函数：

```python
def run_release_checks(*, run_tests: bool = True, repo_root: Path | None = None) -> ReleaseCheckReport:
    return run_release_check_matrix(
        repo_root=repo_root,
        profile="full",
        run_tests=run_tests,
    )
```

## 11. 单项超时设计

当前 `_run()` 没有 timeout。v7.5 必须补。

建议：

```python
def _run(command: list[str], cwd: Path, timeout_seconds: int | None = None) -> CompletedProcess[str]:
    ...
```

如果 timeout：

- 返回 `status=timed_out`。
- detail 写明 `timed out after Ns`。
- 不能抛未捕获异常。

对 callable smoke：

- 用 `threading` 很难安全终止。
- 第一版可以只对 subprocess check 加 timeout。
- smoke callable 的耗时仍要记录。
- 如果要对 callable 强制 timeout，建议暂缓，不要用不安全线程杀死。

推荐默认 timeout：

```text
pytest.full: 1800
git/security/meta: 60
latest smoke: 300
heavy v6/v7 smoke: 600
legacy smoke: 300
remote: 30
```

## 12. 预期 warning 处理

当前 release-check 里有 duplicate ZIP entry 的 Python warning，这是安全测试刻意构造重复 entry。

v7.5 要做：

1. 报告里显示 warning。
2. 如果匹配 `expected_warnings`，标记为 expected。
3. expected warning 不影响 check ok。
4. unexpected warning 默认不阻断，但在 JSON 中记录。

不要简单吞掉 warnings。它们是诊断信息。

## 13. GitHub Remote Check 设计

新增 remote 检查，但不要让它默认阻断本地验证。

建议检查项：

```text
remote.origin_master_match_head
remote.version_tag_matches_head
remote.latest_release_matches_tag
```

实现策略：

1. 优先用普通 git：

```powershell
git ls-remote origin refs/heads/master refs/tags/v7.5.0^{}
```

2. 如果失败，返回 `network_error`，detail 写明错误尾部。
3. 不在 v7.5 内自动读取 `githubkey.txt`。
4. 不在 v7.5 内自动调用 GitHub API。
5. 不把 `curloptResolve` 固化进代码。

原因：

- token 文件是本机私有流程，不应写进通用检查。
- GitHub 网络失败和代码失败要分开。
- 真正发布时，开发仍可用既有手工方法或 API 方法补远端核验。

## 14. JSON / Timing 报告

### 14.1 report-out

命令：

```powershell
python -m song_agent.cli release-check --profile latest --json --report-out runs\release-check-latest.json
```

要求：

- stdout 输出 JSON。
- `report-out` 写同一份 JSON。
- 即使失败也写报告。
- 退出码仍按 `report.ok` 决定。

### 14.2 timing-out

命令：

```powershell
python -m song_agent.cli release-check --profile v7 --timing-out runs\release-check-v7-timing.json
```

内容：

```json
{
  "profile": "v7",
  "duration_ms": 123456,
  "slowest": [
    {"check_id": "v74.attestation_portal_smoke", "duration_ms": 168000}
  ],
  "results": [
    {"check_id": "...", "status": "passed", "duration_ms": 1234}
  ]
}
```

timing report 用于定位慢项，不要求包含完整 stdout。

## 15. v7.5 自身 Smoke

新增 `_v75_release_check_matrix_smoke(root)`。

必须覆盖：

1. `--list` 能列出 v7.4 / v7.5 check。
2. `profile=latest` 只选择 latest 范围，不跑所有历史 smoke。
3. `--only v75.release_check_matrix_smoke` 能只跑单项。
4. `--group portal` 能选择 portal 相关项。
5. `--since 7.0` 能选择 v7.0 到 v7.5。
6. JSON report 包含 duration、summary、results。
7. failing fake check 会让 report.ok=false，退出码 1。
8. timeout fake subprocess 会产生 `timed_out`。
9. expected warning 会被记录但不阻断。
10. report redaction 能隐藏 token /本机 token path。

注意：v7.5 smoke 不要真的再跑一遍 full release-check，否则会造成递归和超时。

## 19. 安全要求

1. 报告不得输出 token。
2. 报告不得输出 `githubkey.txt` 明文路径。
3. 报告不得输出 provider key。
4. remote URL 必须脱敏。
5. `--json` 输出也必须脱敏。
6. `--report-out` 文件也必须脱敏。
7. `--list` 不应读取本机 secret。
8. remote check 不应自动读取 GitHub token。
9. expected warnings 只能标注，不应隐藏原始安全失败。

## 21. 验收标准

v7.5.0 可以发布的标准：

1. 旧命令 `python -m song_agent.cli release-check` 仍可执行。
2. `--profile latest` 能在合理时间内完成。
3. `--profile v7` 能输出每项耗时。
4. `--list` 能列出所有 check。
5. `--only` 能只跑指定 check。
6. `--group portal` 能筛出 Portal 相关 check。
7. `--since 7.0` 能筛出 v7.0+ check。
8. `--json` 和 `--report-out` 输出完整 JSON。
9. `--timing-out` 输出 slowest list。
10. 失败 check 会导致退出码 1。
11. timeout check 会标记 `timed_out`。
12. expected duplicate ZIP warning 被记录但不误报失败。
13. secret scan / report redaction 通过。
14. README / CHANGELOG / version 一致。
15. 工作区干净。
16. tag / Release 发布后远端可核验；如果 GitHub 网络失败，必须记录替代核验方式。


然后：

```powershell
git add .
git commit -m "feat: add release check verification matrix"
git tag -a v7.5.0 -m "v7.5.0"
git push origin master
git push origin v7.5.0
```

如果普通 GitHub push 失败，只能使用已经确认过的安全方式：

- 一次性 `git -c http.curloptResolve=github.com:443:<可用IP> ... push ...`
- 或 GitHub API，token 只走 header。

禁止：

- 把 token 写进 remote URL。
- 把 token 写进代码。
- 把 token 写进 README / material。
- 把 token 打印进 release-check report。

## 25. 最终结论

v7.5.0 应该优先做 Release Check Verification Matrix。

当前项目功能已经足够复杂，继续往公开证明外部门户方向推进之前，必须先让发布验证可观测、可拆分、可复跑。开发交付 v7.5.0 时，不要求全量 release-check 一定永远小于某个固定时间，但必须做到：

- 哪里慢可以看见。
- 哪里失败可以定位。
- 最新关键链路可以独立验收。
- full release-check 仍然保留。
- JSON 证据可以交给 reviewer 留档。

这一步做完，后续版本才能继续安全加速。

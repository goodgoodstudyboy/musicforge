# v5.2.0 Arrangement Mix Controls 编曲混音控制与 Stem 音频体检施工图

日期：2026-05-26

角色定位：reviewer / planner

当前稳定基线：v5.1.0

目标版本：v5.2.0

---

## 1. 背景

v5.0.0 完成真实 WAV 基线：

- Renderer Profile
- WAV Audio Health
- Audio Artifact Manifest
- Release Audio QA
- `verify-release --require-audio`

v5.1.0 完成逐曲人工音频听审证据：

- 每首 Release Track 绑定当前 WAV 的 manual accepted review。
- `require_per_track_audio_review=true` 可阻断缺失、stale、synthetic-only、tampered evidence。
- marker 可以创建 ReviewTask。

现在系统已经能回答：

> 每首歌是否真的渲染成了 WAV？是否有人听过当前 WAV？

下一步要回答：

> 如果听审说“鼓太大”“贝斯太低”“副歌不够亮”“某轨太抢”，系统能不能用最小修改动作修掉，而不是重新生成整首歌？

这就是 v5.2.0 的核心：**基础编曲混音控制层**。

---

## 2. 版本定位

v5.2.0 要做的是 MusicForge 的第一层“可控混音”：

- 给 SongPlan / Project Version 增加稳定的 Mix Controls。
- 支持 track-level volume / pan / mute / solo / velocity scale。
- 支持 section-level track automation。
- 支持基于 mix patch 重新渲染 MIDI / WAV。
- 支持 Stem MIDI/WAV 的健康检查。
- 支持从 Release Audio Review marker 创建 Mix Patch draft。
- 支持 A/B audition 对比 before / after。
- 支持 Release Signoff 要求当前音频 review 基于最新 mix。

这版不是专业 DAW，不追求插件链、EQ、压缩、母带。它只解决最常见的本地自动作曲系统问题：

- 哪条轨太响？
- 哪条轨太小？
- 哪条轨需要靠左/靠右？
- 哪一段需要降低密度？
- 哪一段需要让 hook 更突出？

---

## 3. 明确不做

v5.2.0 不做：

- 不做 EQ / compressor / reverb / delay 插件系统。
- 不做 LUFS 精准响度标准化。
- 不做母带处理。
- 不做多格式导出，MP3/AAC 放 v5.4。
- 不做外部 DAW 工程导出。
- 不做 AI 自动混音替代人工判断。
- 不做 vocal、人声、歌词演唱。
- 不做自动 apply 听审建议，所有修改仍然 manual apply。

v5.2 只做 deterministic、可审计、可回滚的基础 mix controls。

---

## 4. 为什么现在做 Mix Controls

v5.1 之后，人工听审 marker 会越来越多：

- 00:38 鼓太大。
- 01:12 bass 抢主旋律。
- 副歌 hook 不够亮。
- bridge 太空。
- outro 过长且能量不足。

如果每个 marker 都触发完整重新生成，风险很大：

- 可能破坏原来已经通过的部分。
- 版本差异太大，review 成本增加。
- 很难证明“只修了这个问题”。

Mix Controls 可以把一部分反馈变成小范围可控 patch：

- drums velocity -12%
- bass volume -2 dB
- melody volume +1.5 dB
- chords pan -20
- section chorus drums density 0.85

这样更符合工程化创作流程。

v5.2.0 完成后，系统应该支持：

1. Project Version 有可持久化 Mix State。

8. Studio 提供 Mix Board。

10. release-check 增加 v5.2 smoke。

## 6. 核心概念

### 6.1 Mix State

Mix State 是某个 Project Version 的混音控制状态。

它不直接改变 SongPlan 的旋律/和声/结构，而是给 tracks 和 sections 增加播放控制：

- volume_db
- pan
- mute
- solo
- velocity_scale
- section automation

### 6.2 Mix Patch

Mix Patch 是一次修改动作：

- 对某条 track 调整 volume。
- 对某条 track 调整 pan。
- 对某个 section 的某条 track 调整 velocity scale。
- mute / solo。
- 重置某个 track。

Patch 可以 preview，也可以 apply 成新 Project Version。

### 6.3 Mix Render

Mix Render 是把 SongPlan + Mix State 应用后生成：

- mixed MIDI
- mixed WAV
- stem MIDI
- stem WAV
- audio health
- stem health

### 6.4 Stem Health

Stem Health 是针对每条 stem 的音频体检：

- 是否存在。
- 是否静音。
- 是否削波。
- 时长是否和 full mix 接近。
- 是否和 track note count 匹配。

## 9. Mix State 结构

建议结构：

```json
{
  "schema_version": 1,
  "project_id": "project-000001",
  "version_id": "v001",
  "mix_state_id": "mixstate-000001",
  "base_song_plan_hash": "...",
  "base_midi_hash": "...",
  "tracks": [
    {
      "track_id": "track-001",
      "role": "drums",
      "name": "Drums",
      "volume_db": -1.5,
      "pan": 0,
      "mute": false,
      "solo": false,
      "velocity_scale": 0.92
    }
  ],
  "section_automation": [
    {
      "section_id": "section-003",
      "track_id": "track-001",
      "volume_db_delta": -2.0,
      "velocity_scale": 0.85
    }
  ],
  "source": {
    "created_from": "default",
    "parent_mix_state_id": null,
    "review_id": null,
    "marker_id": null
  },
  "source_hash": "...",
  "integrity_hash": "...",
  "created_at": "...",
  "updated_at": "..."
}
```

### 9.1 参数范围

必须限制：

- `volume_db`: -36.0 到 +12.0
- `pan`: -100 到 +100
- `velocity_scale`: 0.0 到 2.0
- `mute`: boolean
- `solo`: boolean

### 9.2 语义

- volume_db 影响该 track 所有 note velocity。
- velocity_scale 进一步缩放 velocity。
- mute 让该 track notes velocity 为 0 或直接移除渲染。
- solo 如果有任意 track solo=true，则非 solo track mute。
- pan 对 MIDI CC10 写入事件；如果当前 MIDI writer 支持不足，v5.2 先写入 track metadata，并在 MIDI writer 加最小 CC10。
- section automation 只影响 section 范围内 note。

## 11. 应用 Mix 到 SongPlan / MIDI

### 11.1 Velocity 计算

建议：

```text
linear_gain = 10 ** (volume_db / 20)
final_velocity = clamp(round(original_velocity * velocity_scale * linear_gain), 1, 127)
```

如果 mute：

- 该 track notes 不进入渲染，或者 velocity=0 且 MIDI writer 不写 note_on。

### 11.2 Section Automation

对于每个 note：

- 找 note.start_beat。
- 找所在 section。
- 如果 section + track 有 automation，叠加 volume delta / velocity scale。

### 11.3 Pan

MIDI CC10：

```text
pan -100 -> CC10 0
pan 0    -> CC10 64
pan +100 -> CC10 127
```

如果当前 renderer/midi writer 支持 program change，应该可以在 track 开始处写 CC10。

### 11.4 Solo

如果任意 track solo=true：

- 只渲染 solo track。
- non-solo track 在 full mix 中静音。
- stem render 不受 solo 影响，除非用户请求 solo render。

## 12. Stem Audio Health

### 12.1 StemHealthReport

建议结构：

```json
{
  "schema_version": 1,
  "report_id": "stemhealth-000001",
  "project_id": "project-000001",
  "version_id": "v002",
  "mix_state_hash": "...",
  "full_mix_wav_sha256": "...",
  "status": "passed",
  "stems": [
    {
      "stem_id": "stem-drums",
      "track_id": "track-001",
      "role": "drums",
      "note_count": 128,
      "midi_sha256": "...",
      "wav_sha256": "...",
      "audio_health_status": "passed",
      "duration_seconds": 92.3,
      "rms": 0.14,
      "peak": 0.77,
      "warnings": []
    }
  ],
  "blockers": [],
  "warnings": [],
  "source_hash": "...",
  "integrity_hash": "..."
}
```

### 12.2 检查规则

必查：

- 有 note 的 track 必须有 stem MIDI。
- 如果要求 stem WAV，有 note 的 track 必须有 stem WAV。
- 有 note 的 stem WAV 不应 silent。
- stem WAV duration 应接近 full mix。
- stem health report 被篡改后 signoff 失败。

可警告：

- 某 stem RMS 远高于其他 stem。
- 某 stem peak 接近 clipping。
- 某 stem duration 偏短但不是完全错误。

## 13. Audio Review Marker -> Mix Patch

v5.2 要让 v5.1 的逐曲听审 marker 变得可操作。

### 13.1 规则映射

输入：

```json
{
  "category": "mix_balance",
  "message": "鼓太大",
  "mapped": {
    "section_id": "section-003",
    "section_role": "chorus"
  }
}
```

输出 Mix Patch draft：

```json
{
  "operations": [
    {
      "op": "set_section_track_velocity_scale",
      "section_id": "section-003",
      "track_id": "track-drums",
      "velocity_scale": 0.85
    }
  ]
}
```

### 13.2 文本关键词

确定性规则即可：

- “鼓太大 / drums loud / kick loud”：drums velocity_scale 0.85
- “bass 太大 / bass muddy”：bass volume_db -2.0
- “melody 太小 / hook weak”：melody volume_db +1.5
- “太空 / too sparse”：chords or pad volume_db +1.0，不自动添加 note
- “太吵 / too busy”：section all non-melody velocity_scale 0.9

必须允许用户修改 draft，不允许自动 apply。

### 13.3 API

```text
POST /api/releases/<release_id>/audio-reviews/<review_id>/markers/<marker_id>/mix-patch-draft
```

响应：

```json
{
  "ok": true,
  "patch": {},
  "explanation": "Detected mix_balance marker; suggested lowering drums in chorus."
}
```

## 20. 安全与完整性

### 20.1 Hash

必须有：

- mix_state.source_hash
- mix_state.integrity_hash
- mix_patch.source_hash
- mix_patch.integrity_hash
- mix_preview.manifest_hash
- stem_health.source_hash
- stem_health.integrity_hash

### 20.2 Stale

以下变化导致 stale：

- base song-plan 变。
- base MIDI 变。
- mix-state 被篡改。
- mix-patch 被篡改。
- renderer profile 变。
- stem WAV 被改。
- per-track audio review 对应 WAV 被 mix apply 后替换。

### 20.3 路径安全

所有 preview/render/stem 文件必须在 Project 目录下。

下载接口必须校验：

- preview id 格式。
- manifest current。
- path relative to expected root。

### 20.4 脱敏

Mix Patch source 可能来自 review marker，必须脱敏：

- marker.message
- review notes
- reviewer name
- task title/instruction

## 22. release-check v5.2 smoke

必须新增：

```text
v5.2 arrangement mix controls smoke
```

流程：

1. 创建 Project。
2. 生成 version v001。
3. 创建 default mix state。
4. 创建 patch：drums volume -3dB，melody +1dB。
5. 创建 mix preview。
6. 验证 MIDI velocity 改变。
7. 渲染 preview WAV，audio health passed。
8. apply 成 v002。
9. Final Export 包含 mix-state / mix-patch。
10. 创建 Release。
11. 对当前 WAV 做 per-track audio review accepted。
12. Release Signoff require audio + per-track review passed。
13. 从 audio review marker 创建 mix patch draft。
14. Stem health valid。
15. 篡改 mix-state，signoff 或 verifier failed。
16. 篡改 stem-health，signoff failed。

输出示例：

```text
v5.2 arrangement mix controls smoke: ok
  project=project-000001, preview=mixprev-000001, version=v002, stem_health=passed, sign=200, tamper=409
```

## 24. Reviewer P1 检查清单

必须检查：

- Mix Patch 是否能越界修改任意文件。
- mix preview 是否会覆盖父版本。
- apply 是否创建 child version，而不是改父版本。
- mute / solo 是否真的影响 MIDI。
- volume_db 是否做范围限制。
- pan 是否写入 MIDI 或至少进入 manifest。
- section automation 是否只影响目标 section。
- mix-state 被篡改后 signoff/verifier 是否失败。
- per-track audio review 是否因 mix apply 后 WAV 改变而 stale。
- signed Release 是否还能重建 mix/audio。
- stem-health 是否能被删除/篡改后绕过。

---

## 25. Reviewer P2 检查清单

需要检查：

- 多 track 同名 role 时 marker draft 是否选错 track。
- drums 太大这种关键词是否有可解释 mapping。
- solo 状态是否不污染 stem render。
- stem WAV missing 时 warning 还是 failed 的口径是否和 gate 一致。
- Studio A/B 播放是否引用 current preview。
- release-check 是否不依赖真实 SoundFont。

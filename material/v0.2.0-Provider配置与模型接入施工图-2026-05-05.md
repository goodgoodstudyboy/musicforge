# MusicForge v0.2.0 施工图：Provider 配置与模型接入

日期：2026-05-05

## 0. 当前状态

v0.1.2 已经完成并发布。当前能力是：

- 本地 MusicForge Studio 面板。
- 本地 deterministic composer。
- 单 job 创建、预览、hide/unhide、cancel、delete。
- Timeline / Tracks / Validator / SongPlan JSON / Logs / Artifacts tabs。
- Startup recovery。
- CLI 旧用法和 `generate` 子命令。
- 测试基线：`51 passed`。

v0.2.0 的目标不是做多 agent，也不是做批量生成。v0.2.0 只解决一件事：

让 MusicForge 可以在保持本地 deterministic 默认能力的前提下，配置 provider，并通过 provider 生成结构化 `SongPlan`，最终仍然落到当前的 validator 和 MIDI render 链路。

## 1. v0.2.0 完成定义

v0.2.0 完成后必须满足：

- 没有 provider 配置时，当前本地生成仍然可用。
- 面板能保存、读取、重置 provider 配置。
- API key 不明文回显。
- 面板能测试 provider 配置。
- 每个 provider job 会写入 masked provider snapshot。
- 用户可以选择 `local` 或 `provider` 生成模式。
- provider 模式会让模型输出结构化 `SongPlan`。
- 模型输出必须通过 `SongPlan.from_dict()` 和 `validate_song_plan()`。
- provider 失败时 job 标记 failed，server 不崩。
- 测试不依赖真实网络。
- README、CHANGELOG、版本号更新到 `0.2.0`。
- 每完成一个合适小包，都要 commit 并 push GitHub。

## 2. v0.2.0 不做什么

明确不做：

- 不做 batch。
- 不做多 agent 图编排。
- 不做歌词、和声、旋律、编曲拆分 agent。
- 不做 critic/repair loop。
- 不做 WAV/MP3。
- 不做远程访问鉴权。
- 不引入大型前端构建链。
- 不要求 CI 或测试访问真实 provider。
- 不把真实 API key 写入仓库。

如果开发发现必须扩大范围，应先停下来汇报。

## 4. 配置存储设计

配置文件建议：

```text
.musicforge/provider.json
```

`.musicforge/` 必须保持在 `.gitignore` 中。

### 4.1 ProviderConfig 字段

建议数据结构：

```python
@dataclass(frozen=True)
class ProviderConfig:
    base_url: str = ""
    wire_api: str = "openai_chat_completions"
    api_key: str = ""
    model: str = ""
    light_model: str = ""
    review_model: str = ""
    gateway_profile: str = ""
    reasoning_effort: str = ""
    service_tier: str = ""
    timeout_seconds: int = 60
    max_retries: int = 1
    max_output_tokens: int = 4000
```

字段说明：

- `base_url`：provider API 根地址。
- `wire_api`：线协议，第一版支持 `openai_chat_completions` 和 `mock` 即可。
- `api_key`：只存在本地配置文件中，不写入 job state。
- `model`：主模型，用于 SongPlan 生成。
- `light_model`：轻量模型，v0.2.0 可先保存不使用。
- `review_model`：review 模型，v0.2.0 可先保存不使用。
- `gateway_profile`：网关 profile，先保存，后续需要时放入请求 header 或 metadata。
- `reasoning_effort`：先保存，具体是否传给 provider 由 wire_api 决定。
- `service_tier`：先保存，具体是否传给 provider 由 wire_api 决定。
- `timeout_seconds`：HTTP 超时。
- `max_retries`：请求失败重试次数。
- `max_output_tokens`：模型输出上限。

### 4.2 Public / masked 配置

任何 API 响应、job state、日志中都不能出现明文 API key。

`GET /api/provider` 返回示例：

```json
{
  "configured": true,
  "config": {
    "base_url": "https://api.example.com/v1",
    "wire_api": "openai_chat_completions",
    "api_key_set": true,
    "api_key_masked": "sk-...abcd",
    "model": "example-main-model",
    "light_model": "example-light-model",
    "review_model": "example-review-model",
    "gateway_profile": "",
    "reasoning_effort": "",
    "service_tier": "",
    "timeout_seconds": 60,
    "max_retries": 1,
    "max_output_tokens": 4000
  }
}
```

mask 规则建议：

- 空 key：`api_key_set=false`，`api_key_masked=""`。
- 长度小于等于 8：显示 `"***"`。
- 长度大于 8：显示前 3 位 + `...` + 后 4 位。

### 4.3 Provider snapshot

每个 provider job 写入：

```text
runs/<job-id>/data/provider-snapshot.json
```

示例：

```json
{
  "mode": "provider",
  "base_url": "https://api.example.com/v1",
  "wire_api": "openai_chat_completions",
  "model": "example-main-model",
  "api_key_set": true,
  "api_key_masked": "sk-...abcd",
  "captured_at": "2026-05-05T00:00:00+00:00"
}
```

禁止：

- 不写明文 `api_key`。
- 不写完整 Authorization header。
- 不写完整 provider 原始响应，如果响应可能包含敏感内容。

## 6. Provider API 设计

### 6.1 GET /api/provider

用途：读取 masked provider 配置。

成功响应：

```json
{
  "configured": true,
  "config": {
    "base_url": "https://api.example.com/v1",
    "wire_api": "openai_chat_completions",
    "api_key_set": true,
    "api_key_masked": "sk-...abcd",
    "model": "example-main-model",
    "timeout_seconds": 60,
    "max_retries": 1
  }
}
```

### 6.2 POST /api/provider

用途：保存 provider 配置。

请求：

```json
{
  "base_url": "https://api.example.com/v1",
  "wire_api": "openai_chat_completions",
  "api_key": "sk-example",
  "model": "example-main-model",
  "timeout_seconds": 60,
  "max_retries": 1
}
```

响应：

```json
{
  "ok": true,
  "config": {
    "base_url": "https://api.example.com/v1",
    "wire_api": "openai_chat_completions",
    "api_key_set": true,
    "api_key_masked": "sk-...mple",
    "model": "example-main-model"
  }
}
```

校验：

- `timeout_seconds` 必须在 5 到 300。
- `max_retries` 必须在 0 到 5。
- `max_output_tokens` 必须在 256 到 16000。
- `wire_api` 只允许已支持值。
- `base_url` 可为空，但 provider test 和 provider job 必须要求它存在。
- `api_key` 可为空，但 provider test 和 provider job 必须要求它存在，mock 除外。

### 6.3 POST /api/provider/reset

用途：删除 `.musicforge/provider.json`。

响应：

```json
{
  "ok": true,
  "configured": false
}
```

注意：

- 不清除环境变量。
- 如果 env 仍然存在，`GET /api/provider` 仍可能显示 configured。

### 6.4 POST /api/provider/test

用途：测试 provider 配置。

请求可为空，默认测试当前 effective config。

成功响应：

```json
{
  "ok": true,
  "provider": {
    "wire_api": "openai_chat_completions",
    "model": "example-main-model",
    "base_url": "https://api.example.com/v1",
    "api_key_set": true
  },
  "message": "Provider test completed."
}
```

失败响应：

```json
{
  "error": "Provider config is incomplete: api_key is required."
}
```

测试要求：

- 单元测试使用 mock，不访问真实网络。
- 真实 provider test 可以作为手工验收，不作为自动测试必要条件。

## 7. Job API 变化

`POST /api/jobs` 请求新增字段：

```json
{
  "title": "Provider Song",
  "language": "zh",
  "style": "city pop",
  "theme": "rainy night",
  "duration_seconds": 120,
  "generation_mode": "provider"
}
```

允许值：

```text
local
provider
```

默认值：

```text
local
```

行为：

- `generation_mode=local`：走当前 deterministic composer。
- `generation_mode=provider`：走 provider-backed SongPlan 生成，再复用 validator 和 MIDI render。
- provider 配置不完整时，job 可以直接创建失败返回 400；也可以创建 job 后标记 failed。建议第一版采用创建前 400，用户体验更直接。

错误示例：

```json
{
  "error": "Provider config is incomplete: model is required."
}
```

job state 中建议写入：

```json
{
  "provider_snapshot": {
    "mode": "provider",
    "wire_api": "openai_chat_completions",
    "model": "example-main-model",
    "api_key_set": true,
    "api_key_masked": "sk-...abcd"
  }
}
```

## 8. Provider-backed SongPlan 生成

### 8.1 输入

输入仍然是 `SongRequest`：

```json
{
  "title": "Rainy Convenience Store",
  "language": "zh",
  "style": "city pop, soft rock",
  "theme": "rainy night memory",
  "duration_seconds": 120,
  "vocal_mode": "guide_melody",
  "tempo_bpm": 92,
  "key": "C major",
  "lyrics": null
}
```

### 8.2 输出

模型必须输出严格 JSON object，结构对齐 `SongPlan`：

```json
{
  "title": "Rainy Convenience Store",
  "key": "C major",
  "tempo_bpm": 92,
  "meter": "4/4",
  "sections": [
    {
      "name": "intro",
      "start_bar": 1,
      "bars": 4,
      "chords": ["Cmaj7", "Am7", "Dm7", "G7"],
      "lyrics": null
    }
  ],
  "tracks": [
    {
      "name": "Melody",
      "instrument": "lead synth",
      "notes": [
        {
          "pitch": 64,
          "start_beat": 0,
          "duration_beats": 1,
          "velocity": 90
        }
      ]
    }
  ]
}
```

### 8.3 解析策略

第一版必须严格：

- 只接受 JSON object。
- 不从一大段自然语言里猜 JSON。
- `json.loads()` 失败则 provider job failed。
- `SongPlan.from_dict()` 失败则 provider job failed。
- `validate_song_plan()` 失败则 provider job failed。

不要在 v0.2.0 做复杂 repair。repair loop 放到 v0.3.0。

### 8.4 Prompt 文件

建议新增：

```text
song_agent/prompts/provider_song_plan.md
```

提示词要求：

- 明确要求只输出 JSON。
- 明确列出 SongPlan schema。
- 明确 MIDI 约束，例如 pitch 0-127、velocity 1-127、duration > 0。
- 明确不要输出 Markdown。
- 明确不要输出解释。

提示词中不要写 provider key、真实账号或本机路径。

## 9. Provider client 设计

建议接口：

```python
class ProviderClient(Protocol):
    def generate_song_plan_json(
        self,
        request: SongRequest,
        config: ProviderConfig,
    ) -> dict[str, Any]:
        ...
```

实现：

```text
MockProviderClient
OpenAICompatibleClient
```

### 9.1 MockProviderClient

用途：

- 单元测试。
- provider UI smoke。
- 不访问网络。

行为：

- 返回一个固定但合法的 SongPlan dict。
- 可以通过参数模拟非法 JSON、schema 错误、网络错误。

### 9.2 OpenAICompatibleClient

第一版支持：

```text
wire_api = openai_chat_completions
```

请求目标通常是：

```text
{base_url}/chat/completions
```

注意：

- 具体 provider 可能要求不同 header 或 path，先用 `wire_api` 隔离。
- 不要把项目绑死在某一家 provider。
- timeout 必须生效。
- response 非 2xx 必须转成可读错误。
- response JSON 缺字段必须转成可读错误。
- 不把完整 Authorization header 记录到 logs。

## 12. 错误类型

建议新增：

```python
class ProviderError(Exception): ...
class ProviderConfigError(ProviderError): ...
class ProviderRequestError(ProviderError): ...
class ProviderResponseError(ProviderError): ...
class ProviderOutputError(ProviderError): ...
```

错误映射：

- 配置缺失：400。
- provider 网络失败：job failed。
- provider 非 2xx：job failed。
- provider 输出不是 JSON：job failed。
- provider JSON 不符合 SongPlan：job failed。
- provider test 失败：API 返回 JSON error，不影响 server。

```powershell
rg -n "C:\\\\Users|githubkey|ghp_|github_pat_|sk-[A-Za-z0-9]|api_key\\s*[:=]|access_token\\s*[:=]" README.md CHANGELOG.md material song_agent tests pyproject.toml
```

允许：

- 代码字段名 `api_key`。
- 文档中安全检查命令。
- 测试中的假 key，例如 `sk-test`.

不允许：

- 真实 key。
- 本机私有 token 文件路径。
- 带 token 的 remote URL。
- 真实账号写进公开发布说明。

如果发现疑似 secret：

- 先不要 push。
- 移除 secret。
- 如果已经提交但未推送，重写本地提交。
- 如果已经推送，必须立即轮换 key，并重写公开历史或做安全处置。

## 17. Reviewer 核验重点

reviewer 检查 v0.2.0 时重点看：

- local 模式是否完全不受影响。
- provider 配置是否永远 masked。
- `.musicforge/provider.json` 是否没有进 Git。

# v12.5.0 Unified Release Program Continuity / Recovery Drill 项目级灾备恢复演练与连续性准出施工图

> 建议下一版：v12.5.0  
> 当前稳定基线：v12.4.0  
> 核心目标：把 v12.4 的 Vault Operations 从“证据总库已受控托管”推进到“证据总库可在隔离环境恢复、重放、深度复验、形成连续性签核”。v12.5 不再新增一个孤立证据包，而是做 Program 级灾备恢复演练与连续性准出，证明 Program 的最终证据链在离开原工作区、只持有 Vault Operations Archive 的情况下仍可恢复验证。

---

## 1. 背景

v12.0 到 v12.4 已经完成 Program 级最终治理链路：

- v12.0：Unified Release Program Board，聚合多个 Release Train Handoff，形成 Program 准出。
- v12.1：Program Operations Center，提供 Program CR、safe runbook、continuous review、lifecycle audit。
- v12.2：Program Final Handoff Board，提供外部交接验收、accepted evidence、quorum 和 handoff archive。
- v12.3：Program Evidence Vault，把 Program / Operations / Handoff / accepted evidence 封存为可离线深度复验的 Vault。
- v12.4：Vault Operations，建立 Vault Registry、Custody Policy、runtime custody review、transfer pack、custody signoff、长期托管 archive。

v12.4 能回答：

> “当前 Program Evidence Vault 是否已经进入受控托管状态，并且当前 Vault ZIP / anchor / verification report / signoff binding 仍匹配？”

但真正的长期交付还缺下一层：

1. 如果原 `.musicforge/` 工作区损坏，只持有 Vault Operations Archive，能否恢复验证？
2. 如果审计方拿到 archive，是否能在隔离目录里重放 Program / Operations / Handoff / Vault 验证？
3. 如果 Vault Operations Archive 自身被污染，能否在恢复演练阶段发现？
4. 如果恢复脚本不小心写回 live workspace，是否会破坏已签核证据？
5. 如果历史 evidence 里仍夹带本机路径或敏感文本，恢复包是否会阻断？
6. 如果恢复演练只读旧 verification report，不真正 deep verify，是否会被伪造包骗过？
7. GA / Release gate 现在可以要求 Vault Operations passed，但还不能证明“灾备可恢复”。

所以 v12.5 建议进入：

**Unified Release Program Continuity / Recovery Drill**

中文名：

**项目级灾备恢复演练与连续性准出**

---

## 2. 版本定位

### 2.1 一句话

v12.5 是 Program 级连续性与灾备演练层：它从当前 Vault Operations Archive 出发，在隔离恢复目录里执行只读 deep restore / replay / verification，生成 Recovery Drill Report、Continuity Runbook、Continuity Readiness、签核和固定结构 Continuity Archive，并把结果接入 Release / GA gate。

### 2.2 和 v12.4 的关系

v12.4：

- 管理 current Vault generation。
- 周期复验 Vault ZIP、anchor、verification report。
- 生成 transfer pack。
- 签核 Vault Operations Archive。

v12.5：

- 不替代 v12.4。
- 不修改 v12.4 archive。
- 以 v12.4 signed archive 作为唯一可信输入。
- 在隔离目录验证“从 archive 恢复并复验”的能力。
- 生成 continuity signoff 和 continuity archive。

### 2.3 本版要解决的问题

1. 建立 Program Continuity Policy。
2. 支持 Recovery Drill Plan。
3. 支持 isolated restore drill：
   - 从 Vault Operations Archive 复制到临时目录。
   - 校验外部 Vault Operations verification report。
   - 校验外部 signoff binding。
   - 解包固定 allow-list entry。
   - 重新 deep verify v12.3 Vault。
   - 重新 verify Program / Operations / Handoff / accepted evidence。
   - 重建 replay manifest。
   - 生成 recovery-drill-report.json。
4. 支持 Continuity Readiness Matrix：
   - source evidence current。
   - archive integrity passed。
   - isolated restore passed。
   - deep replay passed。
   - no secret/local path leakage。
   - no unresolved restore blockers。
   - no unsupported manual step pretending completed。
5. 支持 Continuity Runbook：
   - safe action。
   - manual required action。
   - recovery command sequence。
   - expected artifacts。
   - blocker remediation guidance。
6. 支持 Continuity Signoff：
   - 只允许 passed drill 签核。
   - 签核时写入独立 `continuity-signoff-binding-summary.json`。
   - 签核 history hash chain。
   - 删除 signoff 文件不能绕过已签核状态。
7. 支持 Continuity Archive ZIP：
   - 固定结构。
   - 不嵌入未允许的 ZIP。
   - 包含 drill report、readiness、runbook、restore manifest、signoff binding。
   - verifier 可以离线复验。
8. Release signoff / GA readiness 可要求：
   - `require_unified_release_program_continuity=true`
   - 绑定 Continuity Archive ZIP、verification report、signoff binding、源 Vault Operations Archive 证据。
9. release-check 新增 v12.5 smoke。

### 2.4 本版不做什么

v12.5 不做：

- 不做真实云备份。
- 不接入第三方时间戳服务。
- 不引入 PKI / 公钥签名。
- 不自动覆盖 live `.musicforge/`。
- 不自动 reset Program / Vault Operations。
- 不自动 approve Change Request。
- 不自动恢复用户工作区。
- 不做跨多个 Program 的 portfolio continuity。
- 不做外部 reviewer quorum。
- 不做网络拉取或上传。

如需外部远程锚点、第三方审计签名、跨 Program Continuity Dashboard，应放到 v12.6+。

## 3. 核心原则

### 3.1 恢复演练必须只读源证据

Recovery Drill 只能读取：

- Vault Operations Archive ZIP。
- Vault Operations verification report。
- Vault Operations signoff binding。
- 可选的原 Vault ZIP / anchor / verification report 外部路径。

禁止写入：

- 原 Program 目录。
- 原 Vault Operations 目录。
- 原 release workspace。

所有临时输出必须写入：

```text
.musicforge/unified-release-programs/<program_id>/continuity/
```

或测试专用 temp workspace。

### 3.2 Drill 不能信旧 report 自证

Recovery Drill 必须 runtime verify：

- Vault Operations Archive ZIP。
- Archive 内 manifest / index / signoff binding。
- Archive 绑定的 current Vault ZIP。
- Vault ZIP deep verification。
- nested Program / Operations / Handoff / accepted evidence packages。

旧 verification report 只能作为外部 evidence 参与绑定，不能单独判 passed。

### 3.3 外部 evidence manifest 是主入口

不要依赖 CLI 参数顺序。必须提供或内部生成：

```json
{
  "program_id": "urp-000001",
  "evidence": [
    {
      "evidence_type": "vault_operations_archive",
      "component_id": "vault-ops-current",
      "archive_zip": "...",
      "verification_report": "...",
      "signoff_binding": "..."
    }
  ]
}
```

匹配规则：

- `evidence_type`
- `component_id`
- `program_id`
- `zip_sha256`
- `zip_size_bytes`
- `manifest_hash`
- `verification_report_hash`
- `signoff_binding_hash`

### 3.4 Signoff binding 必须签核时独立落盘

`continuity-signoff-binding-summary.json` 必须在 signoff 创建时生成。

Archive / verifier 禁止从 `continuity-signoff.json` 现读现算。

Verifier 必须能用外部 binding proof 反查：

- signed_by。
- role。
- reason。
- signed_at。
- signoff hash。
- history latest event hash。
- recovery drill report hash。
- readiness hash。
- runbook hash。
- source Vault Operations Archive hash。

### 3.5 签核后不可变

签核后：

- `refresh_policy` -> 409。
- `run_drill` -> 409。
- `refresh_readiness` -> 409。
- `generate_runbook` -> 409。
- `signoff` -> 409。
- `export_archive` -> 409，除非未创建且只复制 frozen snapshot。
- `build_archive_zip` -> 409，除非未创建且只打包 frozen export。

删除 `continuity-signoff.json` 不能绕过。必须读取 `continuity-history.jsonl` 判断当前签核状态。

v12.5 不做 reset。后续如果需要 reset，必须单独设计 approved Change Request reset。

### 3.6 恢复目录必须有 containment

所有解包必须：

- 使用新建 temp root。
- 拒绝绝对路径。
- 拒绝 `..`。
- 拒绝 raw backslash entry。
- 拒绝 `.musicforge/` 或大小写变体直接写入外层。
- 拒绝 trailing bytes。
- 拒绝 duplicate ZIP entry。
- 拒绝符号链接或特殊文件。
- 解压前做 total uncompressed size limit。
- 解压后确认每个 resolved path 在 temp root 内。

### 3.7 不允许假 completed

Continuity Runbook 的 action 状态只能是：

- `completed`
- `blocked`
- `manual_required`
- `skipped_unsupported`
- `not_run`

未实现的 safe action 必须是 `skipped_unsupported`，不能假装 `completed`。

## 7. Continuity Archive ZIP 固定结构

ZIP 文件：

```text
unified-release-program-continuity-archive.zip
```

固定 allow-list：

```text
manifest.json
README.txt
continuity-policy.json
external-evidence-summary.json
recovery-drill-plan.json
restore-manifest.json
replay-verification-report.json
recovery-drill-report.json
continuity-readiness.json
continuity-runbook.json
continuity-signoff.json
continuity-signoff-binding-summary.json
continuity-history.jsonl
file-index.json
redaction-report.json
```

不嵌入：

- Vault Operations Archive ZIP。
- Program Vault ZIP。
- nested Program ZIP。

原因：

- v12.5 的 archive 是 continuity evidence，不是 evidence vault copy。
- 真正的 source Vault Operations Archive 必须作为外部证据传入 verifier。
- 避免 archive 内再嵌套大 ZIP，降低 spoof / stale 风险。

如确需“离线一包全带”，应放到 v12.6 的 Continuity Distribution Kit。

## 8. Verifier 必查项

### 8.1 ZIP 基础安全

Verifier 必查：

- ZIP exists。
- ZIP readable。
- raw central directory no backslash。
- no duplicate entry。
- no trailing data。
- no absolute path。
- no `..`。
- no `.musicforge/` 或大小写变体。
- no nested ZIP。
- fixed allow-list exact match。
- manifest.files exact match。
- file-index exact match。
- file hash match。
- uncompressed total size under limit。

### 8.2 Manifest

`manifest.json` 必须包含：

```json
{
  "package_type": "musicforge_unified_release_program_continuity_archive",
  "program_id": "urp-000001",
  "source_hash": "...",
  "files": [],
  "zip": {
    "filename": "unified-release-program-continuity-archive.zip",
    "entry_count": 14,
    "entries": []
  },
  "integrity_hash": "..."
}
```

不要写自证式 ZIP sha / size。ZIP sha / size 必须由外部 verification report 记录。

### 8.3 Report 绑定

必须验证：

- policy hash。
- external evidence manifest hash。
- restore manifest hash。
- replay verification hash。
- drill report hash。
- readiness hash。
- runbook hash。
- signoff hash。
- signoff binding hash。
- history latest event hash。

### 8.4 外部 Vault Operations 绑定

当 `require_current_vault_operations=true` 时，必须传入：

- `--vault-operations-archive`
- `--vault-operations-verification-report`
- `--vault-operations-signoff-binding`

Verifier 必须 runtime verify Vault Operations Archive，并交叉比对：

- archive ZIP sha256。
- archive ZIP size。
- archive manifest hash。
- verification report hash。
- verification report package_type。
- verification status。
- signoff binding hash。
- signoff binding signer/role/reason。
- continuity external evidence summary。
- continuity signoff binding summary。

### 8.5 Deep restore

当 `--deep-restore` 时，verifier 必须：

1. 先完成 ZIP preflight。
2. 若 preflight 有 blocking failure，禁止 deep extraction。
3. 新建 temp root。
4. 复制外部 Vault Operations Archive 到 temp root。
5. 运行 Vault Operations verifier。
6. 从 Vault Operations Archive 中定位 current Vault evidence。
7. 运行 v12.3 Vault verifier `--deep --require-anchor`。
8. 输出 replay summary。
9. 清理 temp root 或保留脱敏路径摘要。

### 8.6 Redaction

扫描所有文本 JSON / TXT：

- Windows drive path。
- UNC path。
- `.musicforge` 内部绝对路径。
- `sk-...`。
- `api_key=...`。
- `token=...`。
- GitHub token-like strings。
- local username path。

发现即 failed。

### 8.7 Signoff full-resign 防护

必须覆盖攻击：

1. 篡改 `continuity-signoff.json` 的 signed_by。
2. 重算 signoff integrity。
3. 篡改 `continuity-history.jsonl`。
4. 重算 manifest / file-index。
5. 不更新外部 `continuity-signoff-binding-summary.json`。

Verifier 必须 failed。

Smoke detail 建议：

```text
signoff_full_resign=failed
```

## 15. 安全边界

### 15.1 不能信的东西

Verifier 不能只信：

- continuity archive 内的 report。
- continuity archive 内的 external evidence summary。
- old Vault Operations verification report。
- manifest.files 任意声明。
- file-index 任意声明。
- signoff JSON 自身。
- history JSONL 自身。

### 15.2 必须外部绑定的东西

必须外部传入或由 runtime 读取：

- source Vault Operations Archive ZIP。
- source Vault Operations verification report。
- source Vault Operations signoff binding。
- Continuity signoff binding。

### 15.3 不允许的绕过

必须阻断：

- 删除 signoff 文件后重签。
- 签核后重跑 drill 覆盖 report。
- 签核后 export 重新计算 frozen docs。
- Archive ZIP 加 extra benign txt 后重签 manifest。
- nested ZIP spoof。
- raw backslash entry。
- ZIP trailing data。
- temp extraction path escape。
- local path / token redaction leakage。

## 20. 给开发的话

v12.5 的重点不是再造一个“看起来 passed 的 JSON 包”，而是证明 v12.4 交付出去的 Vault Operations Archive 真能在隔离环境恢复和重放。实现顺序建议是：

1. 先做 verifier 和 restore drill，不要先做 UI。
2. Drill 必须 runtime verify v12.4 archive 和 v12.3 Vault，不能只读旧 report。
3. 所有外部证据用 manifest 按 type/id/hash 匹配，不要靠 CLI 参数顺序。
4. signoff binding 必须签核时独立落盘，archive 只能复制，不能现算。
5. 签核后所有会改变 drill/readiness/runbook/source 的动作都要 409。
6. release-check smoke 必须先覆盖 full-resign、source tamper、trailing bytes、raw backslash、signed mutation，再谈 happy path。

如果这版做稳，v12 系列就从“Program 证据可封存”真正推进到“Program 证据可长期恢复和演练”，这是比继续加单点证据更有价值的一步。
